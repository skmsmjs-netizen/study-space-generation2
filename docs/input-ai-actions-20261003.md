# 입력을 사용하는 GPT 도움 · 2026-10-03

사용자 요청: 기존 입력 자리에서 AI 도움(제안 1), 풀이 검토→재연습(제안 4), 실제 웹앱 입력 활용 기능을 구현하고 기존 Pages에 배포한다.

## 실제 사용 경로

| 입력 자리 | 행동 | 기본 작업 |
| --- | --- | --- |
| 공부 기록 작성 | 작성 중인 기록으로 GPT 도움 | 필기 정리 |
| 저장된 기록 | 이 기록으로 GPT 도움 | 설명·논리 검토 |
| 자유 글 | 이 글로 GPT 도움 | 설명·논리 검토 |
| 빠른 메모 | 이 메모로 GPT 도움 | 필기 정리 |
| 코드 연습 | 코드·실행 기록 검토 | 코드·실행 검토 |
| 과목 상세 | 최근 기록 묶음 돌아보기 | 기록 변화 돌아보기 |
| 자료의 힌트·답안 검토·재연습 결과 | 이 답안 검토 준비 / 다른 맥락의 재연습 준비 | 실제 문제·풀이·판단 기준 재사용 |

각 자리에서 기존 공통 Modal을 열고 닫으면 작성하던 입력과 초점으로 돌아간다. 작업 13종을 선택하고 명시적인 실행 버튼에서만 기존 generateStudyMaterial을 호출한다. 자료 열기·입력 갱신·저장·후속 작업 준비에는 생성 호출이 없다.

과목 회고는 같은 소유자·과목의 최근 기록·글·메모 최대 20개를 사용한다. 전체 기간 분석이라고 표현하지 않는다. 전역 메모·무관한 과목·삭제 자료·생성 도움을 저장한 자료는 자동으로 포함하지 않는다. 기존 기록 가져오기에서 사용자가 추가할 자료를 확인·선택한다. 없는 문제 번호·개념 관계·실패·숙달을 만들어 선정하지 않는다.

## 기존 기준과 구현 재사용

프로젝트의 architecture 책임 분리, 작업 진행 정책의 위험 비례 확인, 기능 추천의 현재 입력·선정 부담 기준과 학습 의미 보존을 적용했다. 기존 owner AI 권한, study-ai-request의 구조화된 요청, material-files의 소유자별 IndexedDB 초안, saveStudyMaterial 명령/충돌 버전, ContextPicker 및 StudyResultText를 재사용한다. 별도 API·서버 권한·DB/RPC 변경 없이 기존 운영 study-openai-api를 호출한다. 이번에 추가한 부분은 입력 사본 어댑터, 공통 도움 창, 후속 요청 준비 및 해당 화면 진입점이다. 자체 기능 설계를 학습 효과가 검증된 방법으로 표현하지 않는다.

## 보존과 반복 사용

- 원래 입력을 수정하지 않고 위치·식별자·가져온 시각을 포함한 원문 사본으로 요청한다. 공백·줄바꿈·결합 문자와 이모지를 보존한다.
- 입력 사본, 실제 문제·풀이·기준, 모든 생성 결과를 독립 초안으로 보관한다. 재접속 시 유료 호출 없이 이어 읽는다. 초안 보관이 실패하면 생성 전에 멈추고 다시 보관/파일 내보내기 경로를 둔다.
- 생성 실패·중단은 입력과 기존 결과를 유지한다. 자동 재시도하지 않는다. 닫으면 생성 중단을 요청하고 원래 과업으로 돌아간다.
- 자료 저장은 같은 materialId와 expectedVersion을 재사용한다. 저장 실패 뒤 중복 자료를 만드는 대신 같은 ID로 재시도한다. 서버 전송 성공을 로컬 자료 보관으로 대신 보고하지 않는다.
- 과목 미지정 코드·글은 과목을 임의로 고르지 않는다. 원문 사본을 기기에 보관한 뒤 결과 보관 과목을 직접 선택한다.
- 원문 갱신 후 이전 결과의 후속 작업을 선택하면 생성 당시 원문과 현재 사본의 차이를 확인하고 멈춘다. 이전 GPT 결과를 새 정답 기준으로 자동 채택하지 않는다.
- 원래 문제·풀이·판단 기준으로 같은 원리의 재연습을 준비하며 문제와 답·해설을 접힌 별도 구역에 둔다. 기존 결과도 선택해 다시 볼 수 있고 자료에서 편집할 수 있다.
- 입력 15만 자/기존 결과 30개 상한을 알리고 원본을 유지한다. 저장한 결과와 현재 내용이 같을 때만 새 도움을 시작해 기존 자료를 보존한다.

## 확인 범위

분리 작업본에서 앱 타입/생산 빌드와 백엔드 빌드 통과. 백엔드 빌드의 무관한 생성 파일은 배포 변경에서 제외했다. 관련 단위/컴포넌트 18개 통과(핵심 새 검사 6개 재확인). 새 격리 브라우저 흐름은 iPhone 세로·가로/iPad 세로·가로·절반 창의 5개 WebKit 환경에서 모두 통과했다. 생성 횟수, 원문 보존, 실제 풀이의 후속 재사용, 접힌 해설, 저장 실패/같은 ID 재시도, reload 복구, 외부 요청 없음, 문서 가로 넘침 없음이 대상이다. 네이티브 브라우저에서 검토→재연습의 실제 표시도 확인했다.

합성 생성기를 사용한 프론트엔드 확인이며 실제 유료 생성/운영 저장·서버 Sync·물리 기기의 키보드/VoiceOver·장기 사용·학습 효과 검증과 구별한다. 민석 전용 AI 권한을 유지한다. 필수 CI와 공개 자산/브라우저 확인 결과는 실제 완료 뒤 이 문서와 인계에 연결한다.
