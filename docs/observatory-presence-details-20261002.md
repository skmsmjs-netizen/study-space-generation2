# 천문대 안에 머무는 경험 — 세부 설계 조사

> **현행 확정 기준 — 2026-10-02:** 사용자 「여기까지, ux, ui, 디자인 기준으로 값을 정해둬라」에 따라 합의된 값·공간·문구 원칙은 [천문대 디자인 기준](observatory-design-standard.md)과 [기준값 JSON v2.0.0](observatory-experience-baseline.json)으로 확정했다. 이 문서는 근거·세부 접점·당시 확인 범위를 보존한다. 이전 ‘후보/제안’ 표시는 조사 당시 지위이며 현행 기준과 충돌하면 최신 기준을 적용한다. JSON의 `workSurfaceColors`는 수학 런타임의 이전 색상 호환값이다. `pixelTreatment`는 v2에도 채택한 단일 공통 원본이며 기존 수학 소비자도 재사용한다. 수치는 프로젝트 기본값이며 국제표준이나 존재감 연구가 지정한 최적값이 아니다. **기준 확정과 앱 전체 구현·검증·배포는 별도이다.**

확인일: 2026-10-02. 사용자 요청: 「그런 디테일들을 더 조사해봐. 그런 게 반영되면 이걸 사용하는 사람은, 마치 저 천문대 안에 있는 느낌을 받는 거지.」

상태: **원 연구·제작자 설명·공식 설계 지침과 앱 접점을 대조한 연구 이력 및 확정 기준의 근거**. 실제 사용자에게 천문대 안에 있다는 감각을 유발했거나 공부 효과를 높였다는 검증은 아니다. 이 조사·기준 정리에서 생산 코드·개인 자료·배포를 변경하지 않았다. 홈의 창틀·책상은 후속 [실내 구현 기록](observatory-interior-20261002.md)에서 확인 범위를 관리하며, 전체 네 방향·종이 작업면·v2 값 소비는 별도로 구별한다. 기존 [정체성 대응안](observatory-identity-20261001.md), [MAN-18](https://linear.app/manseeksong/issue/MAN-18)에 이어진다.

후속 공간 정정: 창문 앞 책상과 왼쪽/오른쪽/뒤쪽 기능 배치는 [방향별 기능 배치](observatory-spatial-workspace-20261002.md)에서 관리한다. 이 문서의 디테일은 그 하나의 실내 공간과 현재 사용 과업에 연결한다.

## 1. 이번에 더 구체화한 판단

**사용자가 계속 같은 장소에서 도구를 다루고 있다는 일관성을 만든다.** 화면마다 천문대를 설명하기보다 바깥 풍경·안쪽 책상·자료·관측 도구가 같은 시간과 재료, 위치, 동작 규칙을 공유하도록 설계한다. 문구는 이 관계를 짧게 드러낸다. 천문대가 계속 확장되어도 내부 작업면과 표현의 규칙이 이어져야 한다.

구체적으로는 다음 경험을 목표로 한다. 이는 사용자의 실제 경험을 서술한 글이 아니라 **설계할 사용 장면**이다.

> 다시 들어오면 지난번 펼쳐 둔 자료와 적던 글이 같은 자리에 있다. 창밖 하늘은 지금 시간의 빛을 띤다. 한 주제를 고르면 그 자료가 작업면에 펼쳐지고, 다른 자료는 곁에서 다시 찾을 수 있다. 값을 조절하면 해당 도구가 반응하고 실제 그래프가 변한다. 기록을 남기면 저장 상태가 짧고 정확하게 표시된다. 전체로 돌아와도 방금 보던 대상이 어디였는지 알 수 있다.

이 장면의 요점은 **공간의 일관성, 행동과 결과의 연결, 시간과 흔적의 연속성**이다. 이 세 묶음은 여러 근거를 프로젝트에 맞게 정리한 해석이며 공식 심리 법칙이나 단일 표준의 이름이 아니다. 사진처럼 사실적인 3D나 이동 가능한 아바타를 전제하지 않는다. 픽셀 화면의 형태·층·반응과 직접 입력만으로도 설계할 수 있는 부분을 우선한다.

### 2.1 공간이 읽히고 행동이 이어져야 하는 이유

[Wirth 외의 공간적 존재감 모형](https://research.vu.nl/ws/portalfiles/portal/2250422/202481.pdf)은 공간의 머릿속 모형을 구성하는 것과 자신이 그 안에 있다고 느끼는 것을 구별한다. 이번 앱에서는 창틀이 먼 하늘을 가리고, 같은 광원이 책상과 기구의 같은 방향을 비추고, 가까운 작업면이 고정되어 있는 관계에 적용한다. 이론에서 가져온 설계 가설이며 이 웹앱에서 효과를 검증한 결과는 아니다. [Slater의 논의](https://pmc.ncbi.nlm.nih.gov/articles/PMC2781884/)도 데스크톱과 몰입형 VR의 존재감 응답을 같은 수준으로 비교하기 어렵다고 구별한다.

[Data Mountain 원 연구](https://www.microsoft.com/en-us/research/wp-content/uploads/1998/01/p153-robertson.pdf)는 고정 시점·개인 배치·제목·썸네일을 갖춘 데스크톱 문서 환경에서 재탐색을 살폈다. 현재 앱의 Canvas와 이어가기에는 이 연구가 다룬 ‘다시 찾을 단서’가 있다. 다만 연구에서도 각 요소의 독립 기여는 분리되지 않았으므로, 픽셀 그림이나 3D 자체가 재탐색을 개선한다고 해석하지 않는다.

[Worch·Smith의 환경 스토리텔링 발표](https://www.worch.com/files/gdc/What_Happened_Here_Web_Notes_Small.pdf)는 소품·배치·사용 흔적으로 공간의 이야기를 전달하는 제작 방법이다. 여기서는 사용자가 실제로 열었던 자료·남긴 질문·고른 배치가 그 흔적이다. 장면 속 의미를 해석할 여지는 있어도 조작에 필요한 단서는 명료해야 한다. [HUD 제거 연구의 공개 초록](https://pure.york.ac.uk/portal/en/publications/removing-the-hud-the-impact-of-non-diegetic-game-elements-and-exp/)에서도 FPS 경험 수준에 따른 조건부 결과를 보고한다. 천문대 그림에 모든 버튼을 숨기는 보편적 근거로 사용할 수 없다.

## 3. 실제 기능으로 연결할 24가지 디테일

다음은 기존 기준값과 구현을 바탕으로 한 적용 제안이다. **표의 장면을 이미 구현했다고 보고하지 않는다.** 새로운 효과마다 같은 행의 반복/실패 조건을 함께 구현해야 한다. 현재 재사용 경로와 연결이 더 필요한 부분은 [앱 접점 조사](../work/observatory-presence-20261002/app-touchpoints.md)를 따른다.

## 4. 문구를 실제 기능과 연결하는 방식

기본 목소리는 **차분함·호기심·정확함·존중**으로 둔다. 진입·회고에서는 호기심과 장소의 감각을 더하고, 저장·실패·권한에서는 정확함을 더한다. 이 네 단어는 Apple의 상황별 목소리 작업을 프로젝트에 맞게 적용한 제안이다.

문구는 개별 화면의 임의 상수가 되지 않게 `src/domain/brand.ts`와 기존 담당 카피 원본에서 역할별로 관리한다. 모든 상태를 무작위 문장으로 교체하지 않는다. 사용자 이름/날짜/학습 결과/마지막 방문을 사용한다면 실제 값·계정 범위·불확실성을 확인한다. 천문대가 감정이나 지능을 평가하는 인물처럼 말하거나 새 대화 상대를 만든다고 약속하지 않는다.

## 5. 확정 기본값과 조사·검증 이력

### 2026-10-02 후속 — 어두운 실내의 색감

사용자 「천문대 안은 어둡겠지. 약간 클로드 … 다크모드 UIUX 색감처럼」를 **낮은 채도의 따뜻한 먹색·짙은 회갈색 실내, 한 단계씩 밝아지는 도구 면, 부드러운 미백색 글자와 작은 황갈색 빛**으로 구체화했고 후속 기준 확정에 반영했다. 바깥의 남색·청색·보라 성운은 확장 천문대 원본을 유지한다. 실제 읽고 쓰는 내용에는 이후 요청한 크림색 종이 역할을 적용한다. 이전의 보라 기운이 강한 어두운 작업면 후보보다 이 현행 역할을 우선한다. 특정 Claude 화면에서 색을 추출한 결과가 아니다.

| 실내 역할 | 현행 확정값 | 사용 방식 |
| --- | --- | --- |
| 방 전체 바탕 | `#1F1E1B` | 저채도 먹색, 넓은 면 |
| 방 안의 기본 도구 면 | `#282722` | 바탕보다 조금 밝은 면. 실제 문서·기록의 종이 역할과 구별 |
| 떠 있는 도구·선택 면 | `#33312D` | 명도 단계로 앞뒤를 구별. 선택은 별도 표식/상태도 제공 |
| 본문·보조 글자 | `#E8E3D7` / `#B7B0A2` | 부드러운 밝음과 읽을 수 있는 보조 정보 |
| 장식선·필요한 조작 경계 | `#514A42` / `#8B8071` | 장식선을 입력의 유일한 경계로 사용하지 않음 |
| 초점·주요 행동의 작은 빛 | `#D7B477` | 넓은 패널 전체를 밝히지 않고 필요한 곳에 사용 |
| 주요 행동 hover·pressed·글자 | `#E5C890` / `#C2A062` / `#1F1E1B` | 상태별 대비와 눌림을 함께 제공 |

참고 확인: [Claude Code 공식 테마 설명](https://code.claude.com/docs/en/terminal-config#match-the-color-theme)은 터미널 자체의 색과 Claude Code의 테마 설정을 구별한다. 사용자에게서 정확한 참조 화면을 받지 않은 상태에서 위 값을 ‘Claude 공식 팔레트’라고 부르지 않는다. 기존 WCAG 대비 기준과 픽셀/조작 기준을 재사용하며, 어두운 분위기를 위해 글자·포커스까지 흐리게 만들지 않는다.

조사 당시 위 실내 색쌍의 불투명 sRGB 대비 계산: 세 바탕에서 본문10.14–13.02:1, 보조 글6.02–7.74:1, 필요한 조작 경계3.35–4.30:1, 주요 버튼 글자는 세 상태6.75–10.32:1이다. 관련 [글씨4.5:1](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)·[필수 비문자3:1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) 문턱을 충족한다. 작업면과 선택 면의 차이는1.15:1이므로 별도 선택 표시가 필요하다. 금색 버튼의 금색 포커스는 어두운 간격과 바깥선으로 분리한다. 이 계산은 실제 렌더링·투명도·모든 상태·제품 전체 접근성 검증이 아니다.

호환 이력: 수식 탐색의 `scripts/sync-math-observatory.mjs`는 `workSurfaceColors`와 `pixelTreatment.componentRadiusPx`를 소비한다. 이 중 `workSurfaceColors`만 이전 색상 호환값이며, `pixelTreatment`는 v2에도 그대로 채택한 단일 공통 원본이다. 책임은 JSON의 `sourceOwnership`에 따른다. **현행 실내/종이 색은 [새 기준 문서](observatory-design-standard.md)와 JSON의 `materials`를 따른다.** 초기 보조 `#60594D`와 경계 `#817565`는 선택 면 대비를 위해 조정한 과거값이다. 기준 확정이 생성기·제품 CSS의 새 색 소비를 뜻하지 않으며, 담당 작업면·전체화면의 실제 조합은 적용 단계에서 확인한다. 저장된 사용자 테마와 기존 장면·픽셀 애니메이션은 유지한다.

### 기존 수치와 동작 기본값

현행 [기준값 원본](observatory-experience-baseline.json)의 본문16px/1.65·label15px·caption14px·픽셀 계단2px·일반 radius0·대화상자2px·48/44px 조작·피드백120ms/방향 전환180ms·움직임 감소0ms를 확정 기본값으로 적용한다. 기존 눌림1px를 재사용하며, 이 수치는 프로젝트 선택이고 presence 연구의 최적 수치가 아니다. 확장 중 천문대의 장면 주기/FPS/시간대 계산은 현재 담당 소스가 결정한다.

색은 각각 **장소 안에서 맡는 역할**까지 정한다. 아래는 기존 팔레트를 세부 경험에 대응시킨 제안이며, 모든 색을 한 화면에 같은 면적으로 쓰거나 자동 테마 전환을 강제하는 기준이 아니다.

| 색·재료 | 공간과 기능에서 맡는 역할 | 일관성 조건 |
| --- | --- | --- |

가까운 창틀이 먼 하늘을 일부 가리고, 작업대 모서리와 기구 받침에 같은 방향의 빛이 닿으면 ‘화면 안의 우주’에서 ‘우주를 바라보는 내 자리’로 관점이 이동한다. 이는 이번 프로젝트의 시각 설계 해석이다. **픽셀성은 장면·도구 윤곽·작은 반응에서 유지하고 긴 한국어·수식의 글자까지 저해상도로 만들지 않는다.**

이번 조사에서 구체화한 운영 기본값 제안은 다음과 같다.

- **강제 진입 연출 0회:** 자료를 쓰기 전에 캐릭터 이동·실내 투어를 완료할 필요가 없다. 직접 과업으로 들어간다.
- **자료 변경 때문에 추가되는 화면 이동 0회:** 환경 피드백은 현재 과업 안에서 설명한다. 효과를 보기 위해 홈으로 강제 이동하지 않는다.
- **소리 기본 off:** 사용자가 켰을 때만 재생하며 실제 오디오 기능 도입 전 라이선스·브라우저 재생·음량 균형을 별도 확인한다. 특정 dB/주파수를 효용 근거 없이 정하지 않는다.
- **타이핑·자동 저장마다 장식 효과 0회:** 명시적 과업의 결과와 일반 자동 저장 상태를 구별한다. 동작 피드백은 실제 상태를 따른다.
- **새로 겹치는 장식 이벤트 대기열 0개:** 놓친 장식을 복귀 시 몰아 보여주지 않는다. 기존 천문대의 동시 효과 한도는 기존 소스의 계약을 확인하고 보존한다.
- **개인 배치 자동 초기화 0회:** 화면 크기 변경은 보이는 방식만 조정하며 개인 좌표/선택/글을 변경하지 않는다.

모든 장면에 적용할 사운드 재생 간격·공간 비율·이벤트 수를 임의의 보편값으로 확정하지 않는다. 실제 장면과 자료량에서 충돌하는 값이 있으면 원인과 적용 범위를 기록해 조정한다. 기존 기준도 정체성과 실제 사용 결과에 따라 수정할 수 있다.

## 6. 작은 동작을 끝까지 설계한 예

Dan Saffer의 네 부분을 사용해 ‘이전 자료 다시 펼치기’를 정리한다. 같은 형식을 문구·소리·모션만 따로 검토하는 일을 줄이는 데 사용한다.

| 부분 | 이번 앱의 구체 동작 |
| --- | --- |
| 시작 조건 | 사용자가 유효한 최근 자료의 `이어가기`를 선택 |
| 규칙 | 현재 계정·자료 존재·권한을 확인하고 현재 원문/초안/지원되는 읽던 위치를 연다 |
| 피드백 | 선택한 제목을 작업면에도 유지하고 짧은 펼침/강조로 출처 연결. 움직임 감소에서는 즉시 표시 |
| 반복/모드 | 같은 자료를 여러 번 열어도 소개 반복 없음. 정지·소리 설정 유지. 자료 삭제 시 빈 편집본 생성 없이 사실 안내와 선택 경로 제공 |

이렇게 작동해야 ‘책상에 두었던 자료를 다시 펼친다’는 비유가 실제 동작에 근거한다. 초안이나 위치를 복원하지 못하는 경로에서 복귀가 완성됐다는 문구부터 표시하지 않는다.

## 7. 우선 적용 순서와 확인

조사 당시 소스 대조는 12개 접점 중 **기존 경로 재사용8, 연결 추가3, 미확인1**로 기록했다. 이는 해당 조사 시점의 범위이며 후속 구현으로 자동 갱신된 집계가 아니다. 여기서 재사용은 코드 경로가 있다는 뜻이며 실제 장기 사용·물리 기기 확인을 뜻하지 않는다. 이후 홈의 `ObservatoryRoom`·`ObservatoryDesk` 창틀/책상 구현은 [실내 구현 기록](observatory-interior-20261002.md)을 따르고 전체 네 방향·종이 작업면·v2 소비 여부와 구별한다.

- **이미 연결할 기반:** 시간대별 하늘, 풍경 정지 선택, 최근 유효 자료·글 이어가기, 직접 남긴 다음 행동, 자료의 읽던 위치, 저장된 Canvas 배치·시점.
- **표현/기능 연결이 필요한 곳:** 천문대는 현재 홈에만 표시된다. 자료·기록 화면의 작은 창이나 공통 광원, 저장 상태와 픽셀 표시의 연결은 추가 구현이다. 일반 자료를 책상에 영구 고정하는 기능도 이번 담당 소스에서는 확인되지 않았다. 먼저 기존 이어가기로 목적을 충족하는지 본다.
- **보존 범위를 구별할 곳:** 자료 목록의 탭 상태, 경로별 위치, 실제 초안·원장은 저장 범위가 다르다. 그래프의 고정과 통계의 근거 고정은 방문 중 상태다. 현재 천문대 카메라 시점은 임시 상태이며 touch에서는 해당 포인터 탐색을 제공하지 않는다.

저장에 반응하는 연출은 특히 현재 상태 계약을 따라야 한다. 현재 구현에서 `await flush()`는 오류·충돌을 상태로 기록하고 끝날 수도 있으므로, 완료만으로 성공을 표시하지 않는다. 기존 편집기처럼 `getStatus().phase === 'saved' && pending === 0`을 확인하고, 전역 상태와 특정 글의 저장 전이를 구별한다. 구현 책임·관련 소스는 [앱 접점 조사](../work/observatory-presence-20261002/app-touchpoints.md)의 저장 절을 따른다.

1. **하던 자리의 연속성:** 홈→자료/기록→돌아오기에서 D04/D05/D12/D13을 묶는다. 기존 기능을 사용하며 경로별 원문·선택·위치의 복원 범위를 확인한다.
2. **보이는 도구와 실제 동작의 일치:** 수식/그래프/추천 중 한 실제 과업에서 D06/D07/D09/D11을 연결한다. 같은 값·대상·출처와 저장 상태를 유지한다.
3. **문구·빛·재료의 공통 적용:** D01/D02/D17–D19를 기존 공통 부품과 카피에 연결한다. 천문대 확장과 같은 원본을 따른다.
4. **선택한 감각 확장:** D20–D24를 실제 집중 과업에서 확인한 뒤 더한다. 주변 효과·오디오의 구현 비용과 반복 사용 부담을 확인한다.

확인은 세 층으로 나눈다.

- **과업:** 첫 사용자가 버튼 결과를 예상하는가, 원문을 수정하고 되돌아올 수 있는가, 저장/실패 상태를 정확히 이해하는가. 입력 중단·잘못된 대상 이동·초안 손실 같은 회귀는 허용하지 않는다.
- **장소의 감각:** 천문대라는 답을 미리 알려주지 않고 사용 후 어떤 공간이 떠오르는지, 무엇이 그렇게 느끼게 했는지 묻는다. 장소감의 자발적 설명과 단순히 예쁜 그림이라는 평가를 구별한다.
- **반복 사용:** 다음 방문·장문·누적 자료·좁은 화면·소리/모션 끔·그리기 실패에서도 과업과 복귀가 이어지는지 본다. 첫 감상·장기 사용·학습 성과는 별도 기록한다.

사용자 비교가 필요하면 동일 과업·자료로 순서를 바꾸어 문구/장면 변화의 영향을 비교한다. 과업 성공·오해·재찾기·방해를 함께 보고, 작은 정성 관찰을 통계적 효과 크기나 학습효과로 확대하지 않는다. presence 설문을 쓰더라도 2D 공부 앱에 그대로 검증된 척도인지는 별도로 판단한다.
