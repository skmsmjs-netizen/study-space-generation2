# 공부 기록 직접 입력·보수 · 2026-10-01

사용자 “너가 직접해봐. 입력해보고 보수작업해봐.” 요청에 따라 현재 웹앱의 여러 주제 기록→화면 이동→복귀→새로고침→저장과 저장 실패→초안 유지→재시도를 격리된 예시 공간에서 직접 실행했습니다. 실제 개인 공부 기록·계정·서버 자료를 수정하지 않았습니다. 공개 배포와 운영 서버 변경은 수행하지 않았습니다.

기존 공통 UI·Search·EmptyState·기록 초안/저장 인터페이스·보존 계약과 study-fix-issue/Browser 스킬을 재사용했습니다. 개발 파일 감시 설정은 [Vite 공식 server.watch](https://vite.dev/config/server-options#server-watch)를 확인해 적용했습니다. 기록·원문·ID·이력·저장 키와 병행 변경을 보존했습니다. 다른 화면에 새 범위 정책을 일괄 적용하지 않았습니다.

## 직접 확인한 결과

- 앱 브라우저에서 두 주제를 선택해 서로 다른 한국어 원문과 체크/미체크 상태 입력, 화면 이동·재접속 복원, 저장 후 표시를 확인했습니다. 긴 글1709자와 공백·줄바꿈을 유지했습니다.
- 명시적 격리 시험 페이지에서 실제 저장 명령의 localStorage 쓰기를 QuotaExceededError로 실패시켰습니다. 실패 안내·두 원문 유지·재시도 성공과 한국어 안내를 직접 확인했습니다. 시험 제어는 제품 화면에 추가하지 않았습니다.
- 공부 범위 밖의 주제를 초안에서 삭제하지 않으며, 검색에 숨겨진 선택도 계속 저장할 수 있습니다. 글만 남긴 기록은 공부함·정답·숙달로 자동 환산하지 않습니다.
- 가까운 기존 회귀와 추가 회귀4파일64검사 통과. 선택 범위·빈 검색·공간 부족 뒤 동일 회차 재시도·초안·수정 이력·부팅 복구를 포함합니다.
- 현재 공유 소스 타입 검사와 격리 사본의 npm run build(타입·디자인 검사 포함) 통과. 디자인26 CSS 파일 오류0. 공유 의존 파일 손상과 병행 수학/펜 타입 변경 중의 초기 실패는 로그에 보존했습니다. 별도 의존 사본과 병행 수정 반영 후 확인했으며 다른 작업의 코드를 되돌리지 않았습니다.
- iPhone17Pro 세로/가로, iPadPro13 세로/가로/좁은 창에서 각2흐름(두 주제 저장/복귀, 저장 실패/재접속/재시도)을 확인했습니다. 합성 원장 원문·done=true/false·동일 sessionId·중복 없음·초안 정리와 가로 넘침≤1px 확인. 초기 시험이 좁은 화면에 숨겨진 주 메뉴를 기다려2건 실패하여 표시되는 링크를 사용하도록 시험을 고쳤습니다. 큰 화면3환경6건은 초기 통과, 좁은2환경4건은 수정 후 통과입니다.
- 검사 당시 사본과 공유 소스의 RecordForm/message 본문을 공백 정규화 후 SHA256으로 대조해 일치했습니다. 앱 전체의 병행 기능·공개본 일치 확인으로 확대하지 않습니다.

재사용 회귀: `e2e/devices/records.pw.ts`가 기존 test:devices의 다섯 환경 목록에 포함됩니다. 이번 선택 실행 설정과 로그/화면은 `work/record-maintenance-20261001/`에 있습니다. 보수 확인용 빌드는 http://127.0.0.1:5437/?space=demo#/record 에서 열어 두었습니다.
