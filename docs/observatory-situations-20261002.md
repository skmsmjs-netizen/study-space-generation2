# 천문대 — 기존 상황마다 여섯 장면 추가

2026-10-02 사용자 「랜덤 상황도6가지 각각에6개씩 추가하라」를 여섯 시간대의 기존 여섯 상황 각각에 적용한다. 기존36장면을 보존하고216장면을 추가하여 총252장면이다. 시간대당 기존6+추가36=42장면, 한 상황당 원형1+추가6=7장면이다.

## 실제 연결과 보존

`domain/observatory-events.ts`의 `OBSERVATORY_EVENTS`는 기존36개의 ID와 의미를 유지한다. `OBSERVATORY_SITUATIONS`가 원형과 새 변형을 함께 제공하고 `baseId`, `variant:0..6`으로 대응한다. 새 ID는 `기존ID--1`부터 `--6`이다. `observatory-event-variants.ts`가216개의 표시 이름, `ui/observatory-event-variations.tsx`가 추가 형태와 운동을 맡는다. 실제 홈의 `StudyLandscapes → ObservatoryWorld → ObservatoryEvents`가 같은 목록을 사용한다.

기록·날짜·수면 입력을 추가하지 않는다. 수면/건강/능력/숙달을 추론하거나 장면의 개수를 공부 성과로 저장하지 않는다. 원문·ID·초안·이력·정지/층 선택의owner별 저장키와version1을 유지한다. 상황별 성장 제한도 새로 만들지 않으므로 기존12단계 모두에서 새216장면이 가능하다.

## 선택과 연속 반응

기존30분 상황 순열과 끝2분 smoothstep 교차, 시간대 경계의40분 혼합을 재사용한다. 하위 변형은 계정·시간대 발생일·원형ID를 바탕으로7일 묶음의 결정적 순열을 만든다. 원형과 여섯 변형이 모두 순환하고 같은 시간대의 여섯 상황을 다시 돌 때도 하위 변형을 옮긴다. 날짜·시각·계정이 같으면 재접속과 기록 수정으로 장면이 다시 뽑히지 않는다. 늦은 밤은 시작한 날을 기준으로 하여 자정에 임의 변경되지 않는다. 경계에서도 동시 상황은 최대3개이다.

공부 엔진의 `position`, 세 채널의 `recent/background/change`는 기존 식 그대로 개수·밝기·운동 폭·주기·색 농도에 연결한다. 개수의 소수 부분은 다음 입자의 투명도로 드러낸다. 단계가 그대로여도 미세한 엔진 변화가 표시값을 바꾸며 반올림 문턱을 추가하지 않는다. 상황 종류의 무작위 선택과 기록에 따른 표현 강도는 서로 다른 역할이다.

## 시각과 반복 사용

구름·광륜·기류·지형·항로·미세입자의 여섯 표현 계열에서 각 모티프의 여섯 변형에 다른 공간 배치·윤곽·운동을 적용한다. 이름·색만 바꾼 복제 대신 기존 고유 모티프를 갈라짐·겹침·마디·나선·방사·잔상 등에 연결한다. 지면의 안개/풀과 하늘의 별/구름은 기존 위치 역할을 유지한다. 기존 작은 픽셀·다홍/주황 팔레트·확대LOD·카메라·GPU/벡터 대체 경로를 재사용한다.

비교 화면 `work/pixel-daily-20261001/showcase.tsx`는 시간대6개 → 원형6개 → 장면7개로 모든252개에 접근한다. 한 번에252개의 하늘을 마운트하지 않고 선택한 한 묶음만 보여준다. 작은 카드는 확대하지 않으므로 `thumbnail` 모드에서 확대LOD/GPU 부분을 마운트하지 않고 기존SVG 장면과 운동을 보여준다. 크게 열거나 실제 홈에서 보면 기본 전체 렌더링을 사용한다. 화면 밖 운동/캔버스 중단, 사용자 정지/OS 모션 감소, 확대 보기·12단계 보기·재생을 유지한다. 이 비교 화면의 합성 기록을 개인 공부로 처리하지 않는다. 일반 홈에는 장면명·총점·설명 패널을 추가하지 않는다.

추가 장면의 정적 모양은 SVG `defs`에 한 번만 두고 슬롯별 `use`로 참조한다. 각 슬롯은 배치/소수투명도·운동·참조3노드이며 각 변형의 총 장식은 `16 + capacity × 3` 노드 이하이다. 초기 최대 성장 화면2268노드에서 기존2200미만 검사에 실패해 예산을 늘리지 않고 이 재사용으로 보수했다.

## 재사용한 근거와 한계

기존 조사·채택된 [SVG 픽셀 경계](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/shape-rendering), [WCAG Pause/Stop/Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html), 프로젝트의 `daily-study-landscapes.md` 및 `observatory-advanced-20261002.md`를 재사용한다. React Best Practices의 파생 계산/안정된ID/일시값분리/조건부 마운트를 적용한다. 별도 엔진이나 새 패키지 없이 기존 렌더러의 부족한 상황 구성만 직접 그렸다. 추가 형태·선택 주기·계수는 미술 및 표시 정책이며 물리 시뮬레이션의 정확성이나 학습 효과가 검증된 표준은 아니다.

## 첫 기록·최근 입력 밀도·확대 성능 보완

같은 날 후속 요청으로 `observatory-response.ts → StudyLandscape.response → observatory-reactivity.tsx`를 실제 홈과 비교 화면에 연결했다. `createdAt`의 한국 입력일과 고유 `[sessionId, subjectId, targetId]`만 사용한다. 소유자/범위/최신 수정본/삭제 선별은 기존 `buildStudyLandscape`가 담당한다. 공부 날짜 미상은 입력 시각이 알려져 있으면 보존하며, 입력 시각 자체가 미상 또는 미래이면 집계하지 않는다. 글 길이·수면·실제 공부 시간·숙달을 대신 추정하지 않는다.

입력일별 고유 수 `n_d`에서 최근 밀도 원값은 `r = (1-exp(-1/3)) Σ min(12,n_d) exp(-(D-d)/3)`이다. `density=1-exp(-r/2)`, 누적 첫 별빛 `earlyGlimmer=1-exp(-N/3)`, 천문대 조명 `activity=.25×earlyGlimmer+.75×density`이다. 지수 가중이라는 기존 EWMA 방법을 재사용하되 3일·하루12개 상한·포화 계수는 장식 정책이다. 관측된 입력 빈도이며 공부 시간당 성과나 검증된 보상 효과가 아니다. 최근 입력이 뜸해져도 누적 첫 별빛은 유지하며, 원장 정정·삭제·복원 시 실제 현재 입력으로 다시 계산한다.

0→1→2개에서 누적 별빛은0→.2835→.4866, 당일 입력 밀도는0→.1321→.2468이다. 하늘의 작은 별 수는 `min(8,2log2(1+N))`이고 소수 부분을 다음 별의 투명도로 표시한다. 하늘에 미세한 따뜻한 광량이 남으며 창문·창 밑 반사광은 activity, 돔 윤곽과 신호등의 이동광은 density를 그대로 읽는다. 실제 제품에는 점수나 설명 패널을 붙이지 않는다. 합성 비교 화면의 ‘첫 기록’에서0/1/2/6/12개를 같은 장면으로 비교한다.

머무름 확대가 시작되면 원점을 고정하고 이후 포인터 이동은 확대를 유지한 감쇠 패닝이다. 내부에서 드래그를 놓아도 유지하고, 바깥 이탈/취소/창 포커스 해제 시260ms 계수로 완만히 복귀한다. 정지/모션 감소/숨김/터치는 즉시 안정 상태이며 재진입은 복귀 중 시점을 이어받는다. 좌표/잔상 노드를 캐시하고 수렴 뒤 카메라 rAF를 중단한다. JS 보간과 겹친 CSS 전환을 제거했다.

국소 리뷰에서 기록/자정 갱신의 `response` 의존성이 포인터 연결을 다시 만들어 확대를 초기화하는 경로를 발견해 함께 수정했다. `updateResponse`로 연결 수명을 유지하며 관찰 중에는 시작 시점의 목표 배율을 사용하고 다음 관찰부터 최신 반응값을 읽는다. 표시되는 별/조명은 현재 원장을 즉시 반영한다. 실제 기록 추가·다음 입력일의 컴포넌트 재계산에서 반응값은 바뀌고 카메라/원점/정착 상태는 유지되는 검사를 연결했다.

하늘 전체에 걸린 변위 필터를 제거하고 근접 성운의 작은 영역에만 적용했다. 확대 상세에는 쌍성3·나선은하2·작은 성운3을 추가하고 기존 벡터 먼지는64→32개로 줄여 요소 예산을 유지했다. 셰이더는 중첩 수치 curl 대신 기존 CPU 흐름과 같은 해석적 curl을 조합하고3옥타브 노이즈를 한 번 계산한다. 소스 기준 픽셀당 노이즈 해시100→12회이며 실기기FPS 배율을 의미하지 않는다. 이동 중400px/정착640px와 실제 rAF 간격의 지연·회복 누적을 쓰고 짧은 변동에 해상도가 왕복하지 않게 한다.

GPU 연결의 `update`는 기록/시간 변경 때 GL/입자/카메라/장면 시계를 유지한다. 입자 버퍼를 재사용하고 실제 표시 수만 갱신한다. 초신성 WAAPI 시간은 시작/정지/모델 변경 때만 맞추며 프레임별 강제 시간 대입을 제거했다. 28초 파장은 실제 경과 시간을, 입자 적분은 제한된dt를 쓴다. 기존 Pointer Events/WAAPI/Filter Effects/WebGL2 기준을 재사용한 국소 수정이며 새 의존성이나 저장 필드가 없다.
