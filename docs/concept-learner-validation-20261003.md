# 개념 전집 — 실제 중학생 이해 확인 준비

2026-10-03 사용자 「해」에 따라 실제 중학생의 이해를 확인할 수 있는 로컬 평가 꾸러미를 작성했다. **현재 준비 완료, 실제 참여자 0명·실제 응답 0개다.** 합성 검사와 내용 검토를 실제 독자의 이해 성공으로 바꾸지 않는다. Figma/기기/접근성 작업은 다른 담당 결과와 구별한다.

## 바로 사용할 결과

[참가자 화면](../work/concept-completion-20261003/learner/participant.html), [진행자 안내](../work/concept-completion-20261003/learner/facilitator-guide.md), [진행자 전용 평가 키](../work/concept-completion-20261003/learner/assessment-key.md), [응답 구조](../work/concept-completion-20261003/learner/response.schema.json), [평가 서식](../work/concept-completion-20261003/learner/assessment-template.json), [전체 개념 인벤토리](../work/concept-completion-20261003/learner/inventory-1168.json)를 제공한다. `serve.py` 실행 시 참가자 진입 주소는 `http://127.0.0.1:6091/participant.html`이다. 참가자 화면과 `assets/`만 제공하며 평가 키/결과 파일의 직접 요청을 차단한다. 로컬용이며 공개 배포를 실행하지 않는다.

1회분은 1~3개를 자유롭게 고른다. 기본 구성은 3·3·3·3·2개 다섯 묶음이다. 선택·중단·재접속·원문 자유 응답·내보내기·복구 사본을 연결했다. 이름/학교/연락처/생년월일·음성/사진을 요구하지 않으며 계정 생성이나 서버 전송을 하지 않는다. 연습/합성 검사를 기본값으로 두고 실제 중학생 참여 때 진행자가 별도로 지정한다.

## 재사용한 기준과 도구

프로젝트의 [개념 제작 기준](concept-interaction-design.md)의 중학생용 설명과 PhET·DeFT·NCTM·WCAG 적용을 재사용했다. 각 자료가 설명/표현 대응/수학 교육/접근성에서 맡는 일과 7유형이 프로젝트 편집 분류라는 한계는 기존 문서를 유지한다.

[IES의 학습 지침](https://ies.ed.gov/ncee/wwc/practiceguide/1)은 이유를 설명하는 질문의 방향을 뒷받침한다. 이에 따라 자기 말로 관계와 이유를 설명하게 한다. 만든 과제와 점수의 타당도까지 인증하는 자료로 사용하지 않는다. [W3C WAI의 사용자 참여 평가](https://www.w3.org/WAI/test-evaluate/involving-users/)에 따라 실제 대표 사용자와 기기의 과업/장벽을 관찰하고, 작은 표본 결과의 적용 범위를 제한한다. WCAG 대조·브라우저 모사·실제 사용자 평가를 서로 대체하지 않는다.

화면은 공개 정본의 장면과 제품의 `ConceptText`·`MathFormula`·`ConceptFigureView`·`KnowledgeStructure`를 재사용한다. 기존 KaTeX의 HTML/MathML과 실제 나눔명조 파생 `ManSeekSong Paper` Bold700·95% 서체를 묶는다. 본문 넓은18px·좁은16px, 양쪽 정렬·마지막 줄 시작 정렬을 적용한다. 새로 만든 부분은 사람의 자유 응답을 수집하는 짧은 로컬 흐름과 진행자용 평가 자료이며 전체 웹앱을 복제한 도구가 아니다.

## 무엇을 관찰하는가

설명을 덮은 뒤 자기 말 설명 → 새 사례 적용 → 조건·예외의 자유 응답을 받는다. 답변 키는 참가자 화면·자산에 넣지 않는다. 필요하면 설명을 다시 볼 수 있으며 재열람과 응답 시점은 원문 응답과 별도로 보존한다. 문구가 친숙하다는 평과 실제로 관계를 설명할 수 있다는 증거를 구별한다.

평가 축은 관계/이유, 전이, 경계다. `2`는 핵심 관계와 필요한 조건이 맞음, `1`은 일부만 맞음, `0`은 실제 응답의 핵심 오해, `null`은 무응답/건너뜀/미평가다. 이는 프로젝트의 형성 평가 작업 척도이며 읽기 수준 인증이나 검증된 심리척도로 표현하지 않는다. 숫자만 합쳐 숙달률을 만들지 않으며 실제 답의 인용·해석 이유·도움·선행 경험·조작 장벽을 함께 기록한다. 수정한 설명은 원문/판본을 보존하고 다른 사례로 다시 확인해야 한다.

## 실제 진행에 필요한 조건

중학생이 자발적으로 실제 응답할 수 있는 상황과 필요한 보호자 동의, 읽을 수 있는 기기/브라우저가 있어야 한다. 실제 iPhone/iPad·VoiceOver 조건을 확인하려면 해당 물리 기기와 사용할 수 있는 참여자가 필요하다. 현재 루프백 페이지가 컴퓨터에서 열리는 것과 휴대 기기에 제공된 상태는 다르다. 공개 배포·자료 외부 전송·원격 접근을 임의로 추가하지 않는다.

실제 응답을 받으면 내보낸 JSON과 평가 키로 원문 응답을 검토해 개념/장면/문구/오해/수정 후보를 연결한다. 실제 응답이 없는 현재는 이해 성공률·학생의 예측 답·학습 효과를 만들지 않는다.

진행자 안내 마지막 절에 실제 공개 앱의 iPhone/iPad·VoiceOver 최소 6과업을 연결했다. [물리 기기 관찰 서식](../work/concept-completion-20261003/learner/physical-device-observation-template.json)에 공개 판본·화면 상태·실제 발음·초점·도움·재현 절차를 기록한다. 이 서식의 현재 상태는 미측정이다. 실제 기기 검사의 성공과 중학생의 개념 이해 성공을 구별한다.

## 꾸러미 자체의 확인 결과

다섯 WebKit 화면 모사에서 표본 14개/33장면을 순회해 총 165장면을 확인했다. 공개 본문의 문단 원문 동일성, 실제 Bold700·95% 서체 로드, 넓은18px/좁은16px·양쪽 정렬/마지막 줄 시작 정렬, 수식 오류 0·가로 넘침 0을 확인했다. 14개 질문의 수식 토큰이 줄 안에 표시되는지도 확인했다. 자유 응답의 줄바꿈/띄어쓰기, 새로고침, 다운로드, 같은 참여 코드의 복구 사본 추가와 기존 응답 보존을 검사했다. 합성 저장 실패 시 화면 입력과 내보내기가 유지됐고 손상된 저장 원문을 덮어쓰지 않았다.

초기 순회 후 좁은 화면 이미지를 실제로 보고 질문의 수식 토큰에 넓게 적용된 `span` 조판 규칙을 발견해 질문의 바로 아래 문구에만 적용하도록 고쳤다. 최종 5환경 순회에서 수식 영역 높이도 확인했다. 본문 동일성 검사의 처음 선택자가 도해 문구까지 포함한 실패는 직접 본문 문단으로 범위를 바로잡았으며 실패 로그를 보존했다. 이를 실제 사용자 실패나 학습 효과로 해석하지 않는다.

근거는 `learner/verification.json`, `verification-final.log`, `access-separation.json`, 화면 이미지에 있다. 참가자 자산에 평가 키가 없고 진행자 자료/응답 4개 직접 경로가 404임을 실제 확인했다. 모든 입력·내보내기 증거는 명시적으로 합성이다. 실제 중학생/물리 기기/VoiceOver 발음 검증은 여전히 0이다.

별도 검토자가 14개 개념의 42개 질문을 실제로 읽어 심슨의 역설 전이 질문의 ‘분수 개수’ 표현이 모호함을 지적했다. 성공/전체 시도 수치는 보존하고 각각 ‘몇 번 던져 몇 번 넣었는지’로 풀었다. 새 문구의 LaTeX 이스케이프에 TAB이 섞인 초기 실패를 수정했고 42개 질문의 제어 문자 0을 실제 코드 포인트로 확인했다. 마지막 수정 후에는 그 질문의 숫자/단위/줄바꿈과 자유 응답 재접속만 다섯 환경에서 확인했으며 165장면 순회를 반복하거나 검사 수에 더하지 않았다. 근거는 `question-review.json`, `question-ordinal-proof.json`, `verification-question-final.json`과 질문 수정 전/실패/최종 로그에 있다. 독립 편집 검토와 중학생의 실제 답은 구별하며 실측 0을 유지한다.
