# 천문대 OS 프론트엔드 추가 개발 검토

확인일: 2026-10-02. 사용자 요청: “그전에 프론트앤드의 추가개발, 고급기능 등이 가능하지 않은지 검토하라.”

## 판단과 범위

**추가 개발은 가능하며, 먼저 권하는 것은 조절 가능한 공부 작업면·상황별 명령·원문 발췌 검색·그래프 연결 탐색이다.** 현재 있는 자료·메모·수식·코드·기록·통계를 함께 쓰는 방법을 확장하므로 천문대의 책상·책장·탐구 작업대 정체성과도 맞는다. 기존 시각값은 조정 가능한 기본값이며 새 기능의 상한으로 삼지 않는다.

이는 코드와 공식 문서에 근거한 기술·제품 적합성 검토다. 우선순위는 이번 검토의 제안이며 검증된 학습 효과·새 확정 요구·실제 구현 완료가 아니다. 생산 코드, 원장, 패키지, Figma 설계, 운영 서버·배포는 변경하지 않았다. 소스 검토에서 가능함을 확인한 것과 실제 장치의 효용·성능 확인을 구별한다.

현재 공유 소스·선별 release·공개판은 서로 다르다. [기존 프론트 구현](frontend-followup-20261002.md)의 로컬 확인을 공유 소스 전체나 이번 제안의 실행 검증으로 확대하지 않는다. 이전 운영 보수·통합 배포의 승인과 의존은 이 검토가 변경하지 않는다.

### A01. 자료를 고정하고 옆에서 작업하기

**현재:** App.tsx의 자료·수식·코드는 서로 다른 경로에서 렌더링된다. 자료 아래 곁 메모는 `details`이며 메모 소유 대상은 `material.topicId ?? material.subjectId`다. 현재 기능을 자료 전용 문단 주석으로 오인하지 않는다.

**추가:** 넓은 iPad/데스크톱에서 원자료를 한 면에 두고 다른 면의 메모·수식·코드·기록을 전환한다. 너비 조절, 한쪽 확대, 접기, 원래 크기로 복귀를 제공한다. 좁은 화면은 한 면씩 표시하고 같은 자료/도구 상태를 유지한다. 네 고정 장소는 큰 과업 위치로 유지한다.

**방법:** 기존 화면·저장 명령을 재사용한다. CSS Grid/Container Queries로 배치하고, 조절 동작은 [react-resizable-panels](https://github.com/bvaughn/react-resizable-panels)를 기존 단순 패널 구현과 비교할 우선 후보로 둔다. APG의 [Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)는 키보드·separator 의미의 참고이며 해당 페이지가 검토 중임을 명시하므로 완결된 인증 기준으로 부르지 않는다.

**완료 조건:** 동일 문서를 두 독립 편집기로 중복 마운트하지 않는다. 자료 ID·원문·기존 메모 소속·커서·선택·스크롤·초안·수동 너비가 회전/키보드/이탈/재접속 후 유지돼야 한다. 숨긴 GPU·코드 실행은 수명 정책에 따라 정지한다. 자동 레이아웃은 읽기 가능한 최소 폭을 지키되 사용자의 저장 크기를 덮지 않는다.

### A02. 현재 과업에 맞는 명령 찾기

**현재:** 장소별 메뉴와 도구/기록 링크, 코드 편집기의 자체 명령은 있다. 앱 전체의 현재 대상에 결합된 명령 찾기는 검토한 호출 경로에서 확인되지 않았다.

**추가:** 화면 버튼과 선택한 키보드 단축키로 ‘이 주제로 기록’, ‘수식 옆에 열기’, ‘최근 자료로 복귀’를 검색한다. 현재 대상·실행 가능 여부를 표시하고 기존 함수를 호출한다. 명령 검색에 AI·새 서버를 추가할 필요는 없다.

**방법·확인:** 기존 Search의 한글 조합 처리, Modal 초점 복귀, `OBSERVATORY_MENU`와 `studySourceVisit`을 재사용한다. [APG Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)는 검색 결과의 키보드 패턴 참고다. 실제 입력창과 코드 편집기의 단축키·IME를 가로채지 않고 터치에서도 같은 행동을 제공한다. 삭제/초기화의 기존 확인 단계는 유지한다.

### A03. 왜 검색됐는지 보여 주고 해당 원문으로 이동

**현재:** workspace-search.tsx의 결과는 제목·종류·과목 중심이다. domain/workspace-search.ts는 정규화된 검색 문자열을 포함 여부로 찾는다.

**추가:** 일치한 실제 원문을 짧게 보여 주고 해당 부분을 강조한다. 종류·과목 필터와 제목/본문 일치의 설명 가능한 정렬을 제공한다. 정확한 문단 ID가 있는 유형은 그 위치로, 없는 유형은 해당 항목으로 이동한다.

**방법·확인:** 기존 색인·소유권·삭제 필터와 `useViewContext`를 확장한다. 정규화한 문자열을 원문처럼 표시하지 않으며 UTF-16/NFC 차이를 고려한 일치 위치를 검증한다. 수정·삭제·계정 변경 뒤 오래된 결과를 제거한다. 초안/휴지통의 현재 별도 보관 정책은 유지한다. 원격에만 있는 파일의 전체 내용 검색은 별도 추출·저장·권한 작업이다.

### A04. 그래프를 고르면 다른 그래프와 원기록도 같이 보기

**현재:** statistics-gallery.tsx의 다종 개요, statistics.tsx의 원기록 모달·근거 고정, statistics-plot.tsx의 클릭 처리가 있다. 여러 차트가 함께 쓰는 복수 선택 계약은 확인되지 않았다.

**추가:** 날짜 구간·과목·실제 기록 ID의 선택을 차트와 원기록 목록에 공유한다. ‘선택한 범위’와 전체를 구분하고 선택 해제·뒤로 복귀를 제공한다. 다른 차트의 수치를 임의로 바꾸거나 미기록을 0으로 채우지 않는다.

**방법·확인:** 이미 있는 Plotly의 [선택·클릭 이벤트](https://plotly.com/javascript/plotlyjs-events/)와 SVG 조작을 공통 선택 상태에 연결한다. 모든 차트가 같은 선택 도구를 지원한다고 가정하지 않는다. 날짜 미정·분모·집계된 점의 원기록 집합을 보존하고 드래그 외 날짜 입력·값 목록·키보드 조작을 제공한다.

### A05. 사용자가 느끼는 지연을 로컬에서 구별하기

**현재:** request-performance.ts는 요청의 시간/성공 표본 120개를 세션에 보관한다. 입력→표시·검색→결과·긴 이력 표시를 구별하는 진단 소비 경로는 이번 범위에서 확인되지 않았다.

**추가:** 원문·계정 ID·URL·토큰을 담지 않는 제한된 로컬 측정과 선택 내보내기. 외부 분석 서비스 자동 전송 없이도 후보의 전후를 비교할 수 있다.

**방법·확인:** 기존 performance API·Playwright·Lighthouse, [PerformanceObserver](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceObserver), 개발 측정의 [React Profiler](https://react.dev/reference/react/Profiler)를 적합한 구간에 사용한다. API 지원 탐지, 표본 상한, 계측 자체의 부담을 확인한다. 앱 자체 구간과 실제 INP/LCP/CLS를 구별하며 합성 몇 회의 결과를 현장 75백분위라고 표현하지 않는다.

### A06. 누적 이력의 표시 비용 제한

**현재:** App.tsx의 주제 기록은 전량 RecordCard 렌더링이며 topic-recall.tsx의 자기 평가/이전 메모도 전량 표시한다. 반면 검색/메모 목록에는 이미 40개씩 더보기가 있다.

**추가·방법:** 기존 점진 표시와 위치 보존을 기록·이력 경로에 먼저 적용한다. 그래도 DOM/레이아웃이 병목이면 [TanStack Virtual](https://tanstack.com/virtual/latest/docs/introduction)의 가변 높이 목록을 후보로 비교한다. 라이브러리는 이번에 설치하지 않는다.

**완료 조건:** 한글 장문·수식·필기의 높이 변경, 편집/초점 행 유지, 맨 아래 이동·삭제/복원·뒤로 복귀를 확인한다. 브라우저 찾기와 출력에서 가상화가 가져오는 한계를 처리한다. 화면에 그리지 않은 기록도 원문·검색 대상·백업에서 유지한다.

### A07. 검색 계산을 별도 실행하고 변경한 자료만 다시 색인

**현재:** 전체 색인을 useMemo로 만들고 동기 includes 검색 후 일부 결과를 표시한다. 기존 1만 자료에서 빠른 측정 결과도 있으므로 현재 검색이 반드시 느리다고 진단하지 않는다.

**추가·방법:** 실제 장문/증가 자료에서 입력 차단이 관측되면 [Web Worker](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)에 순수 색인·검색을 옮긴다. 기존 그래프 Worker의 생성/실패/종료 패턴을 재사용한다. [useDeferredValue](https://react.dev/reference/react/useDeferredValue)는 결과 갱신 우선순위의 보완이며 별도 스레드나 긴 동기 함수의 자동 분할이 아니다.

**완료 조건:** 계정·공간·자료 버전·요청 번호를 대조해 오래된 응답을 버린다. 기존 결과 ID/순서/범위와 일치하며 전송·복제 비용을 포함해 이득을 확인한다. 로그아웃 때 색인을 폐기하고 Worker 실패 시 읽기/입력/저장을 막지 않는다.

### A08. 과목별로 펼쳐 둔 작업을 다시 열기

**현재:** 마지막 경로, 여러 경로의 읽기/편집 위치, 탭의 journey가 있다. 자료+도구+메모 구성의 이름 있는 복수 작업 묶음과는 다르다.

**추가:** 사용자가 고른 자료 ID·도구·패널 크기·위치를 ‘이어 둘 작업’으로 저장한다. 내용·초안을 복제하지 않고 기존 ID를 참조한다. 실제로 여러 과목을 병행하는 사용에서 A01 다음에 판단한다.

**완료 조건:** 없어진 자료·권한 변경·계정 전환·화면 크기 변화·설정 저장 실패를 처리한다. 묶음을 자동으로 무한 생성하지 않는다. 기기 내 설정으로 시작할 수 있으나 기기 간 동기화는 별도 설정 계약을 확인해야 한다.

### A09. 이동한 곳과 이어지는 대상이 보이는 짧은 전환

**현재:** 네 장소·출발 자료는 추적되며 공통 모션과 정지/모션 감소도 있다.

**추가·방법:** 이미 있는 [Motion의 layout/layoutId](https://motion.dev/docs/react-layout-animations)로 장소 표시와 자료 제목 등 제한된 요소의 연속성을 표현한다. 본문 입력기 전체를 움직이거나 복제하지 않는다. [MotionConfig](https://motion.dev/docs/react-motion-config)의 모션 감소 지원과 기존 사용자 정지를 연결한다. CSS·Motion·GSAP이 같은 속성을 동시에 쓰지 않게 한다.

**완료 조건:** 전환 중에도 다음 조작을 기다리게 하지 않고 이탈 저장·초점 복원이 우선한다. 낮은 모션/성능 조건에서 즉시 전환한다. 천문대의 원본 전체와 바깥 틀을 보존하고 공간 전환이 개인 Canvas 자동 재배치가 되지 않게 한다.

### A10. 수식 조건의 전후를 같은 기준으로 비교

**현재:** math-explorer.tsx와 domain/math-explorer.ts에는 수식·구간·변수·보기·카메라·장면 캡처가 있다. 근접 보기·확대와 별개의 추가분이다.

**추가:** 현재 조건 A를 임시 고정한 뒤 B와 같은 축·배율에서 비교하고 바뀐 변수와 실제 계산값을 표시한다. 기존 저장 장면은 덮어쓰지 않는다.

**방법·확인:** 기존 수학 계산·그리기를 재사용하고 정적 A+동적 B 또는 한 장면의 비교부터 시작한다. GPU 두 개를 상시 실행하는 것을 기본값으로 삼지 않는다. 색 외 선 종류/범례, 정의되지 않는 구간·단위·계산 오차·원문을 유지한다. 영구 비교 묶음은 새 저장 자료형을 별도로 설계해야 한다. 이득은 실제 탐구 과업에서 확인한다.

## 보류하는 방향

- **전면 실시간 3D 천문대·자동 카메라 비행·추가 상시 파티클:** 기존 WebGL2/SVG의 LOD·curl noise·bloom·적응 해상도 위에서 해결할 구체적 필요가 없다. 원문 읽기·입력·전력 부담이 커질 수 있어 기본 경로로 권하지 않는다. 명확한 3D 탐구 요구가 생기면 재검토한다.
- **WebGPU/새 그래픽 엔진 전면 이관:** 현재 WebGL2+SVG로 달성하지 못한 요구와 대상 기기의 실제 이득을 먼저 확인한다. 기술 이름만으로 고급화로 판정하지 않는다.
- **전역 상태·서버 조회·전체 UI 키트의 일괄 교체:** 기존 repository/outbox/초안과 두 개의 원본을 만들 위험과 이관 비용이 있다. 문제 있는 작은 경계에서 도입 이득을 확인할 때만 검토한다.
- **신규 AI 점수·자동 숙달/성격/흥미 추정:** 현재 입력에서 근거가 없는 학습 의미를 생성하므로 이 프론트 확장의 범위에 넣지 않는다.

VoiceOver 전용 구현·검증, 앱 내 녹음, YouTube 전용 가져오기, 튜터 질문, 결제·문의 접수는 기존 제외 결정을 유지한다. Figma Code Connect 게시를 이번 추가 기능의 선행조건이나 추가 요금제 구매 이유로 삼지 않는다.

## 실제로 진행할 때의 작은 묶음

1. A05의 필요한 구간만 계측하면서 **A01 자료+메모 두 작업면**을 기존 앱에 연결한다. 같은 자료를 보며 쓰고 저장/재접속하는 과업부터 확인한다.
