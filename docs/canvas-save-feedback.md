# Canvas 내용 저장 완료 표시

Canvas에서 ‘내용 저장’을 눌러도 편집 카드가 계속 커져 있고 개인 공간에 ‘이 기기에 저장했습니다’가 남아 저장 결과를 알아보기 어려웠습니다. 이제 개인 공간은 공통 저장 인터페이스의 전송 완료 상태(saved·pending 0)를 확인한 뒤 편집 카드를 접고 ‘서버에 저장했습니다’를 표시합니다. 예시 공간은 기기 저장으로 표시합니다.

저장 중에는 중복 제출을 막고 진행 상태를 알립니다. 전송 실패에는 글·초안·기존 작업 ID를 유지하고 재시도하며 실패 뒤 글 수정도 이어갈 수 있습니다. 다른 카드를 열어 둔 사이 도착한 이전 응답이 새 편집기를 닫지 않습니다. 초안 정리가 실패하면 경고와 편집기를 유지합니다. 원문·수정 이력·저장 키·Canvas 저장 좌표와 연결은 유지합니다.

저장 완료 후 카드 폭은 기존 편집 폭에서 읽기 폭으로 돌아가고 편집 버튼에 포커스를 돌려줍니다. 공통 동작 토큰과 움직임 줄이기를 재사용합니다. 새 글 카드가 나타나도 주변 기본 배치가 밀리지 않도록 현재 Canvas 방문의 표시 좌표를 유지하며 직접 저장한 좌표가 우선합니다. 영속 배치 계약을 변경하지 않습니다.

앱 시작 파일을 불러오지 못하면 빈 화면 대신 ‘화면 다시 열기’를 제공합니다. 사용자가 누를 때만 같은 공간·경로를 새 URL로 다시 열며 기록과 초안을 지우지 않습니다. 시작 파일의 로드 실패 복구이며 모든 실행 오류를 처리하는 경계는 아닙니다.

기존 React·React Flow·공통 저장 인터페이스·동작 토큰을 재사용했습니다. Vercel React 작업 기준의 비동기 완료 분기, 일시 상태 ref와 함수형 상태 갱신을 적용했습니다. 새 패키지·서버 API·DB 변경은 없습니다.

배포 전 검증: 기존 공개 버전 ce9ae2a 기준으로 이번 변경만 분리했습니다. Vitest 492개 통과·선택 성능 검사 1개 건너뜀, backend bundle·전체 타입 검사·Pages 경로 빌드 통과. 새 검사는 저장 응답 전/후, 실패/재시도/이후 수정, 로컬 저장/초안 정리 오류, 다른 편집기 보호, 좌표/연결 보존 및 시작 복구입니다. 실제 공개 배포·본인 계정·물리 기기 확인은 별도 실행 증거로 남깁니다.
