# 백업 저장 재시도 보수 — 2026-10-01

사용자 ‘해결해’ 요청으로 백업 화면의 실패 복귀 경로와 상태 안내를 수정했습니다. 이전 코드는 다운로드 요청 직후 ‘내려받았습니다’라고 표시하고, 생성한 파일 주소를 1초 후 폐기했습니다. 다운로드를 차단하거나 파일 전달이 늦은 환경에서 같은 파일을 다시 저장할 경로가 없었습니다. 앱 내 브라우저의 파일 경로 전달 실패 내부 원인은 확정하지 않았습니다.

## 적용

- 준비된 ZIP을 화면에서 유지하며 실제 다운로드 링크 ‘백업 파일 다시 저장’을 제공합니다. 자동 다운로드 요청은 유지하고, 실패 시 같은 준비 파일로 재시도합니다.
- 상태는 ‘백업 파일을 준비했습니다’로 표시하며 브라우저의 실제 저장과 구별합니다. 파일명과 저장 행동을 함께 제공합니다. 임베디드 앱이 다운로드를 지원하지 않을 때 일반 Safari/Chrome에서 여는 경로를 안내합니다.
- 복원 전 사본을 내려받을 때도 같은 파일 준비·재저장 경로를 사용합니다.
- 새 파일이 준비되거나 화면을 떠나면 이전 주소를 정리합니다. 다른 계정/공간으로 바뀌면 이전 파일을 숨기고 정리합니다. 새 백업 생성이 실패하면 앞서 준비한 파일은 유지합니다.
- ZIP 형식, 원문·ID·이력·첨부·초안·기기 설정 수집, 복원/rollback/소유자 검사는 변경하지 않습니다. 인증·개인 자료를 서버로 보내거나 다운로드 검증을 위해 사용자 저장소를 추출하지 않았습니다.

기존 기준·도구 재사용: [MDN의 download 문서](https://developer.mozilla.org/en-US/docs/Web/API/HTMLAnchorElement/download)는 다운로드 속성을 실제 다운로드 완료의 증거로 볼 수 없다고 설명합니다. 브라우저의 기본 anchor/download와 공통 버튼 토큰, 현재 백업 보존 계약, 기존 Playwright 백업 검사를 사용했습니다. 새 기능은 실패 후에도 준비 파일을 유지하는 국소 상태와 실제 저장 링크입니다. 적용 품질 영역은 Q03/Q04/Q09/Q11/Q12/Q14/Q15이며 전체 Q01–Q15 준수로 확대하지 않습니다.
