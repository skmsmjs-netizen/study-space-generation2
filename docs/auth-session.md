# 로그인 상태 유지

2026-10-01 사용자 요청으로 기존 Supabase Auth 로그인에 유지 여부 선택을 연결했습니다. 로그인 화면의 기본 선택은 켜짐입니다.

- 켜짐: 기존 `study-space:auth:v1` 키와 Supabase의 기본 브라우저 저장을 그대로 사용합니다. 기존 로그인은 이관하거나 삭제하지 않습니다.
- 꺼짐: sessionStorage와 탭별 인증 키/알림 채널을 사용합니다. 같은 탭의 새로고침에서는 복원하고 새로 만든 탭에서는 로그인해야 합니다. 임시 로그인 토큰을 localStorage로 복사하지 않습니다.
- 브라우저의 닫은 탭 복원/세션 복원은 sessionStorage를 복원할 수 있습니다. 공용 기기 안내는 사용 후 명시적인 로그아웃을 요청하며 브라우저 종료만으로 인증이 반드시 폐기된다고 보장하지 않습니다.
- 인증 정보만 보관하며 비밀번호를 별도로 저장하지 않습니다. 공부 기록·초안·ID·개인 캐시·테마 저장은 이 선택으로 삭제하거나 변경하지 않습니다.
- 토큰 자동 갱신은 두 방식 모두 유지합니다. 저장 접근을 미리 확인하고 실패하면 로그인 실패와 구별해 저장 설정 확인을 안내합니다. 임시 저장 실패를 영구 저장으로 대체하지 않습니다.
- 성공했을 때만 새 인증 클라이언트를 화면에 연결합니다. 전환한 이전 클라이언트는 서버 로그아웃 없이 SDK dispose로 종료하며 실패하면 기존 선택을 복구합니다. 서버 인증·승인·소유권 및 민석 전용 AI 권한을 우회하지 않습니다.

공식 Supabase [클라이언트 초기화](https://supabase.com/docs/reference/javascript/initializing)·[세션 조회](https://supabase.com/docs/reference/javascript/auth-getsession)·[세션 유지와 갱신](https://supabase.com/docs/guides/auth/sessions)을 확인하고 현재 설치된 SDK의 custom storage·storageKey·dispose를 재사용했습니다. 새 인증 서버나 별도 세션 라이브러리는 추가하지 않았으며 맞춤 코드는 저장 선택과 인증 클라이언트 전환으로 제한했습니다.

자동검사는 실제 SDK에 격리된 합성 응답을 사용해 재접속·갱신·로그아웃·실패·저장 거부·탭별 채널 및 원문 보존을 확인합니다. 별도 시험 계정으로 동일 배포용 파일과 운영 Auth/API에서 로그인→새로고침→탭 닫기/새 탭→유지 선택별 복원→로그아웃→새로고침을 직접 확인했습니다. 시험 계정의 이메일 확인 상태와 가입 승인은 DB로 준비했으므로 실제 가입/메일 수신/관리자 버튼의 증거로 사용하지 않습니다. 민석 본인 계정·물리 iPad·Safari 종료/세션 복원은 이번 검증에 포함하지 않았습니다.
