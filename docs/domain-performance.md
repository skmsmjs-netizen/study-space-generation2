# 도메인 성능 측정 · 합성 기록 10,000개

2026-09-29. 이 결과는 Node/Vitest에서 순수 도메인 함수를 호출한 측정입니다. 실제 브라우저 입력 지연, 앱 시작, 서버·Sync·IndexedDB, 물리 iPhone/iPad의 성능을 측정한 것이 아닙니다.

## 자료와 방법

- 가짜 사용자 `performance-user`, `test` namespace만 사용했습니다. 실제 Vault와 개인 기록은 읽거나 수정하지 않았습니다.
- 학기 8개, 학기당 과목 10개(총80개), 목차 노드 880개(단원80·주제800개), 세션 10,000개, 기록 10,000개, 수정 이력 10,000개입니다.
- 각 기록은 약20회 반복한 합성 문장과 활동 체크1개를 가집니다. 전체 JSON 직렬화 크기는 **19,368,394 bytes**였습니다. 이 크기에는 revision의 원문 snapshot도 포함됩니다.
- `validateState(state)` 전체 무결성 검증과 `applyCommand(updateRecord)`의 본문1개 수정을 각각3회 측정했습니다. 함수가 반환한 기록값·학기/과목 소속 보존·입력 state 불변을 함께 검사했습니다.
- 실행 환경은 이 Mac의 Node/Vitest 실행기입니다. 동일한 합성 fixture를 사용했으나 실행 순서·JIT·메모리 할당·다른 프로세스의 영향을 완전히 통제한 실험은 아닙니다.

재실행:

```sh
cd generation2
DOMAIN_BENCH=1 npx vitest run src/domain/performance.test.ts --reporter=verbose
```

일반 테스트에서는 이 측정을 건너뜁니다. 데이터와 측정 코드는 `src/domain/performance.test.ts`에 있습니다.

## 발견한 원인과 수정

기존 `assertState`는 각 기록마다 세션 배열을 `find`로 다시 찾았습니다. 기록과 세션이 각각10,000개일 때 약5천만번의 세션 ID 비교가 발생할 수 있는 구조였습니다. 노드·과목 조회도 같은 방식이었습니다.

수정은 전체 검증에서 세션/과목/학기/노드를 한 번 인덱싱하고 해당 Map/Set으로 존재와 소속을 검사하는 것입니다. 검증을 생략하거나 기록의 의미를 줄이지 않았습니다. 원문·stable ID·namespace·소속·revision은 그대로 검사합니다.

| 측정 | 수정 전 3회(ms) | 수정 후 3회(ms) | 중앙값 비교 |
|---|---|---|---|
| 전체 state 검증 | 493.72 / 640.46 / 452.32 | 44.07 / 27.96 / 24.24 | 493.72 → 27.96ms |
| 본문 한 개 명령 처리 | 935.10 / 1,336.81 / 1,134.57 | 156.21 / 129.11 / 160.98 | 1,134.57 → 156.21ms |

후속 `unconfirmWrittenReview`와 Undo 의존관계, 초안 검증 수정 후 타입 검사 및 도메인·저장소 자동검사 **42개**를 통과했습니다. 대량 측정은 위 원인 수정 직후 수행한 값이며, 다른 화면의 처리 시간과 합산하지 않습니다.

## 남는 한계

- 단일 명령의 반환 과정에서 전체 state를 복제하고 전후 전체 검증을 수행합니다. 본문 한 개 수정도 중앙값 약156ms이므로 이 결과를 타이핑마다 호출하면 안 됩니다. 현재 UI는 초안 입력과 명시 저장을 구분해야 합니다.
- JSON 전체가 약19.4MB이므로 이 prototype의 localStorage 저장소는 이 부하에 적합한 저장 엔진이 아닙니다. 이 시험은 저장소를 통과하지 않았고 quota 성공을 주장하지 않습니다.
- 온라인 adapter와 후속 IndexedDB에서는 영향받는 엔터티·작업 단위의 transaction, 서버 제약, 증분 검증을 적용해야 합니다. 지금부터 과도한 추상화·Worker를 도입할 근거로 쓰지 않습니다.
- 오래된 revision 증가, 매우 긴 본문, 깊은 목차의 별도 부하, 검색·통계·Canvas 및 동기화는 아직 이 측정에 포함되지 않습니다.
- 성능 때문에 검증을 제거하지 않습니다. 첫 읽기 전체 검증과 이후 명령의 영향 범위 검증을 분리하는 개선은 해당 adapter에서 실패·교차 소속 회귀시험과 함께 검토합니다.

상태: **수정 후 통과** — 여기서 통과는 이 합성 도메인 측정과 무결성 검증 범위에 한정합니다. 실제 대량 사용자 환경의 전체 성능은 **미검증**입니다.
