자동검사는 119개 통과, 성능1개 opt-in 미실행입니다. quota 실패→route 이동→RAM 원문 복원, 손상 disk 초안 비덮기, beforeunload 경고, 기준 새 ID/범위/Undo, 깊이16 및 동명, 한글 조합 이벤트 시험을 포함합니다. RAM rescue는 현재 창 수명 동안만 유효합니다. browser/OS 강제 종료·저장소 퇴거까지 보장하지 않으며 IndexedDB/Offline queue가 아닙니다.

당장 열린 UX: 형제 정렬·대량 관리, 긴 글의 selection/커서 및 내부 스크롤, 전체 modal 입력 초안, 실제 IME·키보드 가림·회전·Split View, 전체112 후보의 채택/실제조작 판정. 물리기기 최소 절차는 배포 URL에서 가짜 주제에 한글 두 줄 입력→다른 화면→복귀→키보드 가림과 본문 보존 확인입니다. iPhone 17 Pro 사용자 보고 결과를 아래 P01에 수신 기록했습니다.

## P01 사용자 보고 물리기기 결과

iPhone 17 Pro에서 요청한 한글 두 줄 입력→다른 화면→복귀 후 글·줄바꿈 유지가 확인되었다고 사용자가 보고했습니다. 키보드 가림은 없어 보인다는 관찰이므로 모든 입력·배치의 무가림 통과로 확대하지 않습니다. 요청 브라우저는 Safari이며 OS/브라우저 버전은 별도로 받지 않았습니다. 직접 관찰한 B01–B09와 구분합니다. 회전·장문·강제종료·서버/상대기기 수신은 미검증입니다.
