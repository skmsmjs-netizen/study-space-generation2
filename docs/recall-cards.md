# 질문 카드와 개인별 복습 간격

기존 주제 이름 카드를 유지하고 한 공부 주제에 직접 입력한 질문 카드를 여러 개 등록합니다. 질문(앞면)과 참고 답변(뒷면)은 원문 그대로 보존하며, 카드 ID마다 답변 초안·참고 설명·복습 날짜·자기 평가 이력·되돌리기를 분리합니다. 질문 수정은 이력과 메모를 초기화하지 않습니다. 답변은 메모 원장에 저장하며 `recallCardId`로 질문에 연결하고, 기존 주제 소속도 유지합니다. 필기 영역 아래의 접을 수 있는 글 입력창을 유지합니다.

예약 복습은 기한이 된 카드와 하루 새 카드 한도에 따르고, 무작위 연습은 날짜를 바꾸지 않습니다. 자기 평가는 기억 간격을 정하는 입력이며 실제 정답·공부 완료·숙달의 증거가 아닙니다.

## 채택한 계산기와 적용 범위

[Anki 공식 FSRS 안내](https://docs.ankiweb.net/deck-options.html#fsrs)의 이력 기반 최적화 흐름을 참고합니다. 예약 계산은 기존 `ts-fsrs@5.4.2`, 학습은 Open Spaced Repetition의 공식 [fsrs-browser@6.6.0](https://github.com/open-spaced-repetition/fsrs-browser)을 사용합니다. 자체 최적화 알고리즘이나 GPT 호출을 추가하지 않습니다. WASI 바인딩 후보는 공개 테스트 단계이고 브라우저의 격리 조건이 같아 이번 앱에는 도입하지 않았습니다.

활성 카드의 실제 자기 평가 중 날짜를 달리한 각 복습 결과를 FSRS 학습 표본으로 만들고, 그 전에 있었던 같은 날 평가도 문맥에 포함합니다. 취소된 평가는 학습 대상에서 빠지고 원문과 수정 이력은 원장에 남습니다. 날짜 경계는 현재 앱의 기기 현지 날짜 기준으로 유지합니다. 이력이 전혀 없거나 날짜를 달리한 복습이 없으면 부족 상태를 표시합니다. 표본이 적으면 공식 계산기가 기본값과 비슷한 결과를 반환할 수 있으며 임의의 최소 400/1000회 제한을 만들지 않습니다.

계산은 별도 창에서 Worker와 공식 WASM으로 실행하며 이력은 외부로 전송하지 않습니다. 계산 화면의 `/optimizer/`에만 격리 헤더를 붙이는 Service Worker를 사용하고 공부 화면의 서비스 워커·인증·저장 방식은 바꾸지 않습니다. 패키지가 생성한 Rayon worker의 디렉터리 import만 정적 호스팅에서 읽을 수 있는 명시적 파일 경로로 바꿉니다. `npm run dev`와 `npm run build`에서 `scripts/build-recall-optimizer.mjs`가 고정 버전의 파일을 준비합니다.

계산 결과는 사용자가 적용할 때 기존 `saveRecallPreferences` 명령으로 저장합니다. 계산 후 이력이나 설정 버전이 바뀌면 다시 계산하도록 안내합니다. 취소·계산 오류·팝업 차단은 기존 설정을 바꾸지 않습니다. 이미 정해진 날짜를 일괄 재예약하지 않고, 다음 자기 평가부터 새 가중치로 계산합니다.

이 구현은 앞뒤 카드·주관 평가·FSRS 예약·직접 날짜 지정·개인별 최적화를 지원합니다. Anki의 apkg 입출력, 노트 유형/템플릿, 빈칸 카드 생성, 미디어, 덱별 설정, 형제 카드 묻기 등 전체 기능을 복제한 것은 아닙니다. 물리 iPad/Pencil, 한글 IME, VoiceOver, 상대 기기 수신 및 학습 효과는 별도 확인입니다.
