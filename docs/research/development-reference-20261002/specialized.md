## 6. 현재 앱에 맞는 전문 기능의 설계 방식

**차트는 현재 Plotly를 중심으로 유지한다.** [통계 기준](../../statistics-chart-selection.md)은 자료의 질문·변수·분모를 먼저 정하고 이미 설치된 Plotly를 사용한다. 비교·추세·분포·관계·구성·흐름을 구별하고 원자료·값 목록·불확실성을 함께 남긴다. ECharts/Vega-Lite를 도입하려면 기존 차트로 해결되지 않는 표현이나 유지보수 문제가 구체적으로 있어야 한다. 자료 형식에 맞는 여러 차트를 제공하되, 없는 관계·목표·학습 효과를 새 그래프를 채우려고 만들지 않는다.

**관계 탐색과 개인 배치는 분리한다.** [현재 그래프 계약](../../graph-and-board.md)의 React Flow+D3 force를 재사용한다. 탐색 화면에서는 실제 글자 크기·연결 밀도·가용 영역에 맞춰 배치를 계산할 수 있다. 사용자가 저장한 Canvas 좌표는 자동 배치의 초기화 대상이 아니다. 방향 그래프의 선 겹침이나 포트 배치가 실제로 문제가 되면 Dagre와 ELK를 비교한다. 새 렌더러 평가에서도 ID·edge 의미·선택·초점·좌표·재접속 보존을 완료 조건에 넣는다.

**수학의 정확한 모델과 천문대의 표현용 모델은 구별한다.** [수학 내용 템플릿](../../math-content-templates.md)의 제한된 식 계산·표본·정의역·시점·원문 보존을 우선한다. 화면에서 예쁜 곡선이 나오는 것만으로 점근선·특이점·불연속·단위·정확성이 확인되지 않는다. 원식과 계산값, 근사와 정확값, 표시 범위와 사용자가 선택한 매개변수 범위를 구분한다. 천문대의 상징적 별/궤도에 과학적 수치나 학습 성과의 뜻을 임의 부여하지 않는다.

**편집기의 교체 비용은 외형보다 데이터와 입력 연속성에 있다.** 단순 입력은 현재 공통 입력을 유지한다. CodeMirror와 Monaco가 이미 선언된 상태에서 Tiptap/Lexical을 추가하려면 문서 구조 편집이라는 별도 필요가 있어야 한다. 최소 비교 사례는 긴 한국어·조합 중 갱신·붙여넣기·선택·undo·재접속·원문 내보내기다. Monaco의 공식 모바일 미지원은 현재 모바일 경로를 별도 판단해야 하는 근거이며, 기존 화면을 이번 조사로 삭제하는 지시가 아니다.

**OCR·AI 출력은 원자료와 분리한다.** PDF.js는 보기·추출, Tesseract는 이미지 글자 인식, AI는 해석·생성의 역할이다. 원문/페이지·출처를 유지하고 결과를 검토·수정·선택 적용할 수 있어야 한다. 사진→목차에서 기기 OCR을 제거한 기존 사용자 결정은 유지한다. 로컬 모델을 채택하더라도 모델 다운로드·라이선스·메모리·한국어 성능과 민석 전용 AI 권한은 따로 확인한다.
