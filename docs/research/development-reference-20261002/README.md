# ManSeekSong OS 개발 기준·도구 조사

조사 기준일: 2026-10-02. 대상: 현재 `generation2` 웹앱과 살아 움직이는 픽셀 천문대 정체성. 요청: 개발에 표준 삼을 대표 사이트·기준·표준·라이브러리·고급 스킬·고급 기술 조사.

이 문서는 프로젝트에서 쓸 후보를 비교하는 조사 보고서다. 기존 채택 지침을 자동 교체하거나 모든 후보를 설치·구현했다는 뜻이 아니다. 공식 표준, 기관 권고, 제작사의 설계 체계, 라이브러리 문서, 영감 자료, 이번 프로젝트를 위한 제안을 구분한다. 가격·계정 자격·브라우저 지원·라이선스는 실제 도입 시 해당 버전과 용도를 다시 확인한다.

## 2. 현재 프로젝트에서 유지할 출발점

- [최우선 디자인·UI·UX 지침](../../design-ui-ux-priority.md), [천문대 정체성](../../observatory-identity-20261001.md), [공통 디자인 시스템](../../design-system.md), [아키텍처 책임](../../architecture.md), [개발 도구](../../development-tools.md)를 기준으로 비교한다.
- `package.json`에서 React·Vite·TypeScript, Storybook·Playwright·axe·Vitest, Plotly·React Flow·D3 force, KaTeX·math.js, CodeMirror·Monaco, 여러 모션 런타임의 선언을 확인했다. 선언된 의존성과 각 화면의 실제 사용·호환성·검증은 별개다.
- 천문대는 현재 SVG·WebGL2를 사용한다는 담당 문서와 관련 import를 확인했다. 이 조사는 렌더러 전면 교체·새 GPU 엔진 설치의 근거가 아니다.
- 기존 문서의 원문·ID·초안·이력·개인 설정/배치·실제 저장 확인·학습 의미·민석 전용 AI 권한을 유지한다. 종료한 앱과 보관본은 조사하지 않는다.

## 3. 통합 선정 방향

1. **정체성 원본은 현재 천문대다.** 다른 회사의 디자인 시스템에서는 부품 상태·정보 위계·상호작용 규칙을 참고하고 외형 전체를 이식하지 않는다.
2. **평가 기준은 검증 가능한 공식 기준과 실제 과업이다.** 사용성·접근성·성능·보안·보존을 외형과 함께 판단한다. 기준 도입만으로 준수를 주장하지 않는다.
3. **현재 구현과 웹 기본 기능을 먼저 재사용한다.** 새 부품/상태/차트/모션 라이브러리는 해결되지 않은 구체적 요구가 있을 때 비교 도입한다.
4. **고급 기술은 관측한 문제에 적용한다.** 가상화·worker·GPU·상태 머신·CRDT 각각에 실제 병목/복잡성/공동 편집 요구가 있어야 한다.
5. **Figma의 전체 목록과 실제 과업 구현을 연결한다.** 공통 토큰·부품·상태·흐름을 설계하고, 입력·저장·실패·복귀를 앱에서 확인한 뒤 확장한다.

## 4. 조사 결과의 규모와 읽는 순서

대표 항목은 **121개**다. 디자인·UX 28개(D01–D28), 프론트엔드·그래픽 31개(F01–F31), 검증·저장 28개(Q01–Q28), 전문 기능·AI 34개(S01–S34)로 나눴다. 기본 권고 32개, 기존 유지 29개, 조건부 43개, 참고 17개다. 한 도구의 기술 문서와 라이선스 문서는 역할이 다르면 별도 항목으로 셌으므로 121개의 서로 다른 제품이라는 뜻은 아니다. 공개 소개나 초록만 확인한 자료, 접근 오류가 있었던 자료도 확인 범위를 표시한 출처 기록에 포함한다.

| 실패 응답의 모사가 여러 검사에 중복됨 | MSW | 현재 fake/route 재사용 가능성, 실제 서버 검증과 차이 |
| 명령 조합에 따라 보존 결함이 발생함 | fast-check | 도메인 생성기·불변조건·재현 seed·유지보수 |
| 출시 후 오류를 재현할 정보가 부족함 | 기존 자체 기록과 Sentry/OpenTelemetry 비교 | 외부 전송·민감정보·샘플링·보관·계정 비용 |

이는 도입 대기 명령이 아니다. 실제 부족이 드러나면 작은 기능에서 현재 방식과 후보를 비교하고, 읽기/입력/성능/보존이 개선되는 쪽을 선택한다. Next.js 전환, 새 전역 store, 전체 Canvas 교체, CRDT 이관, 유료 디자인 키트 구매를 현재 개발의 기본 선행조건으로 권하지 않는다.

## 7. 천문대에 유용한 고급 제작·개발 기술

- **역할 기반 토큰과 단일 담당 원본:** 테마별 물리 색과 글자/표면/선택/경고 같은 역할을 분리한다. Figma 변수와 실제 CSS/JSON의 연결은 변환·검증 경로를 정하고 같은 값을 여기저기 복사하지 않는다. DTCG 형식만 넣는 것으로 자동 동기화가 되지는 않는다.
- **부품의 실제 상태를 실행 가능한 예시로 관리:** Figma의 상태를 Storybook·실제 앱의 상태에 연결한다. 길이가 다른 한글, 빈 자료, 저장 대기/실패, 초점 상태가 같은 부품에서 재현되어야 한다.
- **픽셀 자산의 제작·출력 관리:** Aseprite/Piskel·sprite sheet/atlas를 반복 자산에 검토한다. 원본 크기·DPR·좌표 정렬·보간을 함께 보고, 성운/글자까지 모두 같은 픽셀 규칙으로 뭉개지 않는다. 도구와 그림 자산의 이용 조건은 별개다.
- **화면과 기기에 맞춘 GPU 표현:** LOD·보이지 않는 부분 생략·적응 해상도·필요한 때만 갱신을 실제 병목에 적용한다. 렌더 품질을 바꿀 때 사용자가 보고 있는 의미/선택/좌표를 바꾸지 않는다.
- **상태와 시뮬레이션의 분리:** 저장 명령·UI 상태·천문대 장면 시간이 서로의 성공을 대신하지 않게 한다. 동일 DOM 속성을 CSS/Motion/GSAP이 함께 덮어쓰지 않게 책임을 정한다.
- **자원 수명과 실패 복구:** GPU context loss, 이미지/폰트 실패, 반복 진입·닫기, background 전환에서 자원을 정리하고 재개한다. 첫 화면의 시연만으로 장기 사용 준비를 판단하지 않는다.
- **시각 회귀와 실제 움직임의 별도 확인:** 시간·난수·폰트·화면 조건을 고정한 비교로 배치를 확인하고, 정지하지 않은 실제 장면에서 입력 반응·속도·복귀를 확인한다.
- **원자적 저장과 재시도 가능한 명령:** 글·이력·버전·중복 요청 판정을 함께 다루고 로컬/서버/다른 기기 반영을 구별한다. CRDT나 캐시 도입으로 이 책임을 없애지 않는다.
- **AI의 구조 검사와 의미 평가:** 정형 결과를 검사하되 조건·예외·원문·출처의 누락은 별도 사례로 평가한다. 스킬도 올바른 발동과 발동하지 않아야 할 경우를 함께 확인한다.

## 8. 사이트와 자료를 찾아보는 순서

1. **판단의 근거:** W3C/WAI·ISO 공개 개요·OWASP·Khronos 같은 해당 기관과 원 연구. 발행 지위·적용 범위·유료 본문 미열람을 구분한다.
2. **구현의 근거:** MDN·React·Figma·Storybook·각 라이브러리 공식 문서와 저장소. 프로젝트 버전과 예제 전제를 대조한다.
3. **설계 방법과 운영 사례:** Design Council·NN/g·GOV.UK·Carbon·Spectrum·Material·Apple HIG. 각 기관/플랫폼의 맥락을 그대로 이식하지 않는다.
4. **시각적 영감과 실제 사례:** Mobbin·Awwwards·NASA Eyes·Bruno Simon. 공개 소개/화면을 본 범위와 실제 조작·성능/실패까지 확인한 범위를 구별한다.
5. **스킬·연결:** 설치된 프로젝트/Figma/React/Supabase 스킬을 먼저 확인하고, Agent Skills·공식 제작 스킬·MCP·Context7 등의 추가 필요를 판단한다.

## 9. 실제 확인에서 드러난 중요한 조건

- **지위:** DTCG는 안정된 커뮤니티 명세이며 W3C Recommendation이 아니다. APG는 구현 지침, ISO는 국제표준이지만 이번에는 공개 개요만 읽었다. 법칙/휴리스틱/도구/영감 사이트를 같은 ‘표준’으로 부르지 않는다.
- **Figma:** Code Connect와 일부 라이브러리/모드에는 요금제/seat 조건이 있다. 무료/현재 권한에서 가능한 Figma 설계 자체와 구별한다. 계정의 실제 조건은 조회하지 않았다.
- **렌더링:** WebGPU 지원을 모든 사용 기기에 가정하지 않는다. 현재 WebGL2/SVG를 유지하며 비교한다. GSAP은 MIT가 아닌 해당 무상 라이선스, Rive 런타임과 에셋 제작 요금은 별개다.
- **편집·Canvas:** Monaco는 공식 모바일 미지원이며, tldraw SDK는 개발 사용과 production 배포의 라이선스 조건이 다르다. GeoGebra 전체 제품/자료와 소스의 조건도 구별한다.
- **서버:** GRANT와 RLS를 함께 관리한다. Realtime은 누락 없는 동기화 원장이 아니고 DB 백업은 Storage 객체 bytes와 로컬 초안 전체를 포함하지 않는다.
- **AI 평가:** 공식 문서의 Evals 플랫폼 종료 일정 때문에 새 호스팅 플랫폼 의존으로 권하지 않는다. 과업별 평가 원칙과 기존 자체 사례/실행기는 계속 활용할 수 있다.

세부 확인일·정확한 링크·접근 한계는 담당 보고서와 출처 JSON을 따른다. 요금제/지원/약관은 실제 새 도입 시 다시 확인한다.

## 10. 이번 조사에서 완료한 것과 다음 개발에서 적용할 것

**완료:** 현재 지침·패키지 선언·관련 천문대/전문 기능/저장 계약 대조, 20개 영역의 대표 조사, 121개 출처 항목의 선정/한계 기록, 설치 스킬 14개에 걸친 발동 조건·관련 본문 검토, 통합 권고와 누락 방지표 작성. 기존 Linear [MAN-18](https://linear.app/manseeksong/issue/MAN-18/천문대-정체성의-전체-화면수리엔진위젯색채-대응-설계)을 읽어 병행 정체성 설계의 범위와 이번 연구를 구별했다. 이 작업의 변경은 이 조사 폴더뿐이다.

**다음 개발에서의 적용 순서:** 현재 작업이 정리된 버전의 앱 전수 목록 → 천문대 토큰/공통 부품을 Figma와 연결 → 한 완결 과업의 정상/실패/복귀 구현 → 실제 반복 사용 확인 → 검증한 규칙의 전 화면 확장. 백엔드의 구현 순서는 조정할 수 있지만 저장/실패/소유권/복구 계약은 화면 설계 단계부터 함께 정한다.

**확인하지 않은 것:** ISO/논문의 유료 전체 본문, Mobbin 등의 유료 전체 자료, 모든 후보의 설치/실행 벤치마크, 사용자 Figma 요금제/한도, 실제 기기/장기 사용, 운영 보안 감사, 제품 전체 기준 충족. 일부 공식 페이지는 접근/본문 추출 제한이 있어 공식 대체 자료나 공개 개요로 확인했으며 개별 항목에 남겼다.

새 패키지 설치, 앱/AGENTS/의존성 수정, Figma 파일 생성·발행, 서버 변경, 개인자료 업로드, 공개 배포는 이 조사에 포함하지 않았다. 조사 결과의 기본 권고를 실제 프로젝트의 새 의무 규칙으로 자동 승격하지 않는다.
