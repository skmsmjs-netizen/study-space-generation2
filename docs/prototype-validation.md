# 0.1.0 가짜 자료 Prototype 검증 기록

검사일: 2026-09-29. 대상: 분리된 `generation2`, demo namespace, 로컬 배포 빌드. 원래 Obsidian 앱과 실제 학습 기록은 조작하지 않았습니다. 이 기록은 안정판·온라인 서비스·PWA 완료 보고가 아닙니다.

## 실행 증거의 범위

- TypeScript 및 Vite production build: 통과.
- Vitest: 도메인·저장소·공통 UI·앱 통합 62개. 마지막 결과는 아래 회귀 이력과 함께 확인합니다. 일반 실행에서 성능 시험 1개는 의도적으로 건너뛰며 명시 실행 결과는 `domain-performance.md`에 있습니다.
- 실제 브라우저: Codex 내장 브라우저에서 DOM·스크린샷·클릭·텍스트 입력·선택·페이지 재실행으로 확인했습니다. 테스트 프레임워크의 합성 DOM과 구분합니다.
- 화면 폭: 기본 1280×720, 390×844, 768×1024, 510×768. 768px 첫 시도는 다른 탭에 적용되어 실제 폭이390px였으므로 태블릿 증거에서 제외했습니다. 활성 검사 탭을 바꾼 뒤 `innerWidth=768` 및 `scrollWidth=768`을 다시 확인했습니다. 510px도 DOM 너비가510임을 확인했습니다.
- 한글 텍스트·줄바꿈은 브라우저 입력으로 확인했습니다. 운영체제 한글 IME 조합·커서 이동·화면 키보드·실제 터치는 **미검증**입니다.
- 실물 iPhone/iPad, GoodNotes Split View, 홈 화면 설치, 오프라인 앱 시작, 실제 다기기 수신, 장기 학습 효과는 **미검증**입니다.

## A–G 조작 비용

숫자는 이번 UI에서 실제 실행한 경로의 버튼·선택 조작입니다. 텍스트 도구의 `fill`은 물리 탭이 아니므로 **입력 초점 조작을 별도 표기**합니다. 실제 기기 탭 수, 타이핑 시간, 스크롤 횟수와 혼동하지 않습니다. 최종 물리기기 측정은 남아 있습니다. 1세대는 이번에 열지 않았으므로 모두 미측정이며 ‘기존보다 개선됐다’고 판정하지 않습니다.

| 흐름 | 시작→완료 | 버튼·선택 | 입력 초점 포함 | 입력 필드 | 화면 이동/overlay | 판단 |
|---|---|---:|---:|---|---|---|
| A 내용 없이 공부함 | 홈에 표시된 주제→공부함 | 1 | 1 | 0 | 0/0 | 대상·공부 사실 |
| B 짧은 메모만 | 열린 주제→기록→공부함 해제→입력→저장 | 3 | 4 | 메모1 | 2/0(저장 후 홈 포함) | 메모 대상·공부 사실과 구분 |
| C 두 주제 일괄 | 홈→기록→주제2개→저장 | 4 | 4 | 필수 본문0 | 2/0 | 대상2개 |

## 원인→수정→재검증

1. **본문 수정/시험 서술이 컴포넌트 메모리에만 있던 문제**: 재마운트 시 손실 경로를 발견하여 body·baseVersion을 demo 초안 저장소에 보관했습니다. 기존 기록과 수정 초안의 분리, 화면 이탈·복귀, 수정 revision을 자동/실제 UI로 확인했습니다.
2. **두 창의 sequence 검사 사이 쓰기 경합**: 검사→쓰기 자체는 원자적이지 않습니다. demo 앱 생명주기 전체를 Web Lock의 단일 writer로 제한했습니다. 잠금 미지원은 안전하게 거부합니다. 실제 두 번째 탭에서 차단 문구를 확인했습니다. 정식 서버 충돌 해결을 대체하지 않습니다.
3. **부분 손상 초안과 초안 정리 실패**: 전체 shape 검사와 덮어쓰기 차단, 기록 저장 성공 뒤 removeItem 실패를 별도 피드백으로 처리했습니다. 오류 주입 자동검사로 재검증했습니다.
4. **평소 C2와 시험 점검의 혼합**: 일반 체크는 글 없이 가능하고 시험 점검은 비공백 글을 요구합니다. unconfirm 명령을 별도로 만들어 글·일반 체크를 보존했습니다. 자동검사 및 실제 체크 해제로 확인했습니다.
5. **목차 생성 Undo가 나중에 붙은 자식을 숨길 위험**: 의존 자료가 추가된 경우 Undo를 거부하도록 수정하고 도메인 회귀검사를 통과했습니다.
6. **대량 검증의 반복 검색**: 10,000개 기록에서 Map/Set 조회로 변경했습니다. 전체 상태 검증 중앙값493.72→27.96ms, 단일 본문 명령1,134.57→156.21ms. 상세와 제한은 domain-performance.md를 따릅니다.
7. **저장 알림이 모바일 탐색을 가림**: 510px에서 저장 알림이 ‘기록’ 클릭을 가로챈 것을 실제 재현했습니다. Undo 알림은 하단 탐색 위로, 일반 저장 결과는 본문 흐름의 인라인 피드백으로 옮겼습니다. 수정 뒤 Toast bottom=688, nav top=702.25로14.25px 분리되었고 실제 ‘기록’ 화면으로 이동했습니다. 기록 작성 화면의 Undo도 입력·저장을 가리지 않도록 인라인으로 남깁니다.
8. **알림 개선 뒤 Undo 유실 회귀**: 작성 화면 진입 때 모든 notice를 지우자 빠른 중복 클릭 시험에서 Undo가 사라졌습니다. 전부 지우는 처리를 제거하고 작성 화면에서는 Undo를 인라인으로 유지했습니다. 수정 후 최종 62개 자동검사가 통과했습니다.
9. **기록 의미·재진입 표시**: done=false라도 실제 활동 체크가 있으면 홈 공부 사건 집계에 포함했습니다. 본문만 있는 기록은 제외합니다. 빠른 기록 완료 후 ‘새 기록’으로 새 사건을 명시적으로 열고, 저장 재시도를 반복 수행으로 세지 않습니다.

## 아직 완료하지 않은 단계

GitHub 원격·Pages 공개 배포, Supabase 프로젝트/Auth/RLS/온라인 CRUD가 연결되지 않았습니다. 브라우저 로그인 또는 사용 가능한 프로젝트 연결이 선행되어야 합니다. 사용자가 지정한 순서에 따라 이를 건너뛰어 정식 IndexedDB·Sync·Conflict·Service Worker를 만들었다고 표시하지 않습니다.

이 앱의 localStorage는 가짜 자료 UX 실험용입니다. 최종 Offline-first 계층이나 독립 백업으로 승인하지 않습니다. 일정·할 일·과제·온라인 강의, Canvas/Graph, 기존8종통계, 실제 Import/Export, 전체 학기 E2E, 실사용 후보판·안정판1.0은 후속이며 원래 기능을 제거하기로 결정한 것이 아닙니다.
