## 중학생도 따라올 수 있는 첫 설명

2026-10-01 사용자 정정: 읽기용 설명의 기본 독자는 해당 분야를 처음 접하는 중학생이다. 일곱 유형 모두에 적용한다. 어려운 단어만 치환하지 않고, 무엇을 보고 왜 다음 판단으로 넘어가는지 설명한다. 익숙한 구체적 상황 → 관찰할 차이 → 그 차이가 생기는 이유 → 개념의 이름과 적용 한계를 개념에 맞게 연결한다. 이 흐름은 편집 기준이며 모든 개념에 같은 수의 화면이나 절차를 강제하지 않는다.

- 첫 설명에서 모르는 전문어를 알아야 다음 문장을 읽을 수 있게 만들지 않는다. 필요한 말은 첫 등장에 풀고, 수식이나 엄밀한 표현은 직관과 대응시킨다. 선행 개념이 필요하면 짧게 설명하며 필요한 조건·예외·원문은 보존한다.
- 예시는 누가 무엇을 얼마나 했는지 먼저 밝힌다. 비율은 ‘무엇 중 무엇인지’를 문장으로 연결한다. 쉬운 문제와 어려운 문제처럼 비교 기준을 구별하고, 실제로 더 많이 맞힌 것과 맞힌 비율이 높은 것을 혼동하지 않는다.
- 숫자·표·그림을 보고 이유를 독자가 알아서 추론하게 하지 않는다. ‘왜 이 결과가 나왔는지’를 구체적인 차이와 연결한다. 정의만 반복하거나 ‘가중치가 다르다’ 같은 새 전문어를 이유의 전부로 쓰지 않는다.
- 한 장면은 한 판단을 중심으로 쓴다. 의미 단위로 줄을 나누되 짧은 문장만 많이 나열하지 않는다. 문장·제목·버튼에도 같은 읽기 수준을 적용한다.
- 검토에서는 독자가 사례의 대상·비교 기준·결과·그 결과가 나온 이유·단정할 수 없는 것을 설명할 수 있는지 살핀다. 심슨의 역설에서는 ‘누가 어려운 문제를 많이 풀었는가’, ‘난이도별로 보면 누가 앞서는가’, ‘전체로 합치면 왜 뒤집히는가’가 핵심이다. 형식 검사나 계산 통과를 중학생의 실제 이해 확인으로 보고하지 않는다.

근거는 [W3C의 쉬운 단어 사용 지침](https://www.w3.org/WAI/WCAG2/supplemental/patterns/o3p01-clear-words/)과 [WCAG 2.2 읽기 수준 3.1.5 설명](https://www.w3.org/WAI/WCAG22/Understanding/reading-level.html)을 적용한다. 전자는 인지 접근성 보완 지침이고 후자는 AAA 기준의 해설이며, 이를 AA 필수 항목이나 한국어 읽기 수준 인증으로 표현하지 않는다. 위의 사례·이유 연결 방식은 기존 DeFT 표현 대응과 사용자 요구를 결합한 프로젝트 편집 기준이다. 실제 중학생 독자 검증은 별도다.

심슨의 역설 `01-036`은 두 학생이 각각 10문제를 푼 명시적 가상 사례로 다시 작성했다. 전체 점수(4/10 대 6/10), 쉬운 문제(2/2 대 6/8), 어려운 문제(2/8 대 0/2)를 같은 학생 이름으로 연결하고, 서로 다른 난이도 구성 때문에 비교 결과가 뒤집히는 이유를 설명한다. 기존 원문과 이전 설명 이력은 보존한다.

## 유형과 조작을 따로 고른다

**유형은 설명할 관계를, 조작은 그 관계를 알아볼 방법을 정한다.** 먼저 원문 정의·예시·통찰과 필요한 조건을 읽어 핵심 질문을 잡는다. 원문 태그나 제목은 후보를 찾는 단서이며 분류의 확정 근거가 아니다. 하나의 개념은 주 유형과 보조 유형을 가질 수 있고, 판단이 어려우면 미분류로 둔다.

| 조작 | 선택 조건 | 제외 조건 |
| --- | --- | --- |
| 한 화면에서 읽기 `static` | 뜻·관계·예시를 함께 보여 주면 충분하다. | 이해에 필요한 대응이나 순서가 가려지는 경우 |
| 선택하며 비교·살펴보기 `select` | 같은 사례·전체·대상을 유지하면서 대안, 부분, 판단 기준을 비교한다. | 선택해도 의미 있는 차이를 볼 수 없는 경우 |
| 단계 펼치기 `step` | 전이·판단·논증·작업의 순서와 각 단계의 이유가 있다. | 정의·예시·통찰이라는 필드 세 개를 그냥 다음 버튼으로 넘기는 경우 |
| 값 바꾸며 탐색하기 `parameter` | 변수·단위·범위·초기값과 조건이 있는 검증 가능한 모형이 있다. | 모형을 확인하지 못한 상태에서 임의 수치·점수·확률을 만드는 경우 |

`static`을 기본 후보로 시작하고 조작이 추가로 드러낼 관계가 있을 때만 다른 방식을 고른다. 이는 이 프로젝트의 기본값이며 특정 방식의 보편적 학습 우월성을 주장하지 않는다. 모든 원리형에 슬라이더를, 모든 절차형에 같은 단계 수를 강제하지 않는다.

## 일곱 유형의 틀

| 유형 | 알아볼 질문 | 내용과 화면의 필수 역할 | 적합한 대표 개념 | 특히 피할 것 |
| --- | --- | --- | --- | --- |
| 정의형 | 이 말은 무엇을 뜻하고 어디까지 해당하나요? | 핵심 뜻 → 구체적 사례와 정의의 대응 → 범위·경계. 한 화면도 가능 | 기회비용 / 단순형 변형은 기댓값 | 짧은 정의를 억지로 세 단계로 나누기 |
| 구별형 | 어느 조건에서 두 판단이 갈리나요? | 같은 사례 고정 → 공통 축으로 비교 → 차이가 드러나는 조건·반례 | 상관관계와 인과관계 | 서로 다른 사례의 차이를 개념 차이로 표현하기 |
| 구조형 | 부분은 무엇이며 어떻게 연결되나요? | 전체 관계도 유지 → 부분과 역할 → 연결·계층·포함 관계와 범위 | 스위스 치즈 모형 | 근거 없는 화살표나 사고 확률 계산 |
| 과정형 | 상태가 무엇 때문에 바뀌나요? | 시작 상태 → 전이와 작용 → 다음 상태 → 반복·종료 조건 | 피드백 | 목록을 시간 순서나 인과관계로 꾸미기 |
| 원리형 | 어떤 조건 때문에 이 결과가 따라오나요? | 조건 → 관계·논증 → 결과 → 적용 한계. 필요한 경우만 값 조절 | 비둘기집 원리 | 유한 그림·몇 번의 실험을 일반 증명으로 처리하기 |
| 절차형 | 무엇을 보고 다음 행동을 고르나요? | 목표·입력 → 판단 → 행동과 이유 → 결과를 원래 목표에 대조 | 귀류법 | 이유 없는 순서, 돌아갈 수 없는 분기 |
| 관점형 | 같은 상황에서 기준을 바꾸면 판단이 어떻게 달라지나요? | 공통 상황 → 기준·전제 → 그에 따른 판단 → 대가·긴장·한계 | 공리주의 | 가치 판단에 근거 없는 점수·승자 붙이기 |

화살표는 내용 역할 사이의 흐름이다. 화면 수나 버튼 수가 아니다. 전체 그림이 필요하면 고정해 두고 설명·강조만 바꾸며, 짧은 설명이면 한 화면에 역할들을 배치한다. 단계 수도 개념의 실제 판단 구조에서 정한다.

각 틀의 **선택 조건·제외 조건·필수 내용 역할·허용 조작·금지 구성·검수 질문·대표 내용**은 [기계 판독용 틀](concept-interaction-templates.json)에서 관리한다. 같은 항목을 문서 여러 곳에서 따로 수정하지 않는다. 이 문서의 표는 그 구조를 설명한다.

## 대표 구성의 구체적인 내용

**기회비용 — 정의형 + 선택.** 독서와 산책이라는 두 대안을 유지한다. 선택한 대안과 포기한 대안을 이름으로 연결해 보여 주며, 가장 가치 있는 포기 대안의 가치라는 뜻을 붙인다. 포기한 대안의 가치를 모두 더하는 것으로 오해하지 않도록 경계를 둔다.

**기댓값 — 같은 정의형 + 한 화면.** ‘기댓값이 1이면 한 번의 결과도 1인가요?’라는 질문 아래 0과 2가 각각 확률 1/2로 나오는 예와 `0 × 1/2 + 2 × 1/2 = 1`을 함께 둔다. 한 번에는 0 또는 2가 나온다는 경계를 같은 화면에서 보여 준다. 선택이나 다음 버튼은 필요하지 않다.

**상관과 인과 — 구별형 + 비교.** 두 값이 함께 증가하는 같은 관찰을 유지한다. 공통 원인 후보를 선택하면 관찰은 그대로 두고 해석만 달라지게 한다. 산점도는 동반 변화를, 화살표는 원인 가설을 보여 준다고 명시한다. 나란히 놓는 것만으로 표현의 대응이 설명됐다고 보지 않는다.

**스위스 치즈 — 구조형 + 부분 선택.** 전체 방어층 그림을 유지한다. 특정 층을 고르면 층의 이름·취약점·설명이 같이 강조된다. 치즈의 구멍은 비유이며 구멍 크기로 사고 확률을 계산하지 않는다.

**피드백 — 과정형 + 단계.** 같은 관계도에서 입력, 출력, 돌아오는 출력, 다음 입력을 순서대로 강조한다. 각 전이의 이유를 붙이고 되먹임 경로를 계속 보여 준다. 실제 음향의 시간·증폭률을 검증 없이 계산하지 않는다.

**비둘기집 — 원리형 + 조건 선택.** 12개의 달을 고정하고 12명·13명 조건을 비교한다. 13명인데 모든 달에 최대 한 명이라고 가정하면 전체가 최대 12명이라는 모순을 보여 준다. 12명에서 같은 달의 사람이 보장되지 않는 이유와 생일 ‘날짜’ 보장이 아니라는 범위를 함께 둔다.

**귀류법 — 절차형 + 논증 단계.** 목표 명제, 부정 가정, 사용한 전제, 모순의 두 항, 원래 결론을 연결한다. ‘다음’마다 무엇을 왜 하는지 보여 주고 앞 가정으로 돌아갈 수 있게 한다. 고전 논리라는 적용 범위를 남긴다.

**공리주의 — 관점형 + 기준 선택.** 이익과 손해가 있는 같은 상황을 유지한다. 전체 효용을 평가하는 기준과 권리 우선 기준을 비교하되, 공리주의 내부의 여러 입장과 효용 비교의 전제를 지운 채 단일 점수를 만들지 않는다.

위 내용은 틀에 대입한 설계 초안이다. 기존 12개 화면의 외형·내용이 새 기준을 모두 충족한다는 확인이 아니다. 원문 대조·독립 내용 검토·실제 조작 후 수정할 수 있다.

## 개념마다 채워야 할 설계 기록

1. 원문 ID·원문 전체 해시·해당 항목 해시·설명 시작 버전·틀 버전을 연결한다.
2. 핵심 질문과 주/보조 유형, 이 틀을 선택한 이유를 적는다. 다른 틀에 더 적합하면 변경 이유를 남긴다.
3. 유형별 필수 내용 역할을 실제 내용으로 채운다. 원문의 정의/예시/통찰을 그대로 역할 이름만 바꿔 넣는 것으로 끝내지 않는다.
4. 표현별로 무엇을 보여 줄지 적는다. 여러 표현을 쓸 때는 동일 대상과 대응 관계를 연결한다. 중복·장식 표현은 줄인다.
5. 조작 종류·그 조작으로 볼 관계·초기 상태·복귀·초기화 범위를 정한다. 값 조절은 모형·단위·범위·경계·근거·독립 계산 확인 사례가 있어야 한다.
6. MI01–MI12 각각에 적용 계획 또는 제외 이유를 남긴다. 계획은 실제 확인 결과와 구별한다.
7. 원문과 달라진 설명, 확인되지 않은 주장·출처·예시·조건을 따로 남긴다. 원문을 수정해 차이를 숨기지 않는다.
8. 기존의 유형·의미·조건·예시·문장·화면 여섯 검토를 개념별로 수행한다. 형식 검사만으로 체크나 읽기용 등록을 완료하지 않는다.

## 공통 화면과 검증에 연결할 조건

2026-10-02 [공통 관찰틀의 위치·조작·보존 기준](observation-frames.md)을 함께 적용한다. 비수학 개념은 읽기 한 열 안에서 질문·관찰·선택/단계·근거를 연결하며 정적 설명에 불필요한 조작을 추가하지 않는다. 유형별 의미와 기존 원문/장면 ID·내용 검토는 아래 계약을 유지한다.

현재 앱의 토큰·공통 부품·개념 reader를 재사용한다. 핵심 질문, 표현, 조작, 이유·범위, 펼쳐 보는 출처의 순서를 일정하게 두며 원문·근거는 일반 읽기에서 필요할 때 펼친다. 화면에 항상 편집 검수 정보를 나열하지 않는다.

단계 전환에서 제어 위치와 읽는 영역이 흔들리지 않게 한다. 긴 글·큰 글자·좁은 화면에서 내용이 가려지는 고정 높이는 쓰지 않는다. 의미 단위 줄바꿈과 반응형 자동 줄바꿈을 함께 사용하며 문장 중간을 폭 계산으로 일괄 잘라 넣지 않는다. 기존 전환과 움직임 감소 설정을 재사용한다. 전환 효과는 관계 설명을 대신하지 않는다.

접근성은 관련 WCAG A/AA 항목을 실제 제어에 연결한다. 비텍스트 대안·관계·색 외 단서·대비·reflow, 키보드·초점, 드래그 대체, 목표 크기, 이름·역할·값·상태를 확인한다. 슬라이더는 native range와 정확한 수 입력/버튼을 우선 검토하고 범위·단위·초기값을 명시한다. 단순 콘텐츠 선택에 연속 값 조절을 붙이지 않는다. 전체 WCAG 준수와 물리 기기 보조기술 확인은 이 계획으로 완료하지 않는다.

원리·계산이 있는 개념은 독립 계산 사례와 경계 조건을 확인한다. 정리의 조건을 확인하지 못한 상태를 거짓 결론으로 바꾸지 않는다. 최종 화면에서는 읽기·선택·단계·조절 → 다른 개념 → 복귀 → 재접속과 해당 보기 초기화를 확인한다. 보기 조작은 공부·정답·숙달 기록을 만들지 않는다.

## 전체 목록 적용과 재개

### 전수 제작과 개념별 품질 검토

2026-10-01 전체 제작 방법 정정: 원문 1,168개 모두를 대상으로 하며 기존 65개 초안도 중학생 대상 설명 기준의 재검토에 포함한다. 관리 단위 30개는 현재 저장 도구와 같은 작업 단위이고 검증된 최적 처리량이라는 뜻이 아니다. 개념이 어려우면 묶음 안에서도 따로 검토하며, 내용을 읽지 않은 항목을 같은 문구로 일괄 작성·검토 완료 처리하지 않는다. 이미 허용된 로컬 작업은 작은 묶음마다 사용자의 재승인을 요구하지 않는다.

원문 ID 전체 집합을 기준으로 설계 목록·설명·검토 기록·화면 결과를 대조한다. 원문/항목/설명 버전과 연결되지 않은 검토 증거는 현재 설명의 통과 근거로 쓰지 않는다. 작성 수와 검토 수를 따로 집계하며 보류·미작성도 총계에 남긴다. 누락·중복·출처 없는 결과는 자동 전수 확인하고, 내용의 빠짐없음은 원문의 정의·예시·통찰에 들어 있는 주장·조건·예외를 실제 읽어 확인한다.

## 실제 renderer와 반복 가져오기에 적용한 동작

`ConceptScreen.design`은 채택한 틀 버전·원문 ID/해시·질문·유형 선택 이유·필수 역할의 장면 연결을 보관한다. 기존 화면은 호환해 읽고, 새 메타데이터는 원문 연결·허용 조작·장면 참조를 검증한다. 역할을 연결했다는 사실만으로 해당 설명이 역할을 충분히 수행한다고 판정하지 않는다. 유형을 바꾸면 필요한 역할을 편집 화면에서 직접 다시 연결할 수 있으며 본문과 기존 수정 이력은 유지한다.

`static`은 한 장면이며 선택·이전/다음·보기 초기화 버튼을 붙이지 않는다. 선택과 단계는 필요한 경우만 쓰고 모든 장면이 같은 읽는 영역의 높이 계산에 참여한다. 긴 내용은 읽을 수 있게 늘어나며 해당 개념의 장면 사이 높이는 유지된다. 비교 대상은 두 열에 묶고 긴 한국어·좁은 폭에서 자연스럽게 줄을 바꾼다. 전환은 기존 움직임 토큰과 움직임 감소 설정을 따르며 색 외에 라벨·테두리·선택 상태를 사용한다.

수식은 공통 KaTeX/MathML renderer와 문장 설명을 사용한다. 데이터에 허용한 그림은 이름·상세·관계·강조 대상만 포함하며 생성 HTML이나 개별 실행 코드는 받지 않는다. 표현의 대상 ID와 관계 참조는 확인하되 도해의 의미 정확성·학습 효과는 별도 검토한다.

보기 위치는 공간·계정·원문 ID·안정된 장면 ID로 이 기기에 저장한다. 장면 순서 변경은 저장한 ID에 따라 복원하고, 손상되거나 없어진 보기는 첫 장면으로 돌아간다. 보기 초기화는 현재 개념의 선택·단계에만 적용한다. 서버 동기화와 화면 전체 스크롤 위치 복원을 이 기능의 확인 범위로 확대하지 않는다.

제작 파일은 이전 결과 이력을 먼저 검증한다. 현재 내용이 파일의 마지막 결과와 같으면 이력을 다시 쓰지 않는다. 현재 버전·본문이 파일에 들어 있는 이전 결과와 정확히 같으면 그 뒤 버전부터 이어 가져온다. 가져온 뒤 사용자가 다르게 고친 설명은 오래된 결과로 덮어쓰지 않는다. 지원하는 저장소에서는 전체 명령을 격리 상태에서 검증하고 한 번의 로컬 저장으로 반영하며 각 원문·명령·수정 이력·서버 전송 대기열은 그대로 유지한다. 저장 실패·소유자 오류는 새 부분 상태를 공개하지 않는다. 로컬의 묶음 반영과 서버의 개별/묶음 승인, 실운영 왕복 증거는 구별한다.
