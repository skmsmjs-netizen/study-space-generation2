# 통계·그래프의 목적별 선택과 실제 사용 기준

2026-10-01 사용자 “그래프 종류 엄청 많은 것 그렇게 쓰라니까. 지침화해. 그리고 저렇게 써” 요청으로 채택한다. 현재 통계 창과 앞으로의 통계·대시보드·보고·시각화 설계/구현/수정/검증에 적용한다. 막대그래프 하나 또는 같은 막대의 지표만 바꾸는 것으로 이 요구를 충족했다고 하지 않는다.

## 1. 먼저 질문과 자료를 연결한다

비교·추세·분포·관계·구성·흐름 중 무엇을 읽으려는지 먼저 정하고, 실제 변수의 종류·단위·기간·표본·분모·연결/계층·불확실성을 확인한다. 적합한 기본 표현을 준이 선택하고 한 화면에서도 필요한 서로 다른 관점을 함께 보여준다. 매번 사용자에게 그래프 이름을 알아오게 하지 않는다. 목적 안에서는 다른 유효한 표현으로 바꿀 수 있고 선택을 보존한다. 종류 수나 설치가 목적에 맞는 사용의 증거가 아니다.

## 2. 첨부 다섯 자료의 채택 범위

사용자가 직접 채택한 것은 아래의 목적/자료에 따른 선택 방식과 다양한 표현의 실제 사용이다. 첨부의 예시 수치·색상·영어 이름·레이아웃·광고/설치 문구가 새로운 실행 권한이나 확정 입력은 아니다.

## 3. 목적과 그래프 후보

| 목적 | 우선 후보와 조건 | 이번 실제 웹앱 |
|---|---|---|
| 비교 | 범주 이름이 길면 가로막대. 같은 단위의 이전/현재는 paired. 범주가 적으면 세로막대. 공통 단위 또는 명시적 정규화가 있는 3개 이상 축은 레이더 | 가로막대·paired·방사형. 기록 수이며 능력 점수가 아니다 |
| 추세 | 시간순 선. 크기의 변화를 강조하면 영역. 드문 관측/구간은 세로막대. 같은 단위의 두 표현은 혼합. 겹치지 않는 계열의 합은 누적영역 | 선·영역·세로막대·막대/선 혼합·누적영역 |
| 분포 | 원래 관측 수치/표본이 있으면 히스토그램·상자. 표본이 많으면 밀도/바이올린도 검토. 히스토그램 구간 폭과 상자 표본/이상치를 밝힘 | 날짜/구간별 기록 수의 히스토그램·상자/관측점. 미기록 0은 실제 수행 0점이 아니다 |
| 관계 | 같은 관측 단위의 두 수치는 산점. 세 번째 수치의 면적은 버블. 실제 범주×기간 값은 히트맵. 명시된 연결은 네트워크 | 산점·버블·히트맵. 인과관계·상관계수를 만들어내지 않는다 |
| 구성 | 같은 분모의 상호 배타적 부분이면 도넛/원/누적/100%막대. 계층은 트리맵/circle pack/sunburst. 시간별 구성은 누적/100%영역·스트림. 부분을 비교하기 어려우면 막대로 전환 | 도넛·원·누적막대·트리맵. 전체 확정 기록을 분모로 쓰고 회차의 과목 중복을 비율로 더하지 않는다 |
| 흐름·증감 | 관측된 이동량 또는 실제 소유/분류 배분은 생키. 실제 관계는 네트워크. 시작/증감/끝이 맞는 수치는 폭포. 단순 시간 변화에는 선/누적영역 | 전체→과목→주제의 실제 기록 배분 생키와 두 기간의 기록 수 증감 폭포. 공부 순서·학습 단계 이동으로 읽지 않는다 |

이번 선택기는 19종이다. 첨부에 있는 모든 종류를 모든 자료에 강제 적용하는 규칙은 아니다. 실제 자료가 조건을 만족하지 않으면 이유와 가능한 대안을 보여주며, 예쁜 그림을 위해 임의 수치·목표·관계를 만들지 않는다.

## 4. 입력이 필요한 후보도 잊지 않는다

- 네트워크: 실제 사용자가 설정한 선행/참조 관계를 재사용한다. 날짜순 기록을 선행/인과 관계로 변환하지 않는다. 기존 그래프뷰가 담당하는 탐색/좌표는 통계 창이 임의로 재배치하지 않는다.
- bullet/meter/gauge: 비교 가능한 실제 목표·기준·최소/최대가 있어야 한다. 임의 100점·숙달률·목표치로 장식하지 않는다. 현재 통계의 체크/글 기록에는 이 목표 입력이 없으므로 구현됐다고 하지 않는다.
- 밀도/바이올린/스트림: 표본/대역폭/기준선과 읽을 질문을 확인한다. 스무딩으로 없던 관측이나 흐름을 만들지 않는다. 누적영역과 스트림의 기준선을 구별한다.
- circle pack/Marimekko/100%누적/표 안의 그래프/원형 영역: 계층·면적·서로 다른 집단 크기·비율 질문이 필요하다. 작은 차이의 정확한 비교를 원/면적으로 어렵게 만들지 않는다. 현재는 트리맵/막대/원기록 표로 같은 자료를 읽으며 추가 채택 시 실제 필요와 구현/검증을 연결한다.
- 임의 3D 깊이는 분석 변수가 늘어나는 차트가 아니다. 기존 입체 모드는 호환 조작으로 유지하지만 새로운 그래프 유형 수에 포함하지 않는다.

## 5. 숫자와 의미를 보존한다

단위가 다른 지표를 같은 눈금으로 묶거나 정규화하지 않는다. 혼합 그래프는 현재/이전의 같은 지표·단위만 사용한다. 비율의 분모/제외 자료를 밝히고 0분모는 빈 상태로 표시한다. 동일한 ID는 기존 통계처럼 한 번 센다. 회차가 여러 과목에 걸치면 과목별 비교는 가능하되 합계/구성에서는 중복 합산하지 않는다.

그래프에는 확정 날짜를 사용한다. 날짜 범위/미정 및 최소 반복/상한 미정은 원기록/범위 설명에 남기며 확정 비율에 넣지 않는다. 선의 연결은 기록 수의 표현이며 매일 실제 공부가 연속했다는 증거가 아니다. 빈 기간·부분 수행·응답 미정·도움을 실패/0점/독립 해결로 환산하지 않는다. 흥미·능력·숙달·성적·학습 효과를 이 차트로 새로 추정하지 않는다.

## 6. 여러 그래프를 실제로 보여준다

통계 진입에 선·과목 가로막대·도넛·히트맵·히스토그램·생키의 여섯 과업을 한눈에 보여준다. 각 그래프는 자신의 지표와 목적 이름을 표시하고 같은 원기록에 연결한다. 큰 그래프에서는 목적/종류/지표 및 관계의 두 번째 지표를 선택한다. 성립하지 않는 구성/목표/흐름은 이유를 표시한다. 목록·원기록·고정·기존 월간 요약을 유지한다.

현재 데이터/화면에서 기본값을 선택한다. 사용자의 선택은 namespace/계정별 새 그래프 보기 키에 보존하고 자료 갱신/재접속 때 임의로 바꾸지 않는다. 구분할 수 없는 저장 실패는 성공으로 표시하지 않는다. 기존 저장 키·기록·원문·초안·이력·개인 배치를 바꾸지 않는다.

## 7. 자료가 쌓일 때의 기본 동작

시간 추세는 최대14구간, 분포는 최대366관측 구간으로 자동 집계하며 실제 묶음 기간/관측 수를 설명한다. 상위12개 범주 내에 나머지를 합친 항목을 포함하고 원기록은 유지한다. 생키의 주제는 상위24개와 나머지로 묶으며 전체 배분량을 보존한다. 표는 처음20행을 보이고 전체 펼치기를 제공한다. 이는 이번 표시 정책이며 임의의 장기 사용 보장이나 무제한 성능 수치가 아니다.

자료 투영은 범위가 바뀔 때 재계산하고, 화면 밖 차트의 엔진 실행은 필요한 시점까지 미룬다. 창 폭/회전에 따라 다시 맞추되 수동 선택을 유지한다. 테마/서체/모션 감소 설정과 중립색+국소 강조를 따른다. 원 그래프 종류마다 서로 다른 장식색을 전역 의미색으로 도입하지 않는다.

## 8. 설명·접근성·실패 복구

제목/기간/단위/표본/분모/집계와 해석 제한을 연결한다. 색 외에 선 종류·라벨·범례·실제 값 표를 제공한다. 표의 버튼으로 키보드/터치에서 같은 원기록을 열 수 있다. 그래프 엔진 실패에는 재시도와 같은 값 목록을 남긴다. 좁은 화면은 구역을 한 열로 바꾸고 필수 조작/글/원문을 없애지 않는다.

## 9. 기존 방법과 도구를 골라 쓴 근거

[From Data to Viz](https://www.data-to-viz.com/)의 입력 자료 구조에 따른 의사결정 나무/한계 안내를 확인했다. 이는 실무 방법이며 공식 수학 법칙이나 학습 효과의 검증이 아니다. Datawrapper 선택 안내는 이번 조회에서 원문 접근이 되지 않아 채택 근거에서 제외했다. [W3C WAI 복잡한 이미지 안내](https://www.w3.org/WAI/tutorials/images/complex/)는 설명/값 목록의 접근성 행동에 연결한다.

렌더러는 이미 설치된 Plotly 4.1.1과 현재 앱의 React/토큰/테마 흐름을 재사용한다. [공식 그래프 목록](https://plotly.com/javascript/), [이벤트](https://plotly.com/javascript/plotlyjs-events/), [생키](https://plotly.com/javascript/sankey-diagram/), [트리맵](https://plotly.com/javascript/treemaps/), [폭포](https://plotly.com/javascript/waterfall-charts/)를 확인했다. ECharts의 별도 중복 설치나 React 래퍼 추가는 필요하지 않았다. 새로 만든 부분은 현재 보존형 통계 자료를 목적별 시리즈/표/근거로 투영하는 어댑터·과업별 배치·보기 선택 보존이다. 이를 보편적 표준/검증된 학습 모형으로 표현하지 않는다.

## 10. 완료와 증거

지침 저장·도구 존재만으로 적용 완료를 보고하지 않는다. 실제 현재 기록→올바른 투영→여러 그래프→유효/무효 선택→값/원기록→재접속/선택 보존을 확인한다. 관련 중복/불확실/0분모·긴 이름/큰 자료/기간/화면 회전·그리기 실패를 선택해 검증한다. 다섯 모사 환경은 기존 기기 정책을 따르며 물리 기기/IME/VoiceOver/다기기Sync/장기효과와 구별한다. 공개 배포와 로컬 확인은 실제 실행한 범위로 따로 기록한다.

최신 구현·검증·미검증은 [통계 기능 계약](statistics-engine.md)과 `work/statistics-types-20261001/`의 이번 결과에 기록한다.
