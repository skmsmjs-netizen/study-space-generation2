## 기존 기준과 선택

같은 공간에서 자료·일정·기록을 찾는 [원 게시물 검토](study-os-reference-review-20261001.md), 기존 브랜드 지침·Q01–Q15·계층 책임·기록 보존 계약을 적용했다. [Apple WWDC24 UX writing](https://developer.apple.com/videos/play/wwdc2024/10140/)의 목소리/상황별 표현과 [Notion database templates](https://www.notion.com/help/database-templates)의 재사용 구조를 참고하고, 현재 날짜 함수·일정 편집기·통계 계산·공통 UI·저장 명령을 사용했다. 새로 만든 부분은 이번 주 묶음, 학기 기간의 주차 미리보기·생성/되돌리기 연결, 월별 요약·제품 문구다. 게시자의 경험을 검증된 학습 효과로 처리하지 않는다.

## 저장 책임

여러 TSX 변경 후 `vercel:react-best-practices`의 상태 초기화·불필요한 전역 이벤트 중복·목록 누적·공통 UI·저장 상태 점검을 적용했다. 이번 범위에서는 기존 추천/통계 지연 로딩과 공통 모달·초점 복귀를 재사용하고, 기기 저장의 사용자 구분·버전과 명시적 상호작용에서의 갱신을 유지한다. 서버 JSON 객체의 키 순서가 달라질 수 있다는 [PostgreSQL JSON 문서](https://www.postgresql.org/docs/current/datatype-json.html)의 조건에 맞춰 새 주차 되돌리기는 항목 순서에 의존하지 않고 값·배열 순서·이력을 비교한다. 이후 편집된 주차는 계속 보호한다. 이 비교는 새 묶음의 보호 조건을 위한 최소 구현이며 기존 앱 전체의 비교 함수를 교체한 것은 아니다.

저장된 일정은 기존 `saveLearningPlan` 명령으로 `LearningPlan`에 담긴다. 소유자·namespace·이전 버전 충돌 확인을 유지하고, 원문·기존 일정·수행·이력을 같은 저장 단위에서 보존한다. 새 서버 API나 스키마를 만들지 않았다. 주차 미리보기/되돌림 묶음의 기기 힌트와 선택 월은 사용자별 로컬 보관이며 서버 공부 기록과 구별한다. 주차 초안 쓰기 실패 시 메모를 화면·임시 복구에 유지하고 영구 저장 성공으로 표현하지 않는다.
