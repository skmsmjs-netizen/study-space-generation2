# 공통 관찰틀의 위치·조작·보존 기준

2026-10-02 사용자 요청으로 채택한다. 수식 탐색, 유형별 수학 표현, 개념 탐구실, 개념 전집의 실제 읽기 화면에 적용한다. 전체 자료의 전수 대응 전에 성격이 다른 대표 사례로 틀의 충분성을 확인하는 것이 이번 범위다. 화면·상태를 확인한 범위는 마지막 적용 기록에 남긴다.

## 1. 근거와 담당 범위

상위 기준은 [천문대 확정 기준](observatory-design-standard.md), [최우선 디자인·UI·UX 지침](design-ui-ux-priority.md), [수학 인터랙티브 MI01–MI12](../../docs/수학%20인터랙티브%20설계·검증%20기준.md)이다. 색·서체·조작 크기·움직임은 기존 재료/토큰을 사용한다. 이 문서는 관찰틀의 역할별 위치·조작·보존과 대응 판단을 담당하며 같은 규칙을 화면마다 따로 정의하지 않는다.

- [PhET Look and Feel](https://phet.colorado.edu/publications/PhET%20Look%20and%20Feel.pdf)의 일관된 표현·제어 묶음·의미 있는 초기 상태를 사용한다. 개별 시뮬레이션의 특성에 따른 배치 예외도 허용한다. 오래된 Flash/Java 외형이나 연구 효과를 우리 앱에 그대로 이식하지 않는다.
- [Ainsworth의 DeFT](https://nottingham-repository.worktribe.com/output/23577631)는 표현의 역할·정보 분배·표현 간 대응을 결정할 때 사용한다. 아래의 화면 역할 분류는 프로젝트의 실행 규칙이며 이 연구의 공인 템플릿 목록이 아니다.
- [WCAG 2.2](https://www.w3.org/TR/WCAG22/)의 의미 관계, 읽기/초점 순서, 재배치, 일관된 식별, 키보드·값·상태·드래그 대체를 관련 조작에 적용한다. 동일한 픽셀 좌표를 요구하는 표준으로 해석하지 않는다.
- 기존 React/HTML 제어, 공통 Modal, Plotly, KaTeX, ConceptReader/ConceptFigureView와 저장 어댑터를 재사용한다. 개념 데이터에 새 실행 코드를 넣거나 새 라이브러리를 도입할 필요는 없다.

## 2. 대응의 단위

대응 단위는 **원자료의 항목 + 알아볼 질문 + 관찰할 관계**다. 같은 식의 관계 탐색/단계 전개/조건 판단은 서로 다른 관찰일 수 있고, 서로 다른 식은 같은 틀을 재사용할 수 있다. 선택·단계·연속값 조절은 내용에 필요한 것만 사용한다. 정의 하나로 끝나는 정적 설명에는 불필요한 다음 버튼·슬라이더를 만들지 않는다.

각 대응에는 다음을 남긴다: 원문/개념의 안정 ID와 버전·위치, 원래 질문, 핵심 질문, 표현별 역할과 대응 대상, 정의역/가정/단위, 틀과 허용 계산, 초기값의 이유, 바꿀 값/고정할 값, 경계·미확인·수치 오차, 실제 확인 범위. 기존 source/pages/question/conditions/sections 및 개념 design/scene 필드를 먼저 사용한다. 없는 교재 페이지나 관계는 생성하지 않는다.

전수 대응 시 상태는 `기존 틀로 대응`, `추가 구현 필요`, `부분 대응`, `정적 설명 적합`, `판단 보류`와 개별 이유로 관리한다. 항목 검토, 관찰 구현, 정확성/화면 검증은 별도 상태다. 검토한 항목 수를 완성된 관찰 수로 세지 않는다. 원문 집합과 대응 목록의 ID를 대조하여 누락·중복을 찾는다.

## 3. 역할별 위치

| 역할             | 넓은 관찰 작업면 | 좁은 작업면과 읽기 순서 | 유지할 관계                                                                              |
| ---------------- | ---------------- | ----------------------- | ---------------------------------------------------------------------------------------- |
| 질문 `question`  | 위쪽 전폭        | 첫 번째                 | 이름·알아볼 질문·원식·관련 조건. 원문에 질문이 없으면 임의 내용을 확정하지 않는다.       |
| 관찰 `visual`    | 왼쪽의 넓은 영역 | 질문 다음               | 그래프/도형/구조/과정의 중심 대상. 축·단위·범례와 의미 표식을 함께 둔다.                 |
| 조절 `controls`  | 관찰 오른쪽      | 관찰 바로 다음          | 관련 변수/조건/선택/단계를 묶는다. 연속값은 정확한 숫자 입력을 함께 제공한다.            |
| 현재값 `readout` | 조절부와 인접    | 조절 다음               | 현재 선택/상태에 연결된 값·판단. 조건 미확인일 때 계산 성공을 꾸미지 않는다.             |
| 근거 `reasoning` | 아래 전폭        | 현재값 다음             | 왜 그런지·어떤 조건인지·계산/논증 단계·한계. 이전 단계로 복귀할 수 있다.                 |
| 참고 `reference` | 아래 펼침 영역   | 마지막                  | 정의·출처·원문 위치·메모. 저장·오류·복구처럼 지금 필요한 상태는 펼침 안에 숨기지 않는다. |

실제 DOM에는 해당 역할의 `data-observation-region`을 붙여 화면 검사와 연결한다. 속성 존재만으로 배치·관계·가독성 완료를 판정하지 않는다. 역할이 없으면 빈 패널을 만들지 않는다. 단계 설명에서는 도해와 그 해설을 하나의 장면 안에 유지할 수 있다.

**읽기 중심의 비수학 개념은 한 열을 기본으로 한다.** 선택/단계 제어는 같은 자리에서 현재 장면과 인접하며, 전체 구조·과정 그림과 각 부분의 설명이 연결되어야 한다. 긴 장면에서는 명시적인 현재 관찰로 이동으로 제목/도해에 돌아올 수 있다. 조절 자체가 없는 정적 장면에는 controls/readout을 강제하지 않는다.

전체 화면에서도 질문·원식·조건·근거·출처를 사용할 수 있어야 한다. 화면 크기 변화만으로 개념·값·단계·시점을 초기화하거나 그림을 다른 데이터로 바꾸지 않는다. 본문·그림·조작 영역의 필요 폭으로 한 열/두 열을 선택하며 기기 이름으로 고정하지 않는다. CSS 자동 재배치 뒤 DOM/키보드 순서가 의미 순서와 모순되지 않게 한다.

천문대에서 완전한 수식/관찰 도구의 자리는 탐구 작업대다. 자료/개념의 작은 관찰은 기존 읽던 과업 곁에서 사용할 수 있다. 이 원칙을 새 곁면·전수 링크가 이미 구현됐다는 뜻으로 확대하지 않는다. 현재 제공하는 닫기·목록·이전 과업 복귀를 유지한다.

## 4. 공통 조작과 예외

| 조작                           | 공통 동작                                                              | 보존/예외                                                                                                   |
| ------------------------------ | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 확대/축소/전체 보기            | 해당 관찰 영역의 보기 도구에 둔다. 이름·순서를 유형 사이에서 유지한다. | 보기 범위만 바꾸며 식·조절값·메모·학습 기록을 바꾸지 않는다. 기존 `보기 초기화` 이름에는 범위를 설명한다.   |
| 2D 이동/확대                   | 기존 드래그 이동, 핀치 확대, 이름 있는 버튼/키보드 대체 사용           | 페이지 스크롤을 임의 확대 입력으로 바꾸지 않는다. 축 의미를 회전으로 바꾸지 않는다.                         |
| 3D 시점/점 근접                | 기존 카메라·정사영·현재 점 추적과 이전 시야 복귀 사용                  | 2D 조작과 다른 부분은 해당 3D 도구 안에서 설명한다. 물리 좌표/벡터 방향은 유지한다.                         |
| 값/조건 변경                   | 같은 상태를 수식·그림·현재값·근거에 적용                               | 조절부와 읽기 위치가 불필요하게 뛰지 않는다. 수동 시야가 있으면 유지하며 화면 밖 대상은 전체 보기로 찾는다. |
| 선택/단계 변경                 | 같은 개념의 장면만 바꾸고 현재 선택/단계를 표시                        | 전체 구조와 조절 위치 유지. 긴 내용의 현재 관찰로 이동은 명시적 행동이며 자동 포커스 탈취를 하지 않는다.    |
| 크게 보기/닫기                 | 현재 값·시점·단계로 열고 닫기/Escape 제공                              | 기존 Modal의 초점/호출자 복귀 재사용. 닫기를 내용 초기화로 처리하지 않는다.                                 |
| 이 개념 처음으로/처음부터 보기 | 표시한 현재 개념의 보기만 초기화                                       | 다른 개념·원문·메모·수정 이력은 지우지 않는다. 단계만 초기화하는 제어와 전체 개념 보기 초기화를 구분한다.   |

같은 변수/대상의 수식·그래프·표·그림 대응은 같은 기호·라벨과 기존 의미색/선 표식으로 연결한다. 색만으로 구별하지 않는다. 물리 장면은 계·축·양의 방향·단위·가정을 유지한다. 길이·각도를 비교하는 공간 표현은 같은 축척을 사용하고, 다른 단위의 물리량을 같은 세로축으로 섞지 않는다.

정리의 조건 위반/미확인은 결과의 발산·거짓과 별개다. 수치 표본·유한 적분·수열 관찰은 일반적인 수렴/증명의 대체가 아니다. 표시 소수점 규칙이 내부 계산·저장 정밀도를 덮어쓰지 않는다.

## 5. 반복 사용과 보존

사용자의 원문·ID·출처·메모·이력·개인 서체/테마/배치를 유지한다. 관찰 조작으로 공부·정답·숙달 기록을 생성하지 않는다. 기존 소유자/namespace 계약을 사용한다.

| 상태                       | 현재 담당 경로                             | 요구                                                                                |
| -------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------------- |
| 일반 수식 초안·메모·시점   | math-explorer + math-explorer-draft        | 편집 중 원문과 저장된 정확값 유지, 오류/용량 상태에서 복구 경로 유지                |
| 유형별 수식·개별 시점      | math-templates + math-template-draft       | 항목별 값·카메라 유지, 가져오기 충돌은 기존 사본 정책, 스냅샷 메모와 초안 구별      |
| 개념 탐구실의 값·단계·시야 | concept-interactive-view + iframe host     | 개념별/물리량별 복원, 저장 실패 재시도와 손상 원문 보호                             |
| 개념 전집의 장면·도해 시점 | concept-reading-context + flow-preferences | 원문 ID/안정 장면 ID로 복원, 다른 개념/계정 분리, 단계 재정렬 뒤에도 같은 장면 복원 |

이번 공통 배치는 새 저장 스키마를 만들지 않는다. 각 보기의 기기 저장과 서버에 저장하는 원문/메모는 구별한다. 기기 저장이 다기기 동기화됐다고 표시하지 않는다. 화면 폭/조절값 변화에 따른 레이아웃 재계산은 저장된 수동 시점·개인 설정을 덮어쓰지 않는다.

유형별 숫자 입력에서 아직 완성하지 않은 식과 범위 오류는 현재 화면 세션의 항목/필드별로 유지한다. 전체 화면 닫기·재열기와 항목 전환은 입력을 지우지 않는다. 파싱/범위 검증에 실패하면 실제 조절값을 변경하지 않고 오류를 함께 남긴다. 이 미확정 숫자 입력은 새로고침 후 보존까지 구현된 상태가 아니며, 확정된 정확값·저장된 시점·메모의 기기 복원과 구별한다.

누적 자료는 공통 렌더러를 재사용하고 한 개념의 선택/범위 갱신이 전체 원자료 재작성으로 이어지지 않게 한다. 긴 이름/문장/수식은 자연스럽게 늘어나거나 해당 수식 영역 안에서 스크롤하며 고정 높이로 자르지 않는다. 여러 장면의 높이를 맞추는 기존 처리는 유지하고 현재 장면으로 돌아오는 조작을 제공한다.

## 6. 대표 적용과 충분성 판단

대표는 화면 개수가 아니라 다른 판단/실패 조건을 포함하도록 고른다. 기존 내용과 계산을 재사용하며 가상 자료를 실제 사용자 학습이나 원문 검토 완료로 등록하지 않는다.

| 대표                       | 확인할 질문/관계                                         | 경계와 틀의 한계                                                                     |
| -------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 일반 함수·공간곡선         | 식/현재 점/벡터와 시야 조작의 대응                       | 점 근접/시야 초기화가 식·t·메모를 변경하지 않음. 정의 불가 벡터는 결과를 만들지 않음 |
| 유형별 수학·정의/논증 읽기 | 전체 화면에서도 원식·질문·조건·근거·출처를 확인 가능한가 | 그래프 없는 설명도 유효. 임의 차원 행렬/PDE/기호 증명은 추가 구현 필요               |
| 테일러 전개                | 차수 N·위치 x와 근사/오차의 대응                         | 지수함수·중심0 사례. 관찰 오차와 이론 상계를 구별                                    |
| 대각 선형변환              | a,b와 기저·단위원의 상·행렬식                            | 음수/0 배율의 방향·붕괴. 일반 선형변환 전체 검증으로 확대하지 않음                   |
| 적분판정법                 | 양항/연속/감소 조건과 원래 급수의 판단                   | 교대 부호/미확인 조건에서 정리 사용 보류. 유한 넓이로 수렴 확정 금지                 |
| 역학적 에너지              | 계/가정과 위치·에너지·속력의 대응                        | 비보존력의 일 미확인/손실일 때 보존식 결과 보류                                      |
| 스위스 치즈 모형           | 전체 방어층과 선택한 부분의 관계                         | 설명용 층·구멍으로 사고 확률 계산 금지                                               |
| 피드백 루프                | 입력→출력→되먹임→다음 입력의 연결                        | 실제 시간/증폭률을 없는 자료로 계산하지 않음                                         |
| 귀류법                     | 부정 가정·전제·모순·원래 결론의 관계                     | 단계 관찰은 임의 명제의 자동 증명이 아님                                             |
| 정적 정의                  | 한 장면에서 정의·예시·경계를 이해할 수 있는가            | 불필요한 선택/단계/초기화 제어를 붙이지 않음                                         |

### 충분성의 확인 조건

1. 각 대표의 질문·표현·조절/선택·근거·조건을 실제 공통 화면에서 확인한다. 역할 태그나 문서 표만 확인하고 완료하지 않는다.
2. 관련 다섯 WebKit 프로필에서 관찰/조절 배치, 긴 글/수식, 가로 넘침, 키보드 초점과 해당 조작을 확인한다.
3. 값을 바꾼 뒤 시야 초기화 → 다른 개념 → 복귀 → 재접속에서 값/단계/메모/원자료가 정해진 범위대로 유지되는지 확인한다. 기존 저장 실패·손상 보호 회귀를 재사용한다.
4. 유형별 예외는 이유와 소비 경로를 남긴다. 대표에서 보인 결함은 같은 작업에서 보완하며 새로운 전문 계산이 필요한 범위는 명시한다.
5. 관련 타입/빌드/선택 회귀와 실제 화면이 일치하고 대표 과업의 직접 결함이 해결되면 이번 틀을 안정화한 것으로 보고한다. 전체 앱·전체 교재·물리기기·학습효과 완료와 구별한다.

## 7. 전체 자료 대응으로 넘어갈 조건

이번 대표의 실제 흐름과 관련 저장/복귀가 통과하고, 대응 내용 필드와 공통 렌더러의 버전이 추적 가능하면 전수 목록 작업을 시작할 수 있다. 관련 없는 앱 기능 전체의 완료를 기다릴 필요는 없다. 전체 원문과 ID 집합을 먼저 확정하고 기존 틀 재사용 → 구성 조합 → 필요한 새 계산/표현 순서로 처리한다. 사용자 원문·불확실한 출처·교재 페이지 미확인을 유지한다.

전수 작업에는 누락/중복, 항목별 대응 상태/이유, 구현 버전, 정확성 근거, 실제 화면과 재접속 증거를 남긴다. 이번 대표 적용을 모든 항목의 검토 완료로 환산하지 않는다. 새 공개 배포·외부 자료 전송·자동 예약은 이 기준의 채택에 포함되지 않는다.
