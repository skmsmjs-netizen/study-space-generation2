# 공통 UX 배포 · 2026-10-01

배포 요청의 범위는 공통 팝업·로딩·이동/복귀·화면 실패 복구입니다. 최신 공개 main을 기준으로 이번 수정만 분리했으며 다른 작업의 공개 기능·토큰·서버 연결은 유지합니다. 공개에 없는 수식 화면의 Plotly 변경은 개발 소스에 유지하고 그 기능 전체를 이번 배포에 추가하지 않습니다.

## 기준과 실제 변경

WCAG2.2의 포인터 취소/초점/상태 메시지, WAI-ARIA APG 모달, React의 오류 경계와 기존 공통 UI를 재사용합니다. 8 CSS px의 배경 탭 허용 이동은 프로젝트 값이며 보편 표준이 아닙니다. 관련 품질 기준은 Q03/04/07/09/13/15이며 전체 제품의 모든 기준 통과로 확대하지 않습니다.

- Modal/Sheet는 누르는 순간 닫지 않고 같은 배경의 완료 클릭으로만 닫습니다. 드래그·취소·본문에서 끝난 조작은 닫기로 처리하지 않으며 Escape/닫기 버튼과 기존 초안 정책을 유지합니다. 진입/복귀 초점은 읽던 위치를 이동시키지 않습니다. WebKit이 터치로 연 버튼에 초점을 주지 않아도 실제 열기 조작을 기억해 닫은 뒤 그 버튼으로 돌아갑니다.
- LoadingState가 접근 가능한 대기 상태와 본문 준비 여부를 제공합니다. useRoute는 준비된 본문에서 복귀하고 임시 화면의 잘린 위치를 덮어쓰지 않습니다. 사용자의 새 조작이 우선하며 취소한 탐색 후에도 본문 준비 후 위치 저장을 재개합니다. 가로 메뉴의 초점은 메뉴 안에서만 표시합니다.
- ScreenBoundary는 화면 코드/렌더 실패 안내·재시도와 다른 메뉴를 유지합니다. 저장된 자료를 삭제하지 않으며 최초 앱 모듈·이벤트/서버 오류나 모든 미저장 값의 복구를 보장하지는 않습니다.
- 공통 CSS는 scrollbar-gutter:stable을 사용합니다. 저장 키/형식·ID/원문·권한·학습 의미·개인 배치를 변경하지 않습니다.

## WebKit 실패 복구 보완

모사 검사에서503 실패 후 reload에도 화면 파일의 새 요청이 없음을 네트워크 trace로 확인했습니다. [WebKit270357](https://bugs.webkit.org/show_bug.cgi?id=270357)의 modulepreload 실패 보존과 일치하는 관찰입니다. [Vite build.modulePreload](https://vite.dev/config/build-options#build-modulepreload)의 기존 설정을 false로 두어 native dynamic import와 지연 화면 분할을 유지합니다. 자동 선행 다운로드 최적화는 줄지만 실패 후 다시 요청할 수 있는 동작을 우선합니다. 별도 재시도 라이브러리·자동 새로고침/반복 호출·저장 삭제는 추가하지 않습니다. 느린 연결의 실제 성능 변화는 이번 검사로 측정하지 않았습니다.

## 검증 범위

배포본의 앱 타입/빌드·서버 번들·디자인 검사와 자동 회귀, 다섯 WebKit 모사 환경을 동일한 Pages base로 실행합니다. 새 회귀는 배경 터치 닫기·취소한 드래그·긴 한국어 초안 재열기와 지연 모듈503→다른 메뉴→재시도 복구입니다. 합성 namespace/별도 프로필을 사용하며 실제 개인 자료/본인 계정·서버DB·물리 기기를 조작하지 않습니다.

정확한 검사 결과·commit/Actions·공개 자산 일치·직접 브라우저 확인은 배포 완료 인계에 남깁니다. 전체 lint의 기존 잔여, 물리 IME/Pencil/VoiceOver·장기 누적·실사용 성능·운영계정 저장 왕복과 공개에 없는 기능은 이번 통과로 승격하지 않습니다.
