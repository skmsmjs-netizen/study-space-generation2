# 시작 화면부터 상세·편집·보조면까지 OS 시각 기준 적용

2026-10-03 사용자 확대 요청: 웹앱 시작 화면부터 상세 화면·전체 시각 요소까지 OS 디자인/UI/UX 기준을 실제 구현하고 기존 GitHub Pages에 배포한다. MAN-28에서 통합 소스·검사·공개 근거를 추적한다.

## 범위와 기준

25역할·41경로·29모달·41보조면(111엔터티)을 [소스/대표 패턴 대조](os-layout-audit-20261003.md)에 연결한다. [역할 정본](observatory-feature-identities.json), [배치 선택 계약](layout-standard-contract.json), [재료/치수/글자 기준값](observatory-experience-baseline.json), [지식 구성 계약](knowledge-structure-contract.json)을 재사용한다. 등록 패턴·기존 토큰·공통 부품·실제 저장/복귀를 유지하며 새 시각 체계를 중복 생성하지 않는다. 색·개인 배치·본문·기능을 간소화 명목으로 지우지 않는다.

전체 시각 요소에는 커버/프레임·실내/종이·장소/탐색·맥락/제목·본문/수식/코드·조작/선택/초점·목록/상세/편집·표/도해/그래프·모달/곁면·빈/처리/실패/복구 상태가 포함된다. 기준이 지정한 제외(결제·문의 접수, VoiceOver 전용, 미준비 미래 기능)는 새 화면으로 만들지 않는다. 일반 레이블·터치·키보드·초점·복귀는 유지한다.

## 실제 변경과 전 범위 소비

| 구역 | 실제 소비와 변경 |
|---|---|
| 시작·로그인·가입·승인 대기·복구 | `PersonalSpace → ObservatoryEntry → ObservatoryCover`로 원본 전체 풍경과 바깥 프레임을 재사용한다. 실제 사용자 자료를 읽기 전에 빈 상태를 렌더하며 새 공부 사건/성과를 생성하지 않는다. 별도 풍경 보기 설정만 사용할 수 있다. 로그인으로 바로 이동해도 원래 해시/목적지를 바꾸지 않는다. 종이 면의 제목→상태/설명→필드→실행/보조 행동·복구를 공통 간격으로 연결한다. |
| 41 실제 경로 | 기존 네 장소/천장 접근·공통 커버·원래 과업 복귀와 `featureSurfaceAttributes`의 역할/배치 소비를 유지한다. 제목 위 불필요한 여백과 비조작 제목의 자동 초점 테두리를 보완한다. 긴 제목/설명/버튼은 내용 높이를 늘린다. |
| 공통 부품·모달·보조면 | `components.css`, `observatory-workspace.css`, `os-task-surfaces.css`가 실제 버튼/필드/카드/초점/상태와 포털의 종이 재료를 소비한다. 모달 제목·닫기 줄바꿈/최소 폭, 실행 묶음과 내용 경계를 보완한다. 기존 초점 제한/닫기/호출자 복귀를 유지한다. |
| 카탈로그·자료 모음 | 과목/다음 공부/자료 카드의 실제 모듈에 닫힌 경계·안쪽 여백·주요 행동을 연결한다. 자료 카드는 폭에 따른 그리드·20개 페이지·원자료/답 선택·재접속을 연결한다. 연속 기록과 긴 원문을 강제로 카드화하지 않는다. |
| 일정 계획표 | 기간→날짜/상태 요약 목록→한 개의 상세·명시적 목록 복귀. 넓은 창 안의 좁은 과업 면에서도 실제 배치 좌표로 상세를 드러낸다. 새 저장은 필터를 유지하고 필터 밖 선택에 명시적인 목록 이동을 제공한다. |
| 글·메모·개념·답 읽기 | 기존 본문 서체700/95% 네이티브 폭·18/16/14px 역할·양쪽 정렬/마지막 줄 시작 정렬을 유지한다. 빠져 있던 개념 lead·학습 결과·지식 단계 설명에도 실제 조판을 연결한다. 수식·코드·축/표/조작은 자기 역할을 유지한다. |
| 자유 기록 | 목록→편집의 실제 영역을 만들고 가용 컨테이너40rem에서 한 열로 전환한다. 선택/초안/ID/원문/줄바꿈/저장/이력과 개인 서체·폭을 유지한다. |
| 수학·교재·그래프 | 기존 조건→조작→관찰→값/근거·원문/질문 복귀를 재사용한다. 교재 목록 복귀의 지연 초점이 새 입력을 빼앗지 않도록 보호한다. 공유 main의 그래프 준비/교재 복귀·렌더 대기 수정을 통합한다. 과학 도형·계산·값·개인 좌표를 임의 변경하지 않는다. |

## 검증 근거와 한계

- 첫 확대 빌드의 45 WebKit 검사가 통과했다. OS UI inventory의 전체41경로×5환경(205진입)에서 일반/125% 확대·입력 크기·넘침·접근성 대표·원문 불변을 확인하고 전체41경로의 iPad 가로 캡처를 시각 대조했다. 일정 누적32/55개·자료 카드45개·정확한 입력/저장/재접속·선택/복귀도 포함한다.
- 계정 진입·개인 작업 공간·일정 관련 단위21개가 통과했다. 새 직접 이동·교재35장면·관찰 보관/복원 및 초점 guard의 다섯 환경 검사15개도 통과했다. 최종 시각 보정은 디자인 검사/통합 CI에 연결한다.
- `d7b8be3`의 CI는 그래프311항목 준비5초 제한·교재 목록 복귀 뒤 검색 입력 경합에서 실패했다. 실패 로그를 보존하고 공유 main의 `9238071`/`1c83792`를 재사용했다. 실패를 통과로 표시하거나 검사를 제거하지 않는다.
- 최종 빌드/전체 CI·공개 실제 화면·검사 산출물과 공개 파일 일치는 MAN-28 완료 기록 및 해당 작업의 release-verification.json으로 연결한다. 이전 실패·첫 빌드 검사를 최종 배포 근거로 자동 승격하지 않는다.
- 111엔터티의 모든 권한/실패/자료 조합·실물 기기/한글 IME/Apple Pencil·장기 사용/학습효과·운영 서버/기기 Sync 전체는 위 소스/화면 확인만으로 완료 인증하지 않는다. 실제 계정 자료를 시험 쓰거나 운영 DB/RPC/Edge를 변경하지 않았다.
