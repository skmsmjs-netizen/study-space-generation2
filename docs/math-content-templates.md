# 과목 공통 내용 틀과 수식 유형별 표현

2026-10-01 사용자 ‘공통 틀 완수’와 ‘모든 과목’, 곡면 모눈/전체 화면/논문 그림 기준 요청에 연결한 실제 경로입니다. 수식 탐색 → 모든 과목 · 수식 유형별 탐색에서 사용합니다.

## 채택한 기준과 구현 경계

수식 계산은 기존 math.js의 제한된 표현식 파서, 기호는 KaTeX, 그래프는 기존 Plotly를 재사용합니다. 명령 실행·대입·객체 속성 접근·임의 함수 실행은 허용하지 않습니다. 수식은 LaTeX 실행 코드가 아니라 계산용 문자열이며 표시용 LaTeX를 별도로 생성합니다. 기존 두 유형의 Frenet 계산과 벡터 길이/축 표시 정책을 재사용했습니다.

논문용 그래프에 모든 저널과 모든 그래프를 포괄하는 한 스타일이 있다고 주장하지 않습니다. Nature의 [그림 준비 지침](https://www.nature.com/nature/for-authors/final-submission), [현재 그림 안내](https://research-figure-guide.nature.com/figures/)의 서체 통일·최종 크기에서의 선/글자 가독성·단위·색과 편집 가능한 벡터 선호를 기준으로 선택했습니다. 이 지침의 인쇄용 5–7pt 글씨를 터치 화면에 그대로 강제하지 않습니다. 화면의 Plotly 숫자/일반 축 글자는 Arial/Helvetica 12px, 변수/벡터 기호는 KaTeX입니다. 이는 앱의 적용값이며 보편 표준이나 저널 제출 인증이 아닙니다.

곡면은 [Matplotlib의 wireframe 예](https://matplotlib.org/stable/gallery/mplot3d/wire3d.html)와 [Plotly 표면 조명](https://plotly.com/javascript/3d-surface-lighting/)을 참고해 무광·회색 표면 모눈을 사용합니다. 2026-10-01 후속 요청으로 단색을 불투명(opacity=1) 파랑–밝은 하늘색 그라디언트로 바꾸었습니다. 색은 높이 z에 대응하고 범례를 표시합니다. 기존 info-500/info-100 토큰을 재사용하며 모든 곡면/매개곡면에 자동 적용합니다. 81×81 표본에서 각 방향 21줄의 모눈을 표면의 실제 좌표에 붙입니다. z=f(x,y)는 x/y 방향, 매개곡면은 u/v 방향입니다. 정의되지 않는 부분은 null로 끊고 연결하지 않습니다. 공간 음함수의 등위면에는 이 매개 모눈을 적용했다고 주장하지 않습니다.

전체 화면은 기존 Modal의 키보드 포커스·Escape/닫기·배경 잠금과 viewport 크기를 재사용합니다. 브라우저 [Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API)의 기기별 지원 여부에 의존하지 않고 앱 콘텐츠가 사용 가능한 화면을 채웁니다. 브라우저/운영체제 도구막대를 강제로 숨기는 모드는 아닙니다. 넓은 화면은 그래프/조작 패널, 좁은 화면은 큰 그래프/아래 조작입니다. 열고 닫아도 현재 카메라·좌표·수식·메모를 유지합니다. 후속 요청으로 유형별 탐색의 첫 진입·다른 내용 선택·처음 자료를 그래프로 반영할 때 그래프가 있으면 전체 화면을 바로 엽니다. 전체 화면에서도 내용 선택을 제공하고, 닫은 뒤 같은 내용의 변수/시점을 조작할 때 반복해서 다시 열지 않습니다. 그래프가 없는 설명/빈 자료는 편집 화면을 유지합니다.

## 모든 그래프의 공통 조작 정책

2026-10-01 감도/일괄 자동 적용 요청으로 `math-plot-touch.ts`의 공통 입력과 `mathPlotConfig`를 기존 함수·공간곡선 및 모든 유형별 Plotly 렌더러에 연결했습니다. 과목명·예시 ID·개별 식에 조건을 걸지 않습니다. 표현식 수정, 새 내용 생성, 파일 가져오기, 보관 내용 재열기, 전체 화면에도 같은 렌더러가 적용됩니다. 정의·증명 읽기 틀처럼 그래프가 없는 내용에는 제스처를 억지로 붙이지 않습니다.

[Plotly 공식 설정](https://plotly.com/javascript/configuration-options/)과 [공식 scene 속성](https://plotly.com/javascript/reference/layout/scene/)을 확인했습니다. 문서화된 감도 배율 속성이 없어 기존 3D 마우스 회전·공식 relayout을 재사용하고 입력 전달을 조정했습니다. 2D 이동은 공통 시작 범위와 화면 크기로 이동량을 환산해 공개 relayout으로 갱신합니다. 원래 2D 임시 이동의 범위가 갱신에서 사라지는 현상을 확인해 이 작은 어댑터를 추가했습니다. 함수 숫자의 페이드도 공개 SVG 텍스트를 갱신해 이동 중 재배치를 피합니다. 이 배율은 앱의 사용성 기본값이며 논문 그림 표준이 아닙니다.

- 마우스/한 손가락의 회전·이동을 실제 이동량의 0.35배로 전달합니다. 포인터가 그래프 밖으로 나가도 마우스 drag 종료를 받습니다. 핀치 뒤 한 손가락으로 돌아올 때 새 기준점을 잡아 화면이 튀지 않게 합니다. 창 초점 이탈/해제 때 입력을 정리합니다.
- 핀치는 거리 비율의 0.45승, 휠은 픽셀/줄/페이지 단위를 변환해 사용합니다. 한 프레임의 확대 비율은 최대 1.1배/역수이며 폭주한 이벤트의 잔여 확대를 계속 재생하지 않습니다. 확대·축소 버튼도 1.1배/역수입니다. 기존 GeoGebra의 버튼 배율은 유지합니다.
- 3D 팝업은 공식 `scene.hovermode=false`로 꺼 그래프/점/TNB를 가리지 않습니다. 현재 위치·성분·계산값은 기존 좌표 읽기 영역에서 두 자리로 확인합니다. 2D 자료의 값 살펴보기는 유지합니다.
- 3D 카메라 거리 0.08–80, 2D 반폭 1e-8–1e9 범위에서 보기를 제한합니다. 이것은 수학의 정의역이나 입력값을 제한하는 값이 아닙니다. 수식·변수·현재 점·슬라이더·메모는 보기 조작으로 바꾸지 않습니다.

## 3D 시점과 T·N·B 확인

2026-10-01 ‘아래에서 위로만 봐야 한다’는 시야각 피드백으로 기존 [Plotly camera의 eye·center·up](https://plotly.com/javascript/reference/layout/scene/)와 [공식 시점 예](https://plotly.com/python/3d-camera-controls/)를 재사용합니다. 별도 3D 엔진을 만들지 않았습니다. 저장된 시점이 없는 첫 보기/명시적 보기 초기화는 위쪽 사선이고, 현재 저장 시점은 덮어쓰지 않습니다. 기존 공간곡선과 유형별 공간곡선·곡면·매개곡면·공간 음함수·공간 벡터장에 공통으로 위쪽 사선/xz 정면/yz 측면/xy 위에서 보기와 좌우·높이 15° 조정 버튼을 제공합니다. 위에서 보는 카메라의 up은 y 방향으로 설정해 시선과 수직 방향이 일치하는 특이 상태를 피합니다. 버튼은 기존 44px 조작 크기와 키보드 동작을 재사용합니다.

시점 변경은 eye-center 거리와 center를 유지합니다. 확대도 center를 기준으로 계산하고, TNB 화면 투영/숫자 밀도는 eye 자체가 아닌 eye-center로 계산합니다. 방향 조정 버튼의 높이는 ±85°로 제한해 극점에서 위 방향이 뒤집히는 동작을 피하고, 정확한 위쪽 시점은 별도 선택으로 제공합니다. 이 각도와 간격은 앱의 조작 기본값이며 논문 그래프 표준이라고 주장하지 않습니다.

T·N·B가 모두 정의된 곡선은 ‘세 벡터 보기’를 제공합니다. 단위 직교 프레임의 T+N+B 방향(필요하면 반대 방향)에서 보아 세 방향의 화면 투영이 약 120°씩 분리되게 하고, z≥0인 쪽을 선택합니다. 이는 현재 점의 프레임을 이용한 앱의 표현 선택이며 이후 t/변수를 움직일 때 시점을 자동 추적하거나 수학 값을 바꾸지 않습니다. 벡터 방향 표시는 32–80px 범위(작은 화면 최대48px)로 한정해 전체 곡선 맞춤에서도 읽을 수 있고 확대해도 지나치게 길어지지 않게 합니다. 단위벡터의 실제 성분은 기존 좌표 영역에서 유지합니다. 유형별 내용 시점의 보관/내용 전환/재접속 계약을 재사용합니다.

검증: `work/math-explorer-20261001/display/camera-visible-*`, `camera-verification.json`. 다섯 모사 환경에서 시점/키보드 조작, 위쪽 특이 시점, 세 벡터 분리, 확대 배율·t 보존, 유형별 시점 복귀/재접속을 확인합니다. 다섯 공간 유형의 연결과 2D에서 3D 전용 조작이 없는 조건을 별도로 확인합니다. 실제 로컬 인앱 화면은 모사 환경/물리 기기/공개 배포와 구별합니다.

## 양방향 축·바탕 모눈과 곡선의 표시 구간

2026-10-02 사용자 요청으로 축과 z=0 바탕 모눈을 화면의 양쪽 끝까지 이어 표시합니다. Plotly의 유한 좌표 상자/상자 모눈 대신 실제 세계 좌표의 회색 축·실선 눈금·평면 모눈을 공통 trace로 제공합니다. 공간곡선·곡면·매개곡면·공간 음함수·공간 벡터장에 같은 정책을 적용합니다. 표면에 붙은 기존 곡면 모눈과 바탕 모눈은 별개로 유지합니다.

기존 [Plotly scene의 수동 aspectratio·camera·range](https://plotly.com/javascript/reference/layout/scene/)를 재사용했습니다. 화면 크기와 카메라에 따라 그리는 좌표 범위를 넓히면서 단위당 aspectratio를 일정하게 유지해 축 범위 갱신이 확대 배율을 되돌리지 않게 합니다. 시점 중심을 이중으로 이동시키지 않고 현재 카메라·현재 점·수식·메모를 유지합니다. 눈금은 정수 단위이며 너무 멀어지면 정수 간격을 늘립니다. 숫자는 투영된 눈금 간격에 따라 기존 페이드 정책을 적용합니다.

함수와 공간곡선은 저장된 슬라이더 범위와 그리는 범위를 분리합니다. 2D 함수는 보이는 x 구간과 작은 여유 영역을 계산하고, 공간곡선은 원래 매개구간의 양끝에서 화면 좌표 범위를 벗어날 때까지 구간을 단계적으로 넓힙니다. 원래 슬라이더 시작/끝과 현재 t는 바꾸지 않습니다. 기존 GeoGebra 평면 SVG 곡선도 같은 계산기를 사용합니다. 확대·이동·크기 변경 후 필요한 구간을 다시 계산하며, 현재 점만 움직이거나 카메라 방향만 바꿨을 때 같은 표본은 재사용합니다. 공통 내용의 새 식·가져오기·재열기도 이 경로를 사용합니다.

화면상 굽음/선분 길이와 두 내부 표본을 보고 필요한 곳을 세분화합니다. 넓은 좌표 절단 영역과 세분화할 시야 주변을 분리해 화면 밖의 반복 곡선이 계산량을 소진하지 않게 하고, 수치상 반복되는 닫힌 곡선은 중복 연장을 멈춥니다. 정의되지 않는 값과 해결되지 않은 큰 점근선 변화는 끊습니다. 한 번의 곡선 표본은 평가24000회/표시12000점/분할 깊이12로 제한하고, 매개구간 연장은 각 방향 최대24번 배증합니다. 이 값들은 앱의 작업량 제한이며 수학적 정의역이나 연속성 증명이 아닙니다. 유한 표본으로 모든 고주파 진동·재진입 구간·특이점을 보장하지 않습니다. 무한히 많은 점을 미리 계산하지 않고 현재 화면에 필요한 유한 부분을 이어 그립니다. 실제 자료점·유한 수열·초기값 수치해·곡면 계산 영역을 임의로 무한 연장하지 않습니다.

## 천문대 정체성의 수학 작업면 적용

2026-10-02 ‘어느 정도 천문대 정체성을 반영’ 요청에 기존 [천문대 정체성](observatory-identity-20261001.md#11-색채uiux-기준값)과 [기준값 JSON](observatory-experience-baseline.json) 1.1.0의 수학 작업면·픽셀 기구 규칙을 재사용했습니다. 밝은 화면의 따뜻한 종이색/보조면, 짙은 남색 제목띠, 황금색 정적20px 돔 표식, 직각 입력/버튼/패널을 수식 탐색과 전체 화면 포털에 같은 역할로 적용합니다. 전체 화면은 기존 제목 행을 사용해 별도 장식 행을 추가하지 않습니다. 기존 기능명과 수학 기호는 유지합니다.

`node scripts/sync-math-observatory.mjs`가 기준값 JSON에서 범위를 한정한 `math-observatory-tokens.css`를 생성합니다. 기존 `prepare-math-tools.mjs`에 연결해 일반 dev/build에서도 최신 기준값을 반영합니다. 전역 토큰의 임의 사본을 만들거나 다른 화면을 바꾸지 않고 `.math-explorer` 내부에서 역할을 연결합니다. 기존 명시적/OS 밝음·어두움과 개인 서체/조작 크기를 재사용합니다. 기호·곡선·축은 pixelated 처리하지 않으며 장식 모션/자동 시점 변경을 추가하지 않습니다. 회색 축, 주황 곡선·점, 파랑 T/초록 N/빨강 B의 역할을 유지하고 어두운 작업면에서는 같은 색상의 밝기를 높입니다.

마지막 공간 축 변경의 WebKit 오류 검사는 네이티브 상자축의 `visible:false`, 실제 별도 축/모눈 trace, 독립 hover picking 생략, 공통 숫자 페이드/geometry 갱신 직렬화를 함께 확인합니다. 이전 실패를 삭제하지 않고 최종 결과와 구별합니다. 실제 로컬 화면과 다섯 브라우저 크기의 밝음/어두움 근거는 `work/math-explorer-20261001/display/observatory-unbounded-*`, 통합 기록은 `unbounded-verification.json`입니다.

과목명으로 위 유형을 강제하지 않습니다. 물리/공학도 식의 관계에 따라 곡선·장·자료·설명 틀을 사용합니다. 모든 과목의 원문을 담는 공통 계약과 위 계산 유형의 지원은 서로 다릅니다. PDE·임의 차원 행렬·기호 증명·회로 전체 해석·모든 전문 도해의 자동 생성 완료로 확대하지 않습니다.

## 내용 작성·가져오기·보존

앱의 ‘내용 형식 파일’에서 14유형의 실제 기본 JSON을 받을 수 있습니다. 한 객체 또는 객체 배열을 편집해 ‘내용 파일 가져오기’로 넣습니다. 파일은 2MB, 한 번에100개, 공간 초안500개, 변수12개, 자료10000쌍까지입니다. 범위는 유한 구간이며 축의 시작<끝/현재 위치/초기값을 확인합니다. 새 유형 선택은 기존 내용을 바꾸지 않고 별도 ID를 만듭니다.

공통 필수 필드는 version=1, id, kind, title, expressions, ranges, parameters, cursor, initial, notes입니다. parameters에는 symbol/label/min/max/value, ranges에는 해당 유형 축의 [시작,끝], cursor에는 현재 축 위치를 넣습니다. 계산용 변수는 해당 유형의 좌표와 등록한 스칼라 변수, 허용된 상수/함수로 제한합니다.

선택 필드는 subject, question, conditions 문자열 배열, quantities={symbol,name,unit} 배열, sections={id,title,body,tex?} 배열, source={title,url?,reference?,pages?}, 표시용 tex 배열입니다. data는 dataset={xLabel,yLabel,style,points}를 넣습니다. 자유 원문과 오류가 있는 편집 중 입력도 초안에 유지하며 그래프 오류를 성공으로 표시하지 않습니다.

같은 ID/같은 내용은 재사용하고, 같은 ID/다른 내용은 copy ID와 originId를 가진 새 사본으로 넣습니다. 가져오기 검증은 전체 성공 후 한 번 적용합니다. 기존 원문·선택·다른 내용·메모를 덮어쓰지 않습니다. 단순 blur로 표시용 두 자리 값이 원래 정밀한 숫자를 덮어쓰지 않습니다.

초안은 기존 owner/namespace 저장 정책과 용량 오류 rescue를 사용합니다. 손상된 보관값은 자동 초기화하지 않고 재읽기/현재 초안 파일 보관을 제공합니다. ‘내용과 메모 저장’은 기존 StudyRepository의 saveMemo/flush를 재사용하고 이 기기 저장과 서버 저장을 구별합니다. 저장한 시점의 스냅샷은 기존 memos에 남고 ‘저장한 내용’에서 다시 열 수 있습니다. 가져온 원문·내용별 시점·좌표·변수·메모를 JSON으로 내보냅니다.
