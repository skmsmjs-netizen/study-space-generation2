# 천문대 안의 책상과 방향별 기능 배치

> **현행 확정 기준 — 2026-10-02:** 사용자 「여기까지, ux, ui, 디자인 기준으로 값을 정해둬라」에 따라 [천문대 디자인 기준](observatory-design-standard.md)과 [기준값 JSON v2.0.0](observatory-experience-baseline.json)을 현재 적용 원본으로 삼는다. 정면 공부 책상·왼쪽 자료 책장·오른쪽 탐구 작업대·뒤쪽 기록·계획 벽, 실내/종이 역할색, 기능명과 은근한 보조 문구, 치수·전환값은 합의 기준으로 확정했다. 이전 후보·대화 시안·대비 계산은 당시 이력이며 현행 기준과 충돌하면 최신값을 따른다. JSON의 `workSurfaceColors`는 수학 런타임의 이전 색상 호환값이다. `pixelTreatment`는 v2에도 채택한 단일 공통 원본이며 기존 수학 소비자도 재사용한다. 수치는 프로젝트의 기본값이며 국제표준의 지정 수치가 아니다. **기준 확정과 앱 전체 구현·검증·배포 완료는 별도이다.**

2026-10-02 사용자 정정: 사용자는 천문대 내부의 책상에 앉아 있다. 풍경 위젯의 테두리는 창문처럼 보이며, 다른 기능을 사용할 때 왼쪽·오른쪽·뒤로 돌아앉아 그 자리에 있는 기능을 사용한다. 이에 따라 기능을 구분한다.

상태: **기능 배치·시점·이동 규칙의 확정 기준과 대화 내 배치 설명 이력**. 홈 창틀/책상의 실제 구현은 [실내 구현 기록](observatory-interior-20261002.md)에서 관리한다. 전체 네 방향·종이 작업면·v2 값 소비·저장 연결·공개 배포의 확인은 따로 구별한다. 관련 [정체성](observatory-identity-20261001.md), [실내 다크 색감과 세부 경험](observatory-presence-details-20261002.md), [MAN-18](https://linear.app/manseeksong/issue/MAN-18).

## 1. 이번 정정으로 정해지는 관점

**하나의 천문대 안에서 같은 책상과 주변 작업대를 돌아보는 경험이다.** 정면의 풍경은 창밖으로 이어지고, 사용자가 읽고 쓰는 UI는 방 안의 작업면이다. 왼쪽·오른쪽·뒤쪽에도 동일한 재료·빛·픽셀 윤곽이 이어진다. 공간 방향은 기능을 찾는 기준으로 사용한다.

기능의 본래 자리와 현재 사용하는 자리를 구별한다. 자료는 왼쪽에서 찾아 정면에 펼칠 수 있고, 공부 중 떠오른 메모와 작은 보조 도구는 현재 과업 곁에서 사용할 수 있다. 전체 자료 탐색·큰 도구 작업·넓은 현황 확인처럼 주 과업이 바뀔 때 방향이 바뀐다. 원문이나 저장소를 방향별로 복제하지 않는다.

## 2. 네 방향과 위쪽 천장 조명

| 고정 자리 | 하는 일 | 현재 주요 기능 | 같은 자리에서 이어질 과업 |
| --- | --- | --- | --- |
| **정면 — 공부 책상** | 지금 하나를 읽고, 떠올리고, 적고, 확인한다 | 오늘, 기록, 메모, 시험 연습, 암기시험, 주제 카드 | 최근 자료/초안 이어가기, 실제 자료 펼치기, 오늘의 다음 행동, 작은 통계·보조 도구 |
| **왼쪽 — 자료 책장** | 공부할 범위와 원자료를 찾는다 | 과목, 강의 자료, 자료 카드, 개념 전집 | 원자료·목차·카드 탐색/정리. 선택한 자료는 원래 맥락을 유지한 채 공부에 사용 |
| **오른쪽 — 탐구 작업대** | 조건을 바꾸고 결과를 살핀다 | 수식 탐색, 코딩 연습 | 큰 그래프·좌표·변수·실행 입력/출력. 필요한 경우 현재 공부 자료와 나란히 사용 |
| **뒤쪽 — 기록·계획 벽** | 쌓인 자료·관계를 넓게 보고 다음 흐름을 정리한다 | 통계, 일정·과제, Canvas, 그래프뷰, 칸반보드 | 원기록으로 내려가기, 개인 배치 편집, 오늘 책상에 필요한 일정/작업으로 복귀 |
| **위쪽 — 천장 조명** | 공간 전체를 비추고 조율하는 공통 자리 | 찾기, 저장 상태, 화면/계정 설정, 백업/보관/도움말 | 어느 방향에서든 접근하고 닫으면 진입 직전 방향·과업·포커스로 복귀. AI는 기존 민석 권한과 실제 진입 경로를 유지 |

2026-10-02 사용자 「공통은 위 천장 조명을 바라보는 곳으로 하자」에 따라 이전의 ‘방향 없는 공통’ 자리를 **천장 조명**으로 정했다. ‘천장 조명 · 공통 도구’ 진입과 기존 바로가기를 함께 제공하며 실제 고개/기기 움직임을 필수로 만들지 않는다. 위쪽 시선은 현재 수평 방향 위에서 열리고, 닫기/취소하면 원래 방향과 하던 공부로 돌아간다. 검색 결과처럼 명시적으로 선택한 대상은 정상 목적지로 간다. 저장 오류·현재 과업의 복구·짧은 보조 조작은 해당 과업에서도 계속 접근한다. 조명 선택을 실제 밝기/테마 변경이나 AI 실행으로 연결하지 않으며 상세 동작과 표현은 [정본 기준](observatory-design-standard.md#5-기능의-고정된-자리와-돌아오기)을 따른다.

주 메뉴는 정면6·왼쪽4·오른쪽2·뒤쪽5·공통1로 총18개이다. 이 분류가 메뉴 이름·URL·사용자 자료의 소속을 바꾸는 것은 아니다. 실제 라벨·상세 경로·예외는 [경로별 배치표](../work/observatory-spatial-20261002/route-map.md)와 [기계 판독 대응표](../work/observatory-spatial-20261002/route-map.json)에 기록한다.

현재 장소명과 역할의 정본은 [천문대 디자인 기준](observatory-design-standard.md)이다. 이 문서에서는 자료 책장·탐구 작업대·기록·계획 벽을 책장·작업대·기록벽으로 줄여 부를 수 있다. 초기 조사와 배치표의 ‘자료대·도구대·기록과 계획의 벽’도 같은 장소를 가리킨 과거 별칭이다. 기존 기능 이름은 유지하며 공간 이름으로 메뉴와 버튼을 일괄 개명하지 않는다.

### 분류를 기능 이름만으로 고정하지 않을 곳

- **자료 카드:** 찾아보는 목록은 책장, 실제 질문에 답하는 활동은 공부 책상이다.
- **일정·칸반:** 전체 계획·열 편집은 뒤쪽, 오늘의 한 행동은 정면에서 바로 시작한다.
- **통계:** 전체 범위와 그래프를 비교할 때는 뒤쪽, 지금 필요한 짧은 요약은 정면에 함께 놓는다.
- **과목·목차 상세:** 범위를 찾는 과목/단원은 책장, 선택한 주제로 공부·기록하는 과업은 책상에 연결한다.
- **개념:** 도감을 찾는 위치는 책장이다. 개념 설명과 내장 상호작용을 읽으며 조작하는 동안 매번 작업대로 이동시키지 않는다. 독립 수식 탐색기에서 크게 다룰 때 작업대에 연결한다.
- **찾기:** 모든 자리에서 사용할 수 있다. 결과가 자료·도구·기록 어느 곳에 속하든 직접 열고, 돌아오면 검색어·결과 위치가 유지된다.
- **AI:** 현재 자료·암기시험 등의 기존 패널이 실제 경로이다. 공통 진입은 추가 연결이 필요한 제안이며, 다른 계정에 권한을 넓히지 않는다.

## 3. 풍경 위젯을 창문으로 읽게 하는 디테일

1. **가까운 경계:** 원본 위젯 전체를 유지하고 그 바깥에 창틀·창턱·책상 공간을 더한다. 사용자 후속 「위젯을 자르면 안돼. 위젯 바깥에 테두리」가 우선한다. 장식 잘림 금지·가림 0px이며, 안쪽 경계/창살/그림자 오버레이로 풍경을 덮거나 프레임에 맞춰 원본 viewBox·종횡비·조작 영역을 줄이지 않는다. 좁은 화면에서도 전체 위젯의 비례 조정과 외부 테두리 두께 조정으로 대응한다.
2. **빛의 연결:** 창틀·기구 받침에 기존 하늘의 같은 광원에서 오는 작은 반사광을 둔다. 실내의 먹색/회갈색은 유지하고 읽는 면의 대비가 시간이나 천체 현상에 따라 흔들리지 않게 한다.
3. **방향이 보이는 잔여 단서:** 왼쪽 책장을 볼 때 정면 창은 화면 오른쪽 가장자리에 일부 남을 수 있다. 오른쪽 작업대를 보면 반대 가장자리에 남는다. 뒤쪽은 같은 벽 재료·작업대 높이·작은 조명으로 이어진다. 모든 방향에 동일한 창을 정면으로 복제하지 않는다.
4. **실제 조작 보존:** 창틀·램프·책상 장식은 포인터/터치/키보드 초점을 가로채지 않는다. 기존 하늘의 확대·드래그와 창 안의 시야는 동일한 담당 소스를 따른다. 현재 touch 탐색이 없는 경로를 새로 지원했다고 보고하지 않는다.
5. **동료처럼 바라보는 나:** 사용자 「동료 천문대를 보는 느낌」과 「그 동료가 사실 나」를 함께 적용한다. 실내에서 공부하는 나와 창밖의 천문대로 드러나는 나를 함께 두는 상징적 이중 시점이다. 자기 천문대를 바라본다는 이유로 공간 오류를 교정하려 하거나 원본 건물/확장 애니메이션을 제거·대체하지 않는다. 실제 타인 계정·AI 동료·경쟁 기능을 추가하는 뜻으로 확대하지 않는다.

창틀은 기존 픽셀2px 계단 규칙을 재사용한다. 대화 내 배치 설명의 창틀 두께8px는 조절 가능한 시각 후보이며 제품의 확정 치수가 아니다. 좁은 화면에서는 장식의 보이는 범위를 줄이고, 본문·필수 행동·44/48px 조작 기준을 우선한다. 정면에서 바로 공부를 이어갈 수 있어야 하며 큰 창이 핵심 작업을 화면 아래로 밀어내는지 확인한다.

### 창 아래 기능은 종이를 읽고 쓰는 면으로

후속 사용자 요청: 「하늘과 창문 아래 보고 있는 기능성들은 … 종이에 쓰인 느낌 … 차분히 종이를 보고 하는 듯한 느낌」. 이어 제공한 [사진 1.jpg](../work/observatory-spatial-20261002/paper-reference.jpg)는 「완벽한 그 느낌은 아니지만 얼추 맞는 예시」로 지정했다. 사진에 보이는 **밝은 크림색/미백 면, 얇은 회갈색 경계, 짙은 글자, 그래프·조건 목록·설명의 조판**을 참고한다. 원본의 수식·작은 글을 모두 판독했다고 하지 않으며 전체 화면 배치를 채택한 것으로 처리하지 않는다. 사진 뷰어의 바깥 검은 여백·닫기/저장은 앱 표현의 근거가 아니다.

실내에는 세 역할이 함께 존재한다. 먼 하늘은 움직이는 풍경이고, 방과 책상은 저채도 어두운 재료이며, 실제 읽고 쓰는 내용은 그 위에 펼친 종이 면이다. 기존 다크 작업면 방향은 방·탐색·기구의 기본 면으로 유지하고, 자료·기록·설명·풀이에는 사용자가 요청한 종이 역할을 구체화한다.

| 물성 | 얇은 가장자리와 낮은 픽셀 그림자, 넉넉한 안쪽 여백 | 종이를 기울이거나 매번 접힌 모서리·찢김·낡은 얼룩을 반복하지 않음. 본문은 수평 유지 |
| 기능별 종이 | 기록·메모는 일지, 자료는 펼친 글, 수식은 식/도해/조건을 담은 탐구 노트, 통계는 도표가 있는 기록지 | 작업대의 실제 조절기·실행 상태까지 종이 문구로 숨기지 않음. 원문/자료/공부 기록을 새 저장소로 복제하지 않음 |

이 수치는 사진에서 추출한 공식 색이 아니라 프로젝트가 확정한 기본값이다. **초기 사진 시안의 계산 이력:** 불투명 sRGB에서 본문9.52:1, 당시 보조 `#60594D`5.08:1, 행동 `#554530`6.76:1, 포커스 `#725425`5.12:1을 확인했다. 현행 v2에서는 선택 면 `#D7CBB4`의 대비까지 고려해 보조를 `#5B5448`, 필요한 조작 경계를 `#796D5D`로 조정했다. 현재값과 검증 근거는 새 기준 문서·JSON에서 관리한다. 종이 안의 행동 `#554530`·포커스 `#725425`는 실내 역할과 별도로 적용한다. 색쌍 계산은 실제 제품 전체 접근성·장시간 읽기의 검증이 아니다.

당시 대화 내 배치 설명은 기존 기능 이름 묶음을 종이 위 제목·얇은 줄·잉크색 행으로 수정했으며 실제 편집기·그래프·기록지를 완성한 화면은 아니었다. 이번에는 기준값 JSON을 v2.0.0으로 확정하지만 제품 CSS·사용자 테마·저장의 전체 적용을 뜻하지 않는다. 홈의 창틀/책상 구현과 별도로, 후속 제품 연결에서는 창 아래 실제 읽기/기록 경로에서 장문·선택·한글 입력·좁은 화면을 확인하고 공통 역할로 확장한다.

## 4. 돌아앉는 느낌과 실제 이동 규칙

공간의 고정 좌표는 공부 책상0°·작업대90°·기록벽180°·책장270°로 확정한다. 이는 설계상의 관계이며 실제 3D 카메라를 요구하지 않는다.

- **목적지 선택:** `공부 책상`, `책장`, `작업대`, `기록벽`은 언제나 같은 자리를 연다. 방향은 보조 단서로 둔다.
- **상대 회전:** 별도 ‘왼쪽/오른쪽으로 보기’ 조작을 제공한다면 현재 시점에서 한 자리씩 이동한다. 작업대를 보고 오른쪽으로 돌면 기록벽이다. 고정 목적지와 상대 회전을 같은 명칭으로 섞지 않는다.
- **브라우저 복귀:** ‘뒤로’는 이전 방문으로 돌아간다. 뒤쪽 벽으로 가는 행동명으로 사용하지 않는다.
- **시각 전환:** 방향 전환180ms를 확정 기본값으로 쓴다. 일반 피드백은120ms이다. 인접 방향은 짧은 방향성 이동, 반대편 직접 이동은 목적지 단서와 짧은 교체를 사용할 수 있다. 긴 180° 회전·글자 원근 왜곡·조작 대기는 기본0이다.
- **움직임 감소:** 0ms로 바로 바뀌어도 현재 자리·활성 메뉴·제목·초점으로 동일하게 길을 찾을 수 있어야 한다. 이는 주변 픽셀 애니메이션 전체를 제거하는 요구가 아니다.
- **연속 선택:** 마지막 선택이 목적지가 된다. 이전 애니메이션을 취소하며 중간 방향을 기다리거나 이력에 쌓지 않는다. 모서리에 마우스를 두거나 스크롤하는 것만으로 방이 돌아가지 않는다.

## 5. 하나의 공부 흐름으로 연결하는 예

다음은 설계 예시이며 사용자의 실제 기록을 서술한 것이 아니다.

1. 정면 책상에서 이어가던 공부를 확인한다.
2. 책장을 선택한다. 시야가 왼쪽으로 바뀌고 정면 창의 일부가 오른쪽에 남는다.
3. 자료를 고른다. 현재의 직접 열기 흐름을 재사용해 내용을 펼친다. 자리 선택을 또 요구하는 중간 확인 창은 추가하지 않는다.
4. 설명 속 작은 수식 조작은 자료 곁에서 한다. 독립 수식 탐색기로 작업을 넓히면 오른쪽 작업대로 이동하고 대상 자료와 돌아갈 경로를 유지한다.
5. 기록이나 메모를 남길 때 현재 맥락을 이어 쓴다. 저장 전·후의 실제 상태는 어느 방향에서도 읽을 수 있다.
6. 기록벽에서 관계나 공부 흐름을 넓게 본다. 원기록을 열고 닫으면 선택한 범위와 시점으로 돌아온다.
7. 공부 책상으로 돌아오면 지원되는 자료·초안·읽던 위치가 이어진다.

## 6. 저장·모바일·직접 진입의 경계

- 현재 경로·선택된 자료·구역별 읽던 위치·편집 초안·개인 Canvas 배치·임시 카메라를 구별한다. 방 방향을 새로운 학습 원장이나 숙달 상태로 저장하지 않는다.
- 딥링크와 검색 결과는 해당 기능/대상을 바로 연다. 방을 한 바퀴 돌게 하거나 홈을 거쳐야 하는 단계는 없다. 기존 방문이 없는 경우 가짜 이전 경로를 만들지 않는다.
- 편집 중 방향 이동에서도 한글 조합·초안·저장 실패 복구를 보존한다. 방향 전환이 서버 저장 성공을 뜻하지 않으며, 현재 저장 ACK 계약을 유지한다.
- 스마트폰에서는 네 장소를 텍스트로도 직접 선택한다. 가로 스와이프를 방 전환의 유일한 조작으로 사용하지 않아 필기·그래프·가로 스크롤과 충돌하지 않게 한다. 기존 사용자 밝기·글꼴·모션·배치를 보존한다.
- 장소의 기능 목록과 사용자가 배치한 항목은 별도이다. 업데이트나 새 공간 표현이 개인 Canvas 좌표·칸반 열·자료 순서를 자동 재배치하지 않는다.

## 7. 기존 방법·확인할 조건

앞선 [공간 연구](../work/observatory-presence-20261002/presence-methods.md)의 Wirth 공간 모형, Data Mountain의 위치/문서 재탐색, Worch·Smith 환경 스토리텔링을 재사용했다. 이들은 위치 단서·행동·복귀를 함께 설계할 근거이며 네 구역이나 180ms를 검증한 표준이 아니다. 네 자리는 이 프로젝트에서 제안한 뒤 이번에 확정한 배치 기준이다. 초기 추가 검토는 [공간 규칙 메모](../work/observatory-spatial-20261002/spatial-rules.md)에 보존한다.

실제 제품에 연결할 때는 다음을 확인한다.

- 정면→작업대→기록벽→책장의 고정 관계와 현재 위치 표시, 브라우저 복귀의 일치.
- 자료→공부→작은 도구→기록에서 불필요한 이동 단계가 늘지 않고 원문·초안·선택·포커스가 유지되는지.
- 좁은 화면·한글 입력·필기·그래프 조작에서 창틀/전환이 과업을 가리지 않는지.
- 움직임 감소·빠른 연속 이동·새로고침·딥링크·저장 실패 중에도 최종 목적지와 복귀가 맞는지.
- 설명을 먼저 주지 않은 이용자가 기능의 위치와 돌아갈 자리를 예상하는지. 장소 선호와 과업 성공·학습 효과를 따로 기록.

이 문서는 기능 분류·동작 규칙의 확정 근거와 대화 내 방향 선택 설명 이력을 보존한다. 설명의 창밖 그림은 배치를 보이기 위한 도식이며 확장 천문대 렌더러의 대체본이 아니다. 홈의 실제 창틀/책상, 대화 내 방향 선택, 전체 앱의 네 방향 라우팅·종이 작업면·v2 소비·저장·기기별 확인은 각각 구별한다.
