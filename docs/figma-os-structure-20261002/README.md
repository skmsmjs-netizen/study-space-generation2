# OS 기준값과 Figma 구조 연결

2026-10-02 사용자 요청에 따른 조건부 기준 계약이다. **현재 값은 담당 원본에 유지하고, 역할·사용 조건·조정 규칙·통과 조건·확인 범위를 연결한다.** 이 폴더의 문서는 숫자 원본을 하나 더 만들지 않는다.

[criteria-contract.json](criteria-contract.json)은 공통 기초 8묶음, 공통 상태 8개, 기존 부품 59종, 화면 구성 10개, 기능 역할 25개, 기존 엔터티 111개, 목업 계약 29개를 연결한다. 각 정의의 원문·ID·소스·속성·반복 사용 조건은 원래 파일을 참조한다. **기존 Figma 파일의 구조 정리·세부 기준 연결·원격 재조회와 대표 렌더 확인을 완료했다.**

기존 24페이지의 ID와 내용을 유지하며 이름과 순서를 정리하고, `03 기준 운영` 1페이지를 추가했다. 마지막 조회 시 파일에는 26페이지가 있으며, 병행 작업이 만든 `04 교육 · 구조·명명·어휘`(`170:180`)는 이번 수정 범위 밖으로 보존했다. 현재 이름과 ID는 [figma-state.json](figma-state.json)에 기록했다.

새 기준 페이지는 Figma의 실제 Section 6개 아래 **상세 보드 18개·카드 164개**를 둔다. 기존 부품 페이지는 실제 Section 9개로 묶었다. 기존 부품 59종의 설명, 변수 81개와 글자 스타일 7개의 설명에서 담당 기준 카드로 이동할 수 있다. 값·별칭·코드 연결은 유지했다.

목업 29개는 전체 이미지로 남길 범위, 편집 가능한 주변 UI, 실제 실행 소스와 진입 경로를 연결했다. 그중 기존 Figma 소유 노드를 확인한 20개와 소유 노드가 미확인인 실행 요소 9개를 구별한다. 미확인 9개에도 이번 기준 카드와 소스 경로를 제공하며 기존 목업 노드가 있다고 꾸미지 않는다.

## 완료 확인과 유지보수

[verification.json](verification.json)에 구조·렌더·생성기 확인을 구별해 남겼다.

- 새 상세 카드 164개의 내용·경계·125개 링크, 목차 14개 링크, 기존 부품 59종의 기준 연결을 확인했다. 검사 대상의 겹침·미해결 연결·색 불일치는 0이다.
- 대표 Figma 화면 6곳을 렌더해 살폈다. Section 배경과 종이 위 글자색의 실제 표시 문제를 보정한 뒤 해당 화면을 다시 확인했다.
- 기존 부품 페이지의 원래 최상위 요소 59개의 내부 내용·치수·상호작용·색 연결을 보존했다. 천문대 원본 `10:68`은 전체 960×400, 동일 이미지 해시와 FIT 표시를 유지한다. 원본 위젯을 자르거나 프레임으로 가리지 않았다.
- 다음 재생성이 새 구조를 깨뜨리지 않도록 기존 생성기의 페이지 ID 재사용, Section 내부 원본 찾기, 기준 설명 접미사 보존을 수정했다. 변경 경로의 격리 회귀 24/24가 통과했고, 실제 원격 원본 재사용 호출은 생성·변경 0으로 끝났다.
- 이번 완료 범위는 Figma 구조·세부 기준 연결과 해당 생성기 보수이다. 앱 전체 기준값의 적합성, 물리 기기·장기 사용, 배포의 완료 근거로 확대하지 않는다.

이후 변경은 이 목차에서 해당 역할·부품·목업 계약을 찾아 담당 원본을 바꾸고, 영향을 받는 대표 과업을 확인한다. 값의 사용 조건이 달라지면 이유·범위·확인 결과와 실제 소비 경로를 함께 갱신한다. 재생성 시 이름으로 페이지를 새로 만들지 않고 기록된 ID를 우선 사용한다. 증거와 수정 스크립트는 `work/figma-os-structure-20261002/`에 보존했다.

## 구조와 읽는 순서

1. **OS 기준 안내:** 담당 원본, 현재 소비 경로, 보존 조건과 증거 범위를 먼저 확인한다.
2. **공통 기초:** 실내/종이 색, 글꼴·크기·행간, 간격, 폭/반응형, 조작, 바깥 창틀, 픽셀, 모션을 역할별 묶음으로 본다.
3. **부품과 상태:** 기존 59종의 실제 API/소유 component에 연결하고 default·hover·pressed·focus·disabled·busy·invalid·readOnly 중 의미 있는 상태를 확인한다.
4. **과업 구성과 기능 역할:** 10개 구성과 25개 역할에서 정보 순서·진입/조작/복귀·보존·반복 조건을 읽는다. 기존 111개 ID는 정확히 한 역할에 대응한다.
5. **목업과 실제 구현:** 29개 계약의 이미지 범위·편집 가능한 주변 UI·실제 소스와 진입 경로를 연결한다. 이미지 목업은 실제 입력·계산·저장을 대신하지 않는다.
6. **기준값 적용·보정:** 후보 → 대표 과업 적용 → 원인별 보정 → 확인한 범위의 공통값 채택 → 변경 조건에 따른 유지로 진행한다.

북쪽 책상, 서쪽 자료 책장, 동쪽 탐구 작업대, 남쪽 기록·계획 벽, 위쪽 천장 조명의 과업을 대표 사례로 사용한다. 해당 과업에 중요한 긴 한국어·누적·빈 상태·좁은 화면·오류·중단/복귀를 고른다. 이미지 원본 전체와 바깥 프레임, 원문/ID/이력/초안/개인 테마·서체·배치, 실제 호출 방향·과업 복귀는 계속 보존한다.

## 값 변경과 확인

- 서체·크기·굵기·행간·읽기 폭, 간격·그룹 관계·사용 가능한 폭, 조작 높이·긴 라벨·터치 영역은 함께 평가한다. 단일 px가 맞았다는 이유로 적절하다고 판정하지 않는다.
- 잘못된 적용은 구현에서, 역할 고유 요구는 그 역할 규칙에서, 여러 과업에 반복되는 문제는 공통 원본에서 고친다. 기존 값의 기술 표현 상한은 만들지 않는다.
- 동일한 소스/조건의 기존 확인은 재사용한다. 새 조합이나 실패가 생기면 영향받는 대표 과업을 실제 렌더러로 확인한다. 작은 수정에 관련 없는 전체 QA를 요구하지 않는다.
- Figma의 변수/스타일·Auto Layout·컴포넌트 속성은 실행 코드의 API와 구분한다. 생성 CSS는 담당 JSON/생성기를 통해 바꾸고, 개인 설정을 덮어쓰는 기본값 변경을 피한다.
- 구조·경로 참조 확인, 실제 렌더의 읽기/배치, 실제 입력·저장·복귀, 물리 기기·장기 사용은 각자의 증거로 기록한다. 자동 검사는 편안함·천문대에 머무는 느낌·학습 효과의 증거가 아니다.

기존 브라우저 보고의 5흐름×5 WebKit 환경=25통과와 기존 Figma 구조·렌더 보수 근거는 해당 소스/과업 범위에서 재사용한다. 모든111개 엔터티의 모든 상태나 모든 서체/폭 조합을 검증했다고 확대하지 않는다. 이번 로컬 계약 작성은 JSON·ID 집합·파일/포인터 참조를 확인했으며, 실제 앱을 실행하거나 전체 기준값을 새로 검증하지 않았다.
