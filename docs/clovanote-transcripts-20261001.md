# 클로바노트 전사문으로 학습 자료 만들기

2026-10-01 사용자의 “녹음기능은 뺄게, 대신 네이버클로버노트로 녹음해서 생성한 전사문을 바탕으로 생성” 요청을 반영한다. 이 문서가 이전 앱 내 녹음·Whisper·브라우저 받아쓰기·음성 자동 생성·전사 후 원음 자동 정리 정책보다 우선한다.

클로바노트에서 녹음과 전사를 마친 뒤 음성 기록을 복사해 ‘강의 내용·필기’에 붙여 넣거나, 다운로드한 전사문을 ‘전사문 파일 가져오기’로 넣는다. 기존 텍스트·문서·자막 가져오기와 IndexedDB 원본 저장, 초안, 자료 서버 저장, 생성 결과 근거 연결을 재사용한다. 별도 클로바 로그인이나 음성 업로드 연동은 만들지 않는다.

공식 기준은 [네이버 음성 기록 다운로드](https://help.naver.com/service/24269/contents/12831?lang=ko&osType=MOBILE)이다. 공식 도움말은 음성 기록 다운로드 및 시간·참석자 등 선택 정보를 설명하며, 앱이 읽는 형식 목록과 구별한다. 앱의 전사문 입력은 TXT·MD·DOCX·SRT·VTT를 지원한다. TXT의 화자·시간·공백·줄바꿈을 원문으로 보관하고 자막은 기존 시간 구간 파서를 사용하며 원본 파일 자체도 남긴다.

사용자 흐름은 과목 선택 → 전사문 붙여넣기/파일 가져오기 → 사용할 원문 확인 → GPT 작업 선택 → 직접 생성 → 근거 확인·수정 → 자료 저장이다. 일반 계정도 전사문을 수동 보관한다. GPT 호출·연결·모델 설정은 민석 전용이다. GPT 공급자·사용량·비용 설정은 기존 담당 작업의 최신 결정을 따르며, 이번 전사문 변경은 키 등록·결제·실제 유료 호출의 허용을 추가하지 않는다.

새 자료는 음성을 받지 않는다. 클라이언트는 이전 자료의 audio와 캐시된 음성 전사를 생성 입력에서 제외하고, 서버는 새 audio 필드 요청을 예약·공급자 호출 전에 거부한다. 기존 audio 타입·파일·초안·결과·이력은 읽기/다운로드 호환을 위해 남긴다. 이전 전사 후 정리 예약이 있더라도 저장만으로 원음을 삭제하지 않는다. 중단된 이전 녹음은 새 녹음 재개 대신 내려받기로 복구한다. 로컬 설치 스크립트는 Whisper/PyAV/모델을 새로 설치하거나 다운로드하지 않는다. 기존 설치물과 자료는 임의 삭제하지 않는다.

가져온 파일의 원문은 기존 100만 자 보관 계약을 유지한다. 긴 전사문은 자르지 않고 전체 원본을 보관하며 초기 선택은 12만 자 이내 구간으로 제한하고 안내한다. 사용자는 범위를 바꿀 수 있고 한 번의 GPT 입력은 추가 질문을 포함해 15만 자 이내로 분할한다. 붙여넣기 칸의 한도는 15만 자이며 더 긴 전사문은 파일 가져오기로 보관한다. 가져오기만으로 GPT를 호출하지 않고 생성·저장 재시도도 분리한다.

검증 증거와 실제 GPT/물리 기기/운영 배포의 범위는 아래 완료 기록에서 구별한다. 이번 요청은 실제 GPT 사용량 보류·크레딧 금지와 기존 배포 범위를 변경하지 않는다.
