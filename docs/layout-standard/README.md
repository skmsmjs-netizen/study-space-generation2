## 값의 소유와 변경

**후속 글자 기준:** 최신 사용자 승인값은 [나눔명조700·장평95% 한글/영문 기준](../paper-typography-standard/README.md)이다. 아래500은 이 레이아웃 페이지를 작성한 당시의 반영값이며 기존 레이아웃 보드 전체가 후속700으로 변경됐다는 뜻이 아니다. 최신 승인값/Figma 글자 기준과 실제 앱 구현의 증거 범위를 구별한다. 이번 기존 OS 본문 대응은 위 후속 검토 기록을 따른다.

읽기 최대48rem, 컨테이너40/64rem 후보, 페이지/종이 여백24/16px(root16), 구역/필드/관련 간격24/16/8px, 조작 최소48px/아이콘 목표44px, 창틀8/4px는 `observatory-experience-baseline.json`의 기존 역할별 값을 참조한다. 종이 본문은 최신 `metrics.paper.bodyTypography`: 굵기500/행간2/자간−0.05em, 읽기 면40rem 이하1.85/−0.025em와 양쪽 정렬/마지막 줄 시작 정렬을 반영했다. 일반 글자 기초400과 제목/라벨/수식/코드의 역할 스타일을 구별한다. 개인 서체/크기/폭·원문/강조/명시 줄바꿈은 보존한다.

값은 현재 기본값이며 기술 구현·실제 내용/조작에서 문제를 확인하면 담당 원본의 이유/범위/확인 결과와 Figma/소비 경로를 함께 보정한다. 숫자를 화면마다 복제하거나 개인 설정을 덮어쓰지 않는다. 새 구조는 기존 등록 패턴의 변형/조합을 먼저 검토하고, 해결하지 못하는 요구만 사용 전에 파일/색인/선택 계약에 등록한다.

## 확인한 결과

선택 계약 검사는 등록199항목·25역할·10프로필·111고유 엔터티·미래24분류의 누락/중복과 참조를 확인했다. 소스 참조164개에 존재하지 않는 파일은0개다. 미등록 L999와 화면 구조가 아닌 L014/L091/L118을 대표 화면으로 선택하는 오류를 거부했다. 파일 존재 확인은 실제 소스 동작 검증을 대신하지 않는다.

실제 Figma 재조회에서50보드의 미완/겹침/Auto Layout 내부 넘침0, 대응111개/색인199개/미래24분류/프로필10개를 확인했다. 원본 위젯은944×393.333…px, 비율2.4를 유지했고960px 바깥틀은 clip하지 않는다. 양쪽 정렬 설명130개에 최신 본문 굵기를 확인했다. [전체 안내](evidence/overview.png)와 [조절/관찰 배치](evidence/instrument-profile.png)의 실제 스크린샷을 직접 보아 창밖/실내/종이·바깥틀·글자·전환 배치를 확인했다. URL 다운로드의 sandbox DNS 차단 후 도구의 inline 이미지 응답으로 동일 노드의 시각 근거를 저장했다.

```sh
python3 generation2/docs/layout-standard/scripts/build_standard.py
```

이 명령은 채택 계약·표·문서 검증/투영 데이터를 생성한다. 실제 Figma를 수정하거나 실제 앱 전체의 UI 준수를 자동 판정하지 않는다. 재실행 후 Figma에 투영할 때는 변경된 페이지/노드를 읽고 이 페이지의 소유 범위만 수정하며, 도구 코드 길이 제한에 맞게 해당 단계의 최소 데이터만 전달한다. `scripts/figma_layout.js`는 생성 호출에 사용하는 편집 가능한 보드 구성 코드이며 토큰 원본이 아니다.

## 연결한 담당 문서

루트/웹앱 AGENTS, 천문대 확정 기준, 기능별 정체성 정본, 최우선 디자인·UI·UX 지침, 디자인 시스템, 활성 문서 안내, 원본 검토 폴더의 README와 최신 인계에 연결했다. 새 화면/요소와 큰 변경은 등록 패턴·전환·증가·복귀·보존을 지정하고 변경과 관련된 과업을 확인한다. 작은 수정에 전체111실행/전체 QA를 강제하지 않는다.

기존 앱 전체의 실제 렌더/입력/저장/재접속과 새 배치의 일치 여부는 관련 화면을 실제로 수정하거나 전체 준수 평가를 수행할 때 별도 근거로 남긴다. 이 기준 작업에서 앱 소스·저장·서버·배포는 변경하지 않았다.

## 2026-10-02 실제 웹앱 연결

후속 사용자 구현 요청으로 선택 계약111엔터티를 compact runtime JSON과 기존 featureSurfaceAttributes에 연결했다. 실제 화면은 대표/좁은 패턴·프로필·wrapper 속성을 소비하며 기존 과업 구성/Canvas 좌표/개인 배치를 보존한다. 준비된 개발 목업도 같은 선택을 사용한다. 구현·선택30경로/저장/복귀/다섯화면조건의 결과와 나머지 상태의 범위는 [실제 웹앱 구현 기록](../webapp-implementation-20261002.md)에 남겼다. 이는 아래 과거 기준/Figma 작업의 증거를 실제 앱 전체 준수로 바꾸는 것이 아니다.
