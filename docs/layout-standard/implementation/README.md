## 적용 방법과 보존

[채택 기준](../../layout-standard.md)·[선택 계약](../../layout-standard-contract.json)·기존 Figma 자산을 먼저 재사용했다. Figma 공식 Component Set/Variant, Auto Layout의 Fill/Hug/Wrap, 기존 색·간격 변수와 부품 연결을 사용한다. 선택 계약은 프로젝트 규칙이며 넓은/좁은 예시 폭1008/402px를 공인 최적값으로 표현하지 않는다.

현재 자리의 기존 과업 블록을 대표 패턴 아래로 이동하고 넓은 면에서 목록/상세·조절/관찰 등의 대응 패널과 카드/보드 열을 조합했다. 좁은 면에서는 의미 순서를 지키며 쌓는다. 본문·과업 영역의 높이는 내용에 따라 자라며 고정 prototype viewport의 세로 스크롤은 유지한다. viewport의 의도한 clipping과 내부 원본 장면을 자르는 오류를 구별한다.

공통 장면10:68은 전체 비율2.4를 유지하도록 수정했고 테두리를 장면 바깥에 넣었다. 새 도면에서 기존 입력·버튼·오류·복귀 부품을 인스턴스로 재사용했다. 새 종이 모듈 본문은 최신 Paper/compact 스타일을 재사용하며 양쪽 정렬한다. 기존 글자·개인 오버라이드의 전면 재작성이나 모든 새 본문의 장평95% 윤곽 생성은 이 레이아웃 작업에서 수행하지 않았다. 최신 글자 기준과 앱 대기는 [글자 정본](../../paper-typography-standard/README.md)이 소유한다.

전문 도면에는 기존 실제 작업 구역을 감싸는 등록 패턴의 native Auto Layout과 간격 변수 연결을 추가했다. 기존 관측/읽기 구조가 적절한 부분은 재사용했고 벡터·선·원·사각형의 원래 로컬 좌표와 크기, 기존 문구·컴포넌트 연결·reactions를 전후 대조했다. 그래프·관계 지도·LaTeX 자산의 본질적인2차원 표현을 일반 문단처럼 재배열하지 않았다.

## 확인한 것과 남은 것

279개 기존 도면의 문구·원래 인스턴스의 main component ID·클릭 reactions 보존 대조가 통과했다. 전문113개에서는 벡터/선/원/사각형의 로컬 기하 보존도 통과했다. 생성 응답의56변형/24미래/28현재 보조면/6상태와111개 기능 연결의 누락·중복을 로컬 증거로 대조했다. 생성/수정한 모든 반환 ID는 evidence와 state에 보존한다.

L037의 실제 렌더와 데스크톱 U31의 넓은/좁은 닫힌 모듈·순서·간격을 직접 확인했다. 데스크톱에서 신규 페이지250:180과 현재 보조면들이 표시되는 것도 확인했다. [템플릿 렌더](evidence/template-pilot.png), [U31 실제 앱 캔버스](evidence/current-math-surface.png), [기록 화면의 장면과 외곽](evidence/current-record-screen.png)에 남겼다. 기록 화면 스크린샷에는 기존 교육 주석이 겹쳐 표시되고, 고정 prototype viewport의 아래 내용은 세로 스크롤 대상이다. 이 이미지를 전체 화면 가독성 통과로 확대하지 않는다.

Figma MCP는 Full seat/Professional plan의 tool call limit을 반환했다. 실패한 다음 배치는 종이책 페이지74:399의offset12다. 데스크톱 앱도 동기화 대기 문구를 표시하여 이를 추가 대량 수정 경로로 사용하지 않았다. 추가 계정/요금제 변경·결제는 수행하지 않았다.

직접 남은 범위는 다음과 같다.

- 종이책 읽기 도면72개, 물리 개념 연결36개, 물리 시작3개, 물리 상태9개, 고급 조작 상태77개, 공통 UX 상태42개: 합계239개. 기존 content/root/links를 유지하며 실제 적용 여부를 조회한 뒤 멱등적으로 이어간다.
- 새 템플릿 전체의 변수/속성/바깥 겹침·내부 넘침, 긴 한국어/줄바꿈의 높이 성장, 넓은/좁은 변형의 전체 최종 재조회.
- 템플릿의 입력 부품은 기존 공부 기록 Input을 그대로 재사용하므로 과업별 라벨/예시 값 교체가 필요하다. 예를 들어 수리 배치의 입력은 공부 주제 대신 관찰 조건 역할로 구별해야 한다. 이 부분을 실제 수리 입력 완성으로 보고하지 않는다.
- 기존 주석을 보존한 상태에서 도면 검토 방법을 정리하고 최종 읽기/선택/복귀 렌더를 확인한다. 실제 앱이나 물리 기기의 동작 검증과 구별한다.

## 앞으로의 사용과 재개

새 화면은 등록 패턴 하나를 대표로 선택하고 해당 세트의 Width 변형을 인스턴스로 사용한다. Region의 제목/본문은 내용에 맞게 바꾸고 내부 입력·그림·자료·버튼은 현재 과업의 실제 부품을 연결한다. 원자료→선택/조절→결과→기록/복귀의 순서, 내용 증가와 실패 조건, 원문/ID/초안/개인 배치를 함께 지정한다. 새 배치가 필요하면 기존 변형·조합을 먼저 검토하고 사용 전에 등록한다. 기술 구현에 따른 값 보정은 담당 원본을 갱신한다.

재개 시 state.json과 pending.json, 최신 글자/레이아웃 지침을 읽고 **현재 원격 페이지와 ID를 먼저 조회한다**. 생성한 동일 세트/보조면을 중복 생성하지 않는다. specialized.js는 반환 구조와 보존 검사를 포함한 전문 도면 적용 코드이고 embedded.js는 신규 보조면 작성 코드다. 실제 제출 대상은 현재 pending의 정확한 ID이며 실행 전 병행 변경을 확인한다. summarize.py는 증거에서 결과/재개 파일을 다시 집계하며 Figma 변경·앱 실행을 대신하지 않는다.

이 작업에서 앱 소스·사용자 공부 자료·저장·서버·배포·commit/push는 변경하지 않았다. 전체 요청 완료는239개 후속 적용과 필요한 최종 검토를 마친 뒤 별도 실제 근거로 판정한다.
