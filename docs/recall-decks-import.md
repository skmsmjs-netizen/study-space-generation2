# 덱·빈칸·Anki 파일 가져오기

주제 카드의 실제 입력·저장 흐름에 덱별 복습 설정, 빈칸 카드와 `.apkg` 가져오기를 연결했습니다. 필기 메모와 하단 글 입력창, 자기 평가·FSRS·되돌리기는 기존 경로를 사용합니다. 자기 평가는 실제 정답이나 숙달을 뜻하지 않습니다.

## 채택한 기준과 도구

Anki 공식 [편집 안내](https://docs.ankiweb.net/editing.html)의 노트/카드 구분과 빈칸 번호, [덱 설정](https://docs.ankiweb.net/deck-options.html)의 설정·형제 카드 미루기, [패키지 가져오기](https://docs.ankiweb.net/importing/packaged-decks.html)의 원본 식별을 기준으로 삼았습니다. 같은 번호는 함께 가리고 다른 번호는 개별 카드로 생성합니다. 카드별 자기 평가와 간격 계산은 기존 `ts-fsrs@5.4.2`, 개인별 최적화는 `fsrs-browser@6.6.0`을 재사용합니다.

패키지 해석은 Anki의 [package metadata](https://github.com/ankitects/anki/blob/main/rslib/src/import_export/package/meta.rs), [저장 형식](https://github.com/ankitects/anki/blob/main/rslib/src/storage/upgrades/schema15_upgrade.sql), [노트 서식 protobuf](https://github.com/ankitects/anki/blob/main/proto/anki/notetypes.proto)를 확인했습니다. SQLite는 `sql.js@1.14.2`, ZIP은 `fflate@0.8.3`, Zstandard는 `fzstd@0.1.1`, protobuf는 `protobufjs@8.8.0`, 조건/필드 서식은 `mustache@4.2.0`, HTML의 텍스트 변환은 `htmlparser2@12.0.0`을 사용합니다. ZIP/SQLite/템플릿 엔진을 다시 만들지 않고 앱의 카드·메모·보존 계약을 연결하는 부분만 직접 구현했습니다.

## 계속 사용하는 조건

- 덱은 기존 `recallPreferences`의 선택 필드 `deckName`으로 구별합니다. 선택 필드가 없는 기존 설정·카드는 기본 덱을 유지합니다. 덱마다 목표 기억률·하루 새 카드 수·학습/재학습 단계·최대 간격·개인별 가중치를 저장합니다. 새 덱은 현재 기본 설정을 복사하며 이후 수정은 독립적입니다. 설정 변경만으로 이미 정한 날짜를 바꾸지 않습니다. 미저장 입력과 선택한 덱은 같은 사용자/공간의 기존 초안 키에 보존합니다.
- 빈칸 노트는 문장·추가 설명을 공유하되 번호마다 카드 ID·간격·답변·이력을 분리합니다. 번호 삭제는 이력을 남긴 보관이며 번호 복원은 같은 ID를 사용합니다. 수동으로 보관한 카드는 문장 수정만으로 자동 복원하지 않습니다. 모든 형제 카드의 버전을 함께 확인하고 충돌하면 원문과 초안을 보존합니다.
- 기본적으로 오늘 평가한 문장의 다른 새 카드/일반 복습 카드는 다음 날 보여 줍니다. 진행 중인 분 단위 학습은 계속합니다. 덱 설정에서 해제할 수 있으며 평가 되돌리기는 대상 평가만 되돌립니다. 하루 새 카드 한도는 실제 첫 평가의 현지 날짜를 전체 계정에서 집계하며 필터·보관으로 다시 채우지 않습니다.
- 가져오기 전 주제·덱·처리 가능한 카드·지원하지 않는 이유를 확인합니다. 일부 카드나 미디어 제한이 있으면 확인을 받아 텍스트 카드만 저장합니다. Anki GUID와 카드 ordinal을 원본 식별로 사용하고 같은 파일을 다시 가져와도 중복 생성하지 않습니다. 직접 고친 질문/참고 답변은 덮어쓰지 않습니다. 선택한 갱신도 현재 덱·답변·날짜·이력을 유지합니다. 타인의 평가 이력은 가져오지 않습니다.
- 원본 필드·태그·질문/답변 서식과 표시한 내용을 함께 보존합니다. 가져온 HTML/스크립트를 실행하지 않습니다. 파일 선택 때만 Worker와 SQLite WASM을 불러오며 해석/취소는 브라우저 안에서 진행합니다. 사용자가 확인한 카드만 기존 개인 저장 서버에 보냅니다.
- 파일 128MB, 해제한 SQLite 32MB, 카드 20,000개, 카드 원본 metadata 300,000자 한도를 적용합니다. ZIP의 비대상 미디어는 압축 해제하지 않고 Zstandard 창 크기를 해제 전에 확인합니다. 이 수치는 방어용 상한이며 20,000개 실사용 검증을 뜻하지 않습니다.
- 최대 100개/약 500,000자의 요청으로 나눠 저장하고 요청을 초안에 먼저 보존합니다. 개인 저장은 `flush`와 저장 상태 확인 후에만 완료 처리합니다. 실패/이탈 후 같은 요청 재시도와 같은 파일 재선택으로 이어갈 수 있습니다. 중단 전 저장한 카드와 원본은 남습니다. 목록은 검색과 20개씩 더 보기를 제공하며 빈 검색 결과에서도 검색어를 고칠 수 있습니다.

## 확인한 범위

Anki Python 공식 패키지 26.9.3이 생성한 합성 1,000개 기본 노트와 빈칸 노트 1개를 현재/호환 형식으로 내보냈습니다. 각각 1,002개 카드를 해석했습니다. 실제 앱의 브라우저 Worker로 현재 파일을 읽고 1,002개 분할 저장→새로고침→호환 파일 재가져오기→중복 없음→검색 복귀를 확인했습니다. 브라우저 도구의 native 파일 선택 API가 없어, 격리된 origin의 명시적 합성 버튼이 `File`을 실제 입력 요소에 전달했습니다. 운영체제 파일 선택기를 직접 조작한 증거와 구별합니다.

자동 검사에서 빈칸 힌트/중첩, 삭제/복원/충돌, 덱별 한도/계산값, 저장 실패 후 초안 재열기/동일 요청 재시도, 부분 가져오기 확인, ZIP/SQLite 두 형식과 압축 창 한도를 확인했습니다. 실제 서버의 전용 합성 계정/test 공간에서 덱 설정·빈칸/가져오기 저장·재조회·자기 평가/되돌리기·UTF-16 메모·보관/복원·타인 명령403·기존 코드 모음 보존을 확인했습니다. 가입/메일/관리자 승인 화면이나 실제 사용자 학습의 증거가 아닙니다.

운영 서버의 병행 기능을 덮어쓰지 않기 위해 `scripts/compose-recall-backend.mjs`가 당시 배포된 v18의 복습 모듈/명령/검사/capability만 바꿔 v19로 적용했습니다. 역변환 후 기존 서버의 나머지 모든 byte가 동일한지 검사했고 배포 재조회도 동일했습니다. 이후 병행 기능의 정식 소스가 공개되어 최종 release에 합쳤습니다. 정식 `build:backend`와 v19의 차이가 빈칸 함수의 지역 변수 이름·공백·동일 capability 순서뿐임을 비교한 뒤 정식 bundle v20으로 배포했습니다. 앞으로는 합쳐진 전체 소스를 빌드하고 현재 서버와 비교하는 기본 절차를 사용합니다. 새 DB 컬렉션이나 이력 이관은 없습니다.

## 실제 한계

텍스트 기본/역방향 카드와 빈칸 카드, 알려진 필드/단순 조건을 지원합니다. 이미지·음성 파일 복제, 이미지 가리기, 플러그인 필터/실행 서식, AnkiWeb 동기화, `.apkg` 내보내기, 부모 덱의 계층 한도/프리셋 공유, 자동 일괄 재예약은 구현 범위에 포함하지 않습니다. `::`가 있는 덱 이름은 보존하되 현재 앱에서는 각각 독립적인 덱으로 취급합니다. 물리 iPad/Pencil·한글 IME·VoiceOver·기기간 Sync·장기 관찰/학습 효과는 미확인입니다.
