# 개발 전체의 구조·명명·어휘 기준

2026-10-02 사용자 요청으로 웹앱의 설계·구현·Figma·검토·인계·교육에서 같은 어휘를 사용한다. 원문 정의의 담당 원본은 [웹앱 설계 용어사전](../../../docs/웹앱_설계_용어사전.md)이다. 이 문서는 그 사전을 실제 대상에 연결하는 규칙이며 기존 기능·저장 키·코드 API·개인 자료의 이름을 일괄 변경하는 이관 명령이 아니다.

## 2. 세 가지 위계를 구별한다

**파일 포함 구조:** Figma 파일 → 페이지 → 필요할 때 섹션 → 프레임·컴포넌트·인스턴스·그룹 → 내부 레이어. 모든 단계가 언제나 존재하는 고정 사슬은 아니다. 프레임 안에 프레임/텍스트/인스턴스 등이 함께 있을 수 있다. `parentId`는 실제 포함 관계이며 어휘의 `broader`가 아니다.

**제품과 구성 역할:** 제품 → 장소/기능 영역 → 핵심 과업·사용 흐름 → 실제 화면 → 독립 작업 구역 → 작은 기능 조합 → 기본 요소. 이 프로젝트의 탐색 경로와 Atomic Design의 구성 역할을 연결한 적용 방식이다. `원자/분자/유기체/템플릿/실제 콘텐츠 화면`은 조합을 이해하는 보조 이름이다. 모든 프레임을 일괄 유기체로, 모든 텍스트를 원자로 판정하지 않는다.

**어휘 의미 관계:** 대표명·영어명·동의어·정의·범위·더 넓은/좁은 개념·관련 개념. 사전의 분야는 검색 묶음이며 각 항목이 모두 그 분야명의 하위 종류라고 단정하지 않는다. 다른 의미의 같은 한국어 이름(정렬 Alignment/Sorting, 제약 조건 Constraint/Constraints, 다중 선택 Multi-select/Multi-selection)은 ID와 영어명을 함께 사용한다.

속성·상태·값·토큰은 어느 단계의 요소에도 붙는 별도 축이다. `버튼 → 선 굵기`를 하위 컴포넌트 관계로 만들지 않는다. `State=focus`는 실제 변형 선택이고 `포커스`는 상태 어휘이다. `곡률`은 수학 내용이며 `모서리 반경`은 UI 표현 속성이다.

## 3. 실제 이름을 붙이는 규칙

- 사용자와 대화할 때는 `장소/기능 → 과업/화면 → 구역 → 요소 → 속성 또는 상태` 중 대상을 구분하는 최소 경로를 쓴다. 모든 이름에 전체 긴 경로를 반복하지 않는다.
- Figma 페이지는 현재 번호와 기능명을 유지한다. 컴포넌트는 현재 `Observatory/v2/분류/코드이름`을 유지하고 설명에 한국어 대표명·용도·실제 속성의 번역·소스 연결을 붙인다.
- 구조를 가진 레이어에는 역할과 대상을 표현한다. 장식 벡터의 의미가 불확실하면 `벡터 경로`처럼 확인한 종류까지만 명명하고 접선/법선/곡률 도해라고 꾸미지 않는다.
- 기존 원본/인스턴스/변형/속성명·레이어 오버라이드·생성기 조회 이름을 보존한다. 한글 교육 이름은 설명·주석·대응표에서 연결한다. 실제 재명명이 필요하면 참조 영향과 전후 이름을 같이 확인한다.
- 코드의 컴포넌트·함수·props·CSS·자료·서버 API는 실제 식별자를 보존하고 대응표에서 사전 어휘를 연결한다. 한글화를 이유로 저장 키/ID/API를 일괄 변경하지 않는다.
- 같은 역할은 같은 대표명을 쓴다. 모달이라는 동작 방식과 다이얼로그라는 UI를 구별하고, 화면 장식색을 의미색으로, 체크를 숙달로 읽지 않는다.
- 사전에 없는 전문 속성은 Figma/CSS/SVG 등 공식 어휘를 확인해 별도 보충 항목으로 표시한다. 기존 412항목의 정의를 임의 대체하지 않는다.

## 4. 교육 자료의 읽는 순서

1. 교육 목차에서 파일 구조와 세 가지 위계를 확인한다.
2. 실제 페이지 해설에서 담당 장소·과업·원본·실제 구현 경계를 읽는다.
3. 실제 화면에서 독립 구역과 조작 요소를 찾고, 부품 원본과 인스턴스의 관계를 확인한다.
4. 컴포넌트 설명에서 한국어 이름·실제 속성키·값·상태·소스 API를 대조한다.
5. 글자·선·여백·색·배치·움직임은 속성 대응표에서 이름을 찾는다. 포함 구조와 섞지 않는다.
6. 곡률 사례에서 수학 개념·도해 표현·조작 UI·계산/저장 책임을 연결한다. 실제 있는 노드와 교육용 예시는 구별한다.
7. 전체 사전 색인에서 정의를 확인한 뒤, 기존 UX 경로와 코드 소스로 이동한다. 목업·정적 상태와 실제 입력/계산/저장 실행은 구별한다.

## 5. 개발 전체의 적용과 반복 사용

설계·구현·수정·리뷰·인계에 필요한 해당 분야 어휘를 먼저 찾는다. 화면만 아니라 입력/상태/저장/복구/비동기/검색/접근성/성능/권한/지역화/검증에도 같은 정의를 사용한다. 모든 작업에서 모든 용어를 억지로 사용하거나 모든 코드 줄에 해설을 붙이지 않는다. 중요한 새 대상은 한국어 역할명, 실제 식별자, 상위 맥락, 원문 용어 ID와 담당 소스를 연결한다.

사전 갱신은 원문 해시로 감지하고 안정 ID를 대표명 전체(영어 구분 포함)에서 만든다. 순서가 바뀌어도 ID가 바뀌지 않는다. 용어 이름이 실제로 바뀌면 이전 ID/동의어와 연결하는 별도 이관을 남긴다. 다시 실행할 때 기존 교육 주석만 갱신하고 다른 설명·주석·개인 자료·원본 ID·화면·프로토타입을 보존한다. 새 페이지/새 부품은 다음 대응 생성 시 범위에 포함하며 누락/미확인은 표시한다.

교육 구조·용어 대응·원격 적용·실제 렌더 확인·실제품 기능 완료·배포·교육 효과는 각각 구별해 기록한다. 학습자가 이해했다는 근거 없이 교육 효과를 확인했다고 하지 않는다.

## 6. 담당 산출물

- `vocabulary.json`: 사전 전 항목과 정의, 안정 ID, 기존 분야와 출처를 추출한 색인.
- `contract.json`: 파일 타입·속성·상태와 사전 어휘 연결, 공식 보충 어휘와 프로젝트 규칙.
- `code-map.json`: 기존 구현 대응표의 실제 소스/API와 용어 연결. 현재 소스 확인과 과거 고정판 근거를 구별한다.
- `property-label-supplement.json`: 실제 속성 기본값으로 확인한 요점/출처/연결 대상/조건 예외/관측시간/단위 등의 프로젝트 맥락 이름. 공식 보편 어휘와 구별한다.
- `component-role-labels.json`: 59개 코드 부품의 한국어 역할과 사전 항목. Input/Modal 등의 영어 부분 문자열을 엉뚱한 사전 항목에 연결하지 않는다.
- `figma-coverage.json`: 실제 원격 페이지·구조·부품의 조사/반영 범위와 보존 결과.
- Figma `04 교육 · 구조·명명·어휘`: 기준·전체 구조·구성 단계·속성·상태·실제 사례·사전 분야별 색인·개발 대응을 읽는 자리.

갱신 준비는 `python3 generation2/docs/design-vocabulary/build.py`로 원문 색인을 재생성한 뒤 `python3 generation2/docs/design-vocabulary/render-page.py 실제페이지ID --output /tmp/교육페이지.js`로 해당 페이지의 실행 코드를 만든다. 이 두 명령은 원격 Figma에 쓰지 않는다. 실제 페이지 ID와 최신 원본 목록을 확인한 뒤 Figma 스킬을 적용해 실행한다. 템플릿은 섹션 안의 기존 교육 보드도 찾아 재사용하고, 다른 설명/주석을 보존한다. `create-education.js`는 최초 수업 보드 생성용이며 기존 수업의 내용을 자동 덮어쓰지 않는다. 새 사전 항목은 생성된 색인과 원격 색인을 다시 대조해 추가·정렬한다. [실제 적용 결과](result.md)에 검증 시점과 범위를 남긴다.

Linear 기록은 이번 요청의 외부 전송 승인 부족으로 자동 승인 검토가 거절했다. 해당 기록을 재전송하지 않으며 로컬 담당 문서와 Figma 작업을 이어간다.
