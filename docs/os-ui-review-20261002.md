# OS 정체성에 따른 전체 UI 검토·보수 — 2026-10-02

사용자 「전체 UI, 문구, 폰트, 배치, 디자인 속성」 검토와 「기준값이 부적절할 수 있으니 수정 가능성」 정정을 실제 앱에 적용했다. 어두운 천문대 안에서 종이에 읽고 쓰는 구도, 전체 폭 상단 풍경, 네 고정 장소와 위쪽 공통 자리를 유지하면서 메뉴·정보 위계·글자 역할·빈 상태·복귀를 보수했다. 기존 수치 준수를 사용성의 증거로 삼지 않는다.

## 적용 기준과 범위

- [천문대 확정 기준](observatory-design-standard.md), [값 원본](observatory-experience-baseline.json), [기능별 정체성](observatory-feature-identities.md), [최우선 UI 지침](design-ui-ux-priority.md)의 역할·보존 계약을 재사용했다.
- W3C [일관된 식별](https://www.w3.org/WAI/WCAG22/Understanding/consistent-identification.html)은 메뉴와 실제 목적지 명칭에, [정보와 관계](https://www.w3.org/WAI/WCAG22/Understanding/info-and-relationships.html)는 메뉴 구역과 제목 계층에, [초점이 가려지지 않음](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)은 가로 탐색과 탭에 적용했다. 특정 미감·높이·색값을 W3C 권장값이라고 표현하지 않는다.
- 기존 `study-review`, `study-fix-issue`, React 검토 절차와 공통 토큰·네이티브 링크/details·ResizeObserver·기존 Vitest/WebKit/Axe 도구를 사용했다. 새 라이브러리 설치는 없다.
- 정적 대조 범위는 **25역할, 41경로+29모달+41보조면=111개**이다. 실제 브라우저 순회는 41경로 전부와 변경 관련 설정·대화상자·검색·초안 복귀 흐름이다. 111개 전체의 모든 상태·권한 조합을 실행했다는 뜻은 아니다. 상세 대응은 [검토 범위표](../work/os-ui-review-20261002/ui-inventory-coverage.md)에 남겼다.

| 일정의 결과 없음·보관·휴지통 상태가 구별되지 않거나 해제 행동이 없음 | 원인별 안내와 조건 해제·원래 목록 복귀를 제공한다. 선택 월·달력 보기·보관/휴지통 상태는 보존한다. |
| 없는 메모/자료와 처음 등록하는 상태가 섞임 | 찾을 수 없는 항목·휴지통·첫 등록을 구별하고 실제 휴지통/목록으로 연결한다. 메모를 임시 데이터처럼 설명하는 문구를 제거했다. |
| 다운로드 시작만으로 저장 완료를 단정하거나 JSON 범위를 알아보기 어려움 | `캘린더 파일 내려받기`, `원문·카드 파일로 보관`처럼 실제 행동과 범위를 적었다. 디스크 저장 완료를 단정하지 않는다. |
| 긴 페이지에서 키보드 사용자가 본문까지 많은 메뉴를 지나야 함 | 초점을 받으면 나타나는 `공부 화면으로 건너뛰기`를 추가했다. 본문에 초점을 옮기며 해시 경로를 바꾸지 않는다. |

## 기존 배치값을 바꾼 근거

402×681 실제 인앱 브라우저에서 감사 중간 상태와 수정 후의 높이를 비교했다. 중간 상태는 모바일 제품명 복원이 반영된 시점이며 작업 시작 전 원본과 동일한 표본은 아니다.

| --- | ---: | ---: |
| 상단 도구 | 208.13px | 170.49px |
| 장소 탐색/현재 위치 | 274.48px | 133.49px |

## 자료와 사용 상태 보존

공부 원장·학습 수리엔진·서버 권한·ID·원문·체크의 의미·수정 이력은 수정하지 않았다. 메뉴 재배치로 기능을 없애지 않았다. 사용자 글꼴/테마·읽기 폭·개인 배치·초안과 현재 과업 복귀를 변경 관련 검사에서 확인했다. 데모 원장에 이미 존재하는 필기/기록/수정 이력은 엄격히 대조하고, 최초 빈 필기 화면의 기존 보기 초기화만 별도로 허용했다.

원본 천문대 애니메이션과 각 방위의 카메라/GPU·수리 연결은 앞선 [상단 커버 작업](observatory-cover-20261002.md)을 그대로 사용한다. 이번 UI 보수로 새 공부 점수나 수행·숙달 추정을 만들지 않았다.

## 검증 결과와 한계

검증의 원본 로그·실제 스크린샷·검사 범위·최종 소스 해시는 `work/os-ui-review-20261002/`에 보존한다. 최종 검사 결과는 같은 경로의 `verification.json`과 이 절에 갱신한다.

- 변경 관련 단위 검사: 중복을 제외한 **13파일 94개 통과**. 셸/계정/탭/백업/내비게이션 8파일52개와 문구/일정/메모/자료/통계 5파일42개이다. 같은 검사 재실행을 별도 성공 개수로 더하지 않았다.
- 공통 재료·서체·폼: 격리 WebKit **21관측 통과**. 390/1024폭, 밝게/어둡게, root12/24px, 서로 다른 reading/interface/mono 글꼴, 입력 최소16px·원문 유지·키보드 탭·개인 진입/복구/포털을 확인했다.
- 범례 대비: 격리744×1133에서 밝게/어둡게/OS 자동2모드 × 일반/전체화면 × 5범례를 비교했다. 최소 대비9.51575:1, 밑줄/합성 SVG 선 색·14px·읽기 서체 불변이다. 이 관측 수를 앱의 독립 과업 검사 수에 합산하지 않는다.
- 첫 통합 고정 빌드 `run-zG6zTS`: 새 UI7흐름+기존 검색/작업 공간6흐름을 5WebKit 환경에서 실행하여 **63통과/2실패**. 41경로를 모든 환경에서 끝까지 관찰했고 두 실패의 원본 로그·스크린샷·trace를 보존했다. 실패는 iPhone 가로 홈 링크 타깃 측정과 iPad 분할 창 수식 범례 대비이다. 수정/재검사 결과와 구별하며 처음부터65통과였다고 보고하지 않는다.
- 최종 두 보완(폭 변화에 따른 현재 자리 노출·범례 대비) 이후 타입·디자인 검사56CSS/오류0와 전체 프런트엔드 번들 생성은 통과했다. 일반 `npm run build`의 public 복사와 별도 바이트 복사 모두 호스트의 작은 정적 파일 read에서 분 단위 지연이 발생했다. 원인은 앱 런타임 오류로 단정하지 않으며 process sample과 중단 로그를 보존했다. 기존 Vite 설정을 그대로 읽고 `copyPublicDir:false`와 별도 outDir만 지정한 번들은1.85초에 성공했다. 지연된 이번 작업의 프로세스는 정리했다.
- 수정 후 선택 UI 검사는 최신 index+assets165개, 총166파일의 고정 표본을 사용한다. public 입력은 이 표본에서 제외했고 원본 파일은 변경하지 않았다. 따라서 코드·관련 UI의 검증과 최종 전체 정적 자산을 포함한 배포 묶음 완성을 구별한다. 이 작업에서 전체 배포 묶음의 최종 재생성 완료는 주장하지 않는다.
- 홈의 후속 실제 스크롤·클릭 검사1개는 통과했다. 화면 밖 `content-visibility:auto` 메모의 임시 높이288px와 아직 그리지 않은 자식의 기하값을 검사에서 혼용한 것이 첫 실패의 원인이었다. 실제 PageDown으로 메모를 노출하면 부모 높이386.66px, 통계 링크127.78×48px, 세 지점 hit-test 모두 true, 전체 Axe0이었다. 통계 이동→뒤로→메모 열기/닫기→원문 보존도 확인했다. 메모 CSS는 바꾸지 않고 R01 검사 준비를 실제 스크롤 경로로 보완했으며 접근성 기준/타깃을 제외하지 않았다.
- 범례 보수 후 실제 수식 R09의 iPad 좁은 창 검사1개는 통과했다. 전체 Axe0·기본/125% 재배치·원문 보존을 확인했다. 별도 기하/색 합성 검사와 실제 페이지 검사를 구별한다.
