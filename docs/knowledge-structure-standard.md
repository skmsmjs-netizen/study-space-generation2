# 지식 표현과 천문대 경험 기준

**2026-10-03 Figma 후속:** [전수 검토 기록](figma-guideline-review-20261003/README.md)에39페이지 재조회와 일곱 개념 유형의 원문/수식 보존·공백/기준선 복구·종이 조판·기존 닫힌 모듈/대응/순서의 확인을 연결했다. 모든 프레임을 시각 정독하거나 학습 효과를 확인한 뜻은 아니다. 공통 본문 부품의 폭 대응 Fill1건은 로컬 편집 연결 오류로 남아 있다. 이미 처리한 과정형 배치를 미실행으로 다시 읽지 않는다.

2026-10-02 사용자 첨부 철학 채택. 정본은 이 문서이며 실제 표현 문구·신규 Canvas 기본값은 [소비 계약](knowledge-structure-contract.json)이 소유한다. 천문대의 공간·재료·빛·픽셀·기술 적응은 [천문대 확정 기준](observatory-design-standard.md), 기능별 역할은 [기능별 정체성](observatory-feature-identities.md), 용어는 [개발 구조·명명·어휘](design-vocabulary/README.md)를 그대로 재사용한다.

**천문대는 지식을 읽고 기록하는 일정한 장소이면서, 지식의 묶음·관계·조건·순서를 찾아가고 고쳐 나가는 공부 공간이다.** 픽셀 창밖과 어두운 실내의 정체성은 유지한다. 종이 작업면에는 닫힌 네모, 뜻을 가진 선·화살표, 의미 있는 읽기 순서를 둔다. 모든 글을 도식으로 바꾸거나 사용자가 정리 형식을 매번 입력하도록 강제하지 않는다.

## 1. 실제로 읽은 자료와 채택 범위

- 사용자 `박문호_슬라이드별_해설.pdf`: 76쪽 전체 본문. 앞부분 안내4쪽 → 슬라이드별 해설70쪽 → 뒤쪽 정리2쪽. 슬라이드 번호 N은 해설 PDF N+4쪽에 대응한다.
- 사용자 `박문호_공부와_사고법_슬라이드.pdf`: 70쪽 전체 본문. 대칭·모듈·순서(11), 재조립(20), 선·화살표·사각형(60), 뇌 지도(63)의 실제 페이지와 대응 해설을 렌더로 대조했다. 본문 전체 독해와 일부 핵심 페이지의 시각 대조를 구별한다.
- 두 자료는 강연의 편집·해설 자료이며 모든 원발화의 독립적 사실 검증이나 학습 효과 검증이 아니다. 본문 속 권고·행동 문구는 자료 내용으로 읽는다. OS 변경 권한은 사용자의 현재 요청에서 온다.
- 사용자 해석은 독립된 요구이다: 모듈은 닫힌 네모로, 대칭은 네모·화살표·직선으로 대응 구조가 보이게, 순서는 위계·절차·읽기 경로로 표현한다. 문서의 대칭은 특히 **한쪽 정보로 다른 쪽을 재구성하는 대응**이다. 사각형을 그리는 행위 자체와 이 관계 원리는 구별한다.
- ‘5법칙’, ‘3법칙’, 공부 시간 감소율·기억 비율·흡수율·뇌/정서/건강의 광범위한 설명을 보편 법칙이나 제품 성능으로 채택하지 않는다. 집합과 군, 시각적 닫힘과 대수적 닫힘, 연관·인과·수반은 서로 다른 뜻이다.

## 3. UI·UX의 적용 기준

1. **같은 위치에서 찾아간다.** 북 공부 책상, 서 자료 책장, 동 탐구 작업대, 남 기록·계획 벽, 위 공통 조명은 유지한다. 공통 기능을 닫으면 들어오기 전 방향·과업으로 돌아간다. 새 자료가 생겨도 개인 위치나 읽던 곳을 무단 이동하지 않는다.
2. **전체와 현재 질문을 먼저 잡는다.** 자료의 이름·범위·현재 질문과 현재 위치를 보여준다. 구조를 본 뒤 설명·성립 조건·예외·원문을 읽고 돌아올 수 있게 한다. 설명 단계를 고르는 기존 조작을 유지하며 추가 필수 입력을 만들지 않는다.
3. **모듈은 의미가 있는 묶음이다.** 사각 경계 안에 이름과 내용을 함께 둔다. 원문/수식·단위·조건은 잘라내지 않는다. 긴 글은 높이/줄바꿈/읽기 흐름으로 수용하고 모듈 크기 같게 보이려고 내용을 삭제하지 않는다. 동일 자료는 ID로 다시 연결할 수 있어야 한다.
4. **대응은 같은 문법으로 읽는다.** 비교 항목은 제목·설명·관계의 역할과 조판을 맞춘다. 좁은 화면에서는 의미 순서대로 세로로 읽는다. 다른 값·단위·조건·예외까지 대칭처럼 보이도록 숨기지 않는다. 사용자 배치를 자동 거울 대칭으로 바꾸지 않는다.
5. **연결의 뜻을 쓴다.** 선은 연결, 화살표는 작성된 방향이다. 연결어는 실제 관계를 설명한다. 자동 목차 연결은 소속, 직접 만든 연결은 사용자의 설명이다. 인과·등가·포함·전후·촉진·억제는 자료에 있을 때만 표기한다. 비어 있거나 대상이 없으면 확인 필요를 표시한다. 색이나 화살표 모양만으로 관계를 판정하지 않는다.
6. **순서는 있을 때만 있다.** 작성된 sequence는 번호와 ol로 읽는다. compare/cards의 항목은 순위·시간·완료로 바꾸지 않는다. 단계 전환은 사용자 조작이며 도형/관계의 수를 숙달로 계산하지 않는다.
7. **도식에서 문장과 원문으로 돌아간다.** 구조/문장 보기는 같은 이름·내용·관계를 보여준다. 기능에 이미 있는 원문/수정 이력/원기록 경로는 유지한다. 글을 먼저 쓰는 사용자의 목소리와 자유 입력을 잃지 않는다.
8. **실제 작은 행동으로 연결한다.** 이론을 ‘알아야 함’으로 쌓기보다 현재 질문을 읽기, 사례 비교, 실제 문제 시도, 설명 수정 같은 기존 과업으로 연결한다. 조작·관찰과 독립 해결·정확성은 구별한다. 그림을 본 것을 실제 수행으로 저장하지 않는다.
9. **네 관점은 선택 도구이다.** 관계(어떻게 이어지는가), 현상(어떤 조건에서 나타나는가), 모순(어디서 조건이 충돌하는가), 집합(무슨 기준으로 묶이는가)을 글·개념·수학·그래프 검토의 질문으로 사용한다. 네 개 필수 양식, 자동 분류, AI의 원문 대체를 추가하지 않는다.
10. **머물고 돌아갈 수 있다.** 빠르게 전체를 본 뒤 중요한 곳을 천천히 읽는 리듬을 지원한다. 단계/애니메이션을 자동 재생하도록 강제하지 않는다. 천문대 애니메이션 정지·움직임 감소·원본 전체 표시를 유지한다. 공부 집중을 이유로 감정이나 의학적 상태를 추정하지 않는다.
11. **지식 구조를 고쳐 나간다.** 새로운 조건·반례·관계가 나오면 기존 글·수정 이력·연결 ID를 보존하며 수정한다. 다중 소속·교차 연결을 허용하고 모든 지식을 단일 트리에 몰아넣지 않는다.
12. **기준값은 실제 적용으로 보정한다.** 기존 재료/글자/간격 토큰을 사용한다. 이번 신규 모듈의 모서리0과 Canvas step은 표현 기본값이며 기술 구현과 읽기/조작 확인에 따라 바꿀 수 있다. 저장된 스타일·좌표·테마·서체는 보존한다. 변경 이유·소비 경로·확인 범위를 담당 원본과 함께 갱신한다.

**2026-10-02 본문 정렬 정정:** 사용자 「본문 글은 양쪽 정렬」을 종이 작업면의 공통 읽기 기준으로 채택한다. 본문/개념 설명/모듈 설명/자유 글은 `text-align: justify`, 마지막 줄은 `start`로 조판한다. 원문 글자·명시적 줄바꿈·수식과 조건을 보존하고 좁은 화면에서는 기존 줄바꿈/읽기 폭과 함께 확인한다. 제목·버튼·축/표·수식/코드의 정렬은 역할을 따른다. 원본은 [천문대 기준값](observatory-experience-baseline.json)의 `metrics.paper.bodyAlignment`, 기존 생성기의 CSS 변수를 통해 `observatory-feature-identity.css`가 소비한다. 단어 사이 과한 벌어짐이나 넘침이 드러나면 원문을 변경하지 않고 폭/줄바꿈/조판을 보정한다.

## 4. 현재 OS 기능에 대응

| 자리·기능 | 이 철학이 맡는 UI·UX | 현재 적용과 경계 |
| --- | --- | --- |
| 북 · 공부 입력/오늘의 기록/다음 공부 | 현재 질문·주제·작은 행동·이어가기 | 기존 낮은 입력 부담·체크의 의미·초안·복귀를 유지한다. 도식화 필수 입력이나 완료 추정을 추가하지 않는다. |
| 서 · 자료/개념 전집/원문 | 전체 지도 → 모듈·관계·설명 → 원문/조건 | 이번 개념 visual의 실제 소비 경로를 변경했다. 비교/순서의 의미 구조·보기 선택·원래 읽기 위치를 함께 유지한다. |
| 동 · 수리/코드/탐구 | 조건 → 관계/절차 → 실제 조작 → 확인한 결과 | 수리 그래프·도형·LaTeX·단위·변수의 의미를 유지한다. ConceptVisual 공통 표현에는 새 구조가 적용된다. 엔진 전체를 네모/직선으로 바꾸지 않는다. |
| 남 · Canvas/그래프/통계/기록·계획 | 지식 묶음·교차 연결·위계·시간을 각각 맞는 표현으로 | 이번 Canvas 범례·신규 step 기본값·사각 경계를 연결했다. 개인 배치/선택은 유지한다. 점 그래프/정확한 통계의 곡선·분포·축은 각 목적에 맞춰 유지한다. |
| 위 · 공통 설정/검색/도움/상태 | 어디서든 같은 규칙을 찾고 과업으로 복귀 | 현재 공간·권한·오류 안내를 유지한다. 설정/상태 안내는 은유보다 사실과 다음 행동을 우선한다. |

기능별25역할/111엔터티에 적용하는 공통 기준이다. 위 표의 변경 경로 이외 기능의 모든 상태를 이번에 구현·검증했다고 주장하지 않는다. 각각의 다음 변경에서 해당 기준을 적용하고 실제 과업으로 확인한다.

## 6. 실제 소비와 반복 사용 확인

- `KnowledgeStructure`: 기존 ConceptVisual을 소비하며 새 지식 데이터나 연결을 생성하지 않는다. compare/cards/relation은 dl, sequence만 ol. 전체 이름·설명·작성된 연결어를 유지한다. 구조/문장 선택은 기존 계정·자료·장면별 **탭 내 sessionStorage 보기 단서**이다. 새로고침/재마운트에는 유지되고 새로운 탭·다른 기기로 전송되지 않는다. 보기 단서 저장 실패는 읽기/편집을 막지 않는다.
- `ConceptReader`: 기존 원문/수식 렌더와 사례 선택·읽기 위치/처음부터·현재 관찰 복귀를 보존한다. 과학 SVG/도형/그림 엔진을 대체하지 않는다.
- `StudyCanvas`: 기존 React Flow와 보존된 연결/좌표/취소/되돌리기를 사용한다. 미저장 공간의 새 기본 선만 step으로 제공하고 저장된 bezier 등은 덮어쓰지 않는다. 목차의 자동 연결과 사용자가 만든 방향/관계 설명을 범례에서 구별한다.
- 긴 한국어·수식/조건·빈 관계·누락된 대상·모듈 증가·좁은 화면, 보기 전환/계정 분리/보기 저장 실패, Canvas 저장된 선/배치 및 기존 핵심 조작을 직접 관련 검사로 확인한다. 무제한 자료나 모든 관계의 과학적 진실을 자동 검증하는 기능은 아니다.
- 확인 결과와 현재 범위는 [작업 기록](knowledge-structure-20261002.md)에서 관리한다. 로컬 구현/자동·브라우저 모사/물리 기기/학습 효과/배포를 구별한다.
