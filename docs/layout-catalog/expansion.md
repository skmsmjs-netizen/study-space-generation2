# UI·UX 레이아웃 사전 — 검토와 확장

2026-10-02 · 첨부 `uiux_layout_figma_guide.txt`의 검토·확장본이다. **OS 최종 레이아웃 기준을 정하기 위한 자료 단계**이다. 원본 항목은 삭제하거나 다시 번호 매기지 않았다. 기존 OS 지침을 참조했으며 아래 새 조합과 전환 규칙은 제안이다. 실제 웹앱·Figma 적용과 검증 완료를 뜻하지 않는다.

원본은 36개 PART, 도입 0번과 본 항목 1–186번, 총187개 번호 항목이다. 전체 원문은 `source/uiux_layout_figma_guide.original.txt`, 원문과 이 확장을 함께 읽는 파일은 `uiux_layout_figma_guide.expanded.txt`, 항목별 분류와 전체 기능 대응은 `catalog.json`이다.

## 확장 1. 검토 결론과 자료의 사용법

**원본은 넓은 개념 사전으로 적합하지만, 그 자체가 화면별 배치를 결정하는 완성된 설계 명세는 아니다.** Grid·화면 패턴·구도·간격을 구별한 도입, Hug/Fill/Fixed의 비교, 콘텐츠에 맞춘 Breakpoint, 좌표보다 규칙을 정하는 접근을 유지한다. 여기에 서로 다른 종류의 항목을 구별하고 과업별 선택·내용 변화·복귀 조건을 붙여야 실제 OS 기준의 근거로 쓸 수 있다.

확장 방식은 기존 패턴 재사용 → 부족한 동작 보충 → 필요한 조합에 이름 부여이다. 아래 187–198번은 독립 이론이나 보편 표준이 아니라 기존 패턴을 더 구체화한 작업 패턴이다. 제목 수를 늘리기 위해 같은 패턴의 기기별 모습을 별도 종류로 세지 않는다.

### 1.2 “웹앱은 이 파일의 레이아웃 중 하나”를 적용할 때의 해석 제안

대표 화면 패턴은 원본 또는 이 확장에 등록된 항목에서 선택한다. 내부에 다른 등록 패턴을 조합할 수 있으며 대표 패턴·자식 패턴·전환형을 함께 기록한다. 새 화면이 목록에 없으면 먼저 기존 항목의 변형인지 확인하고, 해결되지 않는 차이만 근거와 함께 사전에 추가한다. **간격 값, Figma 기능, 그림 구도를 화면 패턴 대신 선택할 수 없게 한다.**

전체 앱에 한 패턴만 반복하는 뜻으로 읽으면 본문·수식·표·Canvas가 서로 다른 작업을 제대로 수행하기 어렵다. 대신 각 화면/과업 구역의 선택이 이 목록으로 추적되게 한다. 이 해석은 다음 OS 기준 작업에서 명시해야 하는 제안이며 이번 문서 생성만으로 앱에 강제되지는 않는다.

## 확장 3. 추가 작업 패턴 187–198

공통 조건: 내용과 실제 의미 순서를 보존한다. 선택/초안/스크롤/패널 상태를 과업에 필요한 기간 유지한다. 재배치는 뷰를 바꾸며 원문·ID·개인 Canvas 좌표를 바꾸지 않는다. 아래 이름은 실무 패턴을 정리한 프로젝트 설명명이며 공식 분류 표준이 아니다.

## 187. Resizable Split Pane — 폭을 조절하는 분할면

- 기존 대응: 26 Two-column, 30 Split-screen, 45 Master–Detail, 70 Inspector, 82 IDE.
- 구조: `자료/편집면 | 조절 경계 | 상세/결과면`.
- 사용: 원문과 필기, 코드와 결과, 수식 조건과 그래프를 함께 비교할 때.
- Figma: 각 패널 최소/최대 폭과 넓은/좁은 변형, 경계의 조작 상태를 표현한다. 정지 시안만으로 드래그 동작을 완성했다고 하지 않는다.
- 웹/UX: 경계 드래그 외 키보드 조절·접기·되돌리기·초기 비율 복귀를 제공한다. 콘텐츠 최소 폭이 부족하면 주면 한 열 + 보조면 열기로 전환한다.
- 누적/복귀: 사용자가 정한 비율과 선택을 보존하며 새 자료가 들어와도 자동 초기화하지 않는다.
- 한계: [APG Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)는 초점 가능한 separator의 값·키보드 참고를 제공하지만 해당 문서의 검토/예제 미완 안내도 유지한다. 완성된 인증 패턴으로 표현하지 않는다.

## 188. Docked Multi-pane Workspace — 붙여 놓는 다중 작업면

- 기존 대응: 27 Three-column, 46 List–Detail–Inspector, 70 Inspector, 82 IDE.
- 구조: `대상 목록 | 주 작업면 | 속성` + 필요 시 아래 `실행 결과/로그`.
- 사용: 실제 동시 참조가 필요한 편집·연산·자료 주석. 모든 기능에 네 패널을 강제하지 않는다.
- 동작: 패널 이름·역할·최소 폭·접힘·선택 탭·닫기/다시 열기·복귀를 정한다. 좁은 폭에서는 주 작업면을 유지하고 다른 면을 순차적으로 연다.
- 보존: 개인 패널 선택/폭을 덮어쓰지 않는다. 결과가 늘어나도 입력·선택·스크롤을 뺏지 않는다. 도킹은 문서 배치를 바꾸는 권한이 아니다.

## 189. Tree–Detail Workspace — 계층 색인과 상세

- 기존 대응: 28 Sidebar–Content, 43 List, 45 Master–Detail, 81 Documentation.
- 구조: `계층 색인/찾기 | 선택한 원문/편집`.
- 사용: 과목→단원→주제, 목차, 개념/자료 묶음.
- 동작: 펼침과 선택을 구별하고 현재 소속을 보인다. 항목 이동 시 관련 선택/집계의 기준 ID를 유지한다. 좁은 화면은 목록→상세이며 돌아오면 같은 항목과 펼침 위치이다.
- 누적: 긴 이름·깊은 계층·동명이름·검색 결과의 상위 맥락을 함께 고려한다. 새 기본 자료량을 임의로 확정하지 않는다.

## 190. Document–Annotation Workspace — 원자료와 기록지

- 기존 대응: 26 Two-column, 45 Master–Detail, 60 Filmstrip, 62 Canvas, 81 Documentation.
- 구조: `원문/PDF/그림 | 내 필기/발췌/주석` + 현재 페이지/출처.
- 동작: 두 면의 스크롤 연결 여부를 명시하고 수동 이동을 유지한다. 발췌는 원문과 구별하고 출처로 돌아갈 수 있게 한다.
- 좁은 화면: 원문/기록을 전환하되 페이지·선택 문장·입력 초안을 유지한다. PDF의 본질적 2D 확대와 일반 본문의 재배치를 구별한다.
- 오류: 원자료를 읽지 못해도 기존 기록은 보존하고 자료 재연결 경로를 둔다.

## 191. Contextual Side Sheet / Bottom Sheet — 현재 과업의 곁면

- 기존 대응: 69 Drawer, 70 Inspector, 170 Modal.
- 구조: 주 작업을 배경에 유지하고 오른쪽/아래에서 관련 상세나 짧은 조작면을 연다.
- 선택 조건: 짧은 상세/설정에는 곁면, 긴 편집/복잡한 다단계 작업에는 실제 상세 화면을 고려한다. 아래 시트라는 모양만으로 modal 여부를 정하지 않는다.
- 모달이면 배경 조작 제한과 Dialog 초점 규칙을 적용한다. 비모달이면 주면과 곁면을 오갈 수 있어야 한다. 닫기 후 실제 진입 대상에 복귀한다.
- 모바일: 가상 키보드가 입력/오류/실행 버튼을 덮지 않게 높이와 스크롤 주체를 정한다. 스와이프만으로 닫게 하지 않는다.

## 192. Anchored Popover / Command Surface — 실행자에 붙는 짧은 면

- 기존 대응: 64 Top Navigation, 67 Tabs, 69 Drawer, 70 Utility Panel.
- 구조: `실행 버튼/선택 → 주변 작은 명령면`.
- 사용: 필터 값, 내보내기 선택, 짧은 문맥 명령. 긴 글쓰기·필수 조건 전체를 작은 팝오버에 가두지 않는다.
- 동작: 화면/창틀/스크롤 경계에서 위치를 보정하며 원래 실행자를 보존한다. 키보드/터치로 열기·실행·닫기가 가능해야 한다.
- 주의: popover가 메뉴인지 대화상자인지 단순 설명인지 역할을 먼저 정한다. 모양만으로 ARIA menu를 붙이지 않는다. 작은 면을 닫을 때 답 초안을 버리지 않는다.

## 193. Question–Response–Explanation — 질문·내 답·설명 공개

- 기존 대응: 25 Single-column, 53 Form, 54 Wizard, 75 Comparison.
- 구조: `범위/조건 → 질문 → 내 답 → 명시적 설명 공개 → 결과/수정`.
- 사용: 시험 연습·암기시험·주제 카드. 지식 모듈은 닫힌 사각형으로 구분하되 답과 설명의 공개 시점을 구별한다.
- 동작: 질문으로 복귀하고 답을 수정할 수 있게 한다. 대칭 비교는 같은 기준으로 내 답과 설명을 맞추는 것이며 독립 해결 여부를 임의 판정하지 않는다.
- 긴 답/실패: 제출 실패에도 원문을 유지한다. 과정/조건/예외를 말줄임이나 동일 카드 높이에 맞춰 잘라 내지 않는다.

## 194. Parameter–Visualization–Evidence — 조절·관찰·근거

- 기존 대응: 26/30 분할, 47 Dashboard, 70 Inspector, 82 IDE.
- 구조: `질문/조건 → 조절기 ↔ 시각화 → 현재값/단위 → 계산/설명`.
- 사용: 수리 엔진·과학 도해·실행 도구. 화살표에는 실제 관계나 순서 이름을 붙인다. 과학 도형 자체를 사각 모듈로 변형하지 않는다.
- 동작: 조절과 관찰이 비교 가능해야 한다. 좁은 화면에서는 질문→입력→그림→값/근거 순으로 읽으며 그리기 실패에도 입력과 값/오류를 제공한다.
- 고급 구현: GPU/셰이더/3D를 도입해도 같은 질문·값·오류·복귀를 유지한다. 원본 천문대 커버를 도구 그래프의 뷰포트와 혼동하지 않는다.

## 195. Data View–Record Detail — 여러 표현과 원기록

- 동작: 차트·표·원기록이 같은 범위와 ID를 가리킨다. 좁은 화면에서는 그래프를 순차 배치하고 본질적 2D 표는 해당 영역 안의 가로 탐색/값 목록을 마련한다.
- 한계: 미기록을 0·실패로 바꾸거나 없는 숙달률/관계/목표를 만들지 않는다.

## 196. Graph–Detail Workspace — 관계 지도와 원문

- 사용: 설정·계정·API·백업·휴지통·초안. 읽기 설명과 실제 변경 버튼을 구별한다.

## 확장 4. 천문대 OS에 연결하는 10개 조합 프로필

**공통 외곽은 어두운 실내와 창밖 전체 커버, 과업은 그 아래 읽고 쓰는 종이 면으로 연결한다.** 아래 프로필은 기존 10개 구성 역할을 레이아웃 항목으로 풀어 놓은 제안이다. 장소·재료·기능명을 새로 만들지 않는다. 공간 전환을 반드시 3D 회전으로 구현할 필요는 없으며 현재 장소와 복귀가 명확해야 한다.

```text
공통 접근: 위쪽 천장 조명 — 찾기·설정·계정·저장/복구
┌──────────────────────────────────────────────────┐
│ 창틀 공간 + 원본 위젯 전체 + 창틀 공간             │
│ 창틀은 위젯 바깥에 자리한다. 전체 비율을 유지한다.  │
└──────────────────────────────────────────────────┘
현재 자리/기능명 · 이동/복귀
┌───────────────┬──────────────────────────────────┐
│ 필요할 때만   │ 현재 과업의 종이 면               │
│ 목록/색인     │ 본문/입력/그림/값/상세            │
└───────────────┴──────────────────────────────────┘
```

이 도식은 역할 관계를 보이는 조합 예시이며 확정 좌표가 아니다. 창문 높이를 고정한 뒤 긴 장면을 잘라 맞추지 않는다. 위젯이 접힌 사용자 상태는 유지한다. 상단 커버를 모든 작은 모달 안에 다시 복제하지 않는다. 개인 읽기 테마/서체는 기존 기준대로 우선한다.

| 프로필 | 기존 구성 키 | 대표 패턴 | 필요할 때 조합 | 좁은 화면/복귀 |
| --- | --- | --- | --- | --- |
| P01 연속 기록지 | journal | 25 Single-column | 42 Feed 또는45 선택 상세, 53 입력 | 읽기 한 열; 주제·초안·위치 유지 |
| P02 색인과 펼친 항목 | catalogue | 45 Master–Detail | 189 계층, 55/56 찾기·필터 | 목록→상세; 검색/선택/펼침 복귀 |
| P03 원자료와 곁 기록지 | document | 190 Document–Annotation | 187 분할, 60 Filmstrip | 원문/기록 전환; 페이지/초안 유지 |
| P04 질문과 답안지 | practice | 193 Question–Response–Explanation | 54 단계, 75 비교 | 질문→내 답→공개 설명; 답 보존 |
| P05 연산과 관찰면 | instrument | 194 Parameter–Visualization–Evidence | 187 분할, 188 작업면, 82 IDE | 입력→그림→값/근거; 조건 유지 |

| P10 공간 조율과 복구 | control | 198 Settings–Operation–Recovery | 53 Form, 81 도움말, 191 곁면 | 현재 과업 위에서 열고 원래 자리로 복귀 |

한 프로필의 존재가 모든 기능에 그리드/카드를 강제하지 않는다. 오늘의 기록이 Feed일 때 원문 정렬은 실제 시간/선택 기준을 따르며 추천순을 허위 시간순으로 보이지 않게 한다. 종이는 작업 재료이고 실내는 주변 재료이며 색과 치수는 기존 값 원본을 참조한다.

창밖의 ‘동료 천문대’는 사용자가 자신의 공부 공간을 바라보는 보조 감각이다. 이를 실제 다른 사용자·동료 계정이나 활동 데이터가 있다고 표시하는 장치로 바꾸지 않는다. 자기 기록·이어가기·현재 위치와 연결하되 체크나 애니메이션을 숙달 증거로 표시하지 않는다.

픽셀 느낌과 살아 있는 장면은 하늘·천문대·바깥 틀·선택적 짧은 장식에 집중한다. 본문·입력·표·초점·조작 크기를 픽셀 격자에 강제로 맞추지 않는다. 별의 움직임과 장소 전환은 읽기/입력을 방해하지 않게 하고 기존 정지·접기·동작 줄이기 설정을 유지한다. 고급 렌더러를 도입해도 종이 아래의 글을 움직이는 풍경 위에 겹치지 않는다.

## 확장 5. 수치가 실제 적용에서 어긋나지 않게 기록하는 방식

**한 숫자로 모든 상황을 고정하지 않고, 현재 기본값·허용 성장·구조 전환·수동 설정·확인 조건을 함께 기록한다.** 아래는 현재 원본 값의 참조표이다. 이 문서가 두 번째 토큰 원본이 되지 않는다. 바뀌면 `observatory-experience-baseline.json`과 실제 소비 경로를 함께 갱신하고 이 표는 다시 확인한다.

### 5.1 값 하나에 필요한 최소 기록

```text
역할: 무엇을 읽거나 조작하는 값인가?
원본 참조: 기존 token 또는 JSON 경로
현재 기본값: 단위와 기준 글자 크기를 명시
축별 반응: width / height 각각 Hug·Fill·Fixed·min/max
내용 증가: 긴 제목, 본문, 값, 오류가 늘어나면 어떻게 되는가?
전환 조건: 실제 패널 최소 폭/제어기/글자 확대에서 언제 구조를 바꾸는가?
예외 범위: 본질적 2D인 표/그래프/Canvas 등
수동 설정: 개인 폭·서체·패널·순서가 있으면 어떻게 우선하는가?
복귀: 닫기·회전·재접속 후 무엇이 유지되는가?
확인 결과: 실제 자료/뷰포트/환경·관측 결과·미확인
수정 이력: 이유·범위·원본/소비 코드/Figma의 연결 변경
```

전환 폭을 계산할 때는 먼저 `주면 최소 폭 + 보조면 최소 폭 + 경계/간격 + 안쪽 여백`을 확인한다. 이 계산은 초기 후보를 고르는 방법이며 실제 줄바꿈/폰트/키보드와 사용자 조작으로 보정한다. 고정 70/30이나 황금비를 그대로 필수 비율로 쓰지 않는다.

자동 변경은 가용 폭·콘텐츠·글자 크기·사용자 설정의 관련 변화에만 재계산한다. 상태 갱신마다 창문 비율·패널 폭·선택·초점을 초기화하지 않는다. 새 고급 기술을 도입하면 표현 방법은 바꿀 수 있지만 원본 전체 보존·읽기/조작·자료 의미·개인 설정은 유지한다.

### 5.2 본문 양쪽 정렬과 읽기 접근성

사용자 채택 기본값 `justify`·마지막 줄 `start`를 유지한다. 좁은 한글 문단에서 단어/글자 간격이 과도해지는지, 명시적 줄바꿈과 장문/짧은 마지막 줄이 유지되는지 확인한다.

[WCAG 1.4.8 Visual Presentation](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)은 AAA 수준에서 양쪽 정렬을 해제할 수 있는 방법 등 사용자 제어를 다룬다. 기본 justify 자체가 AA 위반이라는 뜻으로 읽지 않는다. 기존 개인 읽기 설정/사용자 스타일을 보존하고, OS 기준을 최종화할 때 읽기 정렬 선택을 제공할지와 검증 범위를 명시할 것을 제안한다. 기본값만으로 AAA 적합성을 주장하지 않는다.

[WCAG Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)의 행간1.5·문단 뒤2em·자간0.12em·단어 간격0.16em은 기본 미감값이 아니라 사용자가 해당 간격을 적용해도 내용/기능이 손실되지 않아야 하는 확인 조건이다. 이를 기존 행간1.65를 강제로 바꾸라는 지시로 읽지 않는다. 해당 언어/문자에 적용되는 간격 속성을 구별한다.

| 새 결과/자동 갱신 | 관련 결과만 갱신 | 사용자 편집/스크롤/수동 배치가 흔들리지 않음 |
| 저장/그리기/자료 실패 | 원문/현재 입력 유지 + 실제 재시도 | 성공 문구 허위 표시·초안 손실 없음 |
| 재접속/대상 삭제 | 실제 존재 여부 확인 + 대체 목록 | 사라진 대상으로 무한 로딩하지 않음 |

[WCAG Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)의 세로 스크롤 콘텐츠 기준은 320 CSS px 상당 폭이다. 의미상 2D가 필요한 부분의 예외를 구별한다. 이것을 모든 그래프·PDF·Canvas를 한 열 텍스트로 바꾸라는 요구로 사용하지 않는다. 모바일 목업만으로 확대 접근성·실제 iPad 입력·장기 사용을 확인했다고 하지 않는다.

초점은 사용자가 다음 행동을 찾는 실제 위치이며 상단/하단 고정 바·창틀·곁면으로 완전히 가려지지 않아야 한다. 관련 근거는 [WCAG Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)이다. 고정 요소를 추가할 때 그 아래 공간/스크롤/초점 복귀를 함께 정한다.

탭은 현재 선택과 해당 패널을 연결하고, [APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)의 키보드·수동/자동 활성화 조건을 과업에 맞게 참고한다. 탭을 여러 개 그리는 것으로 내용·저장·복귀 연결을 대신하지 않는다.

## 확장 7. Figma에서 실제 앱으로 넘기는 최소 명세

```text
설계 파일 → 페이지 → 기능별 섹션 → 화면 프레임
  → 외곽/주면/보조면 → 부품 인스턴스 → 의미 있는 레이어

화면 프레임 설명:
  실제 기능명 / 기존 역할 ID / 장소 / P프로필
  대표 패턴 번호 / 내부 패턴 번호 / 대체 전환형
  실제 콘텐츠·빈 상태·긴 내용·실패 상태
  크기 반응·토큰 참조·가이드·내용/초점 순서
  진입·입력·실행·취소·복귀와 저장 책임
  웹 구현 연결 / 아직 확인하지 않은 동작
```

Figma 페이지와 실제 제품 페이지, Atomic Design의 템플릿과 실제 콘텐츠 화면을 구별한다. `Page / Desktop`이라는 원본 예시가 파일 Page인지 화면 Frame인지도 역할과 안정 ID로 명확히 한다. 가이드는 정렬 보조이며 저장 동작·CSS 전환을 실행하지 않는다.

Figma에서 프레임 크기를 바꾸는 확인과 실제 브라우저의 렌더/입력/저장/재접속을 별도 기록한다. 원격 파일·인스턴스 오버라이드·레이어 ID를 임의 재생성하지 않는다. 픽셀 하늘의 모든 픽셀을 수만 레이어로 복제하지 않고 대표 장면/상태와 기존 렌더러 참조로 표현한다.

각 패턴은 다음 명세를 채워 다음 기준 단계로 넘긴다.

| 항목 | 필수 내용 |
| --- | --- |
| 식별 | 실제 화면/구역 ID, 사전 항목, 프로필, 소스 |
| 목적 | 사용자가 끝낼 작은 과업과 우선 행동 |
| 정보 | 상위 맥락·본문·보조 정보·의미 순서 |
| 외곽 | 창문/실내/종이·전역 탐색의 적용 범위 |
| 크기 | 축별 반응·최소/최대·토큰 참조·예외 |
| 전환 | 폭/콘텐츠 조건·좁은 구조·기본 위치 복귀 |
| 동작 | 선택·입력·공개·실행·닫기·취소·재시도 |
| 보존 | 원문/ID/초안/이력/개인 배치/수동 값 |
| 확인 | 대표 정상 + 관련 긴 내용/누적/중단/실패 |
| 판정 | 문서 정의/목업/실제 소비/실제 조작/배포를 구별 |

## 확장 8. 다음 OS 기준 작업의 입력과 완료 범위

이 사전 확장은 다음 세 가지를 제공한다. 첫째 원본 전 항목의 추적 가능한 분류, 둘째 현재25역할/111엔터티에 대한 등록 패턴 후보, 셋째 향후 요소·수치·전환·복귀를 기록하는 명세이다.

다음 기준 작업에서는 `대표 패턴을 목록에서 고른다`는 사용자 결정을 프로젝트 정본에 연결하고, 화면/구역별 선택 이유·예외·미정 항목을 적는다. 현재 구현 여부는 실제 소스/화면으로 별도 대조한다. 확장본에 등장하는 패턴이 모두 구현되었다거나 111개 화면의 동작을 검증했다고 판정하지 않는다.

새로 만든 것은 12개 작업 패턴의 설명·10개 프로필 대응·역할/미래 요소별 선택표·수치 기록 양식이다. 기존 가이드/명세가 개별 OS의 장소·위젯 보존·학습 의미·자료 계약까지 지정하지 않기 때문에 이 범위를 프로젝트 제안으로 보충했다. 기존 UI를 바꾸거나 최종 수치를 새로 채택한 작업은 아니다.

조사 범위는 원본 전36장과 Figma 공식 Layout Guide/Auto Layout/Grid/Constraints/Flexbox 변경 설명, Carbon 2x, W3C CSS/Grid/단위·접근성, 원 연구자의 읽기 패턴 자료 및 현재 OS 담당 원본이다. 특정 CSS masonry 출시 상태, 구도 이론의 학습 효과, 실제 기기와 장기 사용성은 미확인이다. 검색에서 확인하지 못한 사항의 부재를 단정하지 않는다.
