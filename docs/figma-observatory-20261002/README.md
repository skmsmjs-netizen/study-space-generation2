# ManSeekSong OS 천문대 · Figma 대응 설계

> 2026-10-02 메모리 보수: 복잡한 장면은 전체 이미지 목업, 실제 기능은 웹앱 구현에 유지한다. 실제 Figma와 재생성 도구에 반영한 [메모리 보수·구현 연결](../figma-memory-20261002/README.md)을 먼저 따른다. 과거 벡터 생성 코드를 내장한 호출 파일은 이력으로 보존하고 현재 생성기와 이미지 hash로 다시 준비한다.

> 최신 보완 결과는 [전체 대응 보완 보고](reconciliation-20261002/report.md)에서 확인한다. 공통 부품59종·168변형, 과업14개·397이동, 고급12영역·77상태의 실제 원격 증거를 추가했다. 아래 기존48종 결과는 최초 범위의 이력으로 보존한다.

이 폴더는 현재 웹앱의 화면·공통 부품·저장과 복귀 상태·121개 연구 출처를 Figma 설계와 연결한다. 실제 작업 파일은 [천문대 Figma 문서](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX)이다. 생성 여부는 계획 문구 대신 `evidence/`의 실제 도구 반환값과 노드 ID로 확인한다.

이 문서와 검토 허브는 구현·배포·실제 저장 시험을 실행하지 않는다. 현재 앱의 원문·ID·초안·이력·개인 설정과 배치·민석 전용 AI 권한을 유지하며, Figma 상태 이동을 서버 권한·동기화·복구 성공으로 환산하지 않는다.

## 로컬 검토 허브 열기

터미널의 현재 위치가 `generation2`일 때 실행한다.

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory docs/figma-observatory-20261002
```

그다음 [로컬 검토 허브](http://127.0.0.1:8765/)를 연다. JSON 자료를 함께 읽으므로 HTML 파일을 `file://`로 직접 여는 방식은 사용하지 않는다. 이 서버는 해당 폴더의 검토 자료만 로컬에서 제공하며 앱의 공부 기록을 읽거나 전송하지 않는다.

- **화면**: 111개 전체 목록에서 화면의 정보·행동·블록·복귀 계약을 보고, 존재하는 실제 프레임 또는 명시적으로 재사용한 노드로 이동한다.
- **기초·부품**: 재질과 글자 기준, 공통 부품 48개의 소스 역할·속성·상태·실제 부품 노드를 확인한다.
- **실패·복귀**: 상태 42개와 안내 문구·허용 행동·보존 조건·다음 상태를 읽는다. 이 허브의 상태 선택은 검토 항목 이동이다.
- **121개 기준**: 개별 근거·공식 링크·설계 적용·선정 조건·보존할 한계를 확인한다. 조건부 도구를 일괄 설치 대상으로 바꾸지 않는다.
- **근거 새로고침**: 추가된 Figma 생성 증거를 다시 읽는다. 자동으로 원격 Figma 작업을 실행하지 않는다.

검토 폭 선택은 이 문서의 가독성과 배치를 살펴보는 기능이다. 실제 기기별 Figma 화면은 각 항목의 해당 프로필 링크로 확인한다. 이 문서의 좁은 폭 표시를 실제 iPhone/iPad·IME·VoiceOver 확인으로 표현하지 않는다. URL의 해시에 검토 탭·항목·폭을 보존하며, 앱 저장소나 개인 기록은 사용하지 않는다.

## 누락과 체크섬 확인

`generation2`에서 다음 명령을 실행한다.

```sh
node docs/figma-observatory-20261002/scripts/verify-coverage.cjs --summary
```

상세 JSON 결과가 필요하면 다음처럼 읽는다. 이 명령은 표준 출력만 사용한다.

```sh
node docs/figma-observatory-20261002/scripts/verify-coverage.cjs
```

호출하는 작업이 별도 보고서를 저장해야 할 때에만 출력을 새 보고서 파일로 받는다. 기존 `evidence/` 파일에 결과를 덮어쓰지 않는다. 마지막 전체 대응 검사에서는 `--strict`를 사용할 수 있다.

```sh
node docs/figma-observatory-20261002/scripts/verify-coverage.cjs --strict --summary
```

검사 결과의 의미는 다음과 같다.

| 결과 | 의미 |
| --- | --- |
| `integrity-error`, 종료 코드 1 | 필수 자료·예상 개수·중복 ID·노드 형식·대상 파일·전이의 출발/도착에서 불일치를 발견했다. |
| `partial-evidence`, 기본 종료 코드 0 | 현재 저장된 증거의 구조는 유효하지만 계획된 대응 일부가 아직 없다. `--strict`에서는 종료 코드 2이다. |
| `all-registered-mappings-evidenced`, 종료 코드 0 | 등록한 범위의 실제 노드 매핑이 모두 대조되었다. 렌더링·학습 효과·웹앱 전체 품질 통과를 뜻하지 않는다. |

각 입력 파일의 바이트 SHA-256과 **순서가 있는 입력 ID 배열을 JSON으로 직렬화한 SHA-256**을 함께 출력한다. 개수만 같고 내용이나 순서가 바뀐 경우도 구별할 수 있다. 화면·블록·모듈·부품·출처·영역·상태·전이는 각각 다른 목록으로 계산한다. 체크섬은 기록된 입력의 동일성 검사이며 내용의 타당성이나 제품 완성을 보증하지 않는다.

검증기는 원격 도구를 호출하지 않는다. `evidence/screens-{batchId}.json`의 화면·블록·조작 매핑과 `evidence/material-memo.json`의 추가 블록·별도 펼침 상태, 부품 생성/회수/리뷰, 출처 D/F/Q/S 배치, 상태 매핑과 전체 노드 회수 결과를 읽는다. 펼친 상태 참조 1개는 기존 155개 화면 프레임 수에 합산하지 않는다. 직접 부품 타입이 기록된 경우와 실제 variant 구조에서 타입을 추론한 경우도 `ownerTypeEvidence`로 구별한다. 과거 `evidence/access.json`의 Starter/View 차단 기록은 현재 접근 실패로 재사용하지 않는다.

새 고급 기술과 실제 사용 결과에 따라 천문대 값은 조정할 수 있으며, 원본 위젯 전체와 바깥 테두리·읽기·조작·자료·개인 설정을 유지한다.

제작 manifest의 스냅샷과 현재 소스가 달라진 `src/App.tsx`·`src/ui/quick-memos.tsx`는 읽기 전용으로 범위를 다시 대조했다. App의 TSX104개·메뉴18개·모달 범위는 유지되며, 자료 상세 메모 누락은 `R23-B02`로 보완했다. quick-memos는 MouseEvent import와 두 곳의 `focus({preventScroll:true})`만 차이가 있고 기존 O24 복귀 계약 안에 있어 새 엔터티는 없다. 대조 결과는 `figma-state.json.sourceDriftReview`에 남겼고 동결한 원본 JSON은 수정하지 않았다.

## 화면 안의 입력 부품 연결 보완

155개 화면에서 **단일 입력 Input 163개·여러 줄 입력 Textarea 129개·체크박스 Checkbox 70개, 합계 362개의 실제 네이티브 인스턴스**를 확인했다. 공통 부품 48개·변형 120개는 재사용 원본의 수이며, 이 362개는 화면에 연결된 세 종류의 사용처이다. 정면 책상은 생성 후 반환이 잘려 기존 인스턴스 154개를 다시 읽었고, 다른 네 공간은 208개를 새로 연결했다. 성공한 시험 적용 11개는 책상 154개에 포함해 중복 계산하지 않는다.

원래 노드 ID·문구·좌표·치수·반응·레이아웃 참여는 유지했다. 기존 시각 요소는 투명하게 보존하고 연결한 인스턴스가 표시를 담당하며, 새 인스턴스에는 Paper 모드를 명시했다. 다섯 [공간별 생성·보존 증거](verification-report.md#화면-안의-입력-부품-인스턴스)에서 원본 노드 비교 차이 0개, viewport·블록 ID 변경 0개, 최종 적용 실패 0개를 확인했다. 프로토타입과 블록의 기존 연결을 바꾸지 않았다.

변환하지 않은 **298개는 모두 Select의 선택 값·화살표를 보존한 항목**이다. 구조를 확정하지 못했다는 사유로 제외된 항목은 0개이며, 선택 입력을 일반 텍스트 입력으로 바꾸지 않았다. 초기 시험 4회의 각 실패는 모두 새 인스턴스를 제거하고 원래 표시를 복원한 `rolledBack:true`, `rollbackDrift:[]` 이력으로 남아 있다. 이 이력을 최종 적용 실패 0개와 구별한다. 실제 웹앱의 입력·선택·IME·저장 동작은 별도 검증 대상이다.

보완 후 [최종 화면 재조회](evidence/screen-structure-after-controls.json)에서도 **155개 화면·연결 인스턴스 362개, 구조 문제 0개·가로 넘침 0개**를 확인했다. 제작 담당이 [모바일 기록](evidence/record-mobile-components.png), [탐구 작업대](evidence/workbench-components.png), [기록·계획 벽](evidence/wall-components.png)의 보완 후 캡처를 직접 확인했다. 원본 JSON 네 파일의 해시와 기존 블록·전이 매핑은 유지했다.
