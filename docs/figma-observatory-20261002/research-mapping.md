# 천문대 OS — 연구 121개와 Figma 설계의 전수 대응

기준일: 2026-10-02. 앞 [개발 참조 조사](../research/development-reference-20261002/README.md)의 121개 출처·20개 영역을 천문대 정체성의 실제 설계 산출물/기술주석/검증 기준에 연결한다. 이 문서는 구조화 원장 [research-mapping.json](research-mapping.json)과 [상태 계약](state-contracts.json)의 읽기용 보기다.

**전수 대응은 모든 도구의 설치를 뜻하지 않는다.** 기존 유지 29개·기본 권고 32개·조건부 43개·참고 17개의 원래 판정을 보존했다. 조건부 후보는 해결할 실제 문제와 선행 조건을 기록하고, 기술/서버 기준은 대응 과업·상태·검증주석으로 표현한다.

## 동일성·누락 점검

- 출처 121개 / 20개 영역 / 20개 설계 보드 / 상태 42개 / 핵심 위험 전이 32개.
- 네 원본 sources JSON의 SHA-256을 구조화 원장에 저장했다. 해시는 동일한 조사 버전을 연결하며 내용의 진실성이나 제품 준수를 증명하지 않는다.
- 실제 Figma 접근은 Starter/View 한도 소진으로 차단되어 원격 생성이 미완이다. null/빈 배열을 유지하며 로컬 제작 패키지와 원격 Figma 완료를 구분한다. 실제 node ID는 접근이 회복된 뒤 제작 담당 root가 연결한다.
- 기존 source status·한계·공식 URL은 121개 모두 그대로 보존한다. 상위 사용자 요청에 따라 실제 설계에 적용하되 가격/계정/지원 미확인이나 조건부 도입을 없애지 않는다.

## 예정 Figma 페이지와 연결

- 00 안내·전수대응
- 01 기초·정체성
- 02 공통 부품·상태
- 03 정면 공부 책상
- 04 왼쪽 자료 책장
- 05 오른쪽 탐구 작업대
- 06 뒤쪽 기록·계획 벽
- 07 계정·설정·복구
- 08 반응형·실패·복귀
- 09 기술·검증·121출처

각 출처·보드·상태의 JSON에 위 페이지 키(00–09)를 연결했다. 같은 공통 기준이 여러 페이지에 적용되면 여러 키를 유지한다. 조건부/참고 후보의 상세 도입 조건은 09 기술·검증·121출처에 남긴다. 현재 원격 페이지 생성·편집·재조회는 미완이다.

## 저장·권한·복구와 AI의 상태 계약

상태 카피는 대표 설계 초안이다. 32개 전이는 핵심 위험 경로이며 전체 앱의 모든 이벤트를 빠짐없이 실행하는 상태 머신을 구현한 것이 아니다. 각 상태의 가능한 행동도 별도로 연결했다. 실제 오류 원인과 보존 위치가 확인된 범위에서만 사용한다. SaveStatus의 checking/saved/pending/saving/error/conflict와 AccessStatus의 pending/approved/rejected/suspended는 현재 코드를 읽어 대조했다. UI의 실제 flag와 설계 상태를 구별해 JSON에 기록했다.

|---|---|---|---|---|
| SAVE-CHECKING | 서버 확인 중 | 이 기기의 기록을 표시하고 있습니다 · 서버 확인 중 | 기다리기 · 저장 상태 열기 | 기기 자료가 보인다는 이유로 서버 최신 자료라 표시하지 않는다. |
| SAVE-LOCAL-WRITING | 기기에 보관 중 | 기기에 보관 중 · 서버 전송 대기 | 작성 위치 유지 | 실제 durable commit 전에는 기기에 저장 완료로 표시하지 않는다. |
| SAVE-PENDING | 기기 보관·미전송 | 이 기기에 저장됨 · 서버 전송 대기 | 계속 작성 · 서버 저장 다시 시도 · 보관본 내려받기 | 미전송 원문·명령·owner를 보존하고 서버 완료 장식은 사용하지 않는다. |

| SAVE-LOCAL-ERROR | 기기 보관 실패 | 이 기기에 보관하지 못했습니다. 작성한 내용을 확인해 주세요. | 원문 복사/내보내기 가능한 경로 · 보관 다시 시도 | 메모리·기기·서버 중 실제 남은 위치를 확인하기 전에는 원문이 안전하다고 단정하지 않는다. |

## 설계에서 실제 구현으로 넘길 때

1. 각 부품/과업 frame에 관련 C/D/F/Q/S ID와 상태 ID를 기록한다. root가 실제 노드 ID를 원장에 결합하고 누락·중복을 대조한다.
2. 저장 성공·서버 권한·GPU 성능·파일 복원은 그림으로 검증되지 않는다. Figma에서는 기대 상태·실패·복귀·조건을 표현하고, 코드/시험 연결은 별도 증거가 생겼을 때 갱신한다.
3. 실제 Figma 흐름에서 모든 조건부 도구를 실행 가능한 기능으로 제시하지 않는다. 도입 조건/대안/미확인 항목을 기술주석으로 남긴다.
4. 천문대 표현은 현재 원본·역할 토큰·픽셀 창/패널·살아 있는 반응을 따르며, 저장 확인·학습 의미·개인 배치를 장식 때문에 바꾸지 않는다.
5. 일반 계정도 기록·수동 자료를 사용할 수 있지만 AI는 민석의 확인된 personal 계정만 서버가 허용한다. 관리자 역할과 AI 소유자 권한은 서로 다르다.
6. 구현/합성 검사/운영 서버/공개 배포/물리 기기/장기 사용 결과를 분리한다. Figma 제작 완료를 앱 전체 완료로 표시하지 않는다.
