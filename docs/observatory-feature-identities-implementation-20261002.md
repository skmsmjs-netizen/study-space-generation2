# 기능별 OS 정체성 정의와 실제 적용 기록

기준일: 2026-10-02. 사용자 「OS에 따른 각각의 정체성 정의, 그리고 정의에 따른 디자인, UX, UI를 본 문서에서 정의해내라. 그리고 그 정의에 따라 수정하라」에 따른 작업이다. [기능별 정체성 정본](observatory-feature-identities.md)과 [소비용 JSON v1.0.0](observatory-feature-identities.json)이 기능 의미와 구성의 원본이며, 이 문서는 실제 변경·검증·남은 조건을 기록한다.

**정의 단계에서는 기존 111개 엔터티를 25개 기능 정체성에 빠짐없이 대응했고, 실제 앱은 같은 JSON으로 경로·모달·보조면의 구성을 선택하도록 연결했다.** 공부 기록·자료·연습·통계·공간 도구·설정의 기존 과업에 맞춰 정보 순서와 화면 구획을 조정한다. 문서 대응, Figma 반영, 소스 연결, 브라우저 조작·저장, 운영 서버·공개 배포는 각각의 근거로 판단한다.

**같은 Figma 파일의 155개 화면과 실제 웹앱에 정의를 반영했고, 변경 관련 5흐름을 다섯 WebKit 환경에서 25/25 통과했다.** 전체111개 기능의 모든 상태·실제 원격 API·물리 기기·공개 배포까지 전수 실행한 결과는 아니다.

## 1. 재사용한 기준과 이번에 정한 부분

| 구분 | 선택한 원본/방법 | 실제 적용과 한계 |
| --- | --- | --- |
| 공간·재료·기초 값 | [천문대 확정 기준](observatory-design-standard.md), [기준값 v2.0.0](observatory-experience-baseline.json) | 네 자리·천장 조명·실내/종이/하늘·기존 글자/간격/초점/모션 값을 재사용한다. 기능별 팔레트나 임의 치수 체계를 새로 만들지 않는다. |
| 구조·상태·공통 부품 | [최우선 디자인 기준](design-ui-ux-priority.md), [디자인 시스템](design-system.md) | 기능 목적에서 정보 순서와 구성 차이를 도출하고 기존 폼·모달·그래프·필기 도구를 유지한다. |
| 역할/값 소유권 | 기존 채택 [DTCG 2025.10](https://www.designtokens.org/tr/2025.10/format/) 방식 | 정체성 JSON과 공통 값 원본을 분리한다. 프로젝트 JSON이며 명세 적합성·W3C 인증을 주장하지 않는다. |
| 읽기·조작·상태 | 기존 채택 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) 조건 | 현재 재료의 대비·색 외 단서·초점·키보드·재배치·오류 안내를 유지한다. 이번 대응만으로 전체 WCAG 적합성을 판정하지 않는다. |
| 그래프와 반복 사용 | [통계 표현 기준](statistics-chart-selection.md), [작업 진행 정책](../../docs/작업%20진행과%20검증%20정책.md) | 다양한 질문/그래프·분모·원기록과 사용자 선택·누적·중단 복귀를 연결한다. |
| 한정 검토 | [study-review](../../.agents/skills/study-review/SKILL.md) | 이번 실제 소비 경로의 잘못된 맥락·설정 덮어쓰기·정의 누락을 읽기 전용으로 확인했다. 앱 전체·서버·Figma 전수 감사로 확대하지 않았다. |

새로 만든 부분은 **25개 기능별 목적/보조 정체성과 10개 화면 구성 역할, 111개 엔터티의 단일 소유 대응, 그 정본을 소비하는 UI 해석기와 국소 구성 규칙**이다. 이는 프로젝트의 설계 결정이며 보편적 최적 UI·학습 법칙·검증된 학습 효과가 아니다. 기존 도구로 처리할 수 있는 범위여서 별도 UI/그래프/필기 라이브러리를 추가하지 않았다.

## 2. 기능별 정본의 전체 대응

| 대응 대상 | 정본 작성 시 확인 | 의미 |
| --- | --- | --- |
| 기능 정체성 | 25개 | 실제 기능명·보조 정체성·자리·목적·구성·우선 행동·디자인·UX·UI·보존·반복 조건을 정의했다. |
| 기존 엔터티 | 41경로 + 29논리 모달 + 41보조면 = 111개 | 각 ID를 한 정체성에 정확히 한 번 배정했다. |
| 누락·중복·미등록 ID | 각각 0 | 원본 [화면 inventory](figma-observatory-20261002/screen-inventory.json)와 전수 집합을 대조했다. |
| 경로 연결 | 43개 | 원래 41경로와 단원 역할의 명시적 분기 2개이다. 새 화면 43개라는 뜻이 아니다. |
| 모달 연결 | 30개 | 29논리 모달에 카드 추가/편집의 실제 제목 변형을 포함한다. |
| 맥락 예외 | 5개 | 단원/주제, 새 자료/기존 자료, Canvas 보기와 호출 과업 안의 원문 편집을 보존한다. |
| 후속 기능 | A01–A10 및 천장 조명 11개 | 별도 정체성을 중복 생성하지 않고 기존 역할의 보조 행동으로 연결했다. |
| 제품용 안내 | 25개 `guidance` | 명세용 목적과 구별한 존댓말 한 문장이다. 실제 기능명과 원문을 대신하지 않는다. |

정본의 주요 역할은 공부 기록=관측일지, 자료=펼쳐 보는 원자료, 과목=공부 범위의 책등, 목차=색인, 주제 카드/Anki=인출 카드함, 수식=관측기, 코드=실행 실험대, 통계=관측판, Canvas=개인 관계 배치도, 그래프뷰=관계 탐색 지도, 칸반=작업 보드, API=외부 연산 연결대이다. 전체25개와 세부 규칙은 [정본의 전체 기능 표](observatory-feature-identities.md#3-전체-기능-정체성)에서 관리하며 이 보고에 다시 복제하지 않는다.

`journal`, `catalogue`, `document`, `practice`, `instrument`, `analysis`, `spatial`, `board`, `timeline`, `control`은 **기존 과업에 맞는 화면 구성**이다. 이름·색·설명만 추가한 것을 전체 적용으로 판정하지 않는다. 또한 엔터티에 정체성 속성이 있다는 사실만으로 그 엔터티의 모든 상태·키보드·저장·복귀를 이번에 새로 실행했다고 보고하지 않는다.

## 4. 맥락·보존의 실제 경계

- `/node/:id`는 같은 엔터티 ID를 유지하면서 주제는 공부 기록 구성, 단원/일반 목차는 목차 구성을 사용한다. 기본 보관 자리 문자열을 기존 실제 장소 결정 로직에 강제하지 않는다.
- `/materials/trash`, `/recall/scheduled`, 암기시험 결과와 같은 정적·예약 경로를 일반 문서/동적 경로보다 먼저 해석한다. 새 자료 등록과 기존 자료 읽기의 실제 장소는 기존 장소 로직을 따른다.
- 모달 제목 “목차 추가”는 `node`/`bulk`의 실제 모드로 구별한다. 개별 수식의 제목은 보존하고 “ · 전체 화면” 접미로 해당 역할을 연결한다.
- 원문·답안·필기·ID·초안·이력·개인 테마/서체/읽기 폭·Canvas 좌표/연결·보드 순서는 기존 보존 대상이다. 정체성 변경을 원자료 재배치·자동 요약 저장·학습 완료 판정으로 사용하지 않는다.
- API는 실제 원격 연산이다. 소유자 권한·전송할 문맥·한도·실제 요청/비용을 기존 연결에서 다루며 Figma의 부품 API 카탈로그와 구별한다. 설정 창을 열었다는 이유로 호출하지 않는다.
- Anki 파일 가져오기와 외부 Anki 앱의 실시간 동기화는 구별한다. 통계의 다양한 그래프는 실제 변수·단위·분모·불확실성·의미색을 유지하며 미입력 목표/숙달/흐름을 만들지 않는다.
- 자료 곁 도구·빠른 명령·검색 발췌·통계 공유 선택·이력 단계 표시·작업 구성·장소 전환·수식 비교 등 A01–A10은 기존 데이터와 조작을 재사용한다. 천장 조명은 공통 도구 진입이며 닫으면 실제 원래 과업/방향으로 복귀한다.

## 5. 한정 검토에서 확인한 사실과 후속 보완

정체성 해석기와 App/공통 모달/통계/API/필기 소비 경로를 읽기 전용으로 대조했다. 아래 결과는 소스 검토이며 실제 브라우저 실행 결과와 구별한다.

| 검토 항목 | 확인한 사실 | 판정 범위 |
| --- | --- | --- |
| 경로 해석 | 정적 예약 경로 우선, 단원/주제 역할 분기, 결과 상세 경로가 정본과 일치한다. | 이번 해석 경로에서 잘못된 역할을 찾지 못했다. |
| 모달 해석 | 목차의 명시 모드·동적 수식 제목·카드 추가/편집을 연결한다. | 미등록 모달은 속성을 생략하며 기존 조작을 막지 않는다. |
| 안내 문구 | 모든 현재 경로가 정의된 안내를 사용한다. | `undefined`가 제품 문구로 출력되는 경로를 발견하지 못했다. |
| API/필기/통계 | API는 폼 구획, 필기는 정체성 연결, 통계는 범위/관찰/선택의 순서 변경이다. | 기존 권한/원획/집계의 변경은 이 소비 연결에서 발견하지 못했다. |
| 개인 읽기 폭 | 새 규칙이 `document`·`practice`·`control`을 제한하면서 `wide` 예외를 `document`에만 적용하는 불일치를 발견했다. | 세 구성 모두 개인 선택을 우선하도록 보수했다. 기존 `wide`는 `.prose`에만 적용돼 있었으므로 과거 연습 화면 지원의 회귀로 단정하지 않는다. 실제 옵션 변경·큰 창의 폭 증가·재접속 유지가 통과했다. |
| 통계 보기 범위 보존 | 실제 재접속 때 날짜·과목·주제·비교 선택이 기본 범위로 돌아가는 누락을 발견했다. | 기존 계정별 v1 보기 설정에 선택적 `range`를 추가했다. 예전 설정 호환, 제거된 대상 대체, 계정 분리, 손상 원문 보존, 실패 재시도를 단위/브라우저 범위에 따라 확인했다. 공부 원장·서버 저장은 바꾸지 않았다. |

## 6. Figma 실제 반영

[기존 Figma 목차](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX?node-id=82-246)에 다섯 장소별 정의 보드와 이동 링크를 추가했다. [공부 책상](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX?node-id=102-31835), [자료 책장](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX?node-id=102-31887), [탐구 작업대](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX?node-id=102-31925), [기록·계획 벽](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX?node-id=102-31942), [천장 조명](https://www.figma.com/design/YHmD1PpWWfR9JGTEs77JsX?node-id=102-31987)에 25개 정의의 목적·디자인·UX·UI·보존/반복 조건·111개 대응과 대표 화면 링크가 있다.
