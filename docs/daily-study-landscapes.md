### 엔진과 개수·색·운동의 직접 대응

상황마다 입력 활동(0), 입력 대상 다양성(1), 재방문(2) 중 한 채널을 선택한다. `g = evolution.position/11`, `r = recent[channel]`, `b = background[channel]`, `c = abs(change[channel])`, `K = 해당 상황의 최대 개수(10–28)`이다. 정수 단계로 반올림하지 않는다.

```text
개수 N = 2 + (K-2)(0.50g + 0.35r + 0.15b)
밝기 L = 0.25 + 0.40r + 0.20g + 0.15b
운동 폭 A = 0.55 + 1.25r + 0.45c + 0.45g
주기 T = 기본 주기 / (0.80 + 0.60r + 0.25b + 0.35g)
따뜻한 색의 비율 C = 0.15 + 0.50g + 0.35r
입자 i의 투명도 = clamp(N-i, 0, 1) × L
```

예를 들어 N이5.2에서5.200001로 바뀌면 여섯 번째 입자의 투명도도 연속적으로 바뀐다. 고정된 최대 K개를 그리며 투명도를 조정하므로 임계값에서 갑자기 입자가 생성되지 않는다. 밝기·운동 폭·주기·팔레트 혼합 비율도 실제 SVG/CSS에 반올림 없이 전달한다. 미세한 수치 변화가 매번 사람 눈에 식별될 만큼 크다는 보장은 아니다. 모션 감소/정지 상태에서는 움직임을 멈추고 파생 색과 개수는 반영한다.

### 무작위 선택·재계산·보존

상황의 선택은 owner/namespace, 한국 날짜의 해당 시간대 시작일, 시간대로 만든 FNV-1a / xorshift32 기반 Fisher–Yates 순열이다. 암호나 보안용 난수가 아니다. 여섯 상황을30분 단위로 순환하며 각 묶음에서 빠짐없이 한 번씩 선택한다. 종료 직전2분 동안 다음 상황과 smoothstep으로 교차한다. 시간대 경계의 전후20분 혼합과 함께 계산해 동시에 최대3상황만 그린다. 늦은 밤은 자정에 시작일이 바뀌지 않아 순열이 갑자기 바뀌지 않는다.

공부 입력 수정은 상황의 종류를 다시 추첨하지 않고 현재 상황의 수치만 갱신한다. 같은 소유자·시각에 다시 접속하면 같은 선택을 얻으며 재접속마다 새 난수를 뽑지 않는다. 활성 탭의 분 경계·숨김 복귀·BFCache 복귀는 기존 시계를 재사용한다. 이번 파생 계산은 공부 원문·ID·이력·초안·설정 저장 구조와 서버 스키마를 변경하지 않는다. `referenceEvent` 강제 선택은 합성 비교 화면/시험만 사용한다.

## 채택한 계산

[NIST EWMA](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm)의 과거 입력에 지수 가중을 주는 재귀식을 재사용한다. 통계적 관리한계, 정상분포 가정, 이상 판정은 채택하지 않는다. 수면압·생리·건강·집중력·숙달·중단 예측과 연결하지 않는다. 아래 시간상수와 비선형 변환은 이번 표시 목적의 선택이며 실증된 학습 계수가 아니다.

현재 owner/namespace·공부 범위의 최신 활성 기록 중 체크/글/항목 메모가 있는 기록을 읽는다. 입력한 날짜 `d`는 원본 `createdAt`을 앱 통계와 같은 Asia/Seoul 날짜로 묶는다. 실제 공부 날짜 `dateEvidence`와 별개다. 날짜 미정 공부라도 입력 시각이 확실하면 입력 신호를 만들 수 있다. 입력 시각이 유효하지 않거나 기준일보다 미래이면 그 입력의 시간 신호만 제외하며 원기록·기존 풍경의 흔적은 보존한다.

하루에 남긴 `(공부사건ID, 과목ID, 대상ID)`의 서로 다른 조합 수를 `n_d`, 대상 수를 `b_d`, 이전 입력일에 보았거나 같은 날 다른 공부사건에서 다시 본 조합 수를 `r_d`로 정한다. 중복 행/재전송/동일판 재저장/글 길이는 신호를 늘리지 않는다. 한 사건에 여러 주제를 실제로 기록한 것은 각 대상의 입력으로 남는다.

```
f(n) = 1 - exp(-n/3)
u_d = (f(n_d), f(b_d), f(r_d))
a_tau = exp(-1/tau)
x_tau(d) = a_tau^(d-d_prev) x_tau(d_prev) + (1-a_tau) u_d
tau_recent = 3 days; tau_background = 14 days
change(d) = x_recent(d) - x_background(d)
```

초기 상태는 기록 신호의 빈 상태0이다. 비어 있는 달력 간격을 펼쳐 계산하는 일별 EWMA와 정확히 같다. 저장을 할 때 이전 계산값에 계속 더하지 않고 **현재 유효한 일별 묶음을 재구성**한다. 정정/삭제/복원/날짜 이동에 따른 재계산은 당시 입력 시각부터 바뀌며 다른 계정과 섞이지 않는다. 미래의 재방문으로 과거 최초 방문을 재방문 처리하지 않는다.

`0 <= u <= 1`, `gap >= 1`, `tau > 0`이면 상태는0~1이다. 마지막 입력일부터 기준일까지 지수 가중을 전파하며 빈 기간을 실패/학습량0/망각으로 해석하지 않는다. 이는 저장된 입력의 최근성을 나타내는 표시 필터다. 같은 총 기록량이라도 어느 날에 입력했는지가 다르면 움직임이 달라진다. 일정이 비어도 기본 풍경과 영구적인 기록 도형은 남고 시듦·사망·벌점은 없다.

## 2026-10-01 현재 구현: 천문대만 유지하고 12단계 연결

사용자 “천문대만 놔…애니메이션 단계 세분화…각각 단계를 보여주는 수리적엔진 대응”을 반영했다. 앞 절의 세 장면 선택은 이전 구현 이력이다. 현재 실제 홈은 천문대만 렌더링하며 섬/종이 기계와 장면 선택 버튼은 제거했다. 기존 version1 표시 키·정지·별빛/혜성/궤도 선택은 보존하며 이전 world 값만 observatory로 읽는다. 개인 공부 원장이나 설정 키를 이관/삭제하지 않는다.

하루 움직임과 누적 발전을 분리한다. 기존 daily-study-dynamics.ts의 일별 EWMA는 최근 입력·다양성·재방문의 움직임에 계속 연결된다. 새 순수 domain/observatory-evolution.ts는 같은 owner/namespace/범위의 최신 활성 기록에서 유효한 입력 시각을 가진 서로 다른 (사건ID, 과목ID, 대상ID) 조합 E를 센다. 중복 전송·글 길이·단순 정정은 누적을 늘리지 않는다. 기준일보다 미래/불명 입력 시각은 시간 근거에서 제외한다. 공부 날짜가 미정이라는 이유로 알려진 입력 시각을 제거하지 않는다.

```
q = min(11, log2(1 + E))
stage = floor(q); blend = q - stage
```
