# 크레딧 일시 허용과 실제 GPT 검증 · 2026-10-01

사용자 “음 그럼 잠깐만 크레딧 쓰게끔 해. 최종 배포때는 차단할거야”에 따라 기존 크레딧으로 대표 작업3개를 실제 생성했습니다. 검증 후 ChatGPT의 외부 앱 크레딧 사용 허용을 다시 껐고, 해당 Mac 실행 사본의 임시 옵션도 제거했습니다. 자동 충전·신규 구매·무료 재설정·별도 유료 API·자동 재시도는 실행하지 않았습니다.

## 일시 허용의 범위와 복귀

계정의 사용량 화면에서 ‘사용량 한도에 도달한 후 다른 앱에서 크레딧 사용 허용’을 직접 켜고 저장 완료 후 켜짐을 확인했습니다. 이 스위치는 해당 공부앱만의 독립 설정이 아니라 계정에서 구독 사용을 허용한 다른 앱에도 적용됩니다. 이번 대표 검증 직후 다시 끄고, 꺼짐과 자동 충전 꺼짐을 확인했습니다. 동시 Codex/다른 작업의 크레딧 사용과 화면 반영 지연이 있어 계정 잔액 차이를 이3회만의 비용으로 환산하지 않습니다.

거짓으로 ‘크레딧 꺼짐 확인’을 체크하지 않고 별도 임시 상태를 구현했습니다. `localStudyAIPlugin({ temporaryCredits: { expiresAt, maxCalls: 3 } })` 옵션은 해당 로컬 검증 실행 사본에만 넣었습니다. 만료 시각은2026-10-01 18:07:00 KST(최대30분), 실제 공급자 시도 상한3회이며 최종 검증 뒤 옵션을 제거했습니다. 소스의 기본 `vite.config.ts` 호출은 옵션 없는 `localStudyAIPlugin()`을 유지합니다.

임시 허용은 서버 메모리·연결 프로필·만료·횟수에 묶고 인증/현재 승인/민석 소유자/loopback/동일 origin 검사를 유지합니다. 실제 공급자 호출 직전에만 횟수를 차감하며 실패도 시도로 계산합니다. 연결 해제하면 남은 허용을 폐기합니다. 운영 모드에서는 옵션이 명시돼 있어도 허용하지 않습니다. 일반 원문/수정 이력/저장 스키마·계정 자격증명은 변경하지 않았습니다.

실행 중인5491 사본은 병행 작업의 기존 별도 소스 사본입니다. 차이를 대조한 뒤 서버/수신/연결 화면의 크레딧 관련 부분만 반영했고 기존 수신 흐름·음성 안내 차이를 보존했습니다. 기존 프로세스를 종료하지 않고 Vite의 설정 갱신으로 반영/복귀했습니다. 이번 생성 성공을 병행 Supabase 원격 공급자의 연결 성공으로 보고하지 않습니다.

## 확인과 최종 배포 조건

- 관련 서버/소유권2파일8검사 통과: 기본 확인 전 차단, 최대3회, 시간 만료, 운영 모드 거부, 비소유자/승인 거부, 모델/기존 연결 보호.
- 공용 앱 build(타입 포함) 통과. 최초 병행 브랜드 시험의 타입 오류는 이후 병행 수정으로 해소됐습니다. 빌드에 기존 경고는 남습니다.
- 다섯 WebKit 모사 환경의 모든 주요 화면·기록 선택/취소/수식/저장/재접속은 최초8통과/2실행 실패였습니다. 좁은 iPad 두 건은 서로 다른 Playwright 실행본이 섞이는 도구 오류로 재실행했고2개 모두 통과했습니다. 두 로그/결과를 모두 보존하며 최초 실패를 삭제하지 않습니다. 합성 화면 확인과 위 실제 모델/개인 저장을 구별합니다.
- 계정 외부 앱 크레딧 허용 꺼짐, 자동 충전 꺼짐, 로컬 임시 옵션 제거를 확인했습니다. 최종 배포에서도 [배포 계약](deployment.md#GPT-크레딧의-최종-배포-조건--2026-10-01)에 따라 다시 확인합니다. 앱은 계정의 스위치를 자동 조회/변경할 수 있다고 주장하지 않습니다.

추가 공개 배포·신규 운영 AI 서버 적용은 수행하지 않았습니다. 개인 서버/원격 승인 검토는 병행 문서의 최신 결정을 유지합니다. 실제 목차 출제·모든19개 작업·지시 공격·긴 자료·실물 기기·학습 효과의 전체 품질 검증은 이번3사례 밖입니다.

증거: `work/gpt-credit-verification-20261001/verification.json`, build/tests/device 원본 및 재실행 로그, 실행 사본의 변경 전 소스/옵션 메타데이터. 토큰·비밀번호·인증 저장소·사용자 실제 원문을 검증 파일에 넣지 않습니다.
