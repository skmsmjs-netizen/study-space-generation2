2026-10-02 최종 레이아웃 채택: 각 기능의 의미/자리/주 행동은 이 정본을 유지하고, 구체적인 등록 패턴 선택·전환·복귀는 [OS 레이아웃 확정 기준](layout-standard.md)과 [111엔터티 전체 대응표](layout-standard/entity-layouts.md)를 따른다. 25역할/10과업 프로필에 현재와 미래 요소를 연결하며 원문/ID/개인 배치·설정과 실제 학습 의미를 보존한다. 대응 등록과 기존111전체의 실제 UI 준수 판정은 구별한다.

2026-10-02 사용자 첨부 철학은 [지식 표현과 천문대 경험 기준](knowledge-structure-standard.md)의 25역할 공통 원칙으로 적용한다. 아래 기능/자리/구성/자료 계약을 유지하며 닫힌 모듈·실제 관계·의미 순서·원문/질문 복귀를 과업에 맞게 연결한다. 개념 visual/Canvas의 이번 실제 소비 범위와 다른 기능의 적용 기준을 구별한다.

**천문대는 실제 공부를 수행하고, 남긴 기록을 돌아보며, 다음 행동을 고르는 개인 작업 공간이다.** 기능마다 다른 역할을 부여하되 원래의 기능 이름과 조작을 유지한다. 관측일지·관측판·카드함 같은 이름은 이 프로젝트가 정한 보조 은유이며, 사용자가 새 용어를 외워야만 조작할 수 있게 만들지 않는다. 실제 화면 제목은 공부 기록·통계·주제 카드처럼 기존 기능명을 우선하고 보조 정체성은 필요한 곳에서 한 번만 표시한다.

이 문서의 범위는 기존 41경로·29논리 모달·41보조면, 합계111엔터티 전부와 후속 A01–A10·천장 조명이다. 문서 대응·Figma 국소 반영·앱 코드 소비·실제 조작/저장·공개 배포는 각각의 근거로 판정한다. 여기의 요구 정의를 기존 모든 기능의 실행 검증 완료로 읽지 않는다.

## 2. 디자인·UX·UI가 실제로 달라지는 기준

**디자인**은 무엇이 먼저 보이고 어떤 면에 놓이는지, **UX**는 사용자가 진입해 과업을 마치고 돌아오는 과정, **UI**는 그 과정을 실행하는 버튼·입력·표시·상태이다. 보조 이름이나 안내 문장만 덧붙이는 것으로 기능별 적용을 완료하지 않는다. 아래 구성에 따라 기존 핵심 영역의 배치·너비·구획·정보 순서를 조정하고 해당 조작·보존 경로와 연결한다.

| 구성 키 | 기본 정보 순서와 실질적인 화면 차이 | 대표 역할 |
| --- | --- | --- |
| `journal` | 대상/기간 → 이어지는 기록·답안 → 선택 입력·이력. 읽고 쓰는 한 열의 연속성을 우선한다. | 오늘·공부 기록·내 생각 |
| `catalogue` | 범위/찾기 → 항목 목록·계층·출처 → 선택 상세. 항목의 소속과 찾기를 우선한다. | 과목·목차·자료 카드·개념·찾기 |
| `document` | 원문/필기/페이지가 주면, 도구는 곁면. 본문/그림을 종이 높이에 맞춰 자르지 않는다. | 메모·필기·강의 자료 |
| `practice` | 범위/조건 → 질문/내 답 → 명시적 설명 공개 → 직접 결과/되돌리기. 답과 기준의 공개 단계를 구별한다. | 시험 연습·암기시험·주제 카드 |
| `instrument` | 질문/조건 → 조작/관찰 → 현재값·실행 결과 → 근거. 원문 편집과 결과를 비교 가능한 면으로 둔다. | 코드·수식 |
| `analysis` | 범위 → 다른 질문을 맡은 여러 그래프 → 선택 값/분모 → 원기록. 좁은 화면에서는 같은 순서로 이어 읽는다. | 통계 |
| `spatial` | 2차원 면 → 선택한 대상 → 상세/원문. 시점 조절과 실제 자료 배치를 분리한다. | Canvas·그래프뷰 |
| `board` | 보드 범위 → 이름 붙은 열 → 카드 → 이동/편집. 가로 탐색과 명시적 이동 경로를 함께 둔다. | 칸반 |
| `timeline` | 기간/학기 → 날짜순 일정과 상태 → 선택 과업/다음 행동. 달력과 목록의 자료를 일치시킨다. | 일정·과제·다음 공부 |
| `control` | 현재 상태·권한 → 실제 변경/전송/복구 범위 → 명시적 실행 → 결과/실패. 위험과 보존 범위를 행동 근처에 둔다. | 설정·API·계정·복구 |

- 재료/색은 공통 실내·종이를 사용한다. 기능마다 새로운 브랜드색을 부여하지 않는다. 기존 그래프/수식/계층/출제 의미색과 개인 설정은 유지한다.
- 실제 기능명을 주 제목으로 두고 `guidance`의 존댓말 한 문장은 필요할 때만 과업 진입 안내로 사용한다. 명세용 `purpose`를 제품 안내로 그대로 출력하지 않는다.
- 무거운 위젯은 Figma에서 가벼운 대표 모양과 상태로 표현한다. 실제 계산·렌더링·원문을 수만 개 레이어로 복제하지 않는다. 상세 UX 원문은 이 문서/기존 소스에 두고 Figma는 요약·참조 링크와 필요한 대표 상태를 사용한다.
- 빈 상태는 현재 과업에 필요한 첫 행동을, 결과 없음은 범위를 바꾸는 행동을, 실패는 원문 보존과 재시도를 보여준다. 저장 완료는 실제 저장 결과가 있을 때만 표시한다.
- 편집·저장·복귀는 동일한 대상 ID와 실제 호출 맥락을 따른다. 모달 닫기·기기 회전·자료 갱신·장소 전환이 편집기를 새로 만들거나 초안/개인 배치를 초기화하지 않게 한다.
- 인증·API·저장의 경계는 기존 서버/저장 계약을 유지한다. 이 시각 정의를 데이터 이관·키 변경·외부 전송·운영 배포의 새 권한으로 해석하지 않는다.

## 4. 기능별 실행 정의

### 01. 오늘 — 오늘 펼친 책상

지금 이어갈 주제와 실제 남긴 기록을 보고 작은 공부 행동을 시작한다.

자리: **북쪽 공부 책상** · 구성: `journal` · 우선 행동: **이어갈 주제를 펼치기**

제품 안내: “지금 이어갈 주제를 펼치고, 오늘 남긴 기록을 확인하세요.”

**디자인과 정보 우선순서**

- 현재 과업 → 오늘 남긴 기록 → 선택 가능한 다음 행동 순서로 둔다.
- 풍경은 공통 커버에 두고 책상에는 읽고 쓸 내용의 종이 면을 둔다.

**UX와 복귀**

- 이어서 열기와 새로 시작하기를 구별하고 실제 마지막 과업이 있을 때만 이어가기를 제시한다.
- 위젯 정지·접기와 기존 바로가기를 유지하고 풍경 조작을 공부 사건으로 기록하지 않는다.

**UI와 상태**

- 오늘·한 주의 기간과 기록 유무를 명시하고 제안을 밀린 의무 목록으로 누적하지 않는다.
- 위젯 전체 비율과 외부 창틀을 유지하며 커버 아래의 과업을 작은 핫스폿 없이 연다.

**보존·해석의 경계**

- 원본 천문대 장면·반응·개인 설정·실제 이어가기 위치
- 미기록·미정 날짜·부분 수행의 의미

**누적·반복·실패 조건**

- 재접속 시 실제 존재하는 마지막 대상을 확인하고 사라졌으면 해당 목록을 제공한다.
- 긴 기록과 여러 주제가 쌓이면 내용 순서와 선택을 유지하며 점진적으로 펼친다.

대상: `R01` 오늘, `O10` 다음에 펼칠 곳을 남겨둘까요?, `O29` 이 주제부터 해볼까요?, `U09` 이어가기와 다음 위치, `U11` 천문대 원본 위젯, `U12` 천문대 세부 렌더러, `U13` 작은 도구와 시계, `U14` 오늘·한 주 공부, `U15` 공부 시작 제안.

### 02. 공부 기록·주제 상세 — 관측일지

한 주제에서 실제로 한 시도와 답·이유·막힘을 남기고 다시 고친다.

자리: **북쪽 공부 책상** · 구성: `journal` · 우선 행동: **공부한 내용을 기록하기**

제품 안내: “공부한 주제에 시도한 내용과 떠오른 생각을 남겨 보세요.”

**디자인과 정보 우선순서**

- 과목·단원·주제 맥락 → 현재 기록/답안 → 선택 입력·이력 순서로 읽힌다.
- 연속된 기록지를 사용하며 체크·긴 글을 각각 장식 카드로 쪼개지 않는다.

**UX와 복귀**

- 여러 주제 선택과 선택 메모·TRACE를 유지하고 날짜·설명·문제 위치를 평소 필수로 만들지 않는다.
- 저장 후 실제 출발한 주제/자료로 돌아가며 오류에는 원문을 남긴다.

**UI와 상태**

- 공부함·수정·취소·이력을 구체적인 행동명으로 유지한다.
- 체크의 시도 상태, 저장 진행/실패, 실제 수행 결과를 다른 표식과 문구로 구별한다.

**보존·해석의 경계**

- 원문·답안·TRACE·날짜 불확실성·반복·수정 이력·ID
- 체크를 숙달·완료·독립 해결로 환산하지 않는 의미

**누적·반복·실패 조건**

- 한글 조합·커서·선택을 유지하고 반복 저장/재시도에서 중복 기록을 만들지 않는다.
- 주제는 책상, 단원 계층은 책장의 기존 역할에 따라 같은 상세 경로의 장소를 정한다.

대상: `R05` 기록, `R20` 단원·주제 상세, `R21` 선택 주제 기록, `O11` 공부 기준 조정, `U19` 공부 기준·TRACE.

### 03. 메모·자유 기록 — 곁에 둔 기록지

하던 자료를 잃지 않고 짧은 생각부터 긴 자유 글까지 남긴다.

자리: **북쪽 공부 책상** · 구성: `document` · 우선 행동: **메모를 남기기**

제품 안내: “짧은 생각부터 긴 글까지, 하던 자료 곁에 남겨 두세요.”

**디자인과 정보 우선순서**

- 글 자체 → 연결 대상 → 편집/이력 순서로 두고 제목 없는 짧은 글도 허용한다.
- 짧은 메모는 자료 곁에서, 긴 글은 같은 종이의 넓은 읽기 면에서 편집한다.

**UX와 복귀**

- 모달을 닫으면 호출 자료와 펼쳐 둔 메모 영역·버튼으로 복귀한다.
- 휴지통 이동은 대상과 복구 경로를 알리고 취소 때 편집 원문을 지우지 않는다.

**UI와 상태**

- 기존 자료 곁에는 기본 접힌 메모를 필요한 만큼 펼치며 전체 목록 진입을 둔다.
- 장문 입력의 높이를 내용에 맞추고 저장·사본·이력을 글과 가까이 둔다.

**보존·해석의 경계**

- 개인 자유 글·선택 글·필기·연결·초안·수정 이력
- 사용자 글을 자동 요약/정리로 대체하지 않는 저자성

**누적·반복·실패 조건**

- 메모 누적 시 찾기·목록·최근 대상 복귀를 유지한다.
- 중단·저장 실패·타 세션 초안을 현재 글에 자동 덮어쓰지 않는다.

대상: `R06` 메모, `R22` 메모 상세, `R30` 자유 기록 목록·기본 글, `R31` 새 자유 기록, `R32` 자유 기록 상세, `O23` 메모를 휴지통으로 옮길까요?, `O24` 작은 메모, `U41` 장문 원문·기록 수정.

### 04. 필기·OCR·PDF 배경 — 손으로 쓰는 관측지

펜과 페이지를 사용해 답·도해·생각을 직접 쓰고 원본과 인식 글을 함께 보관한다.

자리: **북쪽 공부 책상** · 구성: `document` · 우선 행동: **종이에 필기하기**

제품 안내: “손으로 쓰고 그린 내용을 그대로 두고, 필요한 글만 인식해 확인하세요.”

**디자인과 정보 우선순서**

- 필기 원본이 가장 넓은 면을 차지하고 도구는 가장자리에 모은다.
- PDF 배경·원획·OCR 검토를 서로 다른 층으로 보이게 한다.

**UX와 복귀**

- 펜·지우기·선택·되돌리기·페이지 전환을 한 작업면에서 제공한다.
- OCR은 검토/적용 단계가 있으며 인식 실패가 원획을 삭제하지 않는다.

**UI와 상태**

- 현재 도구·색·굵기·페이지를 색 이외 선택 표시로 알린다.
- 좁은 화면에서 도구를 묶되 필기와 페이지·되돌리기 행동을 접근 가능하게 둔다.

**보존·해석의 경계**

- 원획·좌표·페이지·PDF 배경·기존 텍스트·초안·OCR 전 원본
- 기기별 펜 지원/오류 상태를 실제 기능에 따라 안내하는 계약

**누적·반복·실패 조건**

- 회전·확대·중단 복귀에도 페이지와 획 좌표를 보존한다.
- 페이지 증가·긴 인식 글·그리기 실패에서 페이지 이동과 원문 내보내기를 유지한다.

대상: `U29` 펜·OCR·PDF 배경.

### 05. 과목·학기 등록 — 공부 범위의 책등

실제 배우는 학기·과목을 등록하고 해당 범위의 자료와 기록을 찾는다.

자리: **서쪽 자료 책장** · 구성: `catalogue` · 우선 행동: **과목을 등록하거나 펼치기**

제품 안내: “배우는 과목을 등록하고, 그 안의 목차와 자료를 펼쳐 보세요.”

**디자인과 정보 우선순서**

- 학기/현재 범위 → 과목 이름·개요 → 목차/자료 진입 순서로 둔다.
- 책등의 안정된 정렬을 참고하되 긴 과목명을 자르거나 가짜 표지로 내용을 밀지 않는다.

**UX와 복귀**

- 과목 추가는 필요한 이름부터 시작하고 이미 알려진 학기를 재사용한다.
- 취소·실패 때 입력을 유지하며 생성 후 실제 과목 상세에서 계속한다.

**UI와 상태**

- 과목 카드마다 이름·범위와 실제 행동을 보이고 색만으로 과목을 식별하지 않는다.
- 학기 추가는 공통 조작에서 열어도 과목 등록의 원래 맥락으로 복귀한다.

**보존·해석의 경계**

- 과목/학기 ID·기존 개요·순서·개인 색·연결·이력
- 실제 교재·강의 범위와 빈 과목의 상태

**누적·반복·실패 조건**

- 학기/과목 누적과 긴 이름에서 찾기·선택·현재 범위를 유지한다.
- 재접속·중복 입력·저장 실패 때 기존 과목을 복제하거나 이름을 자동 바꾸지 않는다.

대상: `R04` 과목, `R19` 과목 상세, `O01` 학기 추가, `O02` 과목 추가.

### 06. 목차 관리 — 공부 범위의 색인

교재·강의계획서의 단원과 주제를 실제 계층으로 관리한다.

자리: **서쪽 자료 책장** · 구성: `catalogue` · 우선 행동: **목차를 정리하기**

제품 안내: “교재와 강의의 목차를 살펴보며 공부할 범위를 정리하세요.”

**디자인과 정보 우선순서**

- 현재 과목 → 단원/주제 계층 → 선택 항목의 조작 순서로 둔다.
- 들여쓰기·연결선·역할 이름으로 계층을 드러내며 위치 이동은 대상과 결과를 함께 보인다.

**UX와 복귀**

- 하나/여러 목차·표·사진 가져오기를 기존 계층에 연결한다.
- 이름·위치 변경은 미리 확인하고 관련 선택·집계·누락 추적을 같은 ID로 이어간다.

**UI와 상태**

- 추가·이름 수정·위치 옮기기·순서 이동을 실제 역할 이름으로 노출한다.
- 사진/표 결과는 확정 전 검토 가능한 초안으로 두고 불확실한 인식을 표시한다.

**보존·해석의 경계**

- 단원/주제 ID·부모 관계·개인 순서·원문·기존 기록 연결
- 목차 구조와 학습 완료/숙달을 구별하는 의미

**누적·반복·실패 조건**

- 많은 행·긴 이름·깊은 계층에서도 선택·펼침·스크롤을 유지한다.
- 가져오기 실패·중복 후보·부분 입력에서 원초안을 보존하고 취소·재시도를 제공한다.

대상: `O03` 목차 추가, `O04` 여러 목차 추가, `O06` 이름 수정, `O07` 목차 위치 옮기기, `O19` 공부할 목차 만들기, `O22` 사진으로 목차·내용 가져오기, `U16` 목차와 항목 관리, `U17` 표·사진 목차 만들기.

### 07. 강의 자료·PDF — 펼쳐 보는 원자료

원자료를 보관·읽고 필요한 구간을 골라 메모와 다음 공부에 연결한다.

자리: **서쪽 자료 책장** · 구성: `document` · 우선 행동: **자료를 펼치기**

제품 안내: “원자료를 펼치고, 필요한 메모와 도구를 곁에서 사용하세요.”

**디자인과 정보 우선순서**

- 자료 제목·출처 → 원문/PDF → 선택 구간·보조 도구 → 결과/이력 순서로 둔다.
- 원문과 곁도구를 분리된 작업면으로 두되 현재 자료가 화면의 중심을 유지한다.

**UX와 복귀**

- 목록/새 등록은 책장, 기존 자료를 읽는 상세는 책상으로 이어지는 기존 장소 전환을 유지한다.
- 원문 발췌·자료 퀴즈·대화·관계는 선택한 자료 맥락을 드러내며 닫으면 같은 읽기 위치로 돌아간다.

**UI와 상태**

- 전사문 붙여넣기·파일 가져오기와 출처/PDF 구간 선택을 제공한다.
- 기존 음성은 재생·복구·내려받기를 보존하며 새 녹음 기능이 있다고 표시하지 않는다.

**보존·해석의 경계**

- 원문·파일·등록 당시 출처·페이지/선택 구간·수정 전·이력
- 보관과 외부 전송, 생성 결과와 원문을 구별하는 상태

**누적·반복·실패 조건**

- 긴 전사문·여러 파일·중단 복귀에서도 읽기 위치와 초안을 유지한다.
- 보조 도구를 열고 닫거나 화면 폭이 바뀌어도 원문 편집기를 재생성하지 않는다.

대상: `R07` 강의 자료, `R23` 자료 상세·새 자료, `U23` 자료 출처·PDF 구간, `U24` 자료 퀴즈·관계·대화.

### 08. 자료 카드·주제 연결 — 출처가 붙은 발췌함

원자료에서 얻은 조각을 출처와 함께 다시 찾아 주제·코드에 연결한다.

자리: **서쪽 자료 책장** · 구성: `catalogue` · 우선 행동: **자료 카드를 주제에 연결하기**

제품 안내: “필요한 내용을 원자료와 함께 살펴보고 공부할 주제에 연결하세요.”

**디자인과 정보 우선순서**

- 카드 내용 → 원자료/구간 → 연결한 주제와 사용 행동 순서로 둔다.
- 원문 조각과 사용자/생성 해석을 같은 글처럼 합치지 않는다.

**UX와 복귀**

- 원자료와 연결 주제를 바로 열고 실제 이전 선택으로 돌아온다.
- 기존 카드·코드 연결을 바꾸는 행동과 새 주제 등록을 구별한다.

**UI와 상태**

- 원자료·주제 등록·연결 변경을 인접한 동작으로 제공한다.
- 연결이 없거나 원자료가 사라진 경우 상태와 가능한 대상을 명시한다.

**보존·해석의 경계**

- 카드 ID·원문·출처·원자료 링크·코드/주제 연결·이력

**누적·반복·실패 조건**

- 카드 누적은 검색·범위·내용 미리보기로 다루고 원문을 임의 축약 저장하지 않는다.
- 연결 변경 실패 때 기존 연결과 선택을 유지한다.

대상: `R12` 자료 카드, `U25` 카드·코드 주제 연결.

### 09. 개념 전집 — 참조 사전

정의·조건·관계·예제를 찾아 현재 공부와 연결해 읽는다.

자리: **서쪽 자료 책장** · 구성: `catalogue` · 우선 행동: **개념을 찾아 펼치기**

**디자인과 정보 우선순서**

- 개념 이름 → 정의/조건 → 관계·예제 → 출처/개인 기록 순서로 읽힌다.
- 목록은 찾기에, 상세 종이는 연속된 설명과 정밀 도해에 맞춘다.

**UX와 복귀**

- 목록/검색에서 개념으로 바로 진입하고 돌아오면 선택 범위를 유지한다.
- 관련 개념을 명시적 링크로 탐색하고 위치를 관계의 증거로 삼지 않는다.

**UI와 상태**

- 개념 제목·출처·상세 열기를 보여주고 필수 정의를 장식 뒤에 숨기지 않는다.
- 개념별 관찰틀은 기존 질문/관찰/조절/현재값/근거 순서를 재사용한다.

**보존·해석의 경계**

- 기존 개념 원문·ID·출처·개인 메모·관계·도해 조건

**누적·반복·실패 조건**

- 긴 정의와 많은 개념에서 검색어·필터·읽기 위치를 유지한다.
- 저장·읽기 실패는 해당 개념에서 알리고 다른 원문을 지우지 않는다.

**누적·반복·실패 조건**

- 긴 답안·여러 항목·저장 실패에서 비교와 미확인 상태를 유지한다.

대상: `R10` 시험 연습, `R26` 주제 지정 시험 연습, `O18` 지금 확인한 결과, `O20` 답안에서 수행 결과 남기기, `U20` 답안에서 수행 결과.

**UI와 상태**

**보존·해석의 경계**

**누적·반복·실패 조건**

- 항목 증가 시 현재 순서·진행 위치를 유지한다.
- 중단·재접속·생성 실패에도 작성 답안과 기존 기준을 보존한다.

### 12. 주제 카드·Anki·예약 복습 — 인출 카드함

자리: **북쪽 공부 책상** · 구성: `practice` · 우선 행동: **카드에 답하고 확인하기**

**UX와 복귀**

**UI와 상태**

- 예약량·자기 평가·메모 저장·독립 수행을 서로 다른 상태로 둔다.

**보존·해석의 경계**

- 덱·카드 ID·원답안·메모·필기·출처·자기 평가/예약 이력
- 기존 가져오기/중복 처리와 원앱 연동 경계

**누적·반복·실패 조건**

- 카드/덱이 쌓여도 범위·검색·현재 위치·복습 설정을 유지한다.
- 중단 복귀·평가 되돌리기·가져오기 실패에서 기존 카드와 이력을 보호한다.

대상: `R14` 주제 카드, `R29` 예약 복습, `U26` 덱·카드·Anki 가져오기, `U27` 복습 설정·최적화.

- 코드/입력 → 실행·정지 → 출력/오류 → 주제 연결 순서로 둔다.
- 편집기와 실행 결과를 서로 비교 가능한 작업면으로 배치한다.

**UX와 복귀**

- 명시적 실행으로만 연산하고 실행 중 중복 요청을 제한한다.

**UI와 상태**

- 좁은 화면에서는 코드→입력→결과 순서로 세로 배치하되 원문/출력을 잘라내지 않는다.

**보존·해석의 경계**

- 코드·입력·출력·초안·커서·주제 연결
- 실행 성공을 학습 성과로 대체하지 않는 의미

**누적·반복·실패 조건**

- 긴 코드·많은 출력·중단/재실행에서 편집 상태와 최신 실행 결과를 구별한다.
- 실행 불가 환경은 실제 이유와 원문 저장/내보내기 경로를 남긴다.

대상: `R08` 코딩 연습, `R25` 코드 예제 상세, `U30` 코드 편집·구문·터미널.

**디자인과 정보 우선순서**

- 질문/조건 → 관찰면 → 조절값/현재값 → 근거·참고 순서의 기존 관찰틀을 사용한다.

**UX와 복귀**

- 초기화는 대상 조건/보기의 범위를 설명하고 개념 원문이나 다른 탐색을 지우지 않는다.

**UI와 상태**

- 실제 수치·단위·정의 불가·계산 오류·다시 그리기를 명시한다.
- 화면 밖 엔진은 쉬게 하되 돌아온 조건·시점·선택을 유지한다.

**보존·해석의 경계**

- 기존 계산 엔진·정의역·단위·저장 탐색·조건·카메라·개인 설정

**누적·반복·실패 조건**

- 빠른 조절의 이전 계산이 최신 결과를 덮지 않게 하며 화면 크기 변경 때 보기를 맞춘다.
- 긴 수식·여러 조건·렌더러 실패에서 값/근거와 재시도를 유지한다.

**UI와 상태**

- 제목·기간·단위·표본·분모·제외/날짜 불확실성·집계 범위를 함께 읽게 한다.
- 색 외 라벨/선/범례·값 목록·키보드 선택·그리기 실패 재시도를 제공한다.

**보존·해석의 경계**

- 중복 없는 집계·동일한 분모·원기록·월간 요약·불확실성·사용자 보기

**누적·반복·실패 조건**

- 범주/관측 증가 때 담당 통계 계약의 묶음·상위 항목·전체 값 목록을 사용하고 총량을 보존한다.
- 긴 이름·좁은 화면·재접속·엔진 실패에서도 선택/원기록과 값 목록을 유지한다.

- 계정 모달을 닫으면 현재 과업으로 돌아가며 실제 접근 중지는 해당 상태에 맞게 처리한다.

**UI와 상태**

- 로그인·가입·이름 수정·승인·탈퇴의 대상과 결과를 구체적으로 알린다.
- 탈퇴/삭제 범위와 이용 중지/보존을 다른 동작으로 설명한다.

**보존·해석의 경계**

- 기존 사용자 ID·인증·소유권·다른 계정 자료·관리자/민석 전용 AI 권한의 구별

**누적·반복·실패 조건**

- 만료 세션·승인 변경·재접속·거부에서 이전 화면을 성공 상태로 남기지 않는다.
- 입력/검증 실패에서 안전한 입력을 보존하며 비밀정보는 공개 로그/시안에 남기지 않는다.

대상: `R40` 기존 계정 링크, `O08` 가입 계정 관리, `O09` 내 계정, `U02` 개인 공간 진입·인증, `U03` 로그인·가입, `U04` 가입 승인 대기·제한, `U05` 내 계정·탈퇴, `U06` 가입 계정 관리.

### 25. 저장 상태·백업·휴지통·초안 — 기록 보관함과 복구대

기록이 어디에 남아 있는지 확인하고 선택한 자료를 안전하게 되돌린다.

자리: **위쪽 천장 조명** · 구성: `control` · 우선 행동: **보존 상태를 확인하고 복구하기**

제품 안내: “기록이 남아 있는 곳을 확인하고, 필요한 자료와 범위를 골라 복구하세요.”

**디자인과 정보 우선순서**

- 대상/현재 저장 위치·상태 → 원본/보관본 비교 → 복구 범위/실행 순서로 둔다.
- 정상·미전송·충돌·실패를 같은 성공 표식으로 뭉치지 않는다.

**UX와 복귀**

- 기기/서버/초안/파일의 실제 보존 증거를 구별하고 복구 전 범위를 확인한다.
- 취소·사본 보관·재시도를 제공하며 다른 세션의 초안을 자동 적용하지 않는다.

**UI와 상태**

- 백업 만들기·파일 선택·복구·휴지통 복원·초안 열기를 대상과 함께 제시한다.
- 실패 알림은 현재 과업에도 두고 복구대를 닫으면 실제 출발 과업으로 돌아간다.

**보존·해석의 경계**

- 원문·ID·저장 키·초안·이력·개인 설정/배치·충돌 원본·다른 자료

**누적·반복·실패 조건**

- 자료 누적은 대상/시점·필터·점진 표시로 다루고 보관본 내용을 숨겨 삭제하지 않는다.
- 중단·손상 파일·오래된 초안·저장 실패에서 원자료를 덮어쓰기 전에 검증하고 사본을 남긴다.

대상: `R24` 강의 자료 휴지통, `R33` 전체 백업·복구, `R34` 휴지통, `R35` 초안 보관본, `O05` 휴지통으로 옮길까요?, `O21` 내 기록의 저장 상태, `U07` 내 기록의 저장 상태, `U08` 전체 복구 진입.

## 5. 공통 요소와 장소·상태 예외

111엔터티의 `entityIds` 배정은 각각 한 번만 한다. 공통 부품의 모든 사용처를 별도 엔터티로 늘리거나 중복 집계하지 않는다. 여러 과업에서 쓰는 부품은 호출한 맥락의 동작과 아래 예외를 적용한다.

| 대상 | 적용 조건 | 실제 적용 |
| --- | --- | --- |
| `R20` 단원·주제 상세 | `node.role === topic` | 공부 기록의 관측일지 구성과 책상. |
| `R20` 단원·주제 상세 | 단원/일반 목차 역할 | 목차의 색인 구성과 책장. 같은 ID의 원문/계층/기록 연결 유지. |
| `R23` 자료 상세 | 새 자료 `id=new` | 자료 등록은 책장. `document` 원문 중심 구성을 유지. |
| `R23` 자료 상세 | 기존 자료 ID | 읽는 자료는 책상. 곁 도구를 열어도 원문/읽기 위치 유지. |
| `U35` 공통 보기 조작 | 그래프뷰/Canvas | 그래프뷰에 한 번 배정해 관리하되 Canvas 사용 시 개인 좌표 보존 계약을 적용. 전체 보기는 시점 변경이며 개인 좌표 재배치가 아님. |
| `U41` 공통 원문 편집 | 과목/주제/자유 글/Canvas | 메모에 한 번 배정해 관리하되 호출 과업에 머문다. 본문만큼 높이가 늘고 초안/커서/이력을 유지. |
| `O01` 학기 추가·`U39` 브랜드 표식 | 공통 진입/여러 과업에서 사용 | 기능 소유 정체성은 과목/내 생각에 두며 실제 호출 방향으로 복귀. 전체 앱을 해당 자리로 강제 이동하지 않음. |
| `O03`·`O04` 목차 추가 | App의 `node`/`bulk` mode | 실제 모달 제목은 둘 다 “목차 추가”. `dialogMode`로 논리 엔터티를 구별하며 같은 색인 구성을 공유. |
| `O14` 수식 전체화면 | 개별 수식 제목 + “ · 전체 화면” | 동적인 수식 이름을 보존하고 제목 접미로 수식 관측기 역할을 연결. |
| `O27` 카드 추가·편집 | 기존 카드 여부 | “카드 추가”·“카드 편집” 두 실제 제목을 같은 작업 보드 역할에 연결. |

JSON의 `place`는 정체성의 기본 보관 자리이다. 기존 `observatory-place.ts`가 정하는 실제 장소·호출 맥락을 대체하지 않는다. `contextOverrides`는 이 예외를 설명하고, UI는 `routeBindings`와 명시적 모달/보조면 연결을 통해 구성만 선택한다.

## 7. 정본 소비와 갱신

기능 추가·수정 때에는 실제 기능명·목적·보관 자리·정보 순서·주요 행동·상태/복귀·보존·반복 사용 조건을 같은 identity에서 갱신한다. 새 엔터티는 현재 화면 목록과 대응하고 엔터티 소유권은 한 곳에 둔다. 기존 정체성으로 해결할 수 있는 국소 동작 때문에 새 은유/구성/색을 만들지 않는다.

JSON 계약은 다음과 같다.

- `identities`: 25개. `id`는 소비 코드의 안정된 키이며 `label`은 실제 기능명, `metaphor`는 보조 정체성이다.
- `purpose`는 명세용 목적, `guidance`는 사용자에게 보여줄 존댓말 안내, `primaryAction`은 핵심 과업이며 버튼을 자동 새로 만드는 명령이 아니다.
- `composition`은 10개 화면 구성 중 하나이다. 기존 실제 조작을 없애거나 폼/그래프/필기 도구 자체를 대체하지 않는다.
- `design`·`ux`·`ui`·`preserve`·`repeatUse`는 독립적으로 확인할 적용 규칙이다. 모든 항목을 제품 화면에 지침 문단으로 나열하지 않는다.
- `entityIds`는 기존111개를 중복 없이 배정한다. `routeBindings`는 실제41개 경로에 단원 역할 분기2개를 더한43개이고, `dialogBindings`는 기존29개 논리 모달에 카드 제목 변형을 포함한30개이다.
- `contextOverrides`는5개 맥락 예외, `extensions`는 A01–A10과 천장 조명의11개 연결이다. 구현에서는 알려진 명시적 조건을 판단하며 문자열 조건을 실행 코드로 평가하지 않는다.

공통 색·치수·모션 값은 [기준값](observatory-experience-baseline.json)에, 이 기능별 의미/구성은 이 문서와 JSON에 둔다. 같은 결정이 두 원본에 흩어지지 않게 한다. Figma는 정본의 요약/대표 상태를 사용하며 원문 전체를 다시 레이어로 생성하지 않는다.

## 8. 적용 확인과 완료 판정

정본 작성 시 원본 inventory의41경로·29모달·41보조면을 전수 대조했다. 25정체성의 `entityIds` 합계111, 고유111, 누락0, 중복0, 알 수 없는 엔터티0이다. 장소·구성 enum과 비어 있지 않은 정의/디자인/UX/UI/보존/반복 규칙을 확인했다. 이 숫자는 문서 대응의 증거이다.

실제 수정의 완료에는 제목 아래의 정체성 안내뿐 아니라 각 구성의 본문/도구/값/행동 순서와 해당 원자료/저장/복귀의 연결이 필요하다. 관련 대표 과업에서 정상·긴 글/자료 증가·좁은 화면·중단 복귀·실패 중 바뀐 위험을 확인하고, Figma 렌더/앱 브라우저 조작/저장·재접속/운영 반영을 각각 기록한다. 이미 확인한 자료를 같은 범위로 반복 검사하거나 물리 기기·학습 효과를 문서 대응으로 승격하지 않는다.

현재 실제 반영 및 검증 범위는 [최신 인계](resume-handoff.md)와 이 작업의 구현/검증 기록에서 확인한다. 기준의 채택 날짜가 기존 화면 전체의 실행 검증 날짜를 뜻하지 않는다.

이 작업의 실제 소스 연결·한정 검토·Figma·통합 검증 결과는 [기능별 정체성 구현 기록](observatory-feature-identities-implementation-20261002.md)에서 관리한다.
