## 2026-10-01 정정: 전사문 저장 후 녹음 정리

사용자는 전사한 뒤 원본 녹음을 계속 보관할 필요가 없다고 정정했다. 기본값은 전사문 확인·필기 추가 → 자료의 저장 성공 확인 → 앱의 녹음 사본과 연결된 녹음 구간 정리이다. 이 정정이 아래 최초 원음 보존 결정에 우선한다. 전사 실패/저장 실패·사용자가 다시 선택한 녹음 보관·다른 자료/초안의 동일 녹음 참조에서는 원음을 남긴다. 사용자가 보관을 선택하면 그 선택은 checkpoint에 저장한다. 기기의 파일 앱에서 가져온 외부 원본은 브라우저 File 객체의 관리 범위 밖이다.

## 선정한 기존 경로와 범위

공식 [Sign in with ChatGPT 안내](https://developers.openai.com/siwc/token-sharing-open-source)는 원격 호스팅 앱의 접근 신청을 요구한다. 공개 코드만으로 이 앱의 원격 요금제 접근 승인이 성립하지 않는다. 공식 [preview 제한](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)에서 음성 입력·transcription API를 지원하지 않으므로 GPT 연결과 받아쓰기를 나눈다. 원격 OAuth 등록·callback·토큰 보관/갱신·모델 선택·생성은 접근 승인 조건을 받은 뒤 연결한다. 사용자 소유 VM을 현재 Supabase의 승인이나 모바일 연결 완료로 취급하지 않는다.

받아쓰기는 [Transformers.js의 ASR pipeline](https://huggingface.co/docs/transformers.js/api/pipelines#module_pipelines.AutomaticSpeechRecognitionPipeline)을 재사용한다. 별도 Python 설치나 유료 전사 서비스 없이 브라우저 Worker에서 WASM을 실행한다. tiny/base의 합성 한국어 출력이 불충분해 `Xenova/whisper-small`, revision `2d67713f236afa48a18992566e7647f6ca848e13`, q8, 한국어, 라이브러리 4.3.0을 고정했다. 두 ONNX 모델 파일은 합계 약 249MB이며 런타임 WASM은 별도이다. 첫 다운로드와 캐시 저장이 필요하고 브라우저가 캐시를 지우면 다시 내려받을 수 있다. 오인식이 남으므로 자동으로 원문이나 필기를 교체하지 않는다.

## 실제 앱의 처리·보존

- 기존 민석 user ID와 personal namespace 확인 뒤에만 음성·모델·Worker를 읽고 실행한다. 다른 승인 계정이나 관리자에게 AI 실행 권한을 부여하지 않는다.
- 원본 음성은 기존 사용자별 IndexedDB 저장에 남긴다. 16kHz PCM을 30초 구간으로 처리하며, 저장 transaction이 완료된 구간만 진행 완료로 인정한다. 기기 메모리를 고려해 20분 이하 파일만 처리한다. 긴 원본은 지우지 않고 나눈 파일을 가져오도록 안내한다.
- 진행 사본의 키는 namespace/user ID/audio SHA/model version을 포함한다. 기존 model version의 사본·자료·ID를 덮어쓰지 않는다. 완료 플래그·구간 순서·길이·글자 수를 검사하고 손상 사본은 덮어쓰지 않는다.
- 중단·화면 이탈에서는 Worker를 종료한다. 저장된 구간 다음부터 다시 처리하고, 완료 사본은 음성 decoding과 추론 없이 재사용한다. iOS 백그라운드 지속을 보장하지 않는다.
- 받아쓴 글과 사용자 정정 글을 구분해 보관한다. 사용자가 확인한 글만 기존 필기 뒤에 덧붙이며, 같은 추가의 연속 클릭은 하나로 처리한다. 필기 초안 보관과 자료의 서버 저장은 별도이다. 받아쓰기 진행·원본 음성은 이 기기 저장이며 다른 기기로 자동 전달됐다고 표시하지 않는다.
- 계정 탈퇴 정리는 해당 owner prefix의 진행·정정 사본만 지운다. 다른 계정의 음성·필기·진행 사본은 유지한다.

## 원격 서버 적용

기존 Supabase 프로젝트의 `study-ai` v1을 적용했다. GET `/functions/v1/study-ai/status`는 Auth 사용자 확인 → 정확한 민석 ID → 현재 이용 승인 확인 뒤 미연결 상태를 반환한다. 승인 전 source body 파싱·한도 예약·공급자 호출은 실행하지 않는다. POST도 같은 순서로 확인하고 `GPT_REMOTE_APPROVAL_REQUIRED`로 중단한다. 서버 토큰/개인자료/모델 목록은 노출하지 않는다. OPTIONS는 204이고 GET/POST의 CORS를 허용한다. 게이트웨이 JWT 검사는 꺼져 있으나 함수 본문이 Auth 서버의 신원을 매번 확인하는 기존 패턴을 적용한다.

최초 적용 직후 다른 작업에서 자료 작업 목록이 갱신되어 현재 로컬 번들과 원격 v1 전체 byte는 다르다. 실제 다운로드한 v1은 `work/mobile-gpt-20261001/deployed-study-ai.ts`에 보관하고 그 파일을 대상으로 권한·승인 전 차단을 다시 시험했다. 다른 서버 함수와 DB 구조는 이번에 배포/수정하지 않았다.
