# ManSeekSong OS — 천문대 정체성과 전체 경험 대응안

> **현행 확정 기준 — 2026-10-02:** 사용자 「여기까지, ux, ui, 디자인 기준으로 값을 정해둬라」에 따라 현재 적용할 값·공간·문구 규칙은 [천문대 디자인 기준](observatory-design-standard.md)과 [기준값 JSON v2.0.0](observatory-experience-baseline.json)을 따른다. 어두운 실내와 밝은 종이 면, 정면 공부 책상·왼쪽 자료 책장·오른쪽 탐구 작업대·뒤쪽 기록·계획 벽, 기능명 유지와 은근한 보조 문구를 확정했다. 이 문서의 이전 후보·시안·수치 표는 조사와 변경 이력이며, 충돌할 때 현행 확정 기준이 우선한다. JSON의 `workSurfaceColors`는 현재 수학 런타임의 이전 색상 호환값이다. `pixelTreatment`는 v2에도 채택한 단일 공통 원본이며 기존 수학 소비자도 같은 값을 재사용한다. 프로젝트가 정한 기본값이고 국제표준의 지정 수치가 아니다. **기준 확정은 앱 전체 구현·검증·배포 완료를 뜻하지 않는다.**

작성 시작: 2026-10-01. 2026-10-02 사용자 정정 반영. 사용자 요청: 「이 정체성을 더 심층화하여, 지금 웹앱들에 이 정체성을 모두 대응… 디자인, UI, UX, 수리엔진과 대응하는 위젯, 색채… 이러한 작업방식의 표준… 우주와 하늘에서 색채 요소를 찾아라」.

**최우선 후속 정정: 「위젯 애니매이션처럼, 픽셀느낌, 스타듀벨리느낌나는게 핵심이다.」** 픽셀 애니메이션과 살아 있는 작은 세계의 감각을 중심으로 삼는다. 앞서 제안한 차분한 작업면·정확한 도구는 이 픽셀 세계 안에서 구현할 기능적 조건이다. 천문대가 배경 장식 한 곳에만 남는 방향으로 축소하지 않는다.

**추가 진행 맥락: 「천문대 애니매이션이 확장되고있다 알고있어라」.** 확장 중인 실제 천문대 구현과 그 담당 설계가 표현의 기준 원본이다. 아래 단계 수·장면 수·팔레트 수·수식은 조사 시점의 구현을 설명하며 앞으로의 확장을 제한하지 않는다. 연구 보드의 천문대도 해당 시점 소스를 묶은 화면이므로 새 장면·수리 반응·상호작용이 추가되면 원본과 대조해 다시 빌드한다. 이 대응안이 별도 천문대 구현이나 고정된 옛 규격이 되지 않게 한다.

상태: **기존 구현과 공식 자료를 대조한 조사·대응 이력과 현행 확정 기준의 근거**. 초기 설계 제안과 색채 보드를 보존하며, 현재 적용값은 위 현행 기준을 따른다. 전체 제품 적용·공개 배포를 완료한 기록은 아니다. 실행 추적은 [MAN-18](https://linear.app/manseeksong/issue/MAN-18)이다. 기존 천문대 MAN-14, 통계 MAN-10, 공통 디자인 MAN-16과 연결한다.

2026-10-02 초기 기준값 설정 이력: 사용자의 색채·UI·UX 정정에 따라 11절과 기준값 JSON을 설계 기본값으로 설정했다. 이후 실내·종이·공간 정정을 반영한 **현행 v2.0.0과 천문대 디자인 기준이 이 초기값보다 우선한다.** 공통 토큰·생성기 책임은 재사용하며 생산 적용은 별도 상태로 관리한다.

2026-10-02 심층 조사: [천문대 안에 머무는 경험 — 세부 설계 조사](observatory-presence-details-20261002.md)에 공간·사물·빛·소리·문구·복귀의 디테일24개, 기능 문구14개, 원 연구/제작자 사례와 현재 앱의 재사용 경계를 연결했다. 추가 구현의 설계 제안이며 실제 제품 반영·존재감·학습 효과의 검증을 뜻하지 않는다.

2026-10-02 공간 정정: [천문대 안의 책상과 방향별 기능 배치](observatory-spatial-workspace-20261002.md)를 따른다. 사용자는 실내 책상에 앉고 풍경 위젯은 정면 창문으로 읽히게 한다. 정면 공부·왼쪽 자료·오른쪽 도구·뒤쪽 기록/계획의 자리를 고정하며, 자료와 작은 도구는 현재 공부 곁에서 이어 쓸 수 있게 한다. 기능 분류와 창틀/빛/시점/복귀 규칙의 구체화이며 실제 공간 전환 구현 완료를 뜻하지 않는다.

## 1. 정체성의 중심

> 차분한 나의 자리에서 하나를 깊이 들여다보고, 남긴 생각들이 이어지며 내가 바라볼 수 있는 세계가 넓어지는 공간.

천문대는 **픽셀로 살아 움직이는 머무는 장소**, 사용자는 **직접 읽고 질문하고 확인하는 사람**, 하늘은 **탐색할 수 있는 지식의 범위**, 기록은 **다시 찾을 수 있는 관찰의 흔적**, 연결은 **근거를 가진 관계**, 도구와 수리엔진은 **판단을 돕는 관측 기구**로 대응한다. 이 대응은 제품 설계를 위한 비유이며 실제 천체물리·학습효과의 법칙이 아니다.

정체성은 다음 여섯 행동으로 구체화한다.

| 정체성 | 사용 중 확인할 행동 | 설계 판단 |
| --- | --- | --- |
| 나의 자리 | 재접속 후 읽던 자료·초안·선택·배치로 돌아온다 | 복귀와 상태 보존이 첫 경험이다 |
| 가까이 보기 | 한 기록·수식·문제에 집중하면서 필요한 자료를 곁에 둔다 | 작업면은 선명하게, 주변 도구는 필요할 때 펼친다 |
| 멀리 보기 | 상세에서 전체로 돌아가도 보던 대상과 위치를 안다 | 전체/상세의 위치와 선택을 연결한다 |
| 흔적이 남기 | 질문·오답·정정·불확실도 다시 열 수 있다 | 원문·이력·출처를 보존하며 기록을 숙달로 환산하지 않는다 |
| 관계를 발견하기 | 연결을 따라가면 관계 종류와 원문을 확인한다 | 실제 연결·계층·수동 제안의 의미를 구별한다 |
| 스스로 방향 정하기 | 추천을 이해하고 선택·보류·수정한다 | 추천은 근거와 다음 작은 행동을 제공한다 |

기존 「공부가 이어지는 자리.」「다시 펴면, 하던 생각부터.」를 공간과 동작으로 구체화한다. 친숙한 메뉴·버튼 이름을 유지하고 천문학 용어를 새 조작 학습의 선행조건으로 만들지 않는다.

### 세 가지 시각 층

1. **주변 풍경:** 확장 중인 천문대·하늘·시간대 장면. 정체성이 가장 직접적으로 드러나는 곳이다. 현재 확인한 12단계·36상황은 시점별 구현 수치이다. 채택한 모션과 정지/숨김을 보존하며 새 장면·반응을 같은 표현 문법에 연결한다.
2. **공부 작업면:** 읽기·쓰기·수식·필기·코딩. 천문대 안의 종이·책상·정밀 기구처럼 보이는 픽셀 윤곽과 재료색을 현행 확정 기준으로 적용한다. 본문은 선명한 글자·안정된 배치·국소 강조로 유지한다. 커버의 변화가 입력칸과 본문 배경을 흔들지 않는다.
3. **관측 도구:** 통계·추천·복습·그래프·일정. 숫자·범위·관계와 출처가 드러나며 장식과 실제 자료를 혼동하지 않는다.

현재 천문대의 별/궤도/성운은 기록량과 일별 신호에 반응하는 **표시용 도형**이다. 각각을 실제 개념·기록 ID와 일대일로 연결한 지식 그래프라고 설명하지 않는다. 실제 관계는 현재 그래프·Canvas·자료 연결에서 읽는다. 향후 두 화면을 연결할 경우 항목 ID·관계 종류·원문 열기를 명시적으로 구현해야 한다.

### 픽셀 세계의 표현 문법

스타듀밸리에서 참고할 것은 작은 픽셀의 그림뿐 아니라 **정해진 크기의 사물, 명암 덩어리, 가까운 생활감과 먼 풍경, 반복되는 미세 움직임, 손으로 건드렸을 때의 분명한 반응**이다. 실제 참고와 출처는 [픽셀 표현 조사](../work/observatory-identity-20261001/pixel-art-direction.md)에 둔다.

| 요소 | 이번 앱의 방향 | 기능과의 연결 |
| --- | --- | --- |
| 픽셀 크기·윤곽 | 기존 천문대의 작은 계단 윤곽·색 덩어리를 기준으로 공통 아이콘/창 경계의 크기 계열을 정한다 | 확대/고해상도에서도 모양이 흐려지지 않도록 확인한다. 수학 선·필기 원문은 정밀도 유지 |
| 공간 | 먼 하늘→능선/돔→가까운 창·책상·종이의 층 | 홈/전체 시야→자료 선택→읽기/쓰기의 과업 깊이와 연결 |
| 재료·빛 | 종이의 따뜻한 밝음·밤의 짙은 남색·작은 황백 창빛·멀리 보이는 성운 | 작업면·선택·관계·주변 장식을 다른 역할로 조색 |
| 작은 움직임 | 별의 미세 점등·먼지·혜성·창빛·안내등과 기존 초신성 파장 | 현재 기록 동역학·누적·시간대와 연결하고 정지/움직임 감소 제공 |
| 직접 조작 | 선택·누르기·열기·돌아오기에서 한두 단계의 명료한 픽셀 반응 | 실제 선택/저장/실행 상태가 바뀌었을 때 피드백한다 |
| 말과 글자 | 기능명·한국어 본문·수식은 읽기 쉬운 기존 체계 | 픽셀 폰트의 일괄 강제로 긴 공부 글을 희생하지 않는다 |

메뉴마다 장식을 새로 붙이기보다 같은 픽셀 윤곽·면·빛·선택 규칙을 Button/Card/Input/Tab/Modal/차트 도구에 재사용한다. 모든 UI가 게임 조작을 요구할 필요는 없으며, 실제 공부 행동은 기존 직접 입력·검색·터치·키보드로 수행한다. 원작의 자산·캐릭터·농장 화면은 복사하지 않고 현재 천문대 원본과 직접 만든 소품을 사용한다.

장면의 표현은 풍부하게 두되 반복 입력 시 매번 재생·축하·이동이 발생하도록 만들지 않는다. 세계의 느린 변화와 사용자의 즉각적인 조작 응답은 각각의 시간으로 설계한다. 구체 타일 크기·프레임수·주기는 기존 위젯과 실제 화면에서 정하는 값이며 스타듀밸리의 공식 규격이라고 주장하지 않는다.

## 2. 이런 작업의 기존 기준과 방법

조사한 범위에서는 천문대 정체성부터 전체 앱과 엔진을 한 번에 정해주는 단일 공식표준을 확인하지 못했다. 다음 기존 체계를 조합하는 것이 적합하다. 명세의 지위와 설계 제안을 구별한다.

| 기준/방법 | 지위 | 이번에 사용하는 범위 |
| --- | --- | --- |
| [ISO 9241-210:2019](https://www.iso.org/standard/77520.html) | 인간중심설계 국제표준 | 실제 공부 맥락·사용자 요구·설계·평가를 연결. 공개 공식 개요를 확인했으며 유료 본문 전체 적합성 감사는 아님 |
| [Design Council Double Diamond](https://www.designcouncil.org.uk/resources/framework-for-innovation/) | 설계 방법 프레임워크 | 기존 앱 발견→문제 정의→대응안 개발→작은 과업 시험. 매번 전체 조사 재시작을 요구하지 않음 |
| [GOV.UK 경험 지도](https://www.gov.uk/service-manual/user-research/creating-an-experience-map) | 정부 서비스 매뉴얼의 실무 방법 | 진입→공부→기록→중단→복귀의 접점 연결. 실제로 묻지 않은 감정은 가설로 남김 |
| [NN/g 서비스 블루프린트](https://www.nngroup.com/articles/service-blueprints-definition/) | 서비스 설계 실무 방법 | 보이는 위젯과 뒤의 데이터·엔진·저장·오류 복구를 연결. 이번 앱에 필요한 얇은 대응표로 조정 |
| [NN/g 현실과 시스템 대응](https://www.nngroup.com/articles/match-system-real-world/) | 사용성 휴리스틱 | 가까이/멀리·선택·복귀에 비유를 쓰고 버튼은 익숙한 공부 언어 유지 |
| [DTCG 2025.10](https://www.designtokens.org/tr/2025.10/format/) | 안정판 커뮤니티 기술 명세. W3C 표준/표준화 트랙 문서는 아님 | 색·간격·타입·참조를 기록. 기존 CSS/JSON 담당 원본을 유지하며 교환 가능성 참고 |
| [IBM Carbon Themes](https://carbondesignsystem.com/elements/themes/overview/) | 운영 디자인 시스템의 공식 구현 관행 | 역할은 고정하고 밝음/어두움에서 값 변경. 패키지 도입이나 외형 복제는 필요 없음 |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/) | W3C Recommendation | 실제 글자·조작·포커스·색 의미·모션을 확인 |

이들을 **정체성→반복 과업→화면 행동→엔진/근거→역할 토큰/부품→실제 확인**으로 잇는 절차는 이번 프로젝트에 맞춘 합성 제안이다. 개별 방법의 유명세를 정체성 전달·학습효과의 증거로 사용하지 않는다. 자세한 조사 기록은 [방법론 조사](../work/observatory-identity-20261001/design-methods.md)에 둔다.

## 3. 전체 경험의 연결

| 흐름 | 정체성의 구현 | 실패/중단 조건 |
| --- | --- | --- |
| 들어오기 | 일정한 앱 구조와 마지막 과업으로 돌아옴 | 로그인/승인 상태는 사실과 다음 행동으로 안내 |

## 5. 수리엔진과 위젯의 대응

수리엔진은 입력을 처리해 값을 만드는 부분이며, 위젯은 그 값을 사용자가 이해·선택·재확인할 수 있도록 표현하는 작은 화면이다. 분위기를 만드는 계산과 실제 공부 판단을 지원하는 계산을 같은 점수로 합치지 않는다.

다음 계산표는 조사 시점의 코드 연결이다. 천문대 확장 시 담당 원본의 입력 의미와 출력 계약을 먼저 확인하고, 표와 보드를 갱신한다. 시각 효과의 증가만으로 새 학습 의미가 생겼다고 해석하지 않는다.

| 계산 계층 | 현재 입력/출력 | 현재 연결 | 정체성/위젯 대응 |
| --- | --- | --- | --- |
| 일별 기록 동역학 | 최신 유효 기록의 입력일별 활동·다양성·재방문; `f(n)=1-exp(-n/3)`, 3일/14일 EWMA와 차이 | 홈 천문대의 수·광량·주기·운동 폭 | 최근 기록에 반응하는 주변의 잔광과 흐름. 피로/집중력/숙달/실제 공부일 계산은 아님 |
| 누적 천문대 전개 | 고유 `(사건,과목,대상)` 조합 E; `q=min(11,log2(1+E))` | 12단계 사이 연속 변화; 별·성운·은하·초신성·광륜 | 남겨온 기록에 반응하는 풍경. 단계는 미술 좌표이며 학습 단계가 아님 |
| 시간대/36상황 | KST6시간대·안정 순열·30분 장면·경계 혼합 | 시간별 하늘/광량/상황, 일부 양에 위 신호 반영 | 하루의 바깥 시간과 내 공간의 연결. 실제 날씨/천체위치/일출 예측은 아님 |
| 기록 통계 | 8지표·분모·날짜의 정확/범위/미정 | 홈·통계19그래프·값표·원기록 | 관측값을 읽는 도구. 기간/대상/단위를 먼저, 색·선·분포는 질문에 맞게 |
| 다음 공부 추천 | 목표·일정·선행관계·실제 수행 근거/상태 | 최대3후보·근거·보류·이력 | 다음에 시선을 둘 대상. 근거→원문→시작/변경/보류를 연결 |
| 방법 비교 | 사전 기준·같은 척도·독립 평가·귀속·기한·결측/구간 | 조건을 만족할 때 추천의 방법 후보 | 불확실한 범위도 읽는 계측. 인과효과·능력 총점으로 바꾸지 않음 |
| FSRS 복습 | 응답 등급·복습 시각·stability/difficulty·설정 | 예약 큐·다음 간격·덱/최적화 | 다시 관찰할 시기를 잡는 도구. 예측값을 실제 기억률로 표현하지 않음 |
| TodayStudy | 기존 예약 복습·명시 일정 | 복습 링크·기한·원하는 주제 고르기 | 오늘의 작은 관측 목록. 위 엔진들을 한 점수로 합치지 않음 |
| 수식 계산 | 사용자 수식·변수·조건·범위·근사 | Plotly/GeoGebra·좌표·곡선/곡면·벡터 | 정밀 조절 도구. 입력 조건·축·출력·오차/정의불가를 직접 보여줌 |
| 관계 배치 | 엔터티·목차 계층·명시 관계와 좌표 | 그래프/Canvas/자료 개념도 | 실제 자료의 별자리. 기존 자동 탐색 배치와 사용자 저장 좌표를 구별 |
| API 사용량/예산 | 확인된 사용·예약·월상한·추정/미확정 | 예산 요약·도넛·설정 | 기구의 사용 상태. 비용 단위와 실제 예약/잔여를 유지하며 빛 세기로 감추지 않음 |

EWMA는 [NIST의 지수 가중 방식](https://www.itl.nist.gov/div898/handbook/pmc/section3/pmc324.htm)을 재사용한다. 이 앱의3일/14일·포화 상수3·12단계 배치는 기존 표시 정책이며 학습효과를 검증한 계수가 아니다. 같은 사건 재저장·장문·중복 전송은 누적을 늘리지 않는다. 미입력으로 누적 단계가 내려가지는 않지만 삭제/정정/범위 변경은 현재 유효 기록을 다시 반영한다.

현재 **추천·FSRS·통계 수치는 커버에 직접 연결되지 않는다.** 추가 대응의 우선순위는 각 기존 위젯의 근거 열기와 선택/복귀를 같은 방식으로 다듬는 것이다. 모든 계산을 별의 수·밝기·폭발로 한꺼번에 합치는 새 모델을 만들 필요는 없다.

| 다음 공부 | 작은 방향표와 선택된 대상의 국소 창빛 | 기존 추천의 대상과 선택 상태. 빛은 추천의 확신/능력점수를 뜻하지 않음 | 이유 보기·시작·바꾸기·보류 |
| 주제 카드·예약 복습 | 시계 옆에 다시 펼칠 카드 묶음 | 실제 예약 시점과 현재 카드. 수치와 날짜는 읽을 수 있게 제공 | 질문→응답→판단→다음 간격 |
| 일정·과제 | 관측실 벽의 일정판 | 실제 날짜/기한/준비·제출 상태 | 날짜/대상 선택·수정·원래 과업으로 이동 |
| 통계 | 작은 관측 기구의 픽셀 테두리 안에 선명한 차트 | 현재 기간/범위의 실제 관측값 | 표현 선택·값표/근거 확인·이전 기간 비교 |

| 코딩 연습 | 천문대 작업실의 작은 단말 창 | 편집·실행·표준입력·출력·오류 | 코드 읽기/쓰기·실행·오류 수정·재실행 |
| 시험/암기시험 | 한 장씩 집중하는 확인용 종이 | 응답·검토·부분/보류 등 명시 상태 | 답하기·판정 근거 확인·다시 시도 |
| 칸반·찾기 | 이동 가능한 작업표와 조준 표식 | 사용자가 정한 열/순서·검색 결과/현재 선택 | 옮기기·검색·정확한 위치로 이동 |
| AI·사용량·저장/복구·설정 | 같은 세계의 정돈된 도구 서랍/상태 표시 | 실제 요청/예약/비용/전송/복원·선택한 설정 | 권한 있는 호출·취소·원문 확인·재시도·복원 |

새 원장이 없어도 기존 상태를 픽셀 컴포넌트에 대응할 수 있다. 상태가 바뀔 때 표정/빛/소품이 반응하는 경우에도 실제 의미는 라벨·아이콘·값으로 확인할 수 있어야 한다. 장시간 읽는 동안 주변 애니메이션은 정지/축소할 수 있고, 그 선택을 재접속 후에도 유지한다.

### 공통 연결 계약

각 위젯은 `원본 ID/범위 → 입력 근거 → 기존 계산 → 출력 종류/단위 → 화면 표현 → 근거 열기/다음 행동 → 실패·복귀`의 연결을 가진다. 저장되지 않은 화면 변화로 성공 표시를 만들지 않는다. 순서나 단위를 가진 자료는 밝기·크기만으로 암호화하지 않고 기존 값/목록 경로를 제공한다.

원장 변경 시 해당 엔진만 다시 계산하고, 새 시각 값은 기존 선택/스크롤/좌표/커서와 별개로 반영한다. 원본 범위가 다르면 비교하지 않으며 날짜 불명·결측·도움 유무·자기 보고·추정값을 보존한다. 엔진 설명은 내부 설계/도움말에 두고 일반 천문대 커버에 점수·계수 설명을 상시 추가하지 않는다.

## 6. 우주·하늘에서 가져오는 색채

색은 세 종류로 구별한다. **가시광의 관측/촬영색**, **보이지 않는 파장이나 협대역을 가시색에 대응한 표현색**, **제품 가독성을 위해 조정한 디자인색**이다. 사진도 노출·필터·처리·화면에 영향을 받는다. 아래 HEX는 사진에서 실측한 천체의 고유색이 아니라 기존 앱 색과 추가 제안이다.

**청색의 차가운 인상은 미술적 연상이고, 푸른 별은 대체로 더 높은 표면온도이다.** 남색을 우주 자체의 고유색, 보라를 모든 은하의 실제 색이라고 설명하지 않는다. 초신성 잔해의 사진은 폭발 순간의 영상과 다르다. [Webb의 컬러 이미지 제작](https://science.nasa.gov/mission/webb/science-overview/science-explainers/how-are-webbs-full-color-images-made/)처럼 파장을 색에 대응하는 과정은 정보 표현의 참고이며, 인간의 학습 상태를 천체 에너지에 등치하는 근거가 아니다.

초기 색채 조사에서는 기존16색에 세 계열을 추가 후보로 비교했으며, 후속 기준값 설정에서 11절의 역할로 채택했다. 단색 쌍의 계산 대비에서 `#2B6E9F`/흰색5.48:1, `#E7CE84`/깊은 밤12.06:1, `#A995D6`/깊은 밤7.08:1이다. 반대로 황백/흰색1.55:1과 라일락/흰색2.64:1은 작은 글자에 충분하지 않다. 원색은 곧바로 텍스트/버튼색이 되지 않으며 밝은 테마용 더 어두운 파생색과 실제 렌더링 확인이 필요하다. 사진 크레딧과 사용 조건은 [색채 조사](../work/observatory-identity-20261001/cosmic-colors.md)에 유지한다.

### 색의 세 역할과 충돌 방지

- **분위기색:** 남색의 깊이, 성운의 보라, 초신성의 다홍, 대기광의 청록. 천문대 그림·관계 화면의 주변부에 한정된 강도로 사용한다.
- **조작/상태색:** 본문·버튼·포커스는 현행 실내/종이 역할색을 공통 Semantic 토큰에 연결한다. 오류·전송 대기·출제 가능성 주황과 출제 확정 빨강의 의미 계약은 유지한다.
- **자료색:** 그래프의 같은 범주는 화면·테마를 바꿔도 같은 역할을 갖는다. 범례/직접 라벨/선 모양을 함께 사용하고, 보기마다 임의의 우주 색을 다시 배정하지 않는다.

같은 주황을 사용할 수는 있어도 천문대의 빛과 기록의 출제 가능성 표시는 영역·모양·라벨로 구별한다. 주황 발광을 새 성취/숙달 신호로 추가하지 않는다. 보라를 AI·신비·정답과 일괄 등치하지 않는다. 한 화면에 모든 색을 같은 강도로 전시하지 않는다.

## 7. 토큰과 컴포넌트로 내리는 방식

`천체 출처/감각 → 기존 Primitive 또는 필요한 후보 → Semantic 역할 → Component 상태 → 실제 과업` 순서로 대응한다. 기존 `src/ui/tokens.css`, `docs/color-system.json`, `docs/observatory-palette.json`의 책임을 재사용한다. 초기 후보 보드와 아래 비교표는 조사 시점 자료로 남기고, 현재 설계 기본값은 [천문대 디자인 기준](observatory-design-standard.md)과 JSON v2.0.0을 따른다. 특히 아래의 남보라 실내 제안은 먹색/회갈색 실내와 크림색 종이 기준으로 대체되었다. 생산 적용은 기존 생성기를 통해 연결하며 화면별 CSS에 하드코딩하지 않는다.

| 역할 | 초기 밝은 화면 제안 이력 | 초기 어두운 화면 제안 이력 | 적용 경계 |
| --- | --- | --- | --- |
| 기본 작업면 | 따뜻한 종이/밝은 기구 면 후보 | 저채도 남보라의 내부/밝은 글자 | 픽셀 세계의 재료감을 토큰에 반영하되 본문·입력·코드·수식 가독성 우선 |
| 깊이 | 작은 남색 경계/관계 배경 | 남색 공간층과 한 단계 밝은 작업면 | 하늘 표현과 선택형 관계 화면 |
| 읽기 빛 | 흰 면과 따뜻한 밝은 주변부 | 백색/크림색의 국소 빛 | 본문 뒤의 발광·번짐은 제한 |
| 선택/초점 | 현재 브랜드 계열의 선명한 색 | 충분한 대비를 가진 밝은 역할색 | 포커스 경계와 선택 상태를 구별 |
| 관계 | 읽을 수 있는 청색/보라 계열 선 | 밝은 청색/보라 선 | 관계 종류 라벨과 실제 ID가 있는 경우 |
| 강조 | 주요 행동 한 곳 | 주요 행동 한 곳 | 경고/오류/출제 표식과 구별 |

서체는 현재 사용자 선택과 한글/수학/코드의 구별을 유지한다. 픽셀은 일러스트·소품·윤곽·조작 피드백에서 강하게 드러내고 긴 본문은 읽기 쉬운 글꼴로 둔다. 간격은 기존 4/8px 척도와 정렬·근접성으로 만든다. 목록/표는 밀도를 유지하고, 깊이의 인상을 위해 모든 화면을 큰 카드로 나누지 않는다. 기존 중립색 수치 자체를 새 픽셀 정체성보다 우선하지 않으며, 시각 값 변경은 담당 토큰에서 상태/테마를 함께 확인한다.

모션은 기존 천문대에서 충분히 표현하고, 공부 작업면에서는 선택의 출처·상세 열림·원래 위치 복귀를 설명하는 짧은 이동에 사용한다. 현재 모션 기준과 정지·앱/OS 움직임 감소·화면 밖 중단을 유지한다. 상태 알림의 저장 성공은 실제 ACK를 따른다.

| 좁은 화면 | 우선 작업과 분명한 돌아가기, 보조 영역 펼침 | 필수 행동·값·출처를 계속 찾을 수 있는가 |
| 시각 효과 실패 | 기존 목록·텍스트·정지 그림 | WebGL/도형 실패가 기록 읽기/저장을 막지 않는가 |
| 저장 실패/충돌 | 실제 상태·재시도·두 편집본/원문 복구 | 성공처럼 빛나거나 기존 글을 덮어쓰지 않는가 |
| 오랫동안 미기록 | 기존 기록과 기본 공간 보존 | 미기록을 실패/망각/능력 저하로 표현하지 않는가 |

원하는 분위기는 안정감·집중·탐색 가능성이라는 **디자인 의도**이다. 개인 감정이나 학습효과가 확인됐다는 진술이 아니다. 실제 정체성 평가는 비유를 미리 알려주지 않고 사용 후 공간의 느낌과 그 이유를 묻고, 실제 과업 성공·복귀/재찾기와 함께 확인한다.

## 9. 검증 기준과 적용 순서

WCAG 2.2의 1.4.1(A) 색만으로 의미 전달 금지, 1.4.3(AA) 일반 글자 4.5:1/큰 글자 3:1, 1.4.11(AA) 필요한 조작·상태·도형 3:1을 적용한다. 장식선 전체가 3:1 대상이라는 뜻은 아니지만, 의미 있는 연결과 조작 경계는 확인한다. 자동 모션에는 2.2.2(A)의 정지/숨김 조건을 적용하고, 비필수 상호작용 모션 해제 2.3.3은 AAA 기준임을 구별한다. 섬광은 2.3.1(A)의 조건을 지킨다. 일부 대비 통과는 전체 적합성 인증이 아니다.

1. 확정된 현행 역할값과 공통 토큰/상태/천문대 팔레트의 연결을 대조한다. 후보 역할을 다시 정하는 단계로 되돌리지 않는다.
2. 홈→이어가기→기록/자료→복귀의 실제 연결에서 공간감과 가독성을 확인한다.
3. 그래프/Canvas의 실제 관계와 통계/추천/복습 위젯의 근거 접근을 연결한다.
4. 수식/코드/AI/설정/복구까지 같은 역할·상태 규칙을 확장한다.
5. 변경 관련 누적/긴 글/좁은 화면/실패·복귀를 확인하고 실제 적용 범위를 기록한다.

이번 산출물은 조사·전범위 대응안·색채/역할 비교이다. 실제 제품 적용 단계에서는 관련 Q01–Q15와 기존 기기 검증 정책을 사용하며 변경과 무관한 전체 QA를 매번 반복하지 않는다.

## 11. 색채·UI·UX 기준값

2026-10-02 사용자 정정: 「색채, ui, ux의 기준값을 설정해둬야하는건 지침에 의해 알고있으리라 알고있겠다.」 분위기 설명 이후에는 값·단위·역할·상태·예외·담당 원본을 정한다. 숫자로 다룰 수 있는 것은 값으로, 복귀·저장·실패처럼 행동의 문제는 관찰 가능한 동작 규칙으로 관리한다.

후속 「본 정체성에 맞게 수정이 필요하다면 그 기준도 수정해」에 따라 **기존 수치와 외형도 재검토·변경 대상**으로 둔다. 이전 중립 회색 작업면·둥근 모서리·흐린 그림자·선형 아이콘의 관행이 픽셀 천문대의 공간·재료·움직임과 충돌하면 역할별 기준을 수정한다. 오래된 외형은 새 정체성 적용의 거부 조건이 아니다. 원문·학습 의미·읽기/조작 가능성·사용자 설정을 지키면서 구체적인 시각 값은 변경할 수 있다.

**현재 값 원본은 [observatory-experience-baseline.json](observatory-experience-baseline.json) v2.0.0이며, 적용 역할·예외는 [천문대 디자인 기준](observatory-design-standard.md)이 담당한다.** 공통 타입·간격·조작·모션의 구현은 기존 `src/ui/tokens.css`와 생성기를 재사용하되 이전 구현값을 이유로 최신 확정값을 낮추지 않는다. 아래 표는 초기 설정과 호환 이력이다. 기존 표준의 지위는 2절을 재사용하고 색 조합·픽셀 치수·모션 시간은 프로젝트의 선택으로 구별한다.

### UI 치수와 픽셀 표현의 설정 이력

현행 치수·모션의 역할과 예외는 [천문대 디자인 기준](observatory-design-standard.md)과 JSON의 `metrics`·`motion`을 따른다. `pixelTreatment`는 이전 수학 소비자의 입력을 보존하면서 v2에도 그대로 채택한 단일 공통 원본이다. 아래 표는 초기 설정의 설명 이력이며, 별도 픽셀값 사본을 만들지 않는다.

| 항목 | 기준값·원본 | 적용 조건 |
| --- | --- | --- |
| 간격 | 공통 `space-*`: 기본 글꼴16px에서 0/4/8/12/16/24/32/48/64px, `space-group`18px | 실제 rem 토큰 사용. 기존18px와 데이터 의존 치수 보존 |
| 본문·입력 | 본문1rem/행간1.65, 입력 `max(16px, body)` | 긴 한글·수식·코드와 사용자 글꼴 유지 |
| 제목 위계 | Display40/32px, Title28/24px, Heading20px, Subheading18px | 기본16px 환산. 실제 rem/반응형 공통 토큰 사용 |
| 보조 정보 | Label15px/1.5, Caption14px/1.6 | 작은 글자 때문에 조작 영역 축소 금지 |
| 조작 영역 | 일반48px, 아이콘44px 이상 | 긴 이름/확대 시 높이 증가. 기존 부품 참조 |
| 읽기 폭·대화상자 | `layout-reading`48rem, `layout-dialog`36rem | 가용 폭·안전 영역 안으로 축소, 긴 내용 내부 스크롤 |
| 경계·초점 | 일반1px, 초점2px+offset3px | 픽셀 장식과 실제 포커스를 분리 |
| 픽셀 윤곽 | 공통 픽셀 프레임의 계단2px, 버튼/입력/탭/패널/알림 radius0, 대화상자2px | 현재4/6/8/12px는 기존 구현값이다. 새 정체성에서는 위 역할별 값으로 수정하며 포커스·조작 영역은 자르지 않음 |
| 깊이·그림자 | 일반 작업면 none, 떠 있는 창 offset2px/4px·blur0·spread0 | 밝은 면 `#302D3233`, 어두운 면 `#00000066`; 흐린 그림자 중심의 이전 표현을 단단한 픽셀 층으로 수정 |
| 픽셀 아이콘 | 새 소품/아이콘 기본 캔버스20px, 조작 영역44px 이상 | 정수 배율·원래 종횡비 우선. 수학 선과 글자는 pixelated 처리하지 않음 |
| 기본 동작 | feedback120ms, transition180ms, ease-out | 공통 토큰 참조. 움직임 감소에서0ms |
| 장면 움직임 | 확장 중인 천문대 담당 renderer의 시간·단계·프레임 계약 | UI120/180ms나 고정 FPS를 하늘 전체에 강제하지 않음 |

픽셀은 소품·빛·윤곽·반응을 일관되게 만든다. 본문 글꼴을 일괄 픽셀화하거나 실제 수학 도형의 정밀도를 낮추지 않는다. 새 소품은 기존 천문대의 시점·픽셀 스케일과 대조하고 같은 크기/용도일 때 위 기본값을 사용한다.

적용 범위는 주변 그림에 한정하지 않고 공통 버튼·입력·탭·패널·창·아이콘·선택 반응까지 포함한다. 기존 공통 부품의 API와 저장 책임을 재사용하면서 외형 값을 변경한다. 눌림은 기존1px 아래 이동을 재사용하며 모든 입력마다 장면 전환이나 보상 애니메이션을 새로 발생시키지 않는다. 기존표의 중립/모서리/그림자 설명과 충돌하면 이번 정체성의 기준값을 적용 목표로 사용하고 실제 적용 상태를 별도 기록한다.

### 적용 상태와 변경 관리

- **기존 제품 기준을 재사용:** 타입·간격·조작 영역·포커스·짧은 모션·의미색 계약. 해당 토큰이 있다는 사실을 모든 호출처 준수의 증거로 삼지 않는다.
- **현행 확정:** 실내/종이 역할색·픽셀 표현·UI 치수·모션·고정된 네 장소·기능명과 보조 문구 원칙은 새 기준 문서와 JSON v2.0.0에서 관리한다. 이전 설정은 변경 이력으로 보존한다.
- **제품에 적용할 때:** 기존 색 생성기/공통 토큰/부품에 연결하고 실제 상태·화면에서 확인한다. 수식 탐색은 이전 색상 호환값 `workSurfaceColors`와 v2에서도 채택한 공통 `pixelTreatment`를 이미 소비한다. 이 사실이 새 `materials` 색이나 v2 디자인 기준 전체의 반영을 뜻하지는 않는다. 다른 호출처와 연구 보드의 소비 여부도 별도로 확인하고 이번 기준 확정을 전체 앱 반영·배포로 보고하지 않는다.
- **예외:** 역할·필요 이유·적용 범위·대체값·관련 확인을 담당 원본에 남긴다. 사용자 설정은 기본값보다 우선하며 원문/이력/개인 배치는 보존한다.
- **검증 이력:** [기준값 확인 기록](../work/observatory-identity-20261001/baseline-verification.json)은 당시 JSON 파싱·토큰 참조·원본 경로·색 조합 계산의 근거로 보존한다. 이전 기록을 v2 전체 검증으로 승격하지 않으며 실제 렌더링·물리 기기·전체 WCAG 적합성은 계산으로 통과 처리하지 않는다.
