## 적용 방법과 메모리

채택된 천문대·지식 표현·본문·레이아웃 계약을 재사용했다. Figma 공식 Plugin API와 Fill/Hug/Wrap을 사용하고, 원격 도구가 로컬95%글꼴을 불러올 수 없는 부분은 기존 Figma 개발 플러그인을 재사용했다. [플러그인 Manifest](https://developers.figma.com/docs/plugins/manifest/)에 따라 네트워크 허용을 `none`으로 제한했다. 생성기와 확인 응답의 모든 변경 ID는 [evidence](evidence/)에 보존한다. 첨부 두 PDF를 이번에 새로 전체 정독했다는 보고가 아니다.

`ManSeekSong Paper`는 이미 앱이 사용하는 나눔명조 OFL 파생95% 서체이다. 기존 WOFF2를 데스크톱용TTF로 변환하면서 cmap/가로 메트릭을 대조했다.700 기본·800 강조·400 개인 설정을 위한 파일과 라이선스는 [글꼴 묶음](native-plugin/fonts/)에 둔다. Figma에서 실제 편집하려면 해당 로컬 글꼴을 사용할 수 있어야 한다. Text Style 선언만으로 실제95%를 만들었다고 하지 않는다.

개념 파일에서 Figma의 실제 메모리 초과 안내를 확인하고 공식 복구 모드로 열었다. 숨김 레이어도 메모리 부담을 남긴다는 [Figma 메모리 지침](https://help.figma.com/hc/en-us/articles/360040528173-Reduce-memory-usage-in-files)에 따라, 원문·과학 도형을 전후 대조하면서 불필요한 **숨김 파생 글자 윤곽**11,673개를 정리했다. OS에서도2,737개를 정리했다. 본문 일반 텍스트는 실제95%글꼴로 표시되며, 수식 혼합 조판은 보존 원문과 표시 윤곽을 구별한다. 혼합 조판의 원문 수정 후에는 보존 조판 절차로 표시를 갱신해야 한다.

원격 읽기가 다시 가능해졌고39페이지의 반영된 속성을 재조회했다. 원격 폰트 **편집** 지원과 원격 저장/렌더 **읽기** 지원은 서로 다르다. 복구 모드 이후 일반 모드의 실제 재열기와 프로토타입 실제 클릭은 로컬 연결 복구 뒤 확인할 범위로 남긴다. 로컬 복사본 저장 메뉴를 시도한 것으로 실제 백업 파일이 생겼다고 보고하지 않는다.

## 마지막 미적용 보완

개념 공통 본문 부품 `4:29` 안 텍스트 `4:30`은 폭640px 고정으로 남아 있다. 폭592px인 일부 지식 모듈에서 현재 짧은 내용은 보이지만, 긴 내용/폭 변경에서는 부모 폭을 따라 줄바꿈되는 계약이 필요하다. **Fill/Height/Hug를 연결하는1건이 아직 원격에 반영되지 않았다.**

원격 도구는 실제 `ManSeekSong Paper/Bold`를 불러오지 못했고, 로컬 Computer Use는 `Sky Computer Use native pipe startup failed`를 반복 반환했다. 승인 부족으로 대기하는 작업이 아니다. 원문/ID를 보존하는 [수정 코드](pending-source-body-fill.js)와 기존 플러그인의 `sourcefill` 작업을 준비했다. 연결 복구 뒤 이1건을 적용하고 같은 영향을 받는 모듈의 긴 내용/폭 변경, 생성 프레임 높이, 일반 모드 재열기·대표 천장SWAP/CLOSE클릭을 확인한다. 이미 마친 과정형 배치나239레이아웃을 다시 대량 실행하지 않는다.
