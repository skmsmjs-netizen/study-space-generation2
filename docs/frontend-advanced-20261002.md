# 프론트엔드 고급 기법 구현 — 2026-10-02

사용자 「자, 너는 프론트앤드 고급스킬을 구현하라」에 따라 현재 React/SVG/WebGL2 흐름에 세 가지 개선을 연결했다. 기존 [개발 기준 조사](research/development-reference-20261002/README.md)와 [천문대 확정 기준](observatory-design-standard.md)을 적용했으며, 공통 브라우저 기능과 기존 렌더러를 재사용했다. 이번 변경은 로컬 구현·검증 완료이며 공개 배포는 수행하지 않았다.

## 1. 원본을 자르지 않는 창가

`StudyLandscapes → ObservatoryRoom`에서 풍경 위에 덮던 장식 프레임을 실제 바깥 테두리로 바꿨다. 원본 `viewBox="0 -100 960 400"`를 유지하고 `xMidYMid meet`와 960:400 비례 크기를 연결했다. 창턱·책상은 풍경 아래에 별도 공간을 차지하며, 정지·설정은 하늘 바깥의 조작 행에 둔다. 이전 안쪽 조작 경계를 제거하고 원본 하늘 네 가장자리까지 같은 좌표로 반응하게 했다.

창틀·턱·단차의 다섯 값은 `observatory-experience-baseline.json`의 `metrics.window`에서 직접 읽는다. 넓은 면의 창틀은 8px, 40rem 이하 컨테이너는 4px이다. 기존 확정값을 소비 코드에 연결했으며 값 원본을 새로 복제하거나 숫자를 바꾸지 않았다. 앱 전체 네 방향 이동·종이 작업면은 이번 구현 범위가 아니다.

담당: `src/ui/observatory-room.tsx/css`, `study-landscapes.tsx/css`, `observatory-pointer.ts`, `observatory-geometry.ts`.

## 2. 표시 조건에 맞추는 GPU 처리

`ResizeObserver`가 실제 SVG 표시 크기를 관찰한다. 매 프레임 화면 기하를 읽지 않고, 크기 변화가 있을 때 관측값을 갱신해 기존 렌더 루프에서 사용한다. 해상도는 너비 240/320/400/480/640/800/960/1280 단계 중 선택하며, 픽셀 밀도는 1–2, 확대 기여는 최대 3배 확대의 제곱근으로 제한한다. 이 값들은 제품의 조정 가능한 처리 정책이다.

조작 중에는 처리량을 낮추고, 기존 프레임 간격 관측에서 지속적인 부담이 확인되면 최대 400px로 낮춘다. 기존 느린 관측 40회·회복 관측 240회의 전환 조건을 유지했다. 해상도에 따라 입자 크기를 보정해, 선명도 변경 자체가 별의 겉보기 크기를 바꾸지 않게 했다. 정지 중 크기가 바뀌면 시계를 진행하지 않고 한 번 다시 그린다.

화면 밖에서는 기존대로 GPU 자원을 해제하면서 약 6KiB의 입자 배열과 부담 상태를 해당 React 부품의 메모리에 보존한다. 다시 보일 때 이어서 사용한다. 이 상태는 같은 장면이 마운트된 동안의 연속성에 한정하며, 계정 간 공유나 영구 저장을 만들지 않는다. 기존 LOD·Curl Noise·Bloom·OKLCH·정지/모션 감소·WebGL 손실 복구·SVG 대체는 유지했다. 이를 이번에 새로 만든 기능으로 세지 않는다.

담당: `src/ui/observatory-render-budget.ts`, `observatory-gpu.ts`, `observatory-advanced.tsx`, `observatory-shaders.ts`.

## 3. 반복 입력과 복귀의 처리량

입력·키 이동·스크롤마다 실행되던 읽기 위치 탐색과 복귀 정보 직렬화·저장을 한 애니메이션 프레임 안에서 모아서 처리한다. 커서·선택 방향·입력 칸 내부 스크롤 값은 즉시 메모리에 기록한다. 개인 공간의 session/local 저장에는 같은 직렬화 결과를 재사용한다. 공부 원문과 원장 저장 경로는 이 처리 지연의 대상이 아니다.

화면 이동·뒤로/앞으로 가기·탭 숨김·pagehide·포커스 이탈·iframe 이동·부품 해제 때는 대기 중인 정보를 반영하거나 취소한다. 이전 경로의 뒤늦은 이벤트가 새 화면의 복귀 위치를 덮지 않도록 이탈 상태를 구별한다. 단위 검사에서 한 프레임 안의 40회 입력/키/스크롤 묶음이 읽기 위치 탐색 1회·경로 쓰기 1회·편집 위치 쓰기 1회로 모이는 것을 확인했다. 이를 실제 기기 입력 지연의 개선율로 환산하지 않는다.

담당: `src/ui/navigation-context.ts`와 관련 단위 검사.

## 검증과 사용 범위

- 최종 타입 검사·Vite 빌드 통과. 디자인 검사 46개 CSS 오류 0, 변경 관련 코드 검사 오류 0.
- 관련 단위 검사 7개 파일·52개 통과. jsdom의 Canvas 미구현 경고는 남아 있으며 실제 GPU는 브라우저 경로에서 별도로 확인했다.
- 같은 고정 빌드의 WebKit 다섯 프로필에서 11개 흐름씩 **55개 통과, 실패·생략·flaky 0**. 실행은 `work/device-runs/run-BhtrfO`이다. iPhone 세로/가로, iPad 세로/가로/반창 환경을 다뤘다.
- 창틀·확대·정지·모션 감소·층 설정·공부 입력 반영·재접속·저장 실패와 재시도·화면 로딩 실패 복구의 관련 회귀를 확인했다.
- 인앱 브라우저에서 실제 DOM·포인터 확대·정지/재생·402px 화면과 최종 1280px 화면을 확인했다. 한글 예시 초안의 앞뒤 공백·줄바꿈·선택 범위 33–34·뒤쪽에서 앞쪽으로 선택한 방향이 새로고침 후 그대로 유지됐다. 최종 화면의 오류/경고 로그는 0이다.
- 첫 브라우저 실행 `run-5PO560`은 340px 변경이 같은 해상도 단계에 남는 검사 기대의 오류가 있었고, 생산 코드의 최종 보완을 포함하기 위해 중단했다. 검사를 실제 단계가 바뀌는 320px로 수정한 뒤 최종 실행을 완료했다. 이전 실패/중단 로그는 보존했다.

명령·검사 결과·산출물 SHA256은 [검증 기록](../work/frontend-advanced-20261002/verification.json)에 둔다. 화면은 [넓은 화면](../work/frontend-advanced-20261002/desktop.jpg)과 [좁은 화면](../work/frontend-advanced-20261002/mobile.jpg)이다. 로컬 확인 주소는 `http://127.0.0.1:5747/?space=demo#/`이며 별도의 예시 자료로 검증했다.

물리 iPhone/iPad의 성능·배터리·Pencil·OS 한글 조합 입력과 장기 사용 효과는 이번 브라우저 모사로 검증했다고 하지 않는다. 실제 개인 기록 쓰기·서버 변경·공개 배포는 이번 작업에서 수행하지 않았다. 공유 작업 트리의 다른 변경을 유지했으며, 통합 배포에서는 이 변경과 당시 최종 소스/산출물을 다시 연결해야 한다.

## 선택한 공식 근거와 스킬

| 근거 | 이번 적용 | 한계 |
| --- | --- | --- |
| [MDN ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver) | 실제 요소 크기 변경 관측 | GPU 성능 개선을 자동 보장하지 않음 |
| [MDN requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame) | 입력/스크롤의 중복 작업을 프레임별로 통합 | 숨긴 탭에서 중단될 수 있으므로 이탈 시 별도 반영 |
| [MDN preserveAspectRatio](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Attribute/preserveAspectRatio) | 원본 하늘 비율과 전체 표시 유지 | 포인터 좌표와 실제 배치도 함께 수정·확인해야 함 |
| `vercel:react-best-practices` | 여러 TSX 변경의 렌더·이벤트·수명 관리 검토 | 기존 앱 구조와 자료 보존 계약 안에서 적용 |
| `browser:control-in-app-browser` | 실제 입력·새로고침·화면 크기·확대·오류 확인 | 물리 기기 검사와 구별 |

자동 해상도 단계·전환 계수·상태 보존 방식은 위 웹 기능을 이 제품에 맞게 조합한 구현 선택이다. 이를 별도의 공식 표준이나 검증된 학습 효과로 표현하지 않는다.
