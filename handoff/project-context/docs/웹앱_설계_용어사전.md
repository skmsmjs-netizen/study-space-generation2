# 웹앱 설계 용어사전

Codex로 웹앱을 만들 때 쓰는 412개 용어 항목 · 27개 분야

작성일: 2026년 9월 30일

## 사용 방법

2026-10-02 사용자 결정으로 이 사전의 412항목·27분야를 본 개발 전체의 공통 어휘로 사용합니다. 실제 페이지·프레임·컴포넌트·레이어·속성·상태·코드/저장/서버 책임의 대응, 공식 기준/방법론과 교육 구조는 [개발 전체의 구조·명명·어휘 기준](../generation2/docs/design-vocabulary/README.md)이 담당합니다. 기존 정의는 보존하며 같은 이름의 다른 의미는 영어명과 안정 사전 ID로 구별합니다. 사전의 모든 항목을 새 기능으로 도입한다는 뜻은 아닙니다.

이 문서는 용어 암기장이 아니라, 불편을 구체적인 설계·구현·검증 요청으로 바꾸기 위한 참조서입니다. 모든 항목을 앱에 넣으라는 기능 목록은 아닙니다. 도구와 디자인 시스템마다 이름이 조금 다를 수 있으므로, 용어와 함께 실제 동작을 설명하세요.

각 분야는 용어, Codex 요청 예시, 혼동 주의, 근거 문서로 구성합니다. 요청 예시는 이 문서를 위해 작성한 실무 적용안이며 공식 문서의 인용문이 아닙니다. 일반적인 실무 용어의 정의는 아래 문서들을 바탕으로 종합했으며, 프로젝트에 특화한 보존·검수 원칙은 적용 제안입니다.

## 주신 피그마 글을 읽는 기준

주신 글처럼 용어와 적용 원칙을 연결한 자료도 함께 모으는 편이 좋습니다. 공식 안내는 반복이 보이면 비교적 이른 시점에 컴포넌트를 만들고, 작은 요소를 조합하며, 슬래시 이름 또는 페이지·프레임을 이용해 정리하는 방식을 설명합니다. 두 정리 방식은 조합할 수 있습니다. 다만 초기 탐색의 흐름을 방해한다면 나중에 정리해도 된다는 단서도 있습니다.

따라서 ‘언제나 처음부터 완벽한 시스템을 만들어라’로 읽기보다 ‘재사용 이익과 탐색 비용을 보고 구조화하라’로 적용합니다. 실제 작업에는 현재의 Variants, Component properties, Auto layout, Variables 안내도 함께 참고합니다.

근거: [figma-guide], [figma-variants], [figma-props], [figma-layout], [figma-variables]

## 01. 제품과 사용자 경험의 기본

**사용자 인터페이스 (UI · User Interface)**

사람이 제품을 보고 조작하는 화면·입력·출력의 접점입니다.

**사용자 경험 (UX · User Experience)**

사용자가 목표를 이루는 과정에서 겪는 이해·행동·감정·결과를 포괄합니다.

**사용성 (Usability)**

사용자가 목표를 얼마나 효과적이고 효율적이며 만족스럽게 달성하는지를 다룹니다.

**상호작용 설계 (Interaction Design · IxD)**

사용자 행동에 시스템이 어떤 순서와 방식으로 반응할지 설계합니다.

**사용자 요구 (User Need)**

사용자가 실제 상황에서 해결하려는 필요입니다. 기능 이름과 구분합니다.

**사용 맥락 (Context of Use)**

사용자·기기·장소·시간·제약 등 사용에 영향을 주는 조건입니다.

**핵심 과업 (Core Task)**

제품에서 사용자가 반드시 완료할 수 있어야 하는 주요 작업입니다.

**사용 시나리오 (Usage Scenario)**

누가 어떤 상황에서 무엇을 하려는지 구체적으로 서술한 상황입니다.

**성공 기준 (Success Criteria)**

과업을 제대로 마쳤다고 판단할 관찰 가능한 결과입니다.

**제약 조건 (Constraint)**

화면 크기·권한·시간·기술 등 설계가 지켜야 하는 제한입니다.

**사용성 문제 (Usability Problem)**

사용자가 찾기·이해·조작·완료 과정에서 겪는 구체적인 장애입니다.

**안티패턴 (Anti-pattern)**

반복해서 쓰이지만 특정 맥락에서 문제를 키우는 설계 방식입니다.

### Codex 요청 예시

이 앱의 핵심 과업을 먼저 정리하고, 화면 장식보다 과업 완료를 막는 문제부터 개선해 주세요.

### 혼동 주의

예쁘다는 평가와 사용하기 쉽다는 평가는 같지 않습니다. 실제 사용자를 조사하지 않았다면 사용자 요구를 확인된 사실로 단정하지 않습니다.

근거 문서: [nng-heuristics], [gov-patterns], [gov-testing]


## 02. 설계 산출물과 흐름

**정보 구조도 (Sitemap)**

화면이나 콘텐츠가 어떤 계층과 관계로 구성되는지 보여주는 지도입니다.

**사용자 흐름 (User Flow)**

사용자가 목표를 향해 화면·선택·분기를 거치는 경로입니다.

**과업 흐름 (Task Flow)**

특정 작업 하나를 완료하는 절차에 집중한 흐름입니다.

**사용자 여정 (User Journey)**

제품 사용 전후를 포함해 접점·행동·어려움을 시간 순서로 정리합니다.

**와이어프레임 (Wireframe)**

색과 장식보다 정보 배치와 기능 구조를 보여주는 설계도입니다.

**목업 (Mockup)**

실제 화면에 가까운 모양을 보여주는 정적인 시안입니다.

**프로토타입 (Prototype)**

가정한 흐름이나 상호작용을 시험하기 위한 모형입니다.

**충실도 (Fidelity)**

시안이 실제 제품의 모양과 동작을 얼마나 자세하게 표현하는지 나타냅니다.

**와이어플로 (Wireflow)**

와이어프레임에 화면 사이의 행동·분기 연결을 결합한 도식입니다.

**화면 목록 (Screen Inventory)**

설계·수정·검수가 필요한 화면을 빠짐없이 나열한 목록입니다.

**요구사항 (Requirement)**

제품이 제공하거나 지켜야 하는 기능·행동·조건입니다.

**인수 기준 (Acceptance Criteria)**

요구사항의 완료 여부를 판정할 구체적인 조건입니다.

### Codex 요청 예시

과목 선택부터 공부 기록 저장까지의 와이어플로를 작성하고, 각 화면의 진입·이탈·취소·실패 경로를 표시해 주세요.

### 혼동 주의

정적인 목업만으로 뒤로 가기, 저장, 오류 복구가 구현되었다고 판단하지 않습니다.

근거 문서: [nng-wireflow], [nng-ia], [gov-testing]


## 03. 이해하기 쉬운 설계의 원리

**멘털 모델 (Mental Model)**

사용자가 시스템이 이렇게 작동할 것이라고 예상하는 방식입니다.

**어포던스 (Affordance)**

사용자와 대상의 관계에서 가능한 행동을 뜻합니다.

**시그니파이어 (Signifier)**

무엇을 할 수 있는지 알려주는 보이는 단서입니다.

**발견 가능성 (Discoverability)**

사용자가 기능이나 행동 경로를 찾아낼 수 있는 정도입니다.

**행동 유도 단서 (Action Cue)**

클릭·편집·끌기 등 가능한 행동을 드러내는 구체적인 표시입니다.

**일관성 (Consistency)**

비슷한 상황에서 용어·모양·행동 규칙이 일치하는 성질입니다.

**관례 (Convention)**

사용자가 다른 제품에서 익혀 기대하는 익숙한 규칙입니다.

**인지 부담 (Cognitive Load)**

작업을 이해하고 기억하며 판단하는 데 필요한 정신적 부담입니다.

**인식 대 회상 (Recognition over Recall)**

기억해서 입력하게 하기보다 필요한 정보나 선택지를 보여주는 원칙입니다.

**점진적 공개 (Progressive Disclosure)**

기본 작업을 먼저 보여주고 필요한 때 추가 설정을 펼치는 방식입니다.

**피드백 (Feedback)**

사용자의 행동이나 시스템 상태 변화를 알아볼 수 있게 돌려주는 반응입니다.

**오류 예방 (Error Prevention)**

실수한 뒤 알리는 데 그치지 않고 실수가 생기기 어렵게 설계합니다.

**사용자 통제 (User Control)**

사용자가 취소·복귀·수정·되돌리기를 할 수 있게 보장합니다.

**피츠의 법칙 (Fitts’s Law)**

대상을 가리키는 시간이 대상까지의 거리와 크기에 영향을 받는다는 원리입니다.

### Codex 요청 예시

클릭 가능한 요소에 시그니파이어를 주고, 자주 쓰는 동작을 찾기 쉽게 배치해 주세요. 고급 설정만 점진적으로 공개해 주세요.

### 혼동 주의

미니멀리즘은 필수 설명이나 기능을 없애는 뜻이 아닙니다. 버튼을 크게 만드는 것만으로 사용성 문제가 모두 해결되지는 않습니다.

근거 문서: [nng-mental], [norman-signifiers], [nng-heuristics], [nng-progressive], [nng-fitts]


## 04. 정보 구조와 탐색

**정보 구조 (IA · Information Architecture)**

정보와 기능을 어떻게 분류·명명·연결할지 정한 구조입니다.

**분류 체계 (Taxonomy)**

같은 성격의 항목을 묶고 관계를 정하는 분류 규칙입니다.

**정보 계층 (Information Hierarchy)**

상위·하위·동등한 정보의 관계와 우선순위입니다.

**명명 체계 (Labeling System)**

메뉴·페이지·항목 이름에 쓰는 일관된 언어 규칙입니다.

**전역 탐색 (Global Navigation)**

앱 전체의 주요 영역 사이를 이동하는 탐색입니다.

**지역 탐색 (Local Navigation)**

현재 영역 내부의 하위 항목 사이를 이동하는 탐색입니다.

**맥락 탐색 (Contextual Navigation)**

현재 내용과 관련된 다음 작업이나 정보를 연결하는 탐색입니다.

**브레드크럼 (Breadcrumb)**

현재 위치의 상위 계층을 경로 형태로 보여주는 요소입니다.

**활성 위치 표시 (Current Location Indicator)**

현재 열려 있는 메뉴·페이지·탭을 식별하는 표시입니다.

**뒤로 가기 (Back)**

사용자가 실제로 거쳐 온 이전 위치로 돌아갑니다.

**상위로 가기 (Up)**

방문 이력과 관계없이 현재 항목의 부모 계층으로 이동합니다.

**라우트 (Route)**

URL과 화면·동작을 연결하는 경로 규칙입니다.

**딥링크 (Deep Link)**

앱 시작 화면을 거치지 않고 특정 항목·상태로 직접 들어가는 주소입니다.

**방문 기록 (History)**

사용자가 이동한 순서를 저장하고 뒤로·앞으로 이동을 지원하는 기록입니다.

**맥락 복원 (Context Restoration)**

복귀할 때 선택·필터·탭 등 작업 맥락을 되살리는 동작입니다.

**스크롤 복원 (Scroll Restoration)**

목록이나 페이지로 돌아왔을 때 이전 읽던 위치를 복원합니다.

### Codex 요청 예시

뒤로 가기와 상위로 가기를 구분하고, 목록 복귀 시 검색어·필터·선택·스크롤을 복원해 주세요. URL 직접 진입도 검증해 주세요.

### 혼동 주의

브레드크럼은 방문 기록이 아니라 정보 계층입니다. 탭을 눌러 화면을 바꿨다고 브라우저 기록이 자동으로 올바르게 구성되지는 않습니다.

근거 문서: [nng-ia], [mdn-history], [nng-mental]


## 05. 화면 배치와 여백

**앱 셸 (App Shell)**

헤더·탐색·본문 등 여러 화면에서 반복되는 공통 외곽 구조입니다.

**뷰포트 (Viewport)**

브라우저에서 웹 콘텐츠를 표시하는 창의 영역입니다.

**컨테이너 (Container)**

관련 콘텐츠를 묶고 폭·배치 기준을 제공하는 영역입니다.

**최대 폭 (Max-width)**

화면이 넓어져도 콘텐츠가 지정된 폭 이상 퍼지지 않게 하는 제한입니다.

**그리드 (Grid)**

행·열에 따라 요소를 정렬하는 배치 체계입니다.

**열 (Column)**

그리드에서 세로로 나눈 배치 단위입니다.

**거터 (Gutter)**

그리드 열이나 행 사이의 간격입니다.

**패딩 (Padding)**

요소의 콘텐츠와 테두리 사이에 두는 안쪽 여백입니다.

**마진 (Margin)**

요소 테두리 바깥에 두는 여백입니다.

**갭 (Gap)**

그리드·플렉스 항목 사이에 지정하는 간격입니다.

**정렬 (Alignment)**

요소의 시작점·중심·기준선 등을 맞추는 방식입니다.

**분배 (Distribution)**

여러 항목을 주어진 공간 안에 나누어 배치하는 방식입니다.

**여백 (Whitespace)**

콘텐츠를 구분하고 시선을 정리하는 비어 있는 공간입니다.

**정보 밀도 (Information Density)**

같은 공간에 배치하는 정보와 조작 요소의 양입니다.

**박스 모델 (Box Model)**

콘텐츠·패딩·테두리·마진으로 요소의 공간을 계산하는 모형입니다.

**보더 박스 (Border-box)**

지정한 폭·높이에 패딩과 테두리를 포함하는 크기 계산 방식입니다.

**플렉스 배치 (Flexbox)**

한 축을 중심으로 항목의 정렬·분배·줄바꿈을 다루는 CSS 배치 방식입니다.

**CSS 그리드 (CSS Grid)**

행과 열을 함께 제어하는 CSS 배치 방식입니다.

### Codex 요청 예시

본문 최대 폭과 여백 규칙을 정하고, 패딩·갭을 일관되게 적용해 주세요. 여백을 맞추려고 빈 요소나 공백 문자를 삽입하지 마세요.

### 혼동 주의

콘텐츠 내부 공간이 문제인지, 항목 사이 공간이 문제인지부터 구분합니다. CSS Grid와 편집 가능한 데이터 그리드는 다른 개념입니다.

근거 문서: [mdn-box], [mdn-responsive], [mdn-position]


## 06. 반응형과 레이어

**반응형 설계 (Responsive Design)**

사용 가능한 화면 공간에 맞춰 배치와 크기가 적응하도록 설계합니다.

**모바일 우선 (Mobile-first)**

작은 화면에서 핵심 기능을 먼저 성립시키고 넓은 화면으로 확장합니다.

**브레이크포인트 (Breakpoint)**

배치 규칙이 바뀌는 기준 폭 등의 경계입니다.

**미디어 쿼리 (Media Query)**

화면 크기나 사용자 환경 조건에 따라 CSS를 적용합니다.

**유동형 크기 (Fluid Sizing)**

화면이나 컨테이너 크기에 따라 요소 크기가 연속적으로 달라집니다.

**리플로 (Reflow)**

화면 조건이 변할 때 내용이 읽고 조작할 수 있는 순서로 다시 배치됩니다.

**오버플로 (Overflow)**

콘텐츠가 배정된 영역을 넘는 현상과 그 처리 방식입니다.

**줄바꿈 (Wrapping)**

공간이 부족할 때 텍스트나 항목을 다음 줄로 배치합니다.

**말줄임 (Truncation · Ellipsis)**

일부 내용을 숨기고 생략 표시를 보여주는 방식입니다.

**고정 배치 (Fixed Positioning)**

보통 뷰포트를 기준으로 요소를 고정하되 조상 요소 조건의 영향을 받을 수 있습니다.

**스티키 배치 (Sticky Positioning)**

스크롤하다가 정한 경계에 닿으면 지정 범위에서 달라붙는 배치입니다.

**절대 배치 (Absolute Positioning)**

일반 흐름에서 빠져 위치 기준 상자에 따라 배치되는 방식입니다.

**레이어 순서 (Z-index)**

겹치는 요소의 앞뒤 순서를 제어하는 값입니다.

**스태킹 컨텍스트 (Stacking Context)**

요소들의 앞뒤 순서가 내부적으로 계산되는 독립된 층 묶음입니다.

**시각적 뷰포트 (Visual Viewport)**

확대나 화면 키보드 등을 반영해 사용자가 실제로 보는 영역입니다.

**가로 스크롤 영역 (Horizontal Scroll Region)**

표나 도해처럼 폭이 필요한 콘텐츠에 가로 이동을 제공하는 영역입니다.

**컨테이너 쿼리 (Container Query)**

브라우저 전체가 아니라 요소가 들어 있는 컨테이너의 조건에 따라 내부 스타일을 바꾸는 방식입니다.

### Codex 요청 예시

작은 화면에서 글자를 일괄 축소하지 말고 배치를 바꿔 주세요. 키보드가 열린 상태에서도 입력란과 저장 동작에 접근할 수 있게 해 주세요.

### 혼동 주의

z-index를 무조건 크게 주어도 다른 스태킹 컨텍스트를 넘어설 수는 없습니다. 넓은 표·캔버스의 가로 이동과 화면 전체의 불필요한 가로 넘침을 구분합니다.

근거 문서: [mdn-responsive], [mdn-position], [mdn-stack], [mdn-viewport], [mdn-container]


## 07. 글자와 시각적 표현

**타이포그래피 (Typography)**

글꼴·크기·무게·간격으로 텍스트의 구조와 읽기 경험을 설계합니다.

**서체 (Typeface)**

글자의 일관된 형태를 가진 디자인 체계입니다.

**폰트 (Font)**

실무에서는 서체나 특정 굵기·스타일의 글꼴 자원을 가리킵니다.

**글자 크기 (Font Size)**

글자를 표시하는 기준 크기입니다.

**글자 굵기 (Font Weight)**

글자의 선 두께와 시각적 강조 정도입니다.

**행간 (Line Height)**

텍스트 줄 사이의 세로 간격을 결정하는 값입니다.

**자간 (Letter Spacing)**

글자 사이의 간격입니다.

**행 길이 (Line Length)**

한 줄에 놓이는 텍스트의 길이입니다.

**글자 크기 체계 (Type Scale)**

제목·본문·보조문 등 역할에 맞춘 크기 단계입니다.

**시각적 위계 (Visual Hierarchy)**

사용자가 중요도와 읽는 순서를 알아보도록 만드는 시각적 차이입니다.

**가독성 (Readability)**

문장과 문단을 편하게 읽고 이해할 수 있는 정도입니다.

**색상 팔레트 (Color Palette)**

제품에서 사용하는 색의 집합입니다.

**의미 색상 (Semantic Color)**

성공·경고·오류·강조 같은 역할에 연결한 색입니다.

**강조색 (Accent Color)**

선택한 행동이나 정보를 두드러지게 하는 색입니다.

**모서리 반경 (Border Radius)**

요소의 모서리가 둥근 정도입니다.

**고도 표현 (Elevation)**

그림자·면 차이 등으로 요소의 층과 깊이를 드러내는 표현입니다.

**투명도 (Opacity)**

아래의 요소가 얼마나 비쳐 보이는지를 정하는 정도입니다.

**그레이디언트 (Gradient)**

색이 구간에 따라 연속적으로 변하는 표현입니다.

**글래스모피즘 (Glassmorphism)**

반투명·흐림 등으로 반투명 유리 같은 층을 표현하는 시각 양식입니다.

### Codex 요청 예시

제목·본문·보조문 위계와 행간을 먼저 정하고, 강조색과 그림자는 역할이 있는 곳에만 적용해 주세요.

### 혼동 주의

시각 양식 이름은 완성도 기준이 아닙니다. 반투명 배경에서는 뒤 콘텐츠가 달라져도 글자를 읽을 수 있는지 점검합니다.

근거 문서: [uswds-type], [uswds-tokens], [nng-glass]


## 08. 컴포넌트와 디자인 시스템

**컴포넌트 (Component)**

반복해서 사용할 수 있게 묶은 UI 단위입니다.

**기본 요소 (Primitive)**

더 큰 UI를 만드는 데 쓰는 낮은 수준의 기초 요소입니다.

**합성 (Composition)**

작은 컴포넌트를 조합해 큰 컴포넌트나 화면을 구성하는 방식입니다.

**중첩 컴포넌트 (Nested Component)**

다른 컴포넌트 안에 포함한 재사용 요소입니다.

**속성 (Props · Properties)**

컴포넌트에 전달하거나 설정하는 값과 옵션입니다.

**변형 (Variant)**

같은 컴포넌트의 크기·종류 등 의미 있는 선택 가능한 형태입니다.

**슬롯 (Slot)**

컴포넌트의 정해진 위치에 다른 콘텐츠를 넣도록 마련한 자리입니다.

**컴포넌트 라이브러리 (Component Library)**

공통으로 사용하는 컴포넌트의 집합입니다.

**UI 키트 (UI Kit)**

화면을 구성하는 시각 요소와 템플릿 등의 모음입니다.

**스타일 가이드 (Style Guide)**

색·글자·여백·표현 규칙 등을 설명한 안내서입니다.

**디자인 시스템 (Design System)**

요소뿐 아니라 사용 규칙·원칙·구현·관리 기준을 함께 묶은 체계입니다.

**패턴 (Pattern)**

특정 사용자 문제를 해결하기 위해 요소와 동작을 조합하는 반복 가능한 해법입니다.

**디자인 토큰 (Design Token)**

색·여백·글자 크기 같은 디자인 값을 이름으로 관리하는 단위입니다.

**기초 토큰 (Primitive Token)**

색 단계나 간격 단계 등 원재료에 가까운 값입니다.

**의미 토큰 (Semantic Token)**

text.primary나 action.danger처럼 값에 용도를 부여한 이름입니다.

**단일 기준 (Single Source of Truth)**

같은 정보나 규칙의 권위 있는 기준을 한곳에 두는 원칙입니다.

**아토믹 디자인 (Atomic Design)**

작은 UI 요소와 조합된 화면을 함께 바라보며 시스템을 구성하는 방법론입니다.

**원자 (Atom)**

아토믹 디자인에서 버튼·레이블 등 기초적인 기능 요소입니다.

**분자 (Molecule)**

여러 기초 요소를 묶어 검색 입력 묶음처럼 하나의 작은 기능을 수행하는 단위입니다.

**유기체 (Organism)**

여러 요소를 조합해 헤더처럼 독립적인 화면 구역을 이루는 단위입니다.

**템플릿 (Template)**

컴포넌트들을 배치해 페이지 수준의 내용 구조를 정한 틀입니다.

**실제 콘텐츠 화면 (Page in Atomic Design)**

템플릿에 실제 대표 콘텐츠를 넣어 다양한 조건을 확인하는 구체적인 화면입니다.

### Codex 요청 예시

반복되는 화면 요소를 공통 컴포넌트로 묶고, 색·간격·모서리는 토큰으로 관리해 주세요. 복잡한 거대 컴포넌트 하나로 모든 경우를 억지로 처리하지 마세요.

### 혼동 주의

컴포넌트 모음만 있다고 디자인 시스템이 완성된 것은 아닙니다. 디자인 토큰, 컴포넌트 속성, 상태, 테마는 서로 다른 층위입니다. 아토믹 디자인은 다섯 단계를 차례대로 완성해야 하는 강제 절차가 아닙니다.

근거 문서: [figma-variants], [figma-props], [uswds-tokens], [gov-patterns], [gov-components], [figma-components], [atomic-design]


## 09. 피그마 파일과 컴포넌트 정리

**파일 (Figma File)**

여러 페이지와 디자인 자원을 담는 작업 문서입니다.

**페이지 (Page)**

파일 안에서 작업 영역을 큰 단위로 나누는 구획입니다.

**섹션 (Section)**

캔버스의 관련 작업들을 의미 단위로 묶어 표시하는 영역입니다.

**프레임 (Frame)**

크기·배치 기준을 가진 디자인 컨테이너입니다.

**그룹 (Group)**

관련 레이어를 함께 다루도록 묶은 단위입니다.

**레이어 (Layer)**

텍스트·도형·프레임 등 디자인을 구성하는 개별 객체입니다.

**에셋 (Asset)**

재사용할 수 있는 컴포넌트나 디자인 자원입니다.

**메인 컴포넌트 (Main Component)**

인스턴스가 참조하는 원본 컴포넌트입니다.

**인스턴스 (Instance)**

원본과 연결되어 사용되는 개별 컴포넌트입니다.

**오버라이드 (Override)**

원본 연결을 유지하면서 특정 인스턴스의 허용된 값을 바꾼 상태입니다.

**연결 해제 (Detach Instance)**

인스턴스를 원본 컴포넌트와 분리하는 작업입니다.

**컴포넌트 세트 (Component Set)**

관련된 여러 변형을 한 컴포넌트군으로 묶은 집합입니다.

**컴포넌트 속성 (Component Properties)**

텍스트·가시성·교체 대상·변형·슬롯 등 편집 가능한 부분을 노출하는 설정입니다.

**인스턴스 교체 (Instance Swap)**

컴포넌트 안의 재사용 요소를 다른 인스턴스로 바꾸는 방식입니다.

**슬래시 네이밍 (Slash Naming)**

Button/Primary처럼 이름의 슬래시로 자원 계층을 표현하는 방식입니다.

**라이브러리 게시 (Library Publishing)**

다른 파일에서 사용할 수 있도록 재사용 자원을 공유·배포하는 절차입니다.

### Codex 요청 예시

반복 요소는 메인 컴포넌트와 인스턴스로 관리하고, 의미에 맞는 컴포넌트 세트와 속성을 설계해 주세요. 슬래시 이름과 페이지·프레임 구분을 일관되게 조합해 주세요.

### 혼동 주의

같이 생겼다는 이유로 서로 다른 의미의 모든 요소를 변형 하나에 묶지 않습니다. 공유 라이브러리의 변경과 소비 파일의 업데이트 수락, 코드의 수정은 별도입니다.

근거 문서: [figma-guide], [figma-variants], [figma-props], [figma-components]


## 10. 피그마 자동 배치와 변수

**오토 레이아웃 (Auto Layout)**

내용 크기와 정렬·간격 규칙에 따라 자식 요소를 자동 배치하는 기능입니다.

**내용에 맞춤 (Hug Contents)**

자식 콘텐츠에 맞춰 부모의 크기를 잡는 크기 규칙입니다.

**컨테이너 채우기 (Fill Container)**

부모에서 사용할 수 있는 공간을 채우는 크기 규칙입니다.

**고정 크기 (Fixed Size)**

지정한 폭이나 높이를 유지하는 크기 규칙입니다.

**배치 방향 (Layout Direction)**

자식 요소를 가로·세로 등 어떤 방향으로 쌓는지 정하는 설정입니다.

**자동 줄바꿈 (Wrap)**

한 줄의 공간이 부족하면 항목을 다음 줄로 배치하는 설정입니다.

**제약 조건 (Constraints)**

부모 크기가 바뀔 때 위치나 크기를 어떤 기준으로 유지할지 정하는 규칙입니다.

**스타일 (Style)**

색·텍스트·효과 등 재사용할 표현 속성의 묶음입니다.

**변수 (Variable)**

여러 곳에서 참조할 수 있도록 이름을 붙인 값입니다.

**변수 컬렉션 (Variable Collection)**

관련 변수를 한 묶음으로 관리하는 집합입니다.

**변수 모드 (Variable Mode)**

같은 변수 집합의 값을 테마 등 맥락별로 달리 제공하는 방식입니다.

**별칭 (Alias)**

한 변수가 다른 변수를 참조하도록 하는 연결입니다.

**테마 (Theme)**

색·표현 값 등을 맥락에 맞게 일관되게 바꾸는 체계입니다.

**개발 전달 (Design Handoff)**

디자인 의도·규칙·자원·상태·행동을 구현자가 재현할 수 있게 전달하는 과정입니다.

**구현 대응표 (Design-to-code Mapping)**

디자인 컴포넌트·속성·토큰이 코드의 무엇과 연결되는지 기록한 표입니다.

### Codex 요청 예시

길이가 다른 한글과 긴 제목을 넣어도 배치가 유지되도록 Hug·Fill·Fixed를 구분하고, 디자인 속성과 코드 속성의 대응을 문서화해 주세요.

### 혼동 주의

Figma Auto Layout과 CSS 배치는 대응을 설계해야 합니다. 이름만 같은 컴포넌트가 있다고 디자인과 구현이 자동으로 동기화되는 것은 아닙니다.

근거 문서: [figma-layout], [figma-variables], [figma-guide]


## 11. 버튼과 선택 입력

**버튼 (Button)**

저장·열기 등 동작을 실행하는 요소입니다.

**링크 (Link)**

다른 위치나 자원으로 이동하는 요소입니다.

**행동 유도 요소 (CTA · Call to Action)**

사용자가 하기를 바라는 핵심 행동을 안내하는 요소입니다.

**주요 버튼 (Primary Button)**

해당 맥락의 핵심 행동을 가장 뚜렷하게 나타내는 버튼입니다.

**보조 버튼 (Secondary Button)**

주요 행동과 구분되는 보조 선택을 제공하는 버튼입니다.

**텍스트 버튼 (Text Button)**

배경 강조를 줄이고 글자 중심으로 표현한 버튼입니다.

**파괴적 동작 (Destructive Action)**

삭제 등 되돌리기 어렵거나 중요한 손실을 일으킬 수 있는 행동입니다.

**아이콘 버튼 (Icon Button)**

주로 아이콘으로 행동을 표현하는 버튼입니다. 접근 가능한 이름도 필요합니다.

**분할 버튼 (Split Button)**

기본 행동과 관련 추가 행동 목록을 나누어 제공하는 버튼입니다.

**체크박스 (Checkbox)**

항목의 선택 여부를 켜고 끄는 입력입니다. 여러 항목을 독립 선택할 수 있습니다.

**라디오 버튼 (Radio Button)**

한 묶음에서 하나를 고르는 선택 입력입니다.

**스위치 (Switch)**

명명된 설정의 켜짐·꺼짐 상태를 바꾸는 입력입니다.

**토글 버튼 (Toggle Button)**

눌림 여부로 특정 옵션의 활성 상태를 나타내는 버튼입니다.

**셀렉트 (Select)**

정해진 선택지 중 값을 고르는 입력입니다.

**콤보박스 (Combobox)**

값 선택을 위한 팝업을 결합한 입력 패턴입니다. 편집형과 선택 전용형이 있습니다.

**다중 선택 (Multi-select)**

한 필드에서 여러 값을 선택하는 입력 방식입니다.

**슬라이더 (Slider)**

범위 안의 값을 위치 이동으로 조절하는 입력입니다.

**숫자 증감 입력 (Spinbutton)**

숫자 입력과 증가·감소 조작을 결합한 입력입니다.

**날짜 선택기 (Date Picker)**

날짜를 입력하거나 달력에서 선택하는 요소입니다.

### Codex 요청 예시

이동에는 링크를, 실행에는 버튼을 쓰고, 여러 값 선택·단일 값 선택·켜짐 설정을 서로 맞는 입력 요소로 구현해 주세요.

### 혼동 주의

드롭다운이라는 말만으로 구현하지 않습니다. 행동 메뉴인지 값 선택인지, 자유 입력을 허용하는지부터 구분합니다.

근거 문서: [wai-patterns], [wai-combo], [gov-components]


## 12. 탐색과 콘텐츠 컴포넌트

**헤더 (Header)**

페이지나 앱 상단의 식별·탐색 영역입니다.

**사이드바 (Sidebar)**

주요 콘텐츠 옆에서 탐색이나 보조 정보를 제공하는 영역입니다.

**탭 (Tabs)**

같은 맥락의 패널 중 하나를 선택해 보여주는 인터페이스입니다.

**아코디언 (Accordion)**

제목을 눌러 각 항목의 내용을 펼치거나 접는 구조입니다.

**디스클로저 (Disclosure)**

관련된 추가 내용을 열고 닫는 단순한 펼침 패턴입니다.

**툴바 (Toolbar)**

관련 작업 버튼을 묶어 제공하는 영역입니다.

**커맨드 팔레트 (Command Palette)**

명령을 검색하고 실행하는 입력 중심 인터페이스입니다.

**카드 (Card)**

한 대상이나 주제를 묶어 보여주는 콘텐츠 단위입니다.

**목록 (List)**

항목을 순서 있게 또는 순서 없이 나열한 구조입니다.

**데이터 표 (Data Table)**

동일 속성을 가진 여러 항목을 행과 열로 비교하는 구조입니다.

**트리 뷰 (Tree View)**

부모·자식 관계의 계층을 펼치고 접으며 탐색하는 요소입니다.

**배지 (Badge)**

숫자·상태 등 짧은 보조 정보를 나타내는 표시입니다.

**태그 (Tag)**

분류나 속성을 나타내는 짧은 표식입니다.

**칩 (Chip)**

짧은 정보·선택·입력값 등을 압축해 표시하는 작은 UI 단위입니다.

**아바타 (Avatar)**

사용자나 대상을 대표하는 이미지 또는 문자 표시입니다.

**구분선 (Divider)**

관련 정보 집합의 경계를 표시하는 선입니다.

**페이지 이동 (Pagination)**

데이터를 여러 페이지로 나누고 페이지 사이를 이동하는 방식입니다.

**캐러셀 (Carousel)**

동일 영역에서 여러 슬라이드나 콘텐츠를 순환해서 보여주는 요소입니다.

### Codex 요청 예시

부모·자식 관계는 트리 뷰로, 같은 대상을 보는 여러 관점은 탭으로 구분해 주세요. 화면 역할과 무관하게 카드만 반복하지 마세요.

### 혼동 주의

Badge·Tag·Chip 같은 이름의 세부 의미는 디자인 시스템마다 다릅니다. 선택·삭제·이동 같은 실제 행동을 함께 명세합니다.

근거 문서: [wai-patterns], [gov-components], [carbon-table]


## 13. 오버레이와 알림

**다이얼로그 (Dialog)**

별도의 대화 영역에서 정보를 제공하거나 입력·확인을 받는 UI입니다.

**모달 (Modal)**

열린 동안 바깥 영역과의 상호작용을 막는 방식입니다.

**비모달 (Non-modal)**

별도 패널이 있어도 바깥 작업을 계속할 수 있는 방식입니다.

**팝오버 (Popover)**

버튼이나 대상과 연결해 주변에 띄우는 보조 콘텐츠 영역입니다.

**툴팁 (Tooltip)**

요소의 뜻을 짧게 설명하는 보조 안내입니다.

**컨텍스트 메뉴 (Context Menu)**

선택한 대상이나 현재 맥락에서 가능한 행동을 보여주는 메뉴입니다.

**드로어 (Drawer)**

화면 가장자리에서 열리는 패널입니다. 모달 여부는 별도 결정합니다.

**바텀 시트 (Bottom Sheet)**

화면 아래쪽에서 올라오는 패널입니다.

**백드롭 (Backdrop)**

오버레이 뒤 배경을 구분하거나 흐리게 표현하는 층입니다.

**토스트 (Toast)**

화면을 크게 가리지 않고 짧게 나타나는 알림입니다.

**스낵바 (Snackbar)**

일부 디자인 시스템에서 짧은 결과 알림과 관련 행동을 제공하는 요소입니다.

**배너 (Banner)**

특정 영역이나 서비스 전체에 적용되는 안내를 띠 형태로 보여주는 요소입니다.

**인라인 알림 (Inline Notification)**

문제나 작업과 관련된 위치에 함께 표시하는 알림입니다.

**알림 대화상자 (Alert Dialog)**

중요한 상황을 알리고 응답을 받는 대화상자입니다.

**상태 메시지 (Status Message)**

처리 중·완료·실패 등 상태를 사용자에게 알려주는 메시지입니다.

### Codex 요청 예시

짧은 참고 설명은 툴팁으로, 간단한 맥락 작업은 팝오버로 처리해 주세요. 모달이 필요하면 포커스 진입·이탈·복귀와 닫기 동작을 구현해 주세요.

### 혼동 주의

화면 가운데 뜬다고 모두 모달은 아닙니다. 저장 실패처럼 사용자가 대응해야 하는 내용은 사라지는 토스트에만 남기지 않습니다.

근거 문서: [wai-dialog], [wai-patterns], [carbon-notifications]


## 14. 입력 폼과 한글 입력

**폼 (Form)**

관련된 입력값을 수집하고 제출하거나 저장하는 구조입니다.

**필드 (Field)**

하나의 값이나 선택을 받는 입력 단위입니다.

**레이블 (Label)**

이 입력이 무엇을 뜻하는지 지속적으로 알려주는 이름입니다.

**플레이스홀더 (Placeholder)**

비어 있는 입력란 내부에 표시하는 예시나 힌트입니다.

**도움말 (Helper Text)**

입력 기준·예시·주의를 설명하는 보조 문구입니다.

**기본값 (Default Value)**

사용자가 따로 선택하지 않았을 때 처음 제시하는 값입니다.

**미리 채우기 (Prefill)**

이미 알고 있는 정보를 입력란에 넣어 반복 입력을 줄이는 방식입니다.

**자동완성 (Autocomplete)**

입력 중 기존 정보나 후보를 제안·완성하는 기능입니다.

**입력 형식 안내 (Input Format Hint)**

날짜·전화번호 등 기대하는 값의 형식을 알려주는 안내입니다.

**입력 마스크 (Input Mask)**

값을 입력할 때 정해진 모양으로 안내하거나 형식을 맞추는 처리입니다.

**유효성 검사 (Validation)**

값이 요구 조건과 형식을 만족하는지 확인하는 과정입니다.

**인라인 검증 (Inline Validation)**

각 입력과 가까운 곳에서 결과와 수정 방법을 안내하는 방식입니다.

**오류 요약 (Error Summary)**

여러 입력 오류를 모아 위치와 수정 과제를 알려주는 안내입니다.

**필수 입력 (Required Field)**

과업 완료에 반드시 필요한 값입니다.

**변경 있음 (Dirty)**

초기 또는 저장된 기준에서 값이 달라진 상태입니다.

**상호작용 이력 (Touched)**

사용자가 해당 입력과 상호작용한 상태를 추적하는 표지입니다.

**미변경 (Pristine)**

기준 상태 이후 입력이 변경되지 않은 상태입니다.

**캐럿 (Caret)**

텍스트를 입력하거나 편집하는 현재 커서 위치입니다.

**조합 입력 (IME Composition)**

한글 등에서 여러 키 입력을 조합해 글자를 확정하는 입력 과정입니다.

**조합 중 상태 (isComposing)**

키 이벤트가 조합 입력 중에 발생했는지를 나타내는 속성입니다.

### Codex 요청 예시

기존 과목·단원 값은 수정 가능하게 미리 채우고, 한글 조합 중 Enter가 제출로 처리되지 않게 해 주세요. 검증 후에도 입력값과 커서 위치를 보존해 주세요.

### 혼동 주의

플레이스홀더는 레이블을 대체하지 않습니다. 프레임워크마다 touched 같은 상태 정의가 조금씩 다르므로 검사 시점을 행동으로 명시합니다.

근거 문서: [wai-validation], [mdn-ime], [react-state]


## 15. 상태 설계와 상태표

**기본 상태 (Default State)**

아직 특별한 상호작용이나 처리가 없는 평상시 상태입니다.

**호버 (Hover)**

포인터가 요소 위에 놓인 상태입니다.

**누름 상태 (Pressed State)**

버튼 등을 누르고 있는 상호작용 상태입니다.

**포커스 (Focus)**

현재 키보드 입력이나 조작을 받을 대상의 상태입니다.

**선택됨 (Selected)**

항목이 선택된 상태입니다. 포커스와 다를 수 있습니다.

**비활성 (Disabled)**

현재 조작할 수 없도록 제한된 상태입니다.

**읽기 전용 (Read-only)**

내용을 읽을 수 있지만 수정하지 못하는 상태입니다.

**로딩 (Loading)**

필요한 처리나 데이터를 기다리는 상태입니다.

**스켈레톤 (Skeleton)**

로드될 콘텐츠의 대략적인 배치를 먼저 보여주는 자리 표시입니다.

**스피너 (Spinner)**

처리가 진행 중임을 반복 움직임으로 표시하는 요소입니다.

**진행 표시 (Progress Indicator)**

진행 중임이나 알려진 완료 비율을 나타내는 요소입니다.

**빈 상태 (Empty State)**

아직 표시할 데이터가 없는 상황을 설명하고 다음 행동을 안내하는 화면입니다.

**검색 결과 없음 (No Results)**

현재 검색·필터 조건에 맞는 결과가 없는 상태입니다.

**부분 성공 (Partial Success)**

여러 처리 중 일부만 성공한 상태입니다.

**오류 상태 (Error State)**

처리가 실패했거나 정상 진행할 수 없는 상태입니다.

**오프라인 (Offline)**

필요한 네트워크 연결을 사용할 수 없는 상태입니다.

**오래된 데이터 (Stale Data)**

현재 서버 등의 최신 상태와 달라졌을 수 있는 데이터입니다.

**상태표 (State Matrix)**

요소나 화면이 각 조건에서 어떻게 보이고 동작하는지 정리한 표입니다.

**상태 전이 (State Transition)**

행동이나 사건에 따라 한 상태에서 다른 상태로 바뀌는 과정입니다.

### Codex 요청 예시

주요 화면에 정상·로딩·빈 데이터·검색 결과 없음·오류·오프라인 상태표를 만들고, 각 상태의 안내와 가능한 행동을 구현해 주세요.

### 혼동 주의

Disabled와 read-only를 같은 모양·동작으로 처리하지 않습니다. 데이터 없음, 권한 없음, 불러오기 실패도 구분합니다.

근거 문서: [wai-patterns], [carbon-empty], [carbon-notifications], [react-state]


## 16. 저장과 복구

**화면 상태 (UI State)**

현재 탭·열린 패널·선택 등 화면의 조작 상태입니다.

**도메인 데이터 (Domain Data)**

과목·공부 기록 등 서비스가 실제로 관리하는 핵심 정보입니다.

**로컬 상태 (Local State)**

특정 화면이나 컴포넌트가 자체적으로 유지하는 상태입니다.

**서버 상태 (Server State)**

서버에서 관리하는 데이터를 받아 표시하고 갱신하는 상태입니다.

**초안 (Draft)**

작성 중이어서 아직 최종 확정하지 않은 내용입니다.

**자동 저장 (Autosave)**

명시적인 저장 버튼 조작 없이 변경 내용을 저장하는 방식입니다.

**영속성 (Persistence)**

화면 종료·새로고침 이후에도 정한 저장소에 데이터가 남는 성질입니다.

**동기화 (Synchronization)**

장치·화면·서버 사이의 상태나 데이터를 맞추는 과정입니다.

**캐시 (Cache)**

다시 쓰기 위해 저장한 데이터의 사본입니다.

**브라우저 저장소 (Browser Storage)**

웹앱이 기기 브라우저 안에 데이터를 보관하는 저장 영역입니다.

**저장 확인 (Save Confirmation)**

정의된 저장 대상이 처리를 완료했음을 확인하는 단계입니다.

**미저장 변경 (Unsaved Changes)**

아직 기준 저장소에 반영되지 않은 변경입니다.

**이탈 보호 (Navigation Guard)**

미저장 변경 손실 등을 막기 위해 이탈을 안내·제어하는 처리입니다.

**충돌 (Conflict)**

서로 다른 변경이 같은 데이터에 적용되어 조정이 필요한 상태입니다.

**실행 취소 (Undo)**

직전 작업의 효과를 되돌리는 기능입니다.

**다시 실행 (Redo)**

실행 취소한 작업을 다시 적용하는 기능입니다.

**소프트 삭제 (Soft Delete)**

즉시 완전 제거하지 않고 삭제 표시나 휴지통 상태로 옮기는 방식입니다.

**복구 (Recovery)**

실패·중단·실수 이후 데이터나 작업을 다시 이어갈 수 있게 하는 처리입니다.

### Codex 요청 예시

저장 중·저장 완료·저장 실패를 실제 저장 응답에 맞춰 표시하고, 실패해도 초안을 유지해 주세요. 새로고침·재접속 후 복원 범위도 명시해 주세요.

### 혼동 주의

컴포넌트 상태 유지, 브라우저 저장, 서버 저장, 기기 간 동기화, 백업은 서로 다릅니다. 브라우저에 저장했다는 이유만으로 영구 보관이 보장되지는 않습니다.

근거 문서: [react-state], [mdn-storage], [react-optimistic], [carbon-notifications]


## 17. 비동기 동작과 중복 방지

**비동기 처리 (Asynchronous Operation)**

응답을 기다리는 동안 다른 작업을 계속할 수 있는 처리입니다.

**낙관적 업데이트 (Optimistic Update)**

서버 성공을 가정해 화면을 먼저 바꾸고 결과에 맞춰 확정·복구하는 방식입니다.

**응답 후 업데이트 (Pessimistic Update)**

서버 등의 성공 응답을 확인한 뒤 확정 결과를 화면에 반영하는 방식입니다.

**롤백 (Rollback)**

실패한 변경의 영향을 이전 상태로 되돌리는 처리입니다.

**디바운스 (Debounce)**

연속 이벤트가 잠시 멈췄을 때 묶어서 처리하는 방식입니다.

**스로틀 (Throttle)**

연속 이벤트 처리 횟수를 일정 빈도로 제한하는 방식입니다.

**경쟁 상태 (Race Condition)**

처리 순서나 완료 시점 차이 때문에 잘못된 결과가 생길 수 있는 상황입니다.

**오래된 응답 (Stale Response)**

최신 사용자 선택이나 요청 의도에 더 이상 맞지 않는 이전 응답입니다.

**요청 취소 (Request Cancellation)**

더 필요 없는 네트워크 요청 등의 작업을 중단하는 처리입니다.

**타임아웃 (Timeout)**

정한 시간 안에 응답이 없을 때 대기를 끝내는 조건입니다.

**재시도 (Retry)**

실패한 작업을 다시 시도하는 처리입니다.

**멱등성 (Idempotency)**

같은 의도의 요청을 반복해도 서버의 의도된 효과가 한 번과 같도록 하는 성질입니다.

**중복 제출 방지 (Duplicate Submission Prevention)**

연속 클릭·재시도로 같은 기록이 중복 생성되지 않도록 하는 처리입니다.

**요청 식별자 (Request Identifier)**

응답이 어느 요청·대상에 속하는지 추적하는 값입니다.

### Codex 요청 예시

검색 요청만 디바운스하고 글자 입력은 즉시 반영해 주세요. 과목을 빠르게 바꿔도 이전 응답이 최신 선택을 덮어쓰지 않게 하며, 재시도로 기록이 중복되지 않게 해 주세요.

### 혼동 주의

요청 취소는 서버에서 이미 완료된 변경을 되돌리는 기능이 아닙니다. 저장 버튼을 비활성화하는 것만으로 서버 중복 처리까지 방지할 수는 없습니다.

근거 문서: [react-optimistic], [mdn-debounce], [mdn-throttle], [mdn-abort], [mdn-idempotent], [react-effect]


## 18. 표·검색·대량 작업

**정렬 (Sorting)**

날짜·이름 등 기준에 따라 결과의 순서를 바꾸는 기능입니다.

**필터 (Filtering)**

조건에 맞는 항목만 표시하는 기능입니다.

**다중 기준 필터 (Faceted Filtering)**

분류·상태·기간처럼 여러 속성의 조건을 조합하는 방식입니다.

**검색 범위 (Search Scope)**

검색이 현재 단원·과목·전체 중 어디에 적용되는지 정한 범위입니다.

**활성 필터 (Active Filters)**

현재 결과에 적용된 조건을 눈에 보이게 표시한 내용입니다.

**필터 초기화 (Clear Filters)**

검색·필터 조건을 기준 상태로 되돌리는 기능입니다.

**저장된 보기 (Saved View)**

필터·정렬·열 구성 등을 이름 붙여 다시 사용하는 설정입니다.

**행 선택 (Row Selection)**

여러 항목 중 작업할 행을 지정하는 기능입니다.

**일괄 작업 (Bulk Action · Batch Action)**

선택한 여러 항목에 한 번에 행동을 적용하는 기능입니다.

**행 확장 (Expandable Row)**

목록을 떠나지 않고 행의 추가 정보를 펼쳐 보는 기능입니다.

**인라인 편집 (Inline Editing)**

별도 화면으로 이동하지 않고 현재 값이 있는 자리에서 수정합니다.

**데이터 그리드 (Data Grid)**

표 구조에서 선택·편집·키보드 이동 등 풍부한 상호작용을 제공하는 요소입니다.

**무한 스크롤 (Infinite Scroll)**

끝에 가까워질 때 다음 데이터를 계속 추가하는 방식입니다.

**가상화 (Virtualization)**

긴 목록 중 화면 주변에 필요한 항목 위주로 렌더링하는 방식입니다.

### Codex 요청 예시

검색 범위와 활성 필터를 항상 알 수 있게 하고, 일괄 삭제는 대상 개수와 복구 가능성을 알려 주세요. 목록 방식은 복귀·키보드 탐색까지 고려해 정해 주세요.

### 혼동 주의

가상화와 무한 스크롤은 다릅니다. 가상화는 렌더링 범위, 무한 스크롤은 데이터를 이어 보여주는 탐색 방식입니다.

근거 문서: [carbon-table], [nng-ia], [gov-patterns]


## 19. 작은 상호작용과 움직임

**트리거 (Trigger)**

상호작용이나 상태 변화를 시작하게 하는 사용자 행동 또는 시스템 사건입니다.

**마이크로인터랙션 (Microinteraction)**

토글 변경이나 저장 피드백처럼 작은 목표 하나를 수행하는 상호작용입니다.

**직접 조작 (Direct Manipulation)**

대상을 가리키거나 이동시키며 그 대상 자체를 조작하는 방식입니다.

**드래그 앤드 드롭 (Drag and Drop)**

대상을 끌어 다른 위치나 영역에 놓는 조작입니다.

**드래그 핸들 (Drag Handle)**

끌어서 이동할 수 있음을 알리고 조작 지점을 제공하는 부분입니다.

**드롭 대상 (Drop Target)**

끌어온 항목을 놓을 수 있는 영역입니다.

**히트 영역 (Hit Area · Hit Target)**

마우스 클릭이나 터치로 실제 반응하는 영역입니다.

**키보드 단축키 (Keyboard Shortcut)**

정한 키 조합으로 행동을 빠르게 실행하는 방식입니다.

**전환 (Transition)**

한 상태나 배치에서 다른 상태로 바뀌는 변화입니다.

**지속 시간 (Duration)**

움직임이나 전환이 진행되는 시간입니다.

**이징 (Easing)**

움직임의 시간에 따른 속도 변화를 정하는 방식입니다.

**모션 감소 (Reduced Motion)**

움직임에 민감한 사용자의 선호에 따라 비필수 모션을 줄이는 대응입니다.

### Codex 요청 예시

상태 변화가 이해될 정도의 짧은 피드백만 넣고, 움직임 감소 설정을 존중해 주세요. 드래그와 별도로 이동 버튼 같은 대체 조작을 제공해 주세요.

### 혼동 주의

애니메이션은 기다림을 숨기거나 실패를 성공처럼 꾸미기 위한 장치가 아닙니다.

근거 문서: [nng-micro], [mdn-motion], [wai-patterns]


## 20. 접근성과 키보드

**접근성 (Accessibility · A11y)**

다양한 능력·기기·입력 방식의 사용자가 콘텐츠와 기능에 접근하도록 하는 성질입니다.

**의미 있는 HTML (Semantic HTML)**

button·label·nav처럼 요소의 역할에 맞는 HTML을 사용하는 방식입니다.

**접근 가능한 이름 (Accessible Name)**

보조기술이 요소를 식별할 때 읽는 이름입니다.

**ARIA (Accessible Rich Internet Applications)**

보조기술에 역할·상태 등을 전달하는 속성 체계입니다.

**스크린 리더 (Screen Reader)**

화면의 의미와 구조를 음성 등으로 전달하는 보조기술입니다.

**키보드 접근성 (Keyboard Accessibility)**

포인터 없이도 키보드로 필요한 기능을 수행할 수 있는 성질입니다.

**탭 순서 (Tab Order)**

Tab 키 등으로 포커스가 이동하는 순서입니다.

**포커스 표시 (Focus Indicator)**

현재 조작 대상의 위치를 눈에 보이게 나타내는 표시입니다.

**포커스 트랩 (Focus Trap)**

모달이 열린 동안 키보드 포커스를 내부에 유지하는 처리입니다.

**포커스 복귀 (Focus Restoration)**

대화상자 등을 닫은 뒤 원래 버튼이나 논리적인 다음 대상으로 포커스를 돌립니다.

**라이브 영역 (Live Region)**

동적으로 바뀌는 알림을 보조기술이 알 수 있도록 지정한 영역입니다.

**대비 (Contrast)**

글자·아이콘·경계 등이 주변과 시각적으로 구분되는 정도입니다.

**색 이외 단서 (Non-color Cue)**

상태를 색뿐 아니라 문구·아이콘·형태 등으로 함께 전달하는 표시입니다.

**대상 크기 (Target Size)**

버튼 등 포인터 입력 대상의 실제 조작 가능한 크기입니다.

**확대 대응 (Zoom Support)**

화면이나 글자를 확대해도 내용과 기능을 사용할 수 있도록 하는 대응입니다.

**드래그 대안 (Alternative to Dragging)**

끌기 없이 클릭·탭 등으로 같은 결과를 얻도록 제공하는 방식입니다.

### Codex 요청 예시

실제 버튼·레이블을 사용하고, 키보드 포커스와 스크린 리더 이름을 검증해 주세요. 모달의 포커스 이동·복귀와 드래그 대체 조작을 포함해 주세요.

### 혼동 주의

WCAG 2.2 AA의 대상 크기 기준은 24×24 CSS px 또는 충분한 간격 등 예외 조건을 포함합니다. 44×44 CSS px는 강화된 AAA 기준이며 예외가 있습니다. 일반 텍스트 4.5:1, 큰 텍스트 3:1 등의 대비 기준도 적용 대상과 예외를 구분합니다. 드래그의 비끌기 포인터 대안과 키보드 지원은 각각 점검합니다.

근거 문서: [wcag], [wai-dialog], [wai-patterns], [wai-validation]


## 21. 체감 속도와 렌더링

**체감 성능 (Perceived Performance)**

사용자가 실제로 느끼는 반응성과 진행 속도입니다.

**지연 (Latency)**

행동이나 요청 후 반응이 나타나기까지의 시간입니다.

**렌더링 (Rendering)**

데이터와 상태를 바탕으로 화면을 계산하고 표시하는 과정입니다.

**리렌더링 (Re-rendering)**

상태나 속성이 바뀌어 화면 구성을 다시 계산하는 과정입니다.

**불필요한 재조회 (Unnecessary Refetch)**

변경과 관계없는 데이터까지 다시 요청하는 처리입니다.

**레이아웃 이동 (Layout Shift)**

요소의 위치나 크기가 바뀌어 화면 배치가 이동하는 현상입니다.

**끊김 (Jank)**

스크롤·입력·애니메이션이 고르지 못하고 튀거나 끊기는 현상입니다.

**주요 콘텐츠 표시 시간 (LCP · Largest Contentful Paint)**

보이는 영역의 주요 큰 콘텐츠가 표시되는 시점을 다루는 성능 지표입니다.

**상호작용 반응 지연 (INP · Interaction to Next Paint)**

사용자 상호작용 후 다음 화면 갱신까지의 지연을 다루는 지표입니다.

**누적 배치 이동 (CLS · Cumulative Layout Shift)**

예상치 못한 레이아웃 이동의 누적 정도를 나타내는 지표입니다.

**성능 예산 (Performance Budget)**

허용할 응답 시간이나 자원 크기 등에 설정한 관리 기준입니다.

### Codex 요청 예시

입력 중 전체 데이터 재조회와 무거운 집계를 분리해 주세요. 저장 직후 포커스·스크롤이 튀는지 측정하고, 체감 개선과 실제 성능 지표를 함께 확인해 주세요.

### 혼동 주의

리렌더링 자체가 오류는 아닙니다. 과도한 계산·불필요한 재마운트·잘못된 상태 초기화 중 무엇이 문제인지 구분합니다.

근거 문서: [web-vitals], [react-state], [react-effect], [mdn-debounce]


## 22. 안내 문구와 콘텐츠

**UX 라이팅 (UX Writing)**

사용자가 다음 행동과 결과를 이해하도록 제품 안의 문구를 설계합니다.

**마이크로카피 (Microcopy)**

버튼·레이블·도움말·상태 메시지처럼 짧고 기능적인 문구입니다.

**보이스 (Voice)**

제품 전반에서 유지하는 말투와 성격입니다.

**톤 (Tone)**

상황에 맞춰 달리하는 표현의 온도와 태도입니다.

**행동 중심 레이블 (Action-oriented Label)**

확인처럼 추상적으로 쓰지 않고 저장·기록 삭제 등 행동을 드러내는 이름입니다.

**맥락 도움말 (Contextual Help)**

사용자가 막힐 수 있는 지점 가까이에 제공하는 설명입니다.

**온보딩 (Onboarding)**

처음 온 사용자가 핵심 가치를 이해하고 첫 작업을 시작하도록 돕는 과정입니다.

**빈 상태 안내 (Empty-state Guidance)**

데이터가 없는 이유와 첫 행동을 연결해 설명하는 안내입니다.

**실행 가능한 오류 안내 (Actionable Error Message)**

무엇이 실패했고 무엇을 하면 되는지 알려주는 오류 문구입니다.

**용어 일관성 (Terminology Consistency)**

같은 대상과 행동을 제품 전반에서 같은 이름으로 부르는 원칙입니다.

**파괴적 행동 확인 (Destructive Confirmation)**

삭제 대상·범위·결과를 확인하고 의도치 않은 손실을 막는 안내입니다.

### Codex 요청 예시

버튼은 확인보다 실제 동작 이름을 쓰고, 저장 실패에는 원인 범위·초안 보존 여부·재시도 방법을 알려 주세요. 과목·단원·기록 이름을 모든 화면에서 통일해 주세요.

### 혼동 주의

작성 완료, 로컬 저장, 서버 저장, 외부 전송 완료를 같은 완료 문구로 표시하지 않습니다.

근거 문서: [nng-heuristics], [wai-validation], [carbon-empty], [carbon-notifications]


## 23. 캔버스와 트리 편집

**노드 (Node)**

캔버스에서 하나의 항목이나 개념을 나타내는 객체입니다.

**엣지 (Edge)**

노드 사이의 연결이나 관계를 나타내는 선입니다.

**포트 (Port · Handle)**

노드에서 연결이 붙거나 새 연결을 시작하는 지점입니다.

**부모·자식 관계 (Parent–child Relationship)**

정보나 객체의 상하위 관계입니다. 가까이 배치했다는 이유만으로 생기지 않습니다.

**캔버스 좌표 (Canvas Coordinates)**

화면 이동·확대와 구분되는 작업 공간 내부의 위치 값입니다.

**패닝 (Panning)**

내용의 좌표는 유지하면서 보이는 영역을 가로세로 이동하는 조작입니다.

**줌 (Zoom)**

작업 공간의 표시 배율을 바꾸는 조작입니다.

**화면 맞춤 (Fit View)**

관련 노드가 보이는 영역에 들어오도록 이동·배율을 맞추는 기능입니다.

**미니맵 (Minimap)**

전체 구조와 현재 보고 있는 위치를 작게 보여주는 지도입니다.

**격자 맞춤 (Snap to Grid)**

노드 위치를 정한 격자 간격에 맞추는 기능입니다.

**드래그 영역 선택 (Marquee Selection)**

사각형 영역을 그려 그 안의 여러 객체를 선택하는 방식입니다.

**다중 선택 (Multi-selection)**

여러 객체를 함께 선택해 이동하거나 편집하는 기능입니다.

**자동 배치 (Automatic Layout)**

관계·방향·간격 규칙에 따라 노드 위치를 계산하는 처리입니다.

**계층형 배치 (Hierarchical Layout)**

부모·자식이나 방향 있는 관계를 층으로 나누어 배치하는 방식입니다.

**충돌 방지 (Collision Avoidance)**

노드나 라벨이 서로 겹치지 않도록 배치하는 처리입니다.

**사용자 배치 보존 (Preserve User Layout)**

사용자가 조정한 좌표를 불필요한 갱신으로 초기화하지 않는 동작입니다.

### Codex 요청 예시

목차의 부모·자식 관계와 캔버스 좌표를 분리해 관리하고, 명시적인 자동 배치 때만 기존 좌표를 재계산해 주세요. 노드 크기·연결선·수동 이동을 함께 검증해 주세요.

### 혼동 주의

Figma Auto Layout, CSS 레이아웃, 노드 자동 배치는 서로 다릅니다. 화면 맞춤과 데이터 구조 수정도 다른 행동입니다.

근거 문서: [flow-terms], [flow-layout], [wcag]


## 24. 권한과 안전한 조작

**인증 (Authentication)**

요청한 사용자가 누구인지 확인하는 절차입니다.

**인가 (Authorization)**

그 사용자가 해당 데이터나 행동에 접근할 수 있는지 판단하는 절차입니다.

**권한 (Permission)**

특정 자원이나 행동에 허용된 접근 범위입니다.

**최소 권한 (Least Privilege)**

필요한 작업 범위만 허용하는 접근 원칙입니다.

**권한 없음 (Permission Denied)**

인증 여부와 별개로 해당 작업을 수행할 수 없는 상태입니다.

**세션 만료 (Session Expiry)**

로그인된 접근 상태가 만료되어 다시 인증해야 하는 상황입니다.

**서버 검증 (Server-side Validation)**

클라이언트 표시와 관계없이 서버에서 값과 요청 조건을 검증하는 처리입니다.

**객체 수준 권한 (Object-level Authorization)**

각 기록·파일 등 개별 대상에 접근할 권한을 확인하는 처리입니다.

**민감 정보 (Sensitive Information)**

노출되거나 오용되면 사용자에게 피해를 줄 수 있는 정보입니다.

### Codex 요청 예시

버튼을 숨기는 것과 별도로 서버에서 각 기록의 접근 권한을 검증해 주세요. 세션이 만료되어도 작성 중 입력을 불필요하게 잃지 않도록 처리해 주세요.

### 혼동 주의

화면에서 수정 버튼이 보이지 않는다고 다른 사용자의 데이터 수정이 차단되는 것은 아닙니다. 초안 보존과 로그아웃 후 민감 데이터 제거 정책도 함께 정해야 합니다.

근거 문서: [owasp-auth], [wai-validation]


## 25. 이미지와 미디어 배치

**대체 텍스트 (Alternative Text · Alt Text)**

이미지의 역할이나 전달하려는 정보를 텍스트로 설명합니다. 장식용 이미지는 별도 처리합니다.

**종횡비 (Aspect Ratio)**

이미지나 영역의 가로와 세로 길이의 비율입니다.

**자연 크기 (Intrinsic Size)**

외부 배치 규칙을 적용하기 전 이미지가 갖는 원래 크기입니다.

**이미지 맞춤 (Object Fit)**

이미지를 정해진 상자 안에 어떤 방식으로 맞출지 결정하는 규칙입니다.

**전체 보이기 (Contain)**

비율을 유지하며 이미지 전체가 영역 안에 들어오게 맞춥니다. 빈 공간이 생길 수 있습니다.

**영역 채우기 (Cover)**

비율을 유지하며 영역 전체를 채웁니다. 이미지의 일부가 잘릴 수 있습니다.

**자르기 (Cropping)**

표시할 이미지 영역을 선택해 나머지를 제외하는 처리입니다.

**이미지 위치 (Object Position)**

이미지를 상자 안에서 어느 위치에 맞출지 정하는 설정입니다.

**반응형 이미지 (Responsive Images)**

화면 공간과 해상도 조건에 맞는 이미지 자원을 선택해 제공하는 방식입니다.

**후보 이미지 집합 (Srcset)**

브라우저가 적절한 이미지를 고르도록 여러 자원 후보와 크기 정보를 제공하는 속성입니다.

**지연 로딩 (Lazy Loading)**

초기 표시 시점에 필요하지 않은 이미지 등의 로드를 뒤로 미루는 방식입니다.

**이미지 대체 표시 (Image Fallback)**

이미지를 사용할 수 없을 때 텍스트나 다른 표현으로 맥락을 유지하는 처리입니다.

### Codex 요청 예시

이미지에 비율과 예약 공간을 지정하고, 전체가 보여야 하는 자료에는 contain을 사용해 주세요. 주요 내용 이미지와 장식 이미지를 구분해 대체 텍스트를 작성해 주세요.

### 혼동 주의

cover로 채우면 원본의 일부가 잘릴 수 있습니다. 화면 첫 부분의 중요한 이미지를 무조건 지연 로딩하지 않습니다.

근거 문서: [mdn-img], [mdn-objectfit]


## 26. 언어·날짜·지역화

**국제화 (Internationalization · I18n)**

제품을 여러 언어와 지역 조건에 대응할 수 있게 구조화하는 작업입니다.

**지역화 (Localization · L10n)**

특정 언어·지역의 표현과 관례에 맞게 제품을 적용하는 작업입니다.

**로케일 (Locale)**

언어·지역 등에 따른 표현 규칙을 지정하는 식별 정보입니다.

**시간대 (Time Zone)**

날짜와 시각을 해석·표시할 때 사용하는 지역별 시간 기준입니다.

**날짜 전용 값 (Date-only Value)**

특정 시각이나 시간대가 아니라 달력상의 날짜를 나타내는 값입니다.

**시점 (Timestamp)**

시간의 흐름에서 특정 순간을 나타내는 값입니다. 저장 형식과 표시 시간대를 구분합니다.

**날짜·시각 형식화 (Date and Time Formatting)**

로케일과 시간대 등의 규칙에 맞게 날짜·시각을 표시합니다.

**숫자 형식화 (Number Formatting)**

소수점·자릿수 구분·단위 등을 해당 지역 관례에 맞춰 표현합니다.

**상대 시간 표현 (Relative Time Formatting)**

지금부터의 차이를 3분 전처럼 상대적인 표현으로 표시합니다.

**복수형 규칙 (Plural Rules)**

언어별 수량에 따라 달라지는 표현을 선택하는 규칙입니다.

**텍스트 확장 대응 (Text Expansion)**

번역이나 긴 이름으로 글이 길어져도 배치와 의미를 유지하는 대응입니다.

**문자열 정렬 (Collation)**

단순 문자 코드 순서가 아니라 언어 규칙에 맞춰 문자열을 비교·정렬하는 방식입니다.

### Codex 요청 예시

공부 날짜와 실제 저장 시각을 구분하고, 표시 시간대를 일관되게 적용해 주세요. 긴 한글 과목명과 다른 지역의 숫자·날짜 표현도 검증해 주세요.

### 혼동 주의

한국어를 사용한다고 시간대가 자동으로 한국 표준시가 되는 것은 아닙니다. 날짜만 의미하는 값을 무심코 시점으로 변환하면 날짜 경계가 달라질 수 있습니다.

근거 문서: [mdn-intl], [mdn-datetime], [mdn-img]


## 27. 검수·테스트·전달

**사용성 테스트 (Usability Testing)**

실제 사용자가 과업을 수행하는 모습을 관찰해 어려움을 확인하는 활동입니다.

**휴리스틱 평가 (Heuristic Evaluation)**

알려진 사용성 원칙에 따라 화면과 흐름을 점검하는 평가입니다.

**과업 성공률 (Task Success Rate)**

정의한 과업을 성공 기준대로 완료한 비율입니다.

**과업 소요 시간 (Time on Task)**

사용자가 특정 과업에 실제로 사용한 시간입니다.

**행동 관찰 (Behavior Observation)**

사용자가 어디서 찾고 멈추고 실수하는지 직접 확인하는 활동입니다.

**회귀 테스트 (Regression Testing)**

수정 후 기존 기능이 깨지지 않았는지 확인하는 테스트입니다.

**시각적 회귀 (Visual Regression Testing)**

기준 화면과 새 화면을 비교해 의도하지 않은 시각 변화를 확인하는 테스트입니다.

**종단 간 테스트 (E2E · End-to-end Test)**

실제 사용자 경로처럼 여러 기능을 이어 실행하며 결과를 확인하는 테스트입니다.

**컴포넌트 스토리 (Component Story)**

특정 속성과 상태의 컴포넌트를 독립적으로 보여주는 실행 가능한 예시입니다.

**엣지 케이스 (Edge Case)**

긴 텍스트·중복 클릭·중단 등 평범한 성공 경로에서 벗어난 조건입니다.

**테스트 행렬 (Test Matrix)**

기기·화면 크기·입력 방식·상태 조합별 점검 범위를 정리한 표입니다.

**완료 정의 (Definition of Done)**

구현·테스트·문서화 등 작업 완료에 요구되는 공통 기준입니다.

**검증 증거 (Verification Evidence)**

실행한 테스트·재현 절차·관찰 결과처럼 완료 판단을 뒷받침하는 기록입니다.

**인계 문서 (Handoff Document)**

다음 작업자가 구조·규칙·미해결 사항을 이어받을 수 있게 기록한 문서입니다.

**에이전트 작업지침 (AGENTS.md)**

Codex가 작업 전에 읽는 프로젝트 지침을 지정된 계층과 범위에 따라 두는 파일입니다.

### Codex 요청 예시

입력·선택 변경·저장·뒤로 가기·새로고침 복구를 실제 브라우저에서 검증해 주세요. 구현됨·검증됨·미검증을 구분해 보고해 주세요.

### 혼동 주의

스크린샷이 맞는 것과 저장이 되는 것은 다릅니다. 자동화 테스트 통과가 실제 사용자 사용성 검증까지 대신하지는 않습니다. 긴 용어집을 AGENTS.md에 모두 넣지 말고 관련 문서를 읽도록 짧게 연결합니다.

근거 문서: [gov-testing], [playwright-visual], [storybook], [codex-agents]


## 자주 혼동하는 구분

**컴포넌트 / 인스턴스 / 오버라이드**

원본 설계 / 연결된 사용본 / 사용본의 허용된 부분 변경입니다.

**변형 / 상태 / 테마**

예: 버튼 크기·종류 / 포커스·로딩 / 라이트·다크입니다. 디자인 도구에서 상태를 변형으로 표현할 수 있어도 개념은 구분합니다.

**스타일 / 변수 / 토큰**

스타일은 표현 속성 묶음, 변수는 참조 가능한 값, 토큰은 디자인 의미를 이름으로 관리하는 단위입니다. 도구에 맞게 대응을 정의합니다.

**뒤로 가기 / 상위로 가기**

방문 이력 복귀 / 데이터 계층의 부모 이동입니다.

**모달 / 팝오버 / 드로어**

모달은 바깥 조작 제한 방식, 팝오버는 대상 주변 보조 영역, 드로어는 가장자리 패널입니다. 위치와 상호작용 제약을 따로 명시합니다.

**메뉴 / 셀렉트 / 콤보박스**

행동 실행 / 정해진 값 선택 / 팝업과 결합한 값 입력·선택 패턴입니다. 콤보박스는 선택 전용일 수도 있습니다.

**호버 / 포커스 / 선택**

포인터가 올라감 / 현재 입력 대상 / 항목의 선택 결과입니다.

**비활성 / 읽기 전용**

조작 제한 / 읽을 수 있지만 값 수정 불가입니다. 포커스·복사·폼 제출 등 실제 동작을 요소별로 확인합니다.

**화면 상태 보존 / 영속 저장 / 동기화**

이동 중 작업 맥락 유지 / 새로고침 이후에도 데이터 보존 / 여러 저장 주체 간 데이터 일치입니다.

**낙관적 표시 / 저장 완료**

예상 결과를 먼저 보여줌 / 실제 저장 대상의 성공 확인입니다.

**디바운스 / 스로틀**

멈춤 후 묶어서 처리 / 계속되는 이벤트의 빈도 제한입니다.

**가상화 / 무한 스크롤**

렌더링되는 항목 범위 제한 / 계속 데이터를 추가하는 탐색 방식입니다.

**요청 취소 / 롤백**

진행 중 요청 중단 / 이미 적용된 변경 효과 복원입니다.

**시각적 테스트 / E2E / 사용성 테스트**

화면 모양 비교 / 실제 기능 경로 실행 / 실제 사용자의 과업 수행 관찰입니다.

```text
Codex 웹앱 UI/UX 작업지침

목표
사용자가 UI/UX 용어를 몰라도 요구한 문제를 정확히 구현할 수 있게 하세요. 용어를 나열하는 것보다 실제 행동·조건·완료 기준을 명확히 하세요.

문제 해석
자연어로 제시한 불편을 해당 UI/UX 개념으로 연결하세요. 중요한 용어는 쉬운 뜻과 적용 이유를 한 번만 설명하세요. 예: 뒤로 가기, 상위 이동, 맥락 복원은 구분합니다. 이름만으로 행동이 결정되지 않는 드롭다운·모달·저장 같은 말은 현재 맥락에서 실제 동작을 정의하세요.

작업 전
기존 코드와 화면 흐름을 확인하세요. 관련 화면·입력·패널·탭·상태·저장 경로를 파악하고, 기존 요구사항과 보존할 사용자 데이터를 기록하세요. 이 용어집은 적용 후보를 찾는 참조 자료이지 모든 기능을 추가하라는 요구가 아닙니다.

정보 구조와 탐색
현재 위치와 편집 대상을 항상 식별할 수 있게 하세요. 뒤로 가기와 부모 계층 이동을 구분하세요. 복귀 시 선택·탭·검색어·필터·스크롤의 필요한 범위를 복원하고 직접 URL 진입도 처리하세요.

컴포넌트와 시각 규칙
반복 요소는 공통 컴포넌트로 관리하고 색·여백·글자·모서리 등은 일관된 토큰을 사용하세요. 변형·상태·테마·콘텐츠 슬롯을 구분하세요. 재사용을 위해 거대한 조건문 컴포넌트 하나를 만들지 마세요.

입력과 상태
알고 있는 값은 수정 가능하게 미리 채우되 모르는 값은 추정해 확정하지 마세요. 입력값·한글 조합·캐럿·선택·포커스를 불필요하게 초기화하지 마세요. 조합 중 Enter와 실제 제출을 구분하세요. 기본·포커스·선택·비활성·읽기 전용·로딩·빈 데이터·결과 없음·오류·오프라인을 필요한 범위에서 정의하세요.

저장과 비동기 처리
화면 상태 유지, 브라우저 저장, 서버 저장, 동기화, 백업을 구분하세요. 저장 중·완료·실패를 실제 저장소의 응답과 맞추세요. 실패 시 초안과 복구 경로를 유지하세요. 빠른 대상 전환에서 오래된 응답이 최신 선택을 덮어쓰지 않도록 하세요. 연속 제출·재시도에서 중복 기록이 생기지 않도록 서버와 클라이언트 처리 범위를 확인하세요. 요청 취소를 이미 완료된 서버 변경의 취소로 간주하지 마세요.

반응형과 접근성
작은 화면에서 글자만 줄이거나 필수 기능을 숨기지 마세요. 긴 한글·확대·화면 키보드·좁은 높이를 확인하세요. 실제 버튼·링크·레이블을 역할대로 사용하고 키보드 조작, 접근 가능한 이름, 포커스 표시와 복귀를 구현하세요. 드래그만 가능한 동작에는 비끌기 대안을 제공하세요. 대비·대상 크기는 적용 기준과 예외를 구분해 확인하세요.

캔버스가 있는 경우
데이터의 부모·자식 관계, 노드 좌표, 뷰포트의 이동·확대를 분리하세요. 사용자가 정한 배치를 갱신 때마다 초기화하지 말고, 명시적인 자동 배치에서만 필요한 좌표를 재계산하세요.

보존 원칙
UI를 간소화한다는 이유로 기존 기능·자유 입력·예외 처리·개인 설정·기록·ID·초안·캔버스 위치를 임의로 삭제하지 마세요. 변경이 불가피하면 영향과 이전 방식을 설명하세요. 기능을 숨겨 버그가 사라진 것처럼 처리하지 마세요.

검증
현재 환경에서 가능한 실제 브라우저 테스트를 실행하세요. 정상 경로뿐 아니라 긴 입력, 한글 연속 입력, 빠른 전환, 반복 저장, 실패와 재시도, 뒤로 가기, 새로고침, 재접속 복구를 검증하세요. 화면 비교와 실제 동작 검증을 구분하세요. 실행하지 못한 검증은 미검증으로 표시하세요.

완료 보고
바꾼 사용자 동작, 적용한 주요 개념, 실제 실행한 테스트와 결과, 남은 제약을 간결하게 보고하세요. 구현·검증·배포·외부 연동 완료를 서로 혼동하지 마세요.

프로젝트 배치
이 작업지침의 핵심을 AGENTS.md에 두고, 긴 용어집은 docs/웹앱_설계_용어사전.md 같은 별도 문서에 두세요. AGENTS.md에는 UI/UX 작업 전 관련 사전 절과 현재 기능 명세를 읽으라는 명시적 참조를 넣으세요. 임의의 docs 문서가 자동으로 모두 읽힌다고 가정하지 마세요.
```
