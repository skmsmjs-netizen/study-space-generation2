## 4. 목차와 확장

- 공부 범위는 사용자가 실제 교재의 목차·소주제를 입력하거나, 교재가 없으면 강의계획서에서 가져오는 데서 시작한다. 입력 자체도 시스템이 안내하는 첫 행동으로 제공한다. 준은 그 현실적인 큰 틀을 작고 실행 가능한 행동으로 나눈다.
- `과목 → 대단원 → 중단원 → 주제`는 예시다. 과목마다 같은 깊이를 강제하지 않는다. 하위 항목 추가, 이름 수정, 다른 항목 아래로 이동을 준비된 조작으로 제공한다.
- 직접 입력과 계층 텍스트 붙여넣기를 모두 보존한다. 번호·`#` 등의 표기를 정리하고 계층을 읽기 쉽게 표시한다. 이름 수정과 이동은 연결된 모든 표시에도 반영한다.
- 새 항목은 선택 목록·집계·상위 단원 현황·누락 추적에 자동 포함되어야 한다. 사용자가 수식 범위나 관계를 직접 수리해야 하는 구조를 완성으로 보지 않는다. 추가·변경 방법의 안내도 제공한다.
- 긴 주제와 짧은 주제는 같은 비중으로 집계한다. 목차 검수 횟수 0회도 의미 있게 표시한다. 검수 횟수나 등록한 목차의 완료율을 실제 시험 범위의 완전함과 같다고 보지 않는다.

- 최초 여섯 행동인 예습훑기·예습요약필사·읽어보기·요약필기·문제풀이·모의시험은 출발 예시이며 고정 목록이 아니다. 강의 중 메모 → 전사문 생성·보유 → 자기 방식의 핵심 재구성 → 관련 문제풀이라는 강의 공부 절차와 구분한다.

- 회차 표시는 주제별 `☑ 1회 · ☑ 2회 · ☐ 3회` 같은 형태를 선호한다. 예시의 3회는 확정 목표가 아니다. 누적 행동 체크와 `+1` 선호도 기존 회차 표시와 함께 해석한다. 주제별 초과 반복으로 다른 주제의 잔량을 상쇄하지 않는다.

## 6. 평소 입력과 어휘

- 기준 상황은 공부 후 책을 정리하고 아이패드만 켠 때다. 여러 주제를 한 화면에서 골라 기록하고, 다시 누르면 취소하며, 잘못된 과거 기록은 원래 기록에서 고친다. 회차가 불확실하면 확실히 기억나는 최소 횟수만 남긴다는 선택을 보존한다.
- 방법 후보는 같은 화면에서 한 번에 보이고 선택하지 않아도 넘어갈 수 있게 한다. 써보기·그려보기·새롭게 바라보기·풀어보기·친근하게 이해하기·인상만 느끼기와 이후 후보를 실제 공부와 대조한다. 새 방법을 추가해 재사용하는 안은 잠정이다. 시스템 구상·제작 자체를 공부로 본 의견도 제외하지 않는다.
- 이어서 할 위치는 기존 목차에서 선택하고, 목차에 없거나 넣기 애매하면 한 줄을 관련 목차에 붙일 수 있게 한다. 빈칸에서 문장을 처음부터 고안하는 부담을 줄인다.
- ‘어려웠다’보다 `직교좌표를 원기둥좌표로 변환하지 못함`처럼 대상과 동작이 구체적인 표현을 지원한다. 대상·동작 선택과 준비된 문장, 짧은 예시를 사용하고 같은 대상은 기존 항목에 연결한다.
- 페이지는 숫자 입력 후 단위 표시처럼 형식을 정돈한다. 명사형·`~함`·결론만 쓰기 등 각 입력의 목적에 맞는 안내를 준비한다. 문제의 자료·쪽수·번호를 기록할 수 있되 상세 입력을 매일의 필수 절차로 임의 승격하지 않는다.
- 최근 ‘내 방식으로 요약하기’ 하나로 기록, 읽기 체크와 중단 위치, 행동 누적·`+1`·즉시 반영 선택은 보존한다. 문제 수·범위와 재풀이 중복 집계는 적용 상황을 구별해 설계한다.

- **2026-09-14 추가 — 프로젝트 전역의 행동 안내:** 모든 화면·문구와 앞으로의 설계·구현에서 입력 항목을 나열하는 데 그치지 않고, 필요한 준비 행동 → 작게 실행할 일 → 돌아와 남길 값과 위치를 상황에 맞는 짧은 동사 문장으로 잇는다. 정보를 모를 때는 무엇을 어디에서 확인하고 어느 입력으로 돌아오면 되는지 알려준다. 예를 들어 과제 기한이 기억나지 않으면 공지의 마감일을 확인한 뒤 남은 날 수를 고르도록 안내하고, 풀이를 시작하려면 선택한 실제 자료·문제를 열어 수행한 뒤 해당 항목에 결과를 남기도록 안내한다. 실제 연결 자료나 사용자가 고른 대상이 없으면 임의의 책·쪽수·문제 번호를 만들어 지시하지 않는다.
- 안내는 다음 행동을 스스로 선택하기 쉽게 만드는 장치다. 이미 알고 있거나 수행한 내용은 바로 기록할 수 있어야 하며, 평소 책을 정리한 뒤 아이패드에서 입력하는 사람에게 매번 책을 다시 펴거나 확인 절차를 반복하게 하지 않는다. 반복 팝업과 추가 필수 체크를 만들지 않는다. 사용자 예시의 ‘문제 3개’는 안내 방식의 예시이며 모든 공부의 공통 분량·의무로 채택하지 않는다. 안내를 보거나 자료를 연 사실, 실제 수행, 입력과 저장을 구별하고 안내 열람만으로 공부·제출·출석 완료를 자동 기록하지 않는다.

## 7. 인출과 실제 수행 확인

- 공부 직후 책을 덮은 상태에서 키워드를 명사형으로 떠올리는 구상을 보존한다. 주제 전체 하나의 평가보다 방향 법칙·계산식·조건별 결과 같은 개별 항목을 다룬다.
- 번호가 붙은 넉넉한 입력칸과 ‘당장 설명 불가’·‘대략 설명 가능’ 구분을 제공하는 안이 있다. 10칸, 각각 5칸은 제안 예시이며 필수 수나 최대치가 아니다.
- 같은 항목에서 못함 → 일부 가능 → 가능, 가능 → 못함의 변화를 보존한다. 가능 여부는 대표 예제의 수행 등 관찰할 수 있는 기준으로 정의한다.
- ‘못함’을 바꾸려는 클릭 → 문제 하나를 새로 풀라는 미션 → 결과 입력 → 상태와 색 변화라는 행동 유도 구상을 유지한다. 반복을 끝낸 사실과 문제를 실제로 해결한 사실을 별도로 표시한다.

## 8. 이유·방법·반응과 시작 부담

- WHY는 `좌표 변환 문제를 스스로 풀고 싶기 때문에`처럼 `~때문에`, HOW는 대상과 구체적인 행동, WHAT은 `원기둥좌표 변환 예제를 풀 수 있음`처럼 가능해진 일로 표현한다.
- 현재 행동 → 해당 단원의 실력 → 시험에서 쓸 능력으로 이어지는 경로를 보여준다. 이유 후보와 WHY·HOW 예시를 제공하고, 세 칸을 매번 필수로 만들지 않는다. 의도·기대와 실제 가능해진 일을 혼동하지 않는다.
- `그런 것 같은데 모르겠다`와 `아닌 것 같은데 모르겠다`, 후보 안에 답이 있는 듯한 유보와 후보 밖인 듯한 유보를 구분하려는 요구를 보존한다.
- 명료함·익숙함·혼란스러움 등 내용에 대한 반응을 우선 다루되, 더 하고 싶음·보통·멈추고 싶음 등 다른 반응이 폐기된 것은 아니다. 실제 감각을 표현할 수 있게 후보의 의미와 묶는 기준을 정한다.
- 행동의 기대 효과와 시작 부담을 별도로 다룬다. 부담이 크면 개념 하나 쓰기처럼 첫 행동을 작게 제시한다. 후보 두세 개는 잠정이며 특정 심리학 이론을 채택했다고 가정하지 않는다.

## 9. 수학적 이론·집계·문구·그래프

- 학습흥미도·문제풀이력·전범위성·개별암기성·인출정확도·성과지표는 검토할 개념이다. 실제 입력에서 어떻게 정의할지, 무엇을 관측하고 무엇을 추론하는지 밝혀야 한다. 그림 그리기 빈도와 흥미·시험 수행의 관계 같은 예시를 확정 사실로 쓰지 않는다.
- 수식은 무엇이 늘면 무엇이 달라지는지 설명 가능해야 한다. 필요한 고급 수학은 사용하되, 계산이 지원하는 판단이 목적이다. 필요한 입력 없이 값을 꾸미거나 쓰지 않을 데이터를 수집하지 않는다. 비수리적 속성도 기준과 불확실성을 명시해 다룬다.
- 기록이 닿은 범위, 주제별 남은 반복, 문제 시도와 처음 스스로 맞힘, 방법 분포, 복습 후보일의 다섯 집계는 전체 수리적 이론의 완성이 아니다. 일부 공부도 ‘기록 있음’에는 포함할 수 있지만 전체 완료와 다르다. 방법 복수 선택은 각 방법 빈도에 반영하되 합산 비율의 의미를 명시한다.
- 화면에는 실제 기록과 선택 가능한 다음 행동을 짧게 보여준다. `처음에 스스로 맞힌`이라는 표현을 보존한다. 예시의 10문제·5문제를 실제 공부로 취급하지 않는다. 판단 근거가 부족하면 부족함을 표시하고 실패·낮은 능력으로 치환하지 않는다.
- 주제별 많이·적게 푼 비교, 전체 문제 수 대비 풀이, 문제 위치·범위와 재풀이 집계 요구는 보존하되 평소 입력 부담과 함께 설계한다. 반복 완료가 실제 해결·암기·성적을 보장하지 않는다.

## 10. 홈·시험 대비·복습

- 홈은 공부 기록 입구와 쌓인 기록의 시각자료가 먼저 보인다. 완료 기록은 회상의 신호이기도 하다. 기록이 닿은 범위는 평소에, 반복 잔량·문제 결과·방법 통계는 필요할 때, 상세 시험·인출 입력은 시험 대비에서 확인한다.
- 시험 대비의 전범위 확인 → 주제별 대표 예제 → 안 풀린 예제 재풀이 흐름을 보존한다. 최초의 시험 기간 3회·전날 1회·당일 1회와 이후 두세 차례 구상은 최종 횟수 확정으로 취급하지 않는다. 전사문 필요성도 유보되었다.
- AI 암기·인출 시험지 생성과 실제 시험지로 인출 연습은 각각의 행동이다. `시험 보기`에서 제한시간 설정, 종료 후 맞고 틀린 수·틀린 번호 입력, 짧은 이유 후보 선택을 지원하는 구상을 유지한다. 이유 복수 선택은 잠정이다.
- 반복을 채웠으나 못 풀었다면 두 사실을 함께 표시한다. 전범위 누락, 유독 어려운 문제, 다루지 않은 내용 등은 짧고 일관된 후보로 점검한다.
- 시간 부족 시 분량을 줄여 전범위를 확인한다는 선택은 잠정이며 과목에 따라 다르다. 수학의 공식 확인과 프로그래밍의 직접 작성처럼 수행 기준을 구분한다.
- 복습 날짜는 후보를 만드는 장치다. 에빙하우스 주기 언급을 검증된 개인 일정 공식으로 고정하지 않는다. 날짜를 넘기면 날짜 부담 없이 후보로 유지한다. ‘아직 못함’을 우선하는 선택과 안내 범위의 미정을 보존한다.

## 11. 일정·과제·온라인 강의·알림

- 주차별 강의, 중간·기말시험, 퀴즈 과제, 일반 과제, 온라인 강의를 추적한다. 과목·제목·해야 할 일·시작일·마감·현재 상태를 바탕으로 캘린더·대시보드·남은 일수와 시간을 보여준다.
- 온라인 강의는 시청 가능 시작과 출석 인정 기한을 다룬다. 출석용 재생, 실제 수강·필기, 출석 인정 확인은 별도다. 과제의 시작·제출 같은 실제 행동에서 상태를 만들고, 제출 준비와 실제 제출을 혼동하지 않는다.
- `과제가 있으신가요?`처럼 안내하는 입구를 두되, 이후 선택된 한 화면 입력을 반영한다. 학기 중 새 과제 누락을 다루고 `최근 추가된 과제가 있나요?`는 홈을 열 때마다 강요하지 않는다. 해당 과목 기록 뒤 묻는 안은 잠정이다.
- 마감 미정도 등록하고 공지 확인일을 정하며 미정 항목을 모아 찾을 수 있게 한다. 마감 변경 시 새 마감이 우선이고 이전 정보는 필요할 때 확인한다.
- 종류별로 구분한 뒤 가까운 기한부터 본다. 같은 기한이면 배점뿐 아니라 과제 내용·실행 가능성·부분 수행의 의미도 고려한다. 임의의 배점/시간 공식으로 우선순위를 고정하지 않는다.
- 매일 오전 9시, 일주일 안에 마감할 일을 한 알림에 묶고 열면 이름과 남은 시간을 보는 선택을 보존한다. 두 시간 전 추가 알림은 잠정이다. iPhone 미리 알림을 우선 고려하고 어려우면 Notion 내 대안을 검토한다. Apple·Notion Calendar·미리 알림 연동 가능성은 실제 확인 대상이며 설정 완료가 아니다.

## 13. 실제 변경과 보존·검증

- 기존 외부 시스템의 조사·변경 보류는 새로 허용된 범위가 생기기 전까지 유지한다. 지침 등록은 삭제·외부 공유·알림 생성·예약·감시의 승인이 아니다. 사용자가 이후 직접 허용한 범위는 진행하고 이미 받은 허락을 반복 확인하지 않는다.
- 수정 전 현재 파일·내용·병행 변경을 확인한다. 원문·실제 응답·질문과 선택지 ID·저장 키·근거·이유·수정 이력을 보존한다. 충돌을 조용히 덮어쓰지 않는다. 참고자료를 외부로 공개하지 않는다.
- 실제 채팅에 제출된 응답과 질문지 내부에만 있는 미제출 입력은 다르다. 환경·기기 간 자동 이관을 가정하지 않는다. 파일 복사 동일성·전달 요청 성공·실제 채팅 수신·복원 결과·설계 반영을 각각 확인한다.
- 조사 재개를 요청받으면 기존 질문지를 이어 사용한다. 표시 경로는 새 대화에 허용된 시각화 폴더에 맞추고, 사본의 바이트 동일성과 질문 ID·저장 키·응답 코드 보존을 확인한다. 기존 빌드·검증 스크립트는 실행 전에 출력·검사 대상 경로와 권한을 확인한다. `sentRevision`을 실제 채팅 수신이나 반영 완료로 보지 않으며 손상되거나 충돌한 저장값을 자동 덮어쓰지 않는다.
- 정적 검사, 수식 계산, 합성 DOM 조작, 브라우저 렌더, 물리 기기 입력, Sync·알림, 실제 학습 효과는 별도 증거다. 보존본 생성은 원래 과거 대화 전수 대조나 실사용 검증이 아니다.
- 현재 인계 기록의 검증 결과는 그 당시 범위로 보고하며 다시 실행하지 않은 검사를 이번 검증으로 주장하지 않는다. 문서 변경만 수행한 경우 관련 없는 설문 테스트·빌드나 UI 작업을 자동 실행하지 않는다.

## 14. 이후 판단을 남기는 방법

설계나 구현을 제안할 때는 해당 사용자 근거와 보존 조건, 선택한 규칙, 미확정 사항, 확인한 사례를 필요한 만큼 연결한다. 모든 답변에 거대한 표를 강제하지 않는다. 기능을 보류하면 이유와 다시 다룰 조건을 남기고 원문에서 삭제하지 않는다.

현재 미확정 중심은 반복 목표·조정 조건, 최종 행동·반응 어휘, 수식과 문구의 연결, 그래프 축, 과목별 시험 구성, 플랫폼과 실제 기기 작동이다. 사용자 조사 종료 전에는 이 목록을 설계 자동 시작의 근거로 쓰지 않는다.

완료 점검: 요청 범위의 세부가 빠졌는가, 이미 답한 것을 다시 물었는가, 예시·잠정안을 확정했는가, 실제 한 공부를 기록할 수 있는가, 계산과 문구가 근거를 넘었는가, 데이터와 병행 작업을 보존했는가, 검증하지 않은 성공을 주장했는가.
