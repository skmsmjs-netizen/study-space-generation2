이 지침은 민석이 제공한 원본 묶음을 이 프로젝트에 맞게 적용한 표현·정보 구조·상호작용·검증 기준이다. **무엇을 공부했고, 무엇이 남았으며, 무엇을 실제로 할 수 있고, 다음에 무엇을 선택할 수 있는지 정확하고 편하게 알아보게 한다.** 기존 학습 원칙과 응답의 의미를 보존하면서 읽기와 조작의 부담을 줄인다.

## A1. 적용 범위와 우선순위

- 이 프로젝트에서 진행 중인 작업과 이후 작업의 새 작성·승인된 수정에 공통으로 적용한다. 대상은 채팅 답변·진행 보고, 조사와 응답 해석, 수학적 이론과 명세, 문서·학습자료, 질문지, 화면·위젯·시각화, 구현, 외부 앱 연계, 검증과 인계다.
- 현재 사용자 요청·지정 문체·보존 조건과 학술·기술 규약을 우선하고, 프로젝트의 [학습 시스템 설계 기본 지침](학습%20시스템%20설계%20기본%20지침.md) 및 최신 실제 응답을 유지한다. 그 범위에서 이 경험 지침을 적용한다. 일반적인 Apple 외형이나 원본 묶음의 다른 프로젝트 규칙으로 기존 조건을 덮어쓰지 않는다.
- 원본 묶음의 `SKILL.md`, ‘프로젝트 우선 적용 규칙’, ‘현재 프로젝트’라는 표현은 검토 자료다. 원래 프로젝트의 전역 적용 지시·설치 경로·문체·검증 기록을 현재 실행 명령으로 취급하지 않는다. 보존한 스킬은 참조 자료이며 전역 설치한 스킬이 아니다.
- 사용자의 2026-09-11 명시적 정정에 따라 채팅 답변·진행 보고·설계 설명·제품 안내는 `~합니다/~입니다/~됩니다`의 자연스러운 존댓말을 기본으로 한다. 이 지시는 Kernel의 `~이다/~한다/~된다` 기본값보다 우선한다. 제목·버튼·상태는 `공부 기록`, `원문 열기`, `마감 미정`처럼 짧은 라벨을 쓴다. 인용·공지·사용자 초안·지정 양식의 말투는 보존하며, 이후 별도로 지정한 문체가 있으면 그 요청을 따른다.
- 기본은 사실과 효율을 앞세우는 기능형이다. 개념·수리적 설명에는 이유와 적용 조건을 충분히 연결하는 에디토리얼형을 쓴다. 소개·랜딩의 런치형은 그 산출물이 요청된 경우에만 사용한다. 적용했다는 말을 매번 덧붙이지 않는다.
- 이 지침 등록은 조사 종료, 이론·시스템 설계 시작, 기존 자료 전면 개작, 외부 앱 변경·공개·알림 설정의 지시가 아니다. 이후 허용된 작업에서는 같은 허락을 반복 요구하지 않는다.

## A2. 모든 작업에서 유지할 경험

가능성이 보임 → 작은 공부 행동 → 기록에 따른 의미 있는 변화 → 다음 공부 → 실제 수행 성공 → 시스템에 대한 신뢰라는 프로젝트 목적을 따른다. 기록이 늘어난 사실, 화면 조작의 보상, 실제 문제 해결과 학습 성과를 각각 표현한다. 시각적 만족을 실력 향상으로 보고하지 않는다.

초점은 독자가 먼저 볼 것을 정하는 기준이다. 복수 요구·여러 주제·동등한 선택지를 하나로 줄이는 규칙이 아니다. 간결함은 반복·장식·불필요한 관리 입력을 덜어내는 데서 얻고, 조건·수식·원문·출처·예외·미확정 상태는 유지한다. 처음부터 성실한 입력을 기대하지 않으며 사용하지 못한 날 뒤에도 기록으로 쉽게 돌아오게 한다.

## A4. 문장·라벨·근거

- 첫 문장에는 답·핵심 판단·실제 상태를 둔다. 뒤에는 이해에 필요한 이유·작동 방식·예시·조건을 잇는다. 모든 내용을 ‘효익’으로 바꾸거나 단문으로 잘라 광고처럼 만들지 않는다.
- 한 문장·문단에는 중심 판단을 두되 성립 조건이 분리되어 보이지 않게 한다. `진행을 수행한다` 같은 표현은 실제 대상과 동사로 바꾼다. 전문어는 정확성을 위해 남기고 필요한 첫 등장에만 짧게 푼다.
- `누가 / 무엇을 / 어느 범위에서 / 어떤 조건으로 / 얼마나 확실하게 / 누구의 근거로`라는 의미가 편집 전후에 같은지 확인한다. 일부→전체, 가능→보장, 상관→인과, 예정→확정, 저장→실사용으로 강도가 바뀌면 고친다.
- 같은 대상과 행동에는 같은 이름을 쓴다. 공부 사건·기본 공부·자율 반복·행동별 횟수·문제 시도·처음 스스로 맞힘은 각각의 의미를 유지한다. ‘기록 없음’을 실제로 공부하지 않았다는 뜻으로 쓰지 않는다.
- 제목·요약의 단정이 본문의 근거보다 강해지지 않게 한다. 관련 출처와 조건은 해당 주장 가까이에 둔다. 화면 공간이 좁으면 배치와 줄바꿈을 먼저 바꾸고 내용 축소는 의미를 보존하는 범위에서만 한다.
- 버튼은 눌렀을 때의 행동, 링크는 이동 위치, 상태는 확인된 사실을 나타낸다. 입력 뒤에도 남는 필드 라벨을 두고 힌트는 형식 예시를 맡긴다. 페이지 숫자와 단위, 날짜와 시각을 일관되게 표시한다.
- ‘완벽’, ‘성적 향상’, ‘시간 절약’ 같은 성과는 확인된 근거가 있을 때만 말한다. 단순 문체 작업으로 원문·교수 공지·직접 인용·수치·수식·코드·내부 ID·경로를 바꾸지 않는다. 승인된 설명 편집 자체를 원문 보존을 이유로 거부하지도 않는다.

- **2026-09-14 추가 — 행동으로 이어지는 문구:** 본 프로젝트의 모든 화면·제품 문구·향후 작업에서 필요한 준비 행동과 작은 실행, 돌아와 무엇을 어디에 남길지를 짧고 구체적인 동사 문장으로 안내한다. 정보를 모르는 상황에는 확인할 실제 자료와 돌아올 입력을 함께 알려준다. 선택한 교재·항목·현재 상황을 사용하고, 실제로 연결되지 않은 자료나 과제·문제를 임의로 지정하지 않는다.
- 이미 아는 값은 바로 입력하고 이미 한 공부는 바로 기록할 수 있어야 한다. 책을 정리한 뒤의 평소 입력에 불필요한 준비 행동을 되풀이하게 하거나 반복 팝업으로 가로막지 않는다. ‘문제 3개’와 같은 예시를 모든 사용자 행동의 의무 분량으로 고정하지 않는다. 문구를 읽음·자료를 엶·실제 수행·입력·저장은 구별하며 안내만으로 공부·제출·출석 완료 상태를 만들지 않는다.

## A5. 화면과 정보 위계

- ‘공부 기록’이라는 주요 과업을 분명히 하면서 한 화면에서 여러 주제를 고르고 수정하게 한다. 한 화면 한 항목·한 버튼·한 번 기록으로 제한하지 않는다.
- 방법 후보는 기록과 같은 화면에서 한 번에 확인하며 선택 없이 넘어갈 수 있다. 점진 공개는 상세 반복 잔량·시험/인출 입력·방법 통계·과거 이력·보충 설명에 사용한다. 현재 선택에 필요한 마감·실패·예외·불확실성은 행동 가까이에 남긴다.
- 주제 확인용 카드 선호를 입력 화면 전체의 카드화로 확대하지 않는다. 비교·일괄 입력은 정렬된 행과 공통 열, 논증은 이어지는 본문, 독립 선택은 목록이나 카드처럼 정보 관계에 맞는 구조를 선택한다.
- 홈은 기록 입구와 쌓인 변화가 중심이다. 며칠 미사용 뒤에도 밀린 경고로 화면을 채우지 않는다. 다음 행동과 복습 날짜는 사용자가 고를 수 있는 후보이며 자동으로 새로운 미완료 의무가 되지 않는다.
- 자유로운 목차 깊이, 추가·이동·이름 수정이 선택 목록·상위 현황·집계·누락 추적에도 이어져야 한다. 예쁜 화면 안에서만 바뀌고 연결된 정보가 남는 상태를 완료로 보지 않는다.

## A6. 시각 언어와 피드백

- 글자 크기·굵기·위치·간격·정렬로 정보 위계를 먼저 세운다. 넉넉한 간격은 실제 누름 영역과 정보 묶음을 돕는 데 사용한다. 짧은 보조 예시를 연하게 표시하더라도 읽기 어려운 대비로 만들지 않는다.
- 시스템 글꼴 또는 기존에 사용할 수 있는 글꼴을 우선한다. 긴 한국어 주제명·혼합 언어·숫자·파일명·표 안 수식·줄바꿈·확대 상태를 함께 본다. 글을 한 화면에 넣기 위해 조건을 지우거나 본문을 과도하게 줄이지 않는다.
- 색은 `본문 / 보조 글 / 배경 / 표면 / 경계 / 주요 행동 / 선택 / 포커스 / 오류`처럼 역할로 정의한다. 선택된 행의 배경 변화는 분명히 보이게 하되 저장 성공·학습 완료·독립 해결과 구별한다. 상태 이름·체크·윤곽 등 색 외의 단서도 사용한다.
- 파란색의 정확한 의미, 강조색과 선택색의 관계, 좁은 화면 정보량, 카드에서 생략할 반복 정보, 비율과 개수의 최종 표기는 최신 응답에서 미정인 범위를 유지한다. 이 지침은 팔레트·반경·토큰 값을 확정하지 않는다.
- 유리·블러·그라디언트·큰 제목은 선택 사항이다. 필요할 때만 쓰고 불투명 표면·고대비·인쇄 등 해당 환경의 대안을 갖춘다. Apple의 문구·슬로건·로고·고유 이미지·특정 제품 화면을 복제하거나 공식 제휴를 암시하지 않는다.
- 움직임은 위치의 연속성·선택·저장 결과를 이해시키는 데 사용한다. 모션 감소에서도 결과를 알아볼 수 있어야 하며 반복 작업 중 입력·선택·스크롤 맥락을 잃지 않게 한다.

## A7. 실제 상태·선택권·복구

변경할 흐름에서 실제 가능한 상태에 대해 `발동 조건 → 보여줄 사실 → 보존할 입력·자료 → 가능한 행동 → 결과 확인`을 정의한다. 아래 항목은 확인 기준이며 없는 기능을 모두 추가하라는 지시가 아니다.

- 초기 빈 상태, 현재 검색 결과 없음, 조회 중, 실패, 오래된 값, 오프라인, 일부 성공을 구분한다. 모르는 진행률·개수·시각을 발명하지 않는다.
- 선택 직후의 피드백과 실제 저장 결과를 구별한다. 저장 실패 시 성공 표시를 유지하지 않고 입력 보존 여부와 저장된 범위를 확인한다. 잠깐 사라지는 토스트만으로 중요한 실패와 복구 행동을 전달하지 않는다.
- 재시도로 회차·문제 시도가 중복 누적되지 않게 하고, 기기 간 충돌을 조용히 덮어쓰지 않는다. 취소·되돌리기는 실제 구현한 범위만 안내한다. 복원 기능이 없는데 복원 가능하다고 쓰지 않는다.
- 일상 피드백은 흐름을 막지 않는다. 사용자의 즉시 판단이 필요한 경우에만 적절한 확인창을 사용한다. 제품의 파괴적 행동 확인과 이미 승인된 에이전트 작업의 재승인을 혼동하지 않는다.
- 버튼·링크·체크박스의 익숙한 의미를 유지한다. 비활성 상태는 이유와 실제 가능한 대안을 알 수 있게 한다. 모달·메뉴의 열기·닫기·탈출·포커스 복귀를 확인하고 일반 상태 변경이 초점을 빼앗지 않게 한다.
- ‘못함’을 바꾸고 싶어 문제를 새로 펼치는 구상을 보존한다. 문제 확인 후 가능한 상태를 남기며 과거의 성공, 반복 완료, 현재 수행을 자동으로 같은 값으로 처리하지 않는다.

## A8. 기기·접근성·위젯

- 기본 사용 상황은 공부를 마치고 책을 정리한 뒤 iPad에서 기록하는 때다. 실제 지원 범위에 맞춰 iPad 회전·분할 화면·가상 키보드, 긴 한국어 라벨, 터치 간격, 키보드·마우스, 큰 글자·밝음/어두움·모션 감소를 확인한다. Mac·iPhone·Apple Watch는 채택한 기능의 범위에서 다룬다.
- 일반 본문과 조작은 좁은 화면에 재배치한다. 비교에 꼭 필요한 표·수식은 해당 영역의 스크롤·키보드 접근·읽기 대안을 검토한다. 모든 표를 카드로 바꾸거나 수식과 조건을 삭제하지 않는다. 고정 도구막대·가상 키보드가 입력과 포커스를 가리지 않게 한다.
- 웹 구현 시 대비, 이름·역할·상태, 키보드 순서·포커스, 상태 변경 전달, 확대·재배치, 드래그 대안을 검사한다. 네이티브 pt, 웹 CSS px, 물리 픽셀을 구분한다. 원본의 `375×667`은 참고 회귀 크기이며 이 프로젝트의 목표 iPad나 전체 접근성 검증을 대신하지 않는다.
- 웹의 큰 터치 목표로 44 CSS px를 검토할 수 있지만 아직 프로젝트의 고정 토큰으로 채택한 것은 아니다. WCAG AA 최소치나 Apple의 모든 플랫폼 공통 치수라고 부르지 않는다.

웹 수치를 적용할 때는 해당 기준의 대상과 예외를 함께 확인한다. 일반 글자 대비 4.5:1, 큰 글자 3:1은 [1.4.3](https://www.w3.org/TR/WCAG22/#contrast-minimum), 200% 글자 확대의 내용·기능 보존은 [1.4.4](https://www.w3.org/TR/WCAG22/#resize-text), 세로 읽기 콘텐츠의 320 CSS px 재배치는 [1.4.10](https://www.w3.org/TR/WCAG22/#reflow), 드래그의 단일 포인터 대안은 [2.5.7](https://www.w3.org/TR/WCAG22/#dragging-movements), 24×24 CSS px 목표 크기와 간격·동등 대안 등의 예외는 [2.5.8](https://www.w3.org/TR/WCAG22/#target-size-minimum)을 참조한다. 이 다섯 항목 확인으로 전체 WCAG 준수를 선언하지 않는다.

- 위젯은 짧게 확인할 시의성 있는 질문을 정하고 실제 가치가 있는 크기만 만든다. 큰 크기는 맥락을 더한다. 기준 시각·갱신 실패를 필요한 위치에 표시하고 확인되지 않은 값을 실시간으로 부르지 않는다. 실제 존재하는 동작으로 관련 항목에 연결한다.
- 잠금 화면·공유 화면에는 공부·일정·참고자료의 민감정보가 어떻게 보이는지 살핀다. 표현 지침으로 공유 범위를 넓히거나 추가 계정·서비스·플랫폼을 채택하지 않는다.

## A9. 수리적 해석·데이터 보존

- 계산 문구는 `입력 사실 / 정의와 가정 / 계산 / 해석 한계 / 제안`에 연결한다. 제안은 실제 효과 판정과 구분하며, 근거가 부족하다는 이유로 사용자가 허용한 가벼운 방법 제안까지 폐기하지 않는다.
- 그래프에는 필요한 축·단위·기간·분모·자료 시각·출처를 남긴다. 등록 범위의 기록 비율을 실제 시험 범위 완전성으로, 방법 분포를 흥미·실력으로 치환하지 않는다. 그래프 축과 수식은 해당 설계 단계에서 정한다.
- 사용자 응답 원장·원문·수정 이력·근거 ID와 안정 키는 보존한다. 표시 이름을 수정할 때는 연결된 참조·수식·필터·뷰도 함께 대조한다. 디자인을 위해 데이터 의미나 저장 계약을 바꾸지 않는다.
- PDF·Word·슬라이드·시트는 해당 제작 도구의 검증을 따른다. 화면 CSS나 Markdown 재독만으로 페이지 조판·수식 재계산을 확인했다고 하지 않는다.

## A10. 검토와 완료 판단

| 변경 규모 | 필요한 검토 | 확대하지 않을 것 |

요청 누락, 사실·경험·출처 발명, 조건·단위·귀속 변형, 원문/ID/수식 파손, 데이터 손실, 핵심 행동 접근 불가, 부분 성공·미확정 은폐는 표현이 좋아도 통과가 아니다. 단순 문체 취향 차이를 이와 같은 실패로 과장하지 않는다.

검토 기록은 필요한 만큼 `위치 / 조건 / 기대 / 관찰·증거 / 수정 / 상태`를 남기고 `통과 / 실패 / 해당 없음 / 검증 불가`를 구별한다. 기존 장부가 있으면 재사용한다. 확인된 결함을 고친 뒤 영향받는 부분을 다시 확인하며 새 변경·실패 근거 없이 전체 검사를 반복하지 않는다.

파일·설정 저장, 코드 실행, 계산 검사, 합성 DOM, 실제 브라우저, 채팅 수신, 답변 복원, 물리 iPad/iPhone, 보조기술, 알림 수신, 학습 효과는 별개다. 확인하지 않은 단계는 대상과 함께 미검증으로 보고한다. 이 지침의 사례나 검토표만으로 모든 미래 산출물의 품질을 보장하지 않는다.

## A11. 진행 중인 작업에 적용하는 방법

1. 작업을 시작하거나 다시 이어갈 때 루트 `AGENTS.md`와 이 지침의 버전·변경 범위를 확인한다. 이미 진행 중이면 다음 작성·수정·검증부터 적용하며, 완료한 원문·응답을 소급 개작하지 않는다.
2. 현재 진행 상태는 `간단 인계.md`와 그 문서가 연결한 최신 결과를 따른다. 공통 경험 지침에 완료 단계를 고정하지 않는다. 이번 지침 작업으로 이론·시스템 설계를 시작한 것으로 처리하지 않는다.
3. 각 작업의 허용 범위를 정하고 A3의 해당 행, 필요한 상세 절을 적용한다. 필요한 결함 수정은 현재 권한 안에서 수행한다. 전체 코드·모든 질문·외부 앱을 일괄 변경하는 작업으로 확대하지 않는다.
4. 기준을 읽었다는 형식적 보고를 반복하지 않는다. 산출물의 구조·문장·상태·조작에 반영하고, 완료 보고에는 결과와 실제 검증·남은 제한을 적는다.
5. 이 지침은 프로젝트 공통 파일과 작업 인계에 연결한다. 파일 등록과 열려 있는 다른 작업의 지침 재독·즉시 재로딩은 별도다. 다른 작업에 전달·재독을 확인하지 않았다면 ‘모든 작업에 적용 완료’라고 보고하지 않는다.

## A13. 학습 프로그램의 전용 화면·표면·곡률 — 2026-09-14 사용자 추가 지시


- **관계 그림은 실제 구조를 보여 준다.** 학기와 과목의 소속, 목차의 부모·자식 연결을 실제 식별자로 그린다. 선을 선수학습·내용 유사성·능력의 관계로 임의 해석하지 않는다. 과목마다 다른 깊이와 같은 이름의 서로 다른 내용을 보존한다. 연결 지도에서 선택·페이지 열기·공부 입력을 구별하며 보거나 누른 것만으로 공부 완료를 만들지 않는다.
- **정보 구획은 미묘한 표면 차이로 구별한다.** 흰 바탕 전체에 텍스트만 놓지 않고 의미 있는 정보 그룹에 옅은 중립 음영을 준다. 배경·그룹·안쪽 입력·떠 있는 창을 공통 표면 변수로 구분하며, 다크 모드에서도 같은 위계를 유지한다. 문장마다 카드를 만들거나 그림자를 반복해 정보 밀도를 높이지 않는다. 선택·실패·기다림·미확인의 상태 표시는 유지한다.
- **곡률은 공통 규칙을 사용한다.** 새 카드·폼·버튼·메뉴·시트·그래프 노드에 임의의 반경을 산발적으로 넣지 않는다. 고정형 둥근 사각형, 캡슐, 바깥 반경과 안쪽 여백에 맞춘 동심 곡률을 컴포넌트 역할에 맞게 사용한다. 원형 저장 표시·체크·그래프의 모양이 갖는 의미는 유지한다. 현재 웹앱의 공통 모서리·표면 토큰을 재사용하고 의도적인 예외만 설명한다.
