# Notion 중심 UI·UX와 벡터 도해 기준

**2026-10-01 우선순위 정정:** 사용자 결정으로 [최우선 디자인·UI·UX 지침](../generation2/docs/design-ui-ux-priority.md)을 먼저 적용합니다. 이 문서의 Notion/Apple/ChatGPT/Claude 미감은 새 기준 아래에서 보완 참고로 사용합니다. 아래의 이전 기본 표현과 사례가 새 우선순위를 낮추지 않으며 원문/초안/설정·배치/학습 의미/저장·권한은 유지합니다.

**2026-09-30 작업 순서 정정:** [작업 진행과 검증 정책](작업%20진행과%20검증%20정책.md)을 따릅니다. 초안을 먼저 제시하고 검사는 변경·위험·실사용 단계에 맞게 선택합니다. 이 문서의 검사·완료 항목은 모든 초안의 선행조건이 아닙니다.

채택일: 2026-09-30 · 버전 1.0 · 적용 대상: 현재 학습 입력 웹앱, 관련 문서·그래프·도해의 허용된 설계·수정·검수.

**선과 글자로 구조를 드러내고, 여백으로 정돈하며, 필요한 곳에 옅은 색을 더하는 표현을 기본으로 합니다.** 사용자는 Notion을 가장 선호하며, Apple·ChatGPT·Claude의 단정함과 실용성, TikZ 계열 PDF 도해의 정밀함도 같은 선호 안에서 설명했습니다. 특히 “코드로 만든 도해의 정밀함과 종이, 연필, 형광펜의 절제된 표현”에 공통된 미감이 있다는 마지막 정정을 우선합니다.

이는 사용자의 선호를 구현 가능한 조건으로 정의한 프로젝트 기준입니다. ‘Notion 스타일’이나 아래 표현 전체가 업계의 단일 공인 양식이라는 뜻은 아닙니다. 공식 원칙·제품 동작·프로젝트 처방을 구별하며, 근거는 각 절의 공식 링크와 [웹앱 UI 표현 정의](웹앱%20UI%20표현%20정의.md)에 연결합니다.

**2026-10-01 제품 품질 확대 채택:** [웹앱 제품 품질 기준](웹앱%20제품%20품질%20기준.md) Q01–Q15 전부를 지난 작업·현재 작업·앞으로의 작업에 적용합니다. 이 문서의 미감·도해 정의와 함께 실제 입력·찾기·복귀·누적 대응·저장·복원·접근성·권한·업데이트를 판단합니다. 이전 화면도 면제하지 않으며 새 기준의 재평가/보완과 기존 증거를 구별합니다. Notion의 기능·요금제·제한을 그대로 복제하거나 표준 인증으로 표현하지 않습니다.

## 1. 공통 미감의 정확한 뜻

**형태를 적게 쓰되, 각각의 형태가 정보를 맡게 합니다.** 화면과 도해 모두 면적·그림자·효과를 먼저 늘리기보다 제목·문장·선·정렬·여백으로 관계를 보여줍니다. 사용자가 좋아하는 ‘종이·연필·형광펜’은 이를 설명하는 참조입니다. 기본 화면에 종이 사진, 낡은 질감, 연필 입자, 무작위로 흔들리는 선, 손글씨 폰트를 추가하라는 요청으로 읽지 않습니다.

| 공통 속성 | 뜻과 적용 | 판단할 실제 질문 |
| --- | --- | --- |
| 선형 표현 — linework | 윤곽·축·연결선·밑줄이 구조를 설명합니다. 선 굵기와 종류는 역할에 따라 소수로 통일합니다. | 선 하나를 지워도 정보가 같다면 장식인지 검토했습니까? |
| 평면 표현 — flat presentation | 불필요한 부피감 없이 글과 자료가 앞에 옵니다. 팝업의 층 구분처럼 이유가 있는 효과는 허용합니다. | 카드·그림자·광택 없이도 묶음과 조작을 구별할 수 있습니까? |
| 정밀한 관계 — alignment and proportion | 같은 역할의 기준선·시작점·간격이 일치하고, 수량과 위치의 관계가 정확합니다. | 눈으로만 맞춘 배치나 데이터와 다른 길이가 없습니까? |
| 여백 — negative space | 비어 있는 공간이 항목의 묶음과 읽는 순서를 설명합니다. 내용과 기능을 밀어내는 빈 공간은 줄입니다. | 가까운 것과 떨어진 것의 관계를 여백만으로도 이해합니까? |
| 글자 중심 위계 — typographic hierarchy | 제목·본문·보조 설명의 크기·굵기·배치 차이가 중요도를 만듭니다. 많은 서체나 모두 굵은 글씨로 해결하지 않습니다. | 제목, 본문, 보조 설명을 색 없이 구별합니까? |
| 제한된 색 — restrained palette | 중성 바탕과 읽을 수 있는 글자·선이 중심이며, 기존 의미색을 작은 면적에 사용합니다. | 이 색의 역할을 설명할 수 있고, 다른 위치에서도 같은 의미입니까? |
| 국소 강조 — selective highlighting | 형광펜처럼 중요한 단어나 영역에 옅은 채움을 더합니다. 글자는 충분히 어둡게 남기며 포커스·선택·경고는 각각 구별합니다. | 강조가 늘어나 무엇이 중요한지 사라지지 않았습니까? |
| 재현 가능한 표현 — reproducibility | 같은 입력·소스·설정으로 같은 구조를 다시 만들고 수정할 수 있습니다. | 원본과 생성 과정이 있어 숫자·문구를 바꿀 수 있습니까? |

종이에 그린 그림도 축·기호·여백을 절제하면 이 조건에 맞습니다. 코드로 만든 그림도 색·효과·밀도를 과하게 쓰면 맞지 않습니다. 따라서 제작 방식만으로 미감을 판정하지 않고 실제 출력과 사용 흐름을 함께 확인합니다. AI가 코드를 작성하는 것은 허용되지만, 정밀한 그래프·회로·기하 도해·UI 아이콘의 기본 결과물은 코드·벡터로 구성합니다. 생성형 AI 비트맵을 정확한 선·글자·수량의 대체물로 삼지 않습니다.

## 2. 참조 제품의 역할과 충돌 해결

**외형과 정보 배치는 최우선 디자인·UI·UX 지침으로 판단하고, Notion과 아래 제품은 충돌하지 않는 부분을 보완하는 참고로 사용합니다.** 여러 제품의 최신 외형을 한 화면에 합성하지 않습니다.

충돌은 다음 순서로 판단합니다.

1. 현재 사용자 요청, 실제 자료·데이터의 의미, 기존 기록·초안·설정·개인 배치를 보존합니다.
2. 읽기·조작·저장·복구·접근성에 필요한 조건을 충족합니다. 얇고 옅게 만들다가 글자나 포커스를 읽을 수 없으면 대비·굵기·영역을 조정합니다.
3. 브라우저 관례와 이미 채택된 공통 토큰·컴포넌트를 우선 재사용합니다.
4. 가능한 표현 중 Notion 중심의 평면·문서·여백·제한된 강조에 맞는 것을 고릅니다.
5. 시각적 선호만으로 해결할 수 없는 충돌은 실제 사례·보존 조건·대안을 남깁니다. 사소한 선택마다 사용자에게 판단을 넘기지 않습니다.

## 3. 기존 56개 UI·UX 정의의 채택과 적용

**[웹앱 UI 표현 정의](웹앱%20UI%20표현%20정의.md)의 A01–H07, 총 56개 정의를 이 문서의 조건 아래 설계·검수 참조로 채택합니다.** 현재 정의는 활성 웹앱 문서에서 읽으며, 종료한 구현의 과거 지침·보관본은 읽지 않습니다. 모든 용어를 별도 기능으로 구현하라는 명령이 아닙니다.

각 정의의 ‘뜻 → 적용 → 경계 → 검수’를 필요한 작업에서 읽습니다. 본문에 있는 제안 수치·예시는 Notion 공식 토큰으로 승격하지 않습니다. [기존 용어사전](웹앱_설계_용어사전.md)은 범용 412개 용어를, 56개 정의는 Notion 중심의 실제 선택을 설명합니다. 새로운 벡터 도해 용어는 5절에서 보완합니다.

| 범위 | 작업에 적용하는 판단 |
| --- | --- |
| A01–A07: 페이지와 글자의 구조 | 문서 중심의 바탕·앱 셸·위계·서체·행간·읽기 폭·정렬을 정의합니다. 한국어·수식의 읽기와 사용자 서체를 보존합니다. |
| B01–B07: 여백과 정보 밀도 | 여백·간격 리듬·인접성·밀도·평면·구분선·모서리를 정의합니다. 일괄 입력을 쪼개거나 모든 항목을 카드로 감싸지 않습니다. |
| C01–C07: 색·면·아이콘 | 작은 강조와 일관된 의미색을 사용합니다. 옅은 면 위의 글자, 포커스, 선택, 오류를 실제 대비와 비색상 단서로 구별합니다. |
| D01–D07: 탐색과 상세 열기 | 사이드바·경로·탭·목록·검색·상세 패널·모달의 대상과 복귀 관계를 정의합니다. 우측 패널은 과업에 맞게 선택합니다. |
| E01–E07: 콘텐츠와 직접 조작 | 블록·인라인 편집·학습 체크·버튼·선택·드래그·점진적 공개를 정의합니다. 실제 수정·선택과 데이터 의미를 보존합니다. |
| F01–F07: 도구의 발견과 조작 상태 | 명령의 단서·맥락 메뉴·hover·포커스·눌림/선택/비활성·툴팁·단축키를 정의합니다. 핵심 조작을 hover에만 의존시키지 않습니다. |
| G01–G07: 입력과 저장과 복구 | 라벨·값 재사용·한글 편집·실제 저장·취소/되돌리기·비동기·빈/오류 상태를 정의합니다. 원문·커서·초안과 복구 경로를 보존합니다. |
| H01–H07: 반응형·접근성·검수 | 긴 한국어·좁은 높이·화면 키보드·확대·키보드·포커스·테마에서 관련 흐름을 검사합니다. 장식이 조작을 가리지 않게 합니다. |

56개 정의와 현재 실제 구현이 충돌하면 차이를 기록하고 이번 수정 범위 안에서 공통 요소로 해결합니다. 이 문서 등록만으로 기존 화면의 합격이나 일괄 재설계를 선언하지 않습니다.

## 4. 화면과 도해에서 반복되는 결정 규칙

| ID | 적용 규칙 | 피할 구현과 검수 |
| --- | --- | --- |
| U01 | 페이지의 제목·내용·실제 다음 행동을 먼저 읽게 합니다. | 큰 홍보 배너·장식·과도한 상단 여백으로 첫 기록이 밀리지 않는지 봅니다. |
| U02 | 기본 화면은 중성 면과 글자로 구성하고, 조작·상태에 필요한 작은 면을 더합니다. | 모든 항목의 두꺼운 테두리·떠 있는 카드·광택·그라데이션을 기본값으로 만들지 않습니다. |
| U03 | 묶음은 가까운 간격, 묶음 사이는 넓은 간격으로 표현합니다. | 고정 기준선에 모든 글자를 억지로 맞춰 목록이 헐거워지지 않게 합니다. 기존 간격 토큰으로 역할을 구별합니다. |
| U04 | 제목·본문·보조 글자·숫자·기호의 위계를 소수의 공통 스타일로 정합니다. | 작은 회색 글씨로 조건·오류를 숨기거나, 한글 문장 전체를 자간·얇은 굵기로 멋만 내지 않습니다. |
| U05 | 강조색은 행동·상태·주목할 자료에 의미를 부여합니다. | 출제 가능성 orange·확정 red 등 기존 의미를 보존하고, 서로 다른 상태가 같은 옅은 면만으로 표현되지 않게 합니다. |
| U06 | 선·아이콘·구분자는 필요한 구조를 설명하며 크기·굵기를 통일합니다. | 예쁜 작은 아이콘과 실제 조작 영역을 혼동하지 않습니다. 기존 44/48px 기준을 따라 충분한 조작 영역을 둡니다. |
| U07 | 기본 조작과 필요한 조건은 보이게 두고 상세를 선택적으로 엽니다. | 단정함을 위해 중요한 기능·실패·마감·입력을 숨기지 않습니다. 상세 입구를 찾을 수 있게 합니다. |
| U08 | 관련 맥락을 유지하는 보기·패널·분할을 선택합니다. | 작은 화면의 본문 폭, 원래 목록 조작, 닫기·포커스·스크롤 복귀를 확인합니다. 패널을 무조건 늘리지 않습니다. |
| U09 | 입력·저장·반영은 자료와 행동의 실제 상태를 따릅니다. | 기록 저장을 공부 완료로 표현하지 않으며, 실패에도 원문·초안과 재시도 경로를 유지합니다. |
| U10 | 움직임은 상태 변화·위치 관계를 이해시키는 범위에서 사용합니다. | 연속 흔들림·장식 애니메이션을 기본으로 만들지 않습니다. 모션 감소와 편집·스크롤 안정성을 확인합니다. |
| U11 | 그래프와 도해도 같은 선·글자·여백·강조 원칙을 적용합니다. | 선호를 ‘손그림용’과 ‘정밀 코드용’의 서로 다른 미감으로 분리하지 않습니다. 목적별 정확성·조작 요구는 구별합니다. |
| U12 | 기존 요소 → 적합한 라이브러리 → 필요한 최소 맞춤 구현 순서로 선택합니다. | 이미 제공되는 포커스·키보드·축·표준 기호를 매번 다시 만들지 않습니다. 도입해도 실제 사용·테마·저장을 검사합니다. |

## 5. 벡터 도해·그래프 용어와 적용 기준

각 항목은 프로젝트 처방입니다. 도구가 제공하는 능력과 결과물의 품질을 구별합니다. 축·마크·척도는 [Apple Charts](https://developer.apple.com/design/human-interface-guidelines/charts), 벡터·혼합 이미지의 범위는 [SVG 명세](https://www.w3.org/TR/SVG2/), 제작 수단은 2절의 공식 패키지 설명을 참고합니다.

### VF01 벡터 기본 요소 — vector primitives

- **뜻:** 점·선·경로·도형·글자를 좌표와 속성으로 표현하는 요소입니다.
- **적용:** 정확한 윤곽·축·화살표·기호는 SVG·TikZ 또는 적합한 라이브러리의 기하 요소로 만듭니다. 숫자·라벨은 소스에서 수정 가능하게 둡니다.
- **경계:** PDF·SVG라는 확장자만으로 전체 벡터라고 판단하지 않습니다. 두 형식 모두 래스터 이미지를 포함할 수 있습니다. 사진이 필요한 자료는 역할과 출처를 구별합니다.
- **검수:** 필요한 부분을 확대해 선·글자·기호의 구조와 소스를 확인하고, 래스터가 섞이면 의도·해상도·역할을 기록합니다.

### VF02 선의 위계 — stroke hierarchy

- **뜻:** 핵심 선, 보조 선, 배경 선을 굵기·명도·종류로 구별하는 관계입니다.
- **적용:** 주 자료·핵심 경로가 먼저 보이고 축·참조선·그리드는 뒤에 놓이도록 소수의 공통 스타일을 씁니다.
- **경계:** ‘연필처럼’이라는 이유로 모든 선을 희미한 hairline으로 만들지 않습니다. 오류·선택·접근성 표시는 장식보다 우선합니다.
- **검수:** 실제 삽입 크기, 확대, 흑백에서 핵심 선을 읽고 서로 다른 역할을 구별할 수 있는지 봅니다.

### VF03 선 끝과 연결 — caps and joins

- **뜻:** 열린 선의 끝 모양과 꺾이는 부분의 접합 방식입니다.
- **적용:** 같은 역할은 동일한 끝·접합을 사용합니다. 회로·기하·아이콘의 관례에 맞춰 접점과 열린 끝을 표현합니다.
- **경계:** 둥근 끝이 늘 더 세련된 것은 아닙니다. 접점·단절·직각의 의미를 장식 때문에 바꾸지 않습니다.
- **검수:** 짧은 선·좁은 각도·확대에서 틈·과도한 돌출·접점 혼동이 없는지 확인합니다.

### VF04 채움과 투명도 — fill and opacity

- **뜻:** 도형 내부를 채우는 색과 겹쳤을 때 비치는 정도입니다.
- **적용:** 강조 영역은 옅게 채우되 자료선·경계·글자가 읽히게 합니다. 핵심 정보가 투명도에만 의존하지 않게 합니다.
- **경계:** 밝은 화면에서 예쁘다는 이유로 어두운 테마·겹침에서 의미가 사라지는 색을 사용하지 않습니다. 출력을 위한 색은 따로 실제 종이 바탕에서 검사합니다.
- **검수:** 겹친 영역, 다크 테마, 흑백 출력에서 분류·라벨·경계가 남는지 봅니다.

### VF05 강조 영역 — highlight region

- **뜻:** 특정 구간·항목·관계를 읽도록 작은 영역을 강조하는 표현입니다.
- **적용:** 형광펜처럼 국소적이고 평평한 강조를 사용하며, 범위·이유를 라벨이나 문맥으로 알 수 있게 합니다.
- **경계:** 강조가 수치의 크기를 임의로 부풀리거나, 선택·정답·위험·출제 여부를 서로 혼동시키면 안 됩니다.
- **검수:** 색을 지웠을 때도 강조 대상과 상태를 문구·표식으로 확인할 수 있는지 봅니다.

### VF06 표면 질감 — texture

- **뜻:** 종이 결·입자·연필 농담 등 재료의 표면을 표현하는 효과입니다.
- **적용:** 기본은 깨끗한 평면입니다. 사용자가 특정 작품이나 참고자료의 질감을 요청한 경우에만 정보 영역을 방해하지 않는 범위에서 선택합니다.
- **경계:** 종이 미감과 종이 사진을 동일시하지 않습니다. 기본 그래프에 랜덤 흔들림·얼룩·연필 노이즈를 넣지 않습니다.
- **검수:** 질감이 글자·수량·선의 정확성과 파일 크기·편집성을 해치지 않는지 확인합니다.

### VF07 정렬과 간격 — alignment and spacing

- **뜻:** 도해 요소의 시작점·중심·간격으로 관계와 읽는 순서를 만드는 방식입니다.
- **적용:** 노드·라벨·범례·축 제목은 기준을 공유합니다. 관련 항목은 가깝게, 독립 묶음은 더 멀리 놓습니다. 줄바꿈도 간격의 일부로 처리합니다.
- **경계:** 기하·물리 위치나 사용자 Canvas 좌표를 단순히 줄을 맞추기 위해 변경하지 않습니다. 정렬과 실제 좌표의 의미를 구별합니다.
- **검수:** 긴 한글·라벨 증가·좁은 폭에서도 관계를 오독하지 않고 잘림·충돌이 없는지 봅니다.

### VF08 글자와 수학 기호 — typography and notation

- **뜻:** 라벨·단위·수식의 형태와 크기로 역할을 일관되게 나타내는 규칙입니다.
- **적용:** 본문과 조화되는 한국어 글꼴, 일관된 변수·단위·첨자 표기를 사용합니다. 글자·수식·도형의 기준선과 크기를 실제 삽입 크기에서 맞춥니다.
- **경계:** LaTeX 기본 글꼴이 사용자의 전체 앱 서체라는 뜻은 아닙니다. 글자를 윤곽선으로 바꾸면 검색·선택·접근성이 달라지므로 이유를 남깁니다.
- **검수:** 한글 누락·대체 폰트·수식 잘림·첨자 크기·마이너스·단위·글자 선택/추출을 확인합니다.

### VF09 척도와 축 — scales and axes

- **뜻:** 데이터 값을 화면 위치·길이 등에 대응시키는 기준과 그 기준을 읽는 축입니다.
- **적용:** 단위·범위·선형/로그·방향을 명시합니다. 길이로 양을 비교하는 막대는 원칙적으로 0을 기준으로 하며, 다른 기준이 필요하면 이유와 절단을 드러냅니다.
- **경계:** 깔끔함을 위해 중요한 기준을 숨기지 않습니다. 서로 다른 범위의 그래프를 같은 크기의 증가처럼 제시하지 않습니다. 변화 분석의 선 그래프는 목적에 따라 범위를 정하되 오독을 검사합니다.
- **검수:** 소스의 실제 값과 좌표·눈금의 대응, 0·음수·누락·로그의 유효 범위와 단위를 대조합니다.

### VF10 눈금과 격자 — ticks and gridlines

- **뜻:** 위치를 읽는 눈금과 값 비교를 돕는 참조선입니다.
- **적용:** 읽을 수 있는 수의 주요 눈금과 약한 참조선부터 사용합니다. 학습용 정밀 판독에 필요하면 보조 눈금을 추가합니다.
- **경계:** 모든 격자를 없애거나 모든 간격에 진한 격자를 그리는 것을 기본값으로 삼지 않습니다.
- **검수:** 실제 폭에서 숫자 겹침·잘림·단위 반복을 확인하고, 필요한 값을 과도한 추측 없이 읽는지 봅니다.

### VF11 시각적 부호화 — visual encoding

- **뜻:** 수량·범주·관계를 위치·길이·면적·색·선 모양 등에 대응시키는 방법입니다.
- **적용:** 비교 목적에 맞는 부호를 고르고 같은 의미는 같은 표현을 씁니다. 기존 학습 상태의 의미를 그래프에서도 유지합니다.
- **경계:** 미기록을 0점으로, 체크를 숙달로, 횟수를 능력으로 변환하지 않습니다. 원 크기를 수량으로 쓰면 반지름과 면적의 차이를 구별합니다.
- **검수:** 알려진 작은 데이터로 실제 마크를 대조하고 결측·부분 수행·불확실·초과 값의 처리를 확인합니다.

### VF12 범례와 직접 라벨 — legends and direct labels

- **뜻:** 선·마크·색과 실제 항목 사이의 대응을 설명하는 요소입니다.
- **적용:** 항목이 적고 공간이 충분하면 자료 가까이에 직접 이름을 둡니다. 복잡한 경우에는 같은 순서의 범례와 구별 가능한 표식을 제공합니다.
- **경계:** 장식용 약어와 색만으로 항목을 구별하지 않습니다. 긴 한국어 이름을 임의로 잘라 의미를 잃지 않게 합니다.
- **검수:** 여러 곡선·겹친 끝점·좁은 폭·키보드 탐색에서도 어느 항목인지 찾을 수 있는지 봅니다.

### VF13 주석과 화살표 — annotations and arrows

- **뜻:** 설명을 특정 요소와 연결하거나 관계·방향을 표시하는 선과 문구입니다.
- **적용:** 선의 출발·끝·방향을 분명히 하고 문구를 자료와 가깝게 둡니다. 원인·순서·참조·전류 등 화살표의 의미를 정합니다.
- **경계:** 단순 관련성을 인과로 그리지 않습니다. 사용자 Canvas 연결선과 기하학적 방향을 임의로 합치지 않습니다.
- **검수:** 선 교차·가려짐·끝점·읽는 순서와 실제 관계를 확인합니다.

### VF14 오차와 불확실성 — uncertainty representation

- **뜻:** 측정 오차·범위·추정의 한계를 드러내는 표현입니다.
- **적용:** 근거 있는 구간·오차막대·영역을 쓰고 무엇의 범위인지 설명합니다. 정보가 없으면 없다고 표시합니다.
- **경계:** 예쁘게 보이도록 임의의 신뢰구간·매끈한 곡선·예측값을 생성하지 않습니다. 추정과 관측은 구별합니다.
- **검수:** 원자료·계산·주석을 대조하고 불확실 영역의 색이 확정 상태와 혼동되지 않는지 봅니다.

### VF15 비율과 기하 정확성 — aspect and geometry

- **뜻:** 도형·거리·각도·그래프 가로세로 비율이 의미에 미치는 관계입니다.
- **적용:** 원·각·거리처럼 기하를 판단하는 그림은 좌표 비율을 보존합니다. 함수 그래프의 종횡비는 목적을 설명할 수 있게 고릅니다.
- **경계:** 원을 타원으로 늘이거나 기울기를 과장하는 좁은 그래프를 무심코 사용하지 않습니다. 개념도는 실제 비례가 아니면 이를 알립니다.
- **검수:** 기준 점·길이·각·화살표·축 비율을 수치나 구성 소스로 확인합니다.

### VF16 2차원·3차원 — dimensionality

- **뜻:** 평면 정보와 깊이·공간 방향을 필요한 만큼 표현하는 선택입니다.
- **적용:** 일반적인 수량 비교는 읽기 쉬운 2차원을 먼저 검토합니다. 공간 좌표·곡면·벡터·회로 배치의 깊이가 실제 의미라면 3차원을 사용하고 좌표·방향·가려짐을 정의합니다.
- **경계:** 3차원을 모두 금지하지 않습니다. 현재 웹앱의 사용자 3차원 기능이 있다면 보존합니다. 수량 비교에 장식적 원근·입체 막대·그림자를 기본으로 더하지 않습니다.
- **검수:** 시점 변화·가려진 라벨·원근·축 방향을 확인하고, 필요한 경우 정면/단면·값·표 등 보완 경로를 제공합니다.

### VF17 표준 기호 — standard symbols

- **뜻:** 분야에서 정한 모양·라벨·접점 관례로 요소를 표현하는 방식입니다.
- **적용:** 회로는 CircuitikZ 등 표준 요소와 해당 분야의 표기 관례를 사용합니다. 기호·극성·접점·분기·단위는 일관되게 구성합니다.
- **경계:** 미감을 위해 저항·접지·접점 등의 의미를 바꾸거나 선 교차를 자동 접속으로 읽지 않습니다. 규격 계열이 다르면 확인한 계열을 명시합니다.
- **검수:** 연결 목록·극성·기호 정의·접점·라벨을 소스와 맞춥니다. 패키지 사용만으로 회로의 물리적 타당성을 인증하지 않습니다.

### VF18 상호작용 — interaction

- **뜻:** 자료 선택·필터·확대·툴팁 등이 읽기와 탐색을 돕는 동작입니다.
- **적용:** 화면에서는 필요한 선택·값 확인·키보드·터치 경로를 제공합니다. PDF에서는 정적인 라벨·설명으로도 의미가 완결되게 합니다.
- **경계:** hover에만 단위·핵심 값을 두지 않습니다. 확대를 이유로 사용자 Canvas 뷰포트·노드 위치를 초기화하지 않습니다.
- **검수:** 선택·해제·줌·복귀·포커스·좁은 화면과 실제 데이터 갱신 뒤 상태를 확인합니다.

### VF19 확대·접근성·대체 설명 — scaling and accessibility

- **뜻:** 표시 크기·시각 조건·조작 방식이 달라도 정보를 읽는 조건입니다.
- **적용:** 실제 삽입 크기와 확대에서 글자·선·라벨을 확인하고, 색 외의 표식·짧은 설명·값 목록이나 표를 목적에 맞게 제공합니다.
- **경계:** 벡터 확대가 작은 글자를 읽기 쉽게 만들어 주거나 스크린리더 접근성을 자동 해결하지는 않습니다. Canvas 렌더와 PDF의 접근성도 각각 확인합니다.
- **검수:** 100%·200% 화면, 필요할 때 더 큰 확대, 흑백, 관련 테마, 키보드·대체 설명 경로를 확인합니다. 물리 기기·보조기술을 실행하지 않았으면 미검증으로 남깁니다.

### VF20 내보내기와 재현 — export and reproducibility

- **뜻:** 다른 화면·문서·인쇄에서 같은 의미를 전달하고 다시 수정·생성하는 조건입니다.
- **적용:** 원자료·생성 코드·스타일 설정·필요한 버전·폰트·변환 과정을 함께 보존합니다. 최종 SVG·PDF의 실제 크기·여백·폰트·잘림을 검사합니다.
- **경계:** PNG 미리보기만 전달하거나, PDF 생성 성공만으로 벡터·글자·데이터·접근성 검수를 끝내지 않습니다. 재현을 위해 불필요한 전체 환경 설치를 요구하지 않습니다.
- **검수:** 실제 결과를 열고 페이지 경계·대체 폰트·선·수식·래스터 포함·글자 추출을 확인합니다. 다시 생성한 결과는 의미·기하·라벨 기준으로 대조합니다.

## 6. 토큰과 실제 구현의 보존

**새 지침의 방향과 현재 코드 값을 구별합니다.** 이번 작업은 디자인 기준의 채택입니다. 제품 토큰·컴포넌트·저장 구조를 변경하지 않았으며, 기존 수치를 Notion 공식 수치로 해석하지 않습니다.

- 현재 웹앱은 [디자인 시스템](../generation2/docs/design-system.md)과 [현재 토큰](../generation2/src/ui/tokens.css)을 사용합니다. 현재 중성 바탕·본문과 인터페이스 서체 구분·의미색·간격·모서리·조작 크기는 구현의 사실이며 이번 기준이 자동 변경한 값이 아닙니다.
- 향후 허용된 화면 변경에서 현재 과도한 카드·모서리·그림자가 실제로 경쟁을 만들면 영향받는 공통 토큰·컴포넌트와 상태를 확인한 뒤 필요한 범위를 조정합니다. 숫자를 화면별로 임의 하드코딩하지 않습니다.
- 출제 가능성 orange·확정 red, 학습 활동·시도·저장·목표·독립 수행의 구별, 원문·ID·메모·반복·초안·개인 기준·Canvas 배치를 유지합니다. 미감을 위해 의미를 재분류하거나 기능·입력·설정을 삭제하지 않습니다.
- 다크 테마에서도 밝은 화면과 같은 위계·정렬·국소 강조를 유지합니다. 인쇄용 종이 바탕과 화면의 밝기 선택은 목적별로 검토합니다. 사용자 테마를 강제로 밝은 테마로 바꾸지 않습니다.
