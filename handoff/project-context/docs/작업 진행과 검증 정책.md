# 작업 진행과 검증 정책

2026-09-30 사용자 정정에 따른 현재 공통 정책. 적용 대상: 진행 중인 학습 입력 웹앱 및 관련 설계·문서·도해 작업.

**기본 흐름은 필요한 맥락·기존 기준과 방법 확인 → 적합한 방법 선택·적용 → 볼 수 있는 초안 → 변경에 직접 필요한 확인·수정 → 유지보수입니다.** 검사는 결과를 개선하는 수단입니다. 모든 검사·문서·근거를 먼저 완성해야 초안을 보여줄 수 있다는 방식으로 운영하지 않습니다. 상세 지침의 ‘전달 전 검증’·‘완료 기준’·검사 목록은 아래 단계에 맞춰 해석하며, 초안 제시의 일괄 선행조건으로 사용하지 않습니다.

## 1. 먼저 보여줄 결과

- 요청을 받은 뒤 대상 세대·수정 위치·보존할 자료를 좁혀 곧바로 첫 결과를 만듭니다. 문서는 실제 본문, 화면은 열어 볼 수 있는 실행 화면이나 시안, 기능은 핵심 정상 흐름을 가진 초안으로 제시합니다. 계획·검사 목록·빈 껍데기만으로 초안을 대신하지 않습니다.
- 작은 문구·간격·배치 수정은 바로 반영하고 해당 부분을 짧게 확인합니다. 새 테스트·보고서·전수 화면 검사를 일률적으로 만들지 않습니다. 이미 이용 가능한 미리보기·브라우저·컴포넌트·라이브러리를 우선 사용합니다.
- 큰 변경도 전체를 설계·감사한 다음에만 공개하지 않습니다. 의미 있는 첫 화면·입력 흐름·도해·본문부터 보여주고 같은 작업 안에서 이어 개선합니다. 예시 자료로 만든 부분은 실제 사용자 기록과 구별합니다.
- 초안·시연에는 미완인 조건을 짧게 표시합니다. ‘초안 준비’와 ‘실사용 준비’를 구별하면, 전체 QA가 끝나지 않아도 결과를 보여줄 수 있습니다. 권한 안에서 가능한 후속 구현은 계속하며 초안만 보인 뒤 불필요한 승인 대기로 멈추지 않습니다.

### 1.1. 기존 기준·방법·스킬·도구의 우선 조사와 선택

2026-10-01 사용자 정정: 모든 작업·연구에서 먼저 잘 만들어진 기존 기준·방법을 찾아 적용합니다. 공통 AGENTS.md와 전역 AGENTS.md의 우선 조사 원칙을 다음 순서로 실행합니다.

1. **작업에 맞는 기존 기준을 확인합니다.** 요청의 목적·산출물·제약을 좁힌 뒤 현재 채택 기준·관련 구현·사용 가능한 스킬과 도구를 확인합니다. 해당 분야의 대표 법칙·표준·방법론·작업 관행·선행 사례에서 필요한 근거를 찾습니다. 새롭거나 불확실하거나 바뀔 수 있는 근거는 공식 문서·표준 기관·원 연구 등을 실제 검색으로 확인합니다. 단순 수정은 관련된 기존 기준과 도구를 짧게 확인하며 전수 조사를 하지 않습니다.
2. **후보를 비교하고 선택합니다.** 목적과 적용 가정·근거·호환성·실제 사용 가능성·비용과 부담·유지보수를 판단합니다. 유명세를 표준이나 효과의 증거로 쓰지 않습니다. 스킬의 본문과 적용 조건을 읽고 선택한 방법을 실제 작업에 연결합니다.
3. **재사용하고 부족한 부분만 만듭니다.** 적합한 기존 기준·방법·도구를 사용하고 필요한 범위만 조정·조합합니다. 직접 설계·구현할 때는 기존 후보로 해결되지 않는 구체적인 요구와 자체 제안 부분을 밝힙니다. 확인하지 못한 기준은 미확인으로 남기며 존재하지 않는다고 단정하지 않습니다.
4. **근거를 짧게 남기고 결과를 만듭니다.** 주요 선택에는 이름·출처·선정 이유·적용 범위와 한계를 기존 담당 문서나 작업 보고에 필요한 만큼 남깁니다. 작은 수정마다 별도 조사 보고서를 만들지 않습니다. 기존 조사의 유효성을 확인했으면 재사용하고, 선택할 근거가 확보되면 초안·실제 구현으로 전환합니다. 사용자 자료·저장·권한·종료한 보관본 제한을 유지합니다.

이 조사·선택은 첫 결과를 만들기 전의 관련 확인이며, 모든 후보 조사·전체 QA·시안 반복의 선행조건으로 확대하지 않습니다. 지침의 위치와 하위 프로젝트 연결은 [AGENTS.md 공식 안내](https://agents.md/)의 형식을 참고합니다. 여기서 정한 기존 방법 우선 원칙과 선정 절차는 이번 사용자 결정입니다.

### 1.2. 생성 단계에서 반복 사용·자료 누적을 반영

2026-10-01 사용자 정정: 그래프뷰의 첫 구현에서 자료 증가에 따른 힘·간격·이름 표시의 자동 조정을 빠뜨린 문제를 생성 단계의 작업 기준으로 바로잡습니다. 이 절은 그래프에 한정하지 않고 새 기능/화면과 큰 변경에 적용합니다. 기존 방법 조사(1.1절) 다음에 관련 사용 조건을 좁히고, 첫 결과의 설계·구현·완료 판단에 함께 반영합니다. 계획이나 긴 검사표를 새 선행 산출물로 요구하지 않습니다.

1. **계속 사용했을 때 바뀌는 조건을 먼저 고릅니다.** 현재 입력·저장 구조와 실제 과업에서 평소 사용, 자료 누적/긴 내용/연결 밀도 증가, 반복 편집·삭제, 중단·새로고침·재접속, 좁은 화면/다른 입력 방식, 지연·실패 중 직접 관련된 것을 선택합니다. 예상 규모는 실제 자료·허용 입력·알려진 사용 방식으로 정하고 근거 없는 고정 수치나 무제한 대응을 요구하지 않습니다. 규모를 아직 모르면 확인용 합성 범위와 미확정을 구별합니다.
2. **사용자가 조절하지 않아도 성립하는 기본 동작을 구현합니다.** 라이브러리의 옵션 존재와 라이브러리 기본값을 현재 과업에 적합한 기본 동작으로 간주하지 않습니다. 필요한 입력/재계산 조건과 자동값 선택을 실제 흐름에 연결합니다. 예를 들어 그래프는 항목 수·연결·이름 길이·영역 변화에 따른 간격/힘/겹침/보기 범위, 칸반은 카드 누적·긴 글·열 증가에서도 찾기/이동/읽기, 입력은 반복 저장·실패 뒤 재시도/복귀가 성립해야 합니다. 이는 현재 과업의 기본 동작이며 새로운 기능 후보를 전부 채택하는 지시가 아닙니다.
3. **자동화와 사용자 상태를 함께 설계합니다.** 언제 다시 계산하고 무엇을 유지할지 정합니다. 내용 갱신이 불필요한 재배치·재마운트·포커스 이동·설정 초기화를 만들지 않게 하고, 빠른 변경의 오래된 결과를 막습니다. 원문·ID·이력·선택/초안·개인 배치/수동 설정의 보존 범위와 복귀 시 복원을 과업에 맞게 구현합니다. 자동으로 계산하는 탐색 배치와 저장된 개인 Canvas 배치는 구별합니다. 결과를 조정/취소/되돌리거나 자동값으로 돌아갈 수 있어야 하며, 필요 없는 고급 값을 평소 입력의 필수 단계로 만들지 않습니다.
4. **관련 변화 조건에서 확인하고 완료를 판정합니다.** 핵심 정상 흐름 외에 고른 증가/변화와 중요한 중단·복귀/실패를 합성 자료 또는 허용된 실제 환경에서 직접 확인합니다. 예를 들어 표시된 글의 겹침·가로 넘침·조작 가능 여부, 입력 지연, 저장/재접속 원문과 순서 일치, 수동 상태 보존처럼 관측할 수 있는 결과를 씁니다. 반복 가치가 있는 실패 경로만 관련 회귀 검사에 연결합니다. 모든 상태·기기의 검증을 초안 공개 조건으로 만들지 않으며, 실제 장기 관찰/물리 기기/학습 효과는 별도 미확인으로 유지합니다.
5. **예측 가능한 필수 누락은 같은 작업에서 처리합니다.** 첫 생성 시 통상적으로 필요한 누적 대응·자동 기본값·복구를 ‘사용자가 아직 말하지 않았다’는 이유로 제외하거나 다음 요청으로 넘기지 않습니다. 현재 과업의 사용을 막는 누락과 선택적인 새 기능을 구별합니다. 큰 작업의 첫 결과를 보여준 뒤 같은 허용된 작업 안에서 연결하며, 관련 없는 앱 전체 개편·외부 배포·개인자료 전송으로 권한을 확대하지 않습니다. 선택한 조건/자동값/보존 범위/확인한 결과와 직접 남은 조건만 기존 계약·인계에 짧게 남깁니다.

근거와 적용 한계: [NN/G 사용성 구성 요소](https://www.nngroup.com/articles/usability-101-introduction-to-usability/)의 반복 사용 효율·재방문·오류 복구와 [점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/)를 설계 판단에 참고합니다. 이는 사용성 권고이며 자동 배치의 최적 공식이나 이번 앱의 효과 검증이 아닙니다. 좁은 화면의 내용/기능 보존은 [W3C Reflow 설명](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)을 참고하며, 그래프처럼 본질적으로 2차원인 영역의 예외를 구별합니다. 전체 WCAG 준수를 이 선택 확인으로 주장하지 않습니다. 위 생성 단계의 실행 책임·완료 조건은 이번 사용자 결정입니다.

### 1.3. 제품 품질 기준을 과거·현재·미래 작업에 적용

2026-10-01 사용자 결정: [웹앱 제품 품질 기준](웹앱%20제품%20품질%20기준.md) Q01–Q15 전부를 현재 웹앱의 지난 작업·진행 중인 작업·앞으로의 모든 작업에 적용합니다. 이전의 완료/배포 보고를 적용 면제나 새 기준 통과의 증거로 쓰지 않습니다.

1. 작업 시작에 관련 Q 항목·기존 연결 경로·보존할 상태·관측할 결과를 고릅니다. 새 설계와 구현뿐 아니라 현재 남아 있는 이전 기능도 같은 기준으로 대조합니다. 통상 필요한 기본 동작의 누락은 같은 허용 범위에서 보완합니다.
2. 전체 품질/잔여 보고는 15개와 주요 기능/데이터 계약을 모두 대조합니다. 과거 검증의 시점·범위·버전은 보존하고 새 기준에 대한 미대조·구현 결함·검증 잔여를 구별합니다. 일부 선택 검사의 통과를 제품 전체 완료로 표현하지 않습니다.
3. 개별 변경의 확인은 2~3절의 위험·시점 기준을 유지합니다. 정상 흐름과 중요한 누적/변화/실패를 선택하고 실제 조작·저장·복귀로 연결합니다. 전 영역 적용을 작은 변경의 전수 QA나 첫 결과 지연 조건으로 확대하지 않습니다.
4. 실제 증거를 자동/직접 흐름/관련 변화·실패/물리 기기·반복 사용의 범위로 구별해 기존 담당 문서·인계에 짧게 남깁니다. 종료한 앱·보관본을 재개하거나 새 외부 전송/배포 권한을 만들지 않습니다. 지침 변경 자체를 제품 재검증으로 보고하지 않습니다.

## 2. 확인의 시점을 나누는 기준

| 단계 | 필요한 확인 | 뒤로 미룰 수 있는 확인 |
| --- | --- | --- |
| 초안·시안·격리된 시연 | 올바른 수정 대상, 요청의 핵심 반영, 기존 자료를 덮어쓰지 않는 범위, 열림·빌드·핵심 경로 중 해당 결과를 보는 데 필요한 확인 | 모든 테마·뷰포트·기기, 실패 조합·성능·전체 회귀, 전수 근거표·기록 감사 |
| 실제 사용·설치·배포 | 바뀐 핵심 경로가 작동하는지, 변경과 연결된 기록 보존·저장·필요한 복구, 대상·산출물·설치/배포 상태. 프로젝트가 실제로 요구하는 빌드·CI·타입·필수 검사를 이 단계에서 충족 | 관련 없는 기능 전체, 영향을 받지 않은 과거 QA, 실제 제공하지 않는 환경·기능 검사 |
| 유지보수·안정화 | 새 오류·반복 문제·공통 요소 영향에 따른 회귀, 추가 기기·접근성·성능·실패 경로, 가치가 있는 반복 검사 자동화 | 근거 없이 같은 검사 반복, 매번 전체 원장·자료·앱 다시 감사 |

위 구분은 초안에서 실제 데이터 손상을 허용하는 뜻이 아닙니다. 삭제·이관·저장 키/형식·ID·동기화·권한·원장 계산 등 손실이나 잘못된 실제 기록을 만들 수 있는 변경은 **그 위험에 직접 연결된 확인을 실제 자료에 적용하기 전에** 합니다. 확인이 오래 걸리면 먼저 격리된 자료나 비파괴 시안을 보여줍니다. 실제 사용의 필수 확인을 유지보수로 미룬 채 안정판이라고 표시하지 않습니다.

물리 기기·OS 한글 입력·Sync·보조기술은 해당 기능을 제공·보장하는 단계에서 확인합니다. 접근할 수 없는 환경 때문에 화면 초안 제시나 다른 허용된 구현을 멈추지 않습니다. 실행하지 않은 환경은 짧게 남기며 통과로 추정하지 않습니다. 검증을 뒤로 미룬 것은 자동 예약·감시·새 대화 실행 지시가 아닙니다.

### 2.1. 핵심 사용자 흐름의 실제 확인과 완료 보고

2026-10-01 사용자 요청: “실제로 해본거야?”라는 재확인을 사용자가 해야 하는 보고를 바로잡고, 계정·권한·탈퇴 작업에서 적용한 실제 조작과 근거 구분을 이후 웹앱 작업의 기준으로 유지합니다.

- **사용자가 하려는 행동을 끝까지 확인합니다.** 바뀐 기능을 사용할 시작 상태·입력·버튼·저장 또는 권한 변경·재접속 후 결과 중 직접 필요한 흐름을 정하고 실행합니다. 기능을 구현·사용 가능 상태로 전달할 때는 해당 핵심 화면을 직접 조작하고 연결된 저장 결과를 확인합니다. 설치·배포까지 허용된 작업은 운영 서버와 배포된 화면의 결과도 확인합니다. 이는 관련 없는 전체 QA·모든 기기 확인을 초안의 선행조건으로 추가하는 뜻이 아닙니다.
- **확인한 환경과 방법을 구별합니다.** 자동검사·모의 서버·격리된 로컬 화면·운영 서버 API·배포된 화면의 직접 조작·실제 사용자 계정·물리 기기의 근거를 각각 구별합니다. 시험 계정이 운영 서버를 사용한 결과는 운영 서버 확인으로 인정하되 민석 본인 계정이나 실제 기기를 조작한 것처럼 보고하지 않습니다. 코드·빌드·CI·자산 일치·API 성공만으로 화면의 전체 사용 흐름이 작동했다고 단정하지 않습니다.
- **계정·권한·탈퇴는 역할과 상태를 바꾸어 확인합니다.** 변경에 맞춰 이름 입력/수정과 관리자 목록, 이메일 확인과 승인 대기, 관리자 결정과 일반 계정의 이용, 본인 탈퇴와 재접속 차단을 필요한 범위에서 연결해 시험합니다. 허용뿐 아니라 타인 계정 변경 거부·일반 사용자의 관리자 접근 거부·중지/탈퇴 후 남은 인증 정보의 접근 거부도 관련 경로에서 확인합니다. 이용 중지의 기록 보존과 탈퇴의 명시적 삭제 범위를 구별하며 다른 사람의 자료·권한이 유지되는지 확인합니다.
- **실제 자료를 시험 자료로 쓰지 않습니다.** 허용된 대상에서 별도 시험 계정과 격리된 자료를 사용하고, 이번에 만든 계정·원장·권한·임시 메일함·인증 정보·기기 사본을 정확한 대상만 지정해 정리합니다. 기존 사용자 비밀번호·세션·기록을 읽거나 복제하여 검증을 대신하지 않습니다. 본인 계정의 실제 탈퇴 같은 되돌릴 수 없는 행동은 검증을 이유로 임의 실행하지 않습니다.
- **대체한 단계는 성공으로 채우지 않습니다.** DB에서 시험 계정을 생성하거나 이메일 확인 상태를 지정한 것은 실제 가입 화면의 성공이나 확인 메일 수신/링크 실행의 증거가 아닙니다. API에서 승인 상태를 바꾼 것은 관리자 버튼을 누른 증거가 아닙니다. 메일 한도·인증·네트워크·접근 불가로 막히면 실패한 단계·원인·확인한 나머지·남은 직접 조건을 밝히고, 가능한 구현과 독립적인 검증은 계속합니다.
- **완료의 범위를 첫 문장부터 맞춥니다.** 구현·서버 적용·공개 배포·핵심 흐름 직접 확인·검증 잔여를 실제 근거에 맞춰 보고합니다. 이번 기능의 핵심 과정이 확인되지 않았으면 “다 끝났다”, “전체 흐름 확인”으로 묶지 않습니다. 사용자가 “실제로 해봤나”를 묻기 전에 무엇을 어디에서 직접 실행했는지와 남은 조건을 짧게 알립니다. 이미 확인한 범위는 유지하며 새 변경·실패·영향 없이 같은 검사를 반복하지 않습니다.

## 3. 검사 범위를 늘리는 조건과 끝내는 조건

- 먼저 ‘이번에 무엇이 바뀌며 어떤 실패를 직접 예방해야 하는가’를 짧게 판단하고 필요한 검사만 고릅니다. 작은 수정에 별도 검증 계획 문서나 점수표를 의무화하지 않습니다.
- 빠르고 관련된 기존 확인을 먼저 사용합니다. 한 가지 속성이 이미 적절한 방법으로 확인됐으면 같은 주장을 다른 형식의 검사로 반복하지 않습니다. 실제 동작처럼 앞 확인이 증명하지 못하는 속성은 별도로 검사하되 필요한 범위로 제한합니다.
- 검사 확대는 새 실패, 공통 컴포넌트·저장 구조 등의 영향, 새로운 수정, 명시적인 전수 검토·배포 요구가 있을 때 합니다. ‘더 확실하면 좋다’는 이유만으로 범위를 계속 늘리지 않습니다.
- 선택한 필수 확인이 통과하면 결과를 전달하고 실행 범위를 완료합니다. 전체 과거 QA의 열린 항목을 이번 작은 작업의 자동 차단 사유로 가져오지 않습니다. 현재 변경과 직접 연결된 필수 실패는 해결하거나 실사용 조건으로 명시합니다.
- 회귀 자동화는 반복 가치가 있는 실패·중요 경로에 한해 기존 구성을 재사용합니다. 구현을 그대로 따라 쓰는 테스트, 검사 횟수 늘리기, 의미 없는 해시·보고서 반복 생성을 피합니다.

현재 사용자 요청이 이 정책과 다른 작업 순서·범위를 지정하면 그 요청을 적용합니다. 적용 가능한 시스템·개발자 지침이나 실제 필수 CI를 프로젝트 문서로 무효화하지 않습니다.
