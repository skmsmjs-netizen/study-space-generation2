# 웹앱 제품 품질 기준

채택일: 2026-10-01. 사용자 결정: “이 기준 다 지침에 적용해. 지난 작업들, 앞으로의 작업들에 저 지침이 모두 적용된다.”

**아래 Q01–Q15 전부를 현재 학습 입력 웹앱의 지난 작업·진행 중인 작업·앞으로의 작업에 적용합니다.** 실제 판매 없이 성숙한 개인 공부 도구의 완성도를 목표로 합니다. 이 문서는 제품 품질의 담당 기준이며 [공통 AGENTS.md](../AGENTS.md)와 [웹앱 AGENTS.md](../generation2/AGENTS.md)를 통해 하위 경로·작업에 상속됩니다. 실행 시점과 검사 범위는 [작업 진행과 검증 정책](작업%20진행과%20검증%20정책.md)이 담당합니다.

채택 근거는 [2026-10-01 제품 품질 조사](../outputs/20261001-product-quality-research/노션급-제품-품질-조사.md)입니다. 해당 조사 문서만 명시적으로 채택한 출처로 연결하며, 다른 과거 outputs나 종료한 보관본을 다시 탐색하는 권한으로 확대하지 않습니다. 조사 당시의 제안·미검증 기록은 보존합니다. 아래 15개 영역의 조합과 앱별 적용 규칙은 프로젝트 기준이며 Notion의 내부 평가표나 ISO의 공식 등급이 아닙니다.

## 1. 적용 대상과 과거 작업의 처리

- 설계·연구·문서·도해·구현·수정·리뷰·검증·배포·유지보수에 적용합니다. 이미 완료·검사 통과·배포를 보고한 현재 웹앱의 화면·기능·저장·서버도 적용 대상이며, 이전 완료 판정을 이유로 면제하지 않습니다.
- 지난 작업의 현재 구현과 증거를 새 기준으로 재평가하고 필요한 보완을 이어갑니다. 기존 검사 결과·버전·시점·자료는 보존합니다. 과거의 제한된 통과를 새 기준 전체 통과로 바꾸거나, 새 기준이 생겼다는 이유만으로 과거 검사가 실패했다고 바꾸지 않습니다. 아직 대조하지 않은 항목은 새 기준 미검증으로 남깁니다.
- 개별 작업에서는 관련 영역과 연결된 기존 기능을 골라 적용하고 확인한 필수 누락을 같은 허용 범위에서 보완합니다. 전체 상태·잔여·제품 품질 평가에서는 Q01–Q15와 실제 기능/데이터 계약의 주요 범위를 모두 대조하고 누락을 드러냅니다. 새 작업에만 적용하거나, 개별 선택 검사로 제품 전체를 완료 처리하지 않습니다.
- 지난 작업은 현재 웹앱에 남아 있는 구현과 계약을 뜻합니다. 종료한 Obsidian·Vault·플러그인·보관본은 재개하지 않습니다. 실제 판매·결제·마케팅·기업 협업 기능은 품질 목표 때문에 자동 추가하지 않습니다.
- 원문·답변·이유·조건·예외·ID·저장 키·이력·초안·사용자 설정·서체·테마·Canvas 좌표/연결/개인 배치를 보존합니다. 민석 전용 AI 권한, 사용자별 자료 격리, 체크와 숙달의 구별을 유지합니다. 자료가 없다는 이유로 결과·완료·정확성·학습 효과를 추정하지 않습니다.

- **웹 지표:** LCP ≤2.5초, INP ≤200ms, CLS ≤0.1을 모바일/데스크톱별 75백분위 권고로 사용합니다. 실제 사용자 측정과 실험실 결과를 구별하고, 입력·검색·저장 왕복·재열기·Canvas는 별도 시나리오로 측정합니다.
- **체감 응답:** 0.1초·1초·10초는 NN/G의 참고 구간입니다. 모든 처리를 0.1초에 완료하거나 10초 지연을 일률 허용하는 기준이 아닙니다. 긴 처리는 사실에 맞는 진행·중단·다른 작업 지속을 제공합니다.
- **접근성:** 일반 글자 대비 4.5:1, 큰 글자 3:1, 글자 200% 확대, 세로 읽기 내용의 320 CSS px 재배치를 관련 WCAG 요구/예외와 함께 확인합니다. 본질적으로 2차원인 표/그래프의 예외를 문서 전체의 불필요한 가로 스크롤로 확대하지 않습니다.
- **조작 대상:** WCAG 2.2 AA 최소 24×24 CSS px 또는 규정에 맞는 간격/예외와 현재 프로젝트의 48px 핵심 조작·44px 아이콘 조작 설계값을 구별합니다. 드래그 없이 가능한 단일 포인터 대안과 키보드 대안은 별도로 확인합니다.
- 측정에는 자료 크기·기기/연결·시작/끝·중앙값과 느린 경우를 남깁니다. 한 사람의 측정을 다수 사용자 통계로 표현하지 않습니다. 원문 손실·잘못된 소유권·중복 기록·막힌 핵심 조작을 다른 품질의 평균 점수로 상쇄하지 않습니다.

## 4. 실제 작업과 완료 판단에 연결하는 방법

1. 요청과 현재 구현을 좁힌 뒤 관련 Q 항목, 보존할 상태, 관측할 정상 결과와 중요한 변화/실패를 선택합니다. 이미 조사·채택한 근거가 유효하면 재사용하고 필요한 부분만 다시 확인합니다.
2. 새 구현뿐 아니라 연결된 기존 화면/저장/서버에도 적용합니다. 필수 누락을 확인하면 현재 허용된 작업 안에서 수정하고, 범위를 넘는 보완은 구체적 대상·이유·의존성을 남깁니다. 전체 평가에서는 15개를 전부 대조하며 미구현을 검증 잔여로 숨기지 않습니다.
3. 볼 수 있는 결과를 먼저 만들고 변경의 위험에 맞는 실제 조작·저장·재접속·중요한 누적/실패 조건을 확인합니다. 자동/합성/브라우저 기기 환경과 물리 기기·반복 사용·학습 효과의 증거를 구별합니다. 사용자에게 다시 허용을 요구하지 않고 기존 권한 안에서 이어갑니다.
4. 보고에는 관련 Q 항목과 `미구현 / 부분 구현 / 구현됐으나 검증 잔여 / 제외·보류`를 연결합니다. 증거는 `기준 정의 / 구현·자동 확인 / 직접 흐름 확인 / 관련 변화·실패 확인 / 물리 기기·반복 사용 확인`의 실제 도달 범위를 버전·환경·시점과 함께 기록합니다. 이는 프로젝트 보고 구분이며 공식 인증 등급이나 매번 전 단계 통과 조건이 아닙니다.
5. 선택한 관련 확인이 통과하면 전달합니다. 새 변경·실패·영향 근거가 없는데 검사를 반복/확대하지 않습니다. 지침 저장·도구 설치·검사 개수·문구 제거를 제품 전체 완료로 표현하지 않습니다.

전체 품질 평가의 대표 흐름은 첫 기록/상세/복귀, 긴 한글 편집/초안 복원, 누적 자료 검색/위치 복귀, 원자료/시험/당시 근거, 개인 배치/자료 증가/재열기, 서버 반영 후 응답 유실/중복 없는 재시도, 기기 전환/동시 편집/충돌 해결, 삭제/버전/내보내기/지원 범위 재가져오기, 이전 자료/오래 열린 탭/업데이트입니다. 구체적인 경로와 합성 규모는 현재 기능·계약에서 고릅니다. 이 목록을 작은 변경의 전수 QA로 강제하지 않습니다.

## 5. 채택 상태와 권한

이 문서의 채택은 과거·현재·미래 작업에 대한 실제 지침 변경입니다. 현재 제품 전체를 Q01–Q15로 이미 재검증하거나 보완한 결과는 아닙니다. 이후 기존 기능의 평가와 보완도 이 기준으로 수행하며 과거 작업이라는 이유로 제외하지 않습니다. 이번 지침 변경만으로 새 공개 배포·개인자료 외부 전송·삭제·유료 결제·외부 신청 제출의 권한을 만들지 않습니다. 해당 대상의 기존 권한과 보류를 유지합니다.
