# 웹앱 디자인 도구 기준

현재 학습 입력 웹앱용 기준입니다. 2026-10-01 사용자 결정으로 디자인 판단은 [최우선 디자인·UI·UX 지침](../generation2/docs/design-ui-ux-priority.md)을 먼저 적용하고 [Notion 중심 기준](Notion%20중심%20UI%20UX와%20벡터%20도해%20기준.md)은 보완 참고로 둡니다. 검사 시점·범위·종료는 [작업 진행과 검증 정책](작업%20진행과%20검증%20정책.md)을 따릅니다. 새 자료/플러그인 목록은 도입 목적·실제 식별·지원/권한을 확인하는 후보이며 중복 일괄 설치로 대체하지 않습니다.

- 현재 공통 컴포넌트·토큰·브라우저 기본 기능을 먼저 사용합니다. 부족한 조작·도해에만 적합한 라이브러리를 검토하고 중복 도입하지 않습니다.
- 실제 웹 화면을 직접 확인할 때는 현재 Browser를 우선 사용합니다. 반복할 가치가 있는 회귀는 프로젝트에 설치한 Playwright로 재현하며 CI와 로컬에서 같은 명령을 사용합니다. Browser와 회귀 실행기의 역할을 구별하고 이미 제공되는 동등한 기능을 중복 설치하지 않습니다.
- Web Design Guidelines 등 외부 규칙은 변경에 적용되는 항목만 검토합니다. 사용자 데이터·학습 의미·선택 입력·테마·원문·ID·초안·개인 배치를 우선합니다. 외부 예제를 이유로 새 색·서체·기술 구성을 강제하지 않습니다.
- Taste는 공부 입력·통계의 기본 지침으로 사용하지 않습니다. 스타일 모음은 출처가 확인된 개별 원칙만 참고합니다. 작은 수정에 이미지 생성이나 Image-to-Code를 의무화하지 않으며 정밀 도해·아이콘·그래프는 코드·벡터를 우선합니다.
- 필요한 확인은 변경한 핵심 조작, 긴 한국어·줄바꿈, 한글 조합·커서, 저장·취소·실패 복구, 상세 열기·닫기·복귀, 관련 스크롤·확대·테마·키보드에서 선택합니다. 모든 기기·실패 조합을 첫 초안에 요구하지 않습니다.
- 코드·합성 DOM·실제 브라우저·OS 입력·물리 기기·웹앱 Sync 수신·학습 효과를 확인한 범위로 구별합니다. 종료한 앱의 실행·설치·원본 비교·호환 검사는 포함하지 않습니다.

## 2026-10-01 선제적인 도구 준비

준이 현재 웹앱과 공식 문서를 확인하여 도구 선정·설치·설정·첫 사용을 담당합니다. 사용자가 이름을 알려 주거나 설치를 재촉해야 시작하는 방식으로 운영하지 않습니다. 숙련된 개발자의 구성 요소별 개발, 코드 검사, 접근성·키보드 확인, 반복 가능한 브라우저 검사 관행을 현재 프로젝트에 맞게 적용합니다. 불필요한 도구 수나 시안 제작을 늘리지 않습니다.

현재 설치와 실행 상태, 계정 진입점, 명령은 [개발 도구 안내](../generation2/docs/development-tools.md)에 둡니다. Storybook은 실제 공통 UI와 토큰을 불러오며 합성 시연 자료만 사용합니다. Playwright·axe는 격리된 부품 화면의 관련 동작을 확인합니다. Biome·Prettier·편집기 확장은 기존 앱을 일괄 재작성하지 않고 개발 중 문제 발견과 변경 파일 정리에 활용합니다.

사용자 ‘플러그인 다 설치해 다 활용해’ 요청에 따라 Figma·tldraw·GitHub·Supabase·Linear·Vercel·Webflow·GitBook을 각 역할의 실제 개발 흐름에서 활용합니다. 사용자 설치 완료 후 재조회에서 새 네 항목 모두 설치됨을 확인했습니다. Vercel은 인증된 조회, GitBook은 비공개 문서 초안 저장/재조회, Linear는 웹앱 프로젝트/작업 항목 생성까지 확인했습니다. Webflow의 계정/사이트 접근은 현재 도구 미제공으로 미검증입니다. 현재 상태와 과거 조회 결과를 구별하고 설치 진입 준비를 설치 완료로 보고하지 않습니다. 도구별 준비 책임과 상태는 개발 도구 안내에서 관리하며 사용자가 매번 사용할 도구를 지정하게 하지 않습니다.

기존 React·TypeScript·Vite·Vitest·Testing Library·React Flow·브라우저 개발자 도구는 재사용합니다. 새 UI·차트 라이브러리는 부족한 기능과 현재 계약을 확인하여 선택하며 기존 기능을 다른 디자인 시스템으로 일괄 치환하지 않습니다. 서비스 계정이 필요한 경우 공식 진입점을 먼저 준비하고 계정 생성·로그인은 사용자와 연결합니다. 설치·로그인·외부 프로젝트 연결·실제 사용을 구별합니다.
