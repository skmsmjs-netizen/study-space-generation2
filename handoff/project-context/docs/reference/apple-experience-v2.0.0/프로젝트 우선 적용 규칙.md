## Apple 경험 언어·인터페이스 기본값

- 이 지침이 제공되는 일반 채팅과 작업 대화에서 새로 쓰거나 의미 있게 고치는 모든 사용자 대면 산출물은 `.agents/skills/apple-experience-system/SKILL.md`를 기본 표현 시스템으로 적용한다. 범위는 GPT 응답과 진행 보고, Obsidian·Notion 문구, 문서·HTML·앱·대시보드·위젯의 정보 구조와 UI이다.
- 텍스트만 만드는 작업은 스킬의 `references/writing-system.md`를 읽고, 화면·위젯·시각 구조를 만들거나 고치는 작업은 `references/interface-system.md`도 읽는다. 두 영역이 함께 있으면 둘 다 적용한다.
- GPT 응답·진행 보고와 Obsidian·Notion에서 새로 쓰거나 요청에 따라 고치는 한국어 설명·안내 문장은 `~합니다/~입니다/~됩니다`처럼 정중하고 자연스러운 말투를 기본으로 한다. 스킬의 일반 문체 기본값보다 이 사용자 지정 말투를 우선한다. 제목·버튼·속성·상태값을 억지로 문장형으로 바꾸지 않으며, 보존 대상 원문·인용과 사용자가 지정한 문체·제출 양식은 유지한다.
- 문체나 스킬을 적용했다는 안내를 매 답변·진행 보고·생성 문서에 반복해서 붙이지 않는다. 적용 기준은 결과물의 구성과 표현에 반영하고, 보고에는 실제 변경·검증 결과와 필요한 다음 행동을 담는다.
- 기본 강도는 정확성과 효율을 앞세우는 `기능형`이다. 설명형 지식 문서는 `에디토리얼형`, 소개·랜딩·쇼케이스는 목적에 맞을 때만 `런치형`을 쓴다. 짧은 문장이나 큰 제목 자체를 Apple다움으로 오해하지 않는다.
- 사용자 원문, 직접 인용, 교수 공지, 법률·학술 명제, 수치, 코드, 수식, 속성명, 내부 ID는 문체를 이유로 바꾸지 않는다. 사실·조건·출처·미확정 상태는 슬로건보다 우선한다.
- Apple의 현행 문구·슬로건·제품 화면·로고·고유 이미지를 복제하거나 Apple의 공식 산출물처럼 보이게 하지 않는다. 공개 디자인 원리에서 `단일 초점, 효익 우선, 명확한 위계, 절제, 정밀한 피드백, 접근성`을 추출해 이 보관소만의 언어로 구현한다.
- 사용자가 다른 문체·브랜드·양식 또는 원문 보존을 명시하면 그 요청이 이 기본값보다 우선한다. 기존 전체 자료를 자동 개작하지 않고, 현재 요청에서 새로 생성하거나 수정하도록 승인된 범위에만 적용한다.

## Notion·Obsidian 문체

- 별도 요청이 없어도 Notion과 Obsidian의 새 생성 및 사용자가 승인한 수정 문구에는 위 스킬과 쓰기 기준을 항상 적용한다. 제목·본문·요약·설명·안내가 대상이며, 기존 자료 전체를 일괄 개작하지 않는다.
- Notion과 Obsidian의 새 작성 문구는 `한눈에 보이는 결론 또는 효익 → 필요한 근거와 작동 방식 → 다음 행동` 순서로 설계한다. 제목은 한 가지 약속이나 대상을 말하고, 첫 화면에는 핵심 상태와 다음 행동만 남긴다.
- 짧고 구체적인 문장, 능동형 동사, 일관된 용어를 쓴다. 기능 목록은 사용자가 얻게 되는 변화와 연결하고, 의미 없는 최상급·상투적 감탄·같은 말의 반복은 줄인다.
- Notion의 속성·데이터베이스명·상태값은 검색과 운영에 유리한 사실형 라벨을 유지한다. Obsidian의 학술 노트는 주장·근거·예시·경계를 충분히 남긴다. 문체를 간결하게 만든다는 이유로 조건·출처·미확정 상태를 생략하지 않는다.
- 기존 아이콘·커버·사용자 작성 구조는 현재 요청이 변경을 포함할 때만 손댄다. 아이콘과 색은 정보 위계를 보조할 뿐, 상태나 의미를 단독으로 전달하지 않는다.

## UI·위젯·시각 구조

- 새 UI와 위젯은 콘텐츠를 주인공으로 두고, 한 화면의 주목점과 기본 행동을 각각 하나로 분명히 한다. 세부 정보와 보조 행동은 점진적으로 드러낸다.
- 플랫폼 기본 구성요소와 의미 기반 색·타이포그래피·간격을 우선한다. 밝은 화면·어두운 화면·고대비·큰 글자·키보드·터치·모션 감소 환경에 적응해야 한다.
- 위젯은 앱의 축소판이 아니라 하나의 시의성 있는 질문에 답해야 한다. 크기가 커질 때 같은 내용을 늘리지 말고, 맥락이나 유용한 행동을 한 층 더 제공한다.
- 소스·CSS·DOM 검사만으로 화면 품질을 완료 처리하지 않는다. 실제 렌더에서 목표 뷰포트, 내용 길이, 확대, 상태 변화, 잘림과 상호작용을 확인하고, 확인하지 못한 플랫폼·기기는 `미검증`으로 남긴다.
