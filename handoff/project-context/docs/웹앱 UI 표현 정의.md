# 웹앱 UI 표현 정의

현재 학습 입력 웹앱의 A01–H07, 56개 시각·조작 용어 정의와 N01–N15 선택 검수 사례입니다. 정의·근거를 보존해 활성 위치로 옮겼으며 종료한 구현의 지침·수치·설치 절차는 포함하지 않습니다. 현재 적용 조건은 [Notion 중심 기준](Notion%20중심%20UI%20UX와%20벡터%20도해%20기준.md), 검사 시점·범위는 [작업 정책](작업%20진행과%20검증%20정책.md)을 따릅니다. 각 처방은 공식 Notion 수치가 아니라 공식 설명과 사용자 요구를 결합한 프로젝트 기준입니다.

## 4. 페이지와 글자의 구조

참조: S02·S03·S05 및 기존 용어사전 04·05·07절. 공식 도움말은 페이지·블록·서체 선택·제목을 설명합니다. 아래 위계와 읽기 규칙은 프로젝트 적용안입니다. [페이지 스타일](https://www.notion.com/help/customize-and-style-your-content), [제목과 구분선](https://www.notion.com/help/columns-headings-and-dividers)

### A01 페이지 바탕과 표면

- **뜻:** 콘텐츠가 놓이는 연속된 바탕과 그 안의 구별되는 영역입니다.
- **적용:** 기록·목차·본문은 공통 바탕 위에 이어 놓습니다. 다른 배경은 입력 영역·보조 안내·선택·일시적 레이어처럼 구별할 목적이 있을 때 씁니다.
- **경계:** 같은 바탕 안에서도 정보 묶음은 간격·제목으로 구별합니다. 모든 문단·행을 둥근 카드에 넣지 않습니다. 갤러리 등 독립 항목 비교에는 카드를 허용합니다.
- **검수:** 각 박스의 목적을 설명할 수 있고, 상자를 제외해도 정보 관계와 조작 단서가 유지되는지 확인합니다. 근거: S02, 사용자 선호.

### A02 앱 셸

- **뜻:** 탐색·상단 정보·본문처럼 화면 사이에 반복되는 외곽 구조입니다.
- **적용:** 공통 탐색과 작업 본문을 구분하고, 본문에서 실제 대상과 행동을 먼저 읽게 합니다. 같은 탐색·저장 상태는 같은 위치와 이름을 사용합니다.
- **경계:** 좁은 화면은 탐색을 접어도 진입 버튼·현재 위치를 유지합니다. Notion의 계정·AI·공유 메뉴를 기능 요구 없이 추가하지 않습니다.
- **검수:** 과목·목차·기록·통계 사이에서 공통 조작 위치가 변하거나 본문 폭이 불필요하게 출렁이는지 확인합니다. 근거: S04, 기존 계약.

### A03 시각적 위계

- **뜻:** 무엇을 먼저 읽고 다음에 무엇을 읽을지 드러내는 강조 순서입니다.
- **적용:** 화면 제목 → 구역 제목 → 항목과 행동 → 보조 설명의 관계를 크기·굵기·정렬·간격으로 세웁니다. 조건·실패·마감은 해당 행동 가까이에 둡니다.
- **경계:** 모든 제목·숫자·버튼을 동일하게 크게 강조하지 않습니다. 실제 우선순위가 같은 여러 선택은 동등하게 보입니다.
- **검수:** 색을 제거해도 제목·본문·도움말·핵심 행동을 구별할 수 있는지 확인합니다. 근거: 기존 Apple A5–A6, S11.

### A04 타이포그래피와 글꼴

- **뜻:** 서체·크기·굵기·행간 등을 조합해 글의 역할을 표현하는 체계입니다.
- **적용:** interface·reading·mono 역할과 공통 크기 위계를 사용합니다. 한글·라틴 문자·숫자·수식이 섞인 실제 내용을 확인하며 사용자 글꼴 설정을 보존합니다.
- **경계:** Inter나 Serif를 Notion 스타일의 유일한 필수 서체로 단정하지 않습니다. 브랜드 소개 제목의 서체를 공부 입력에 일괄 적용하지 않습니다.
- **검수:** 긴 한글 제목·혼합 언어·숫자·괄호가 깨지거나 겹치지 않고, 읽기와 입력의 크기가 구별되어 관리되는지 확인합니다. 근거: S03, 기존 계약.

### A05 행간과 문단 간격

- **뜻:** 행간은 같은 문단의 줄 사이, 문단 간격은 서로 다른 문단 사이의 거리입니다.
- **적용:** 두 역할을 별도 토큰·규칙으로 정합니다. 여러 줄 메모를 한 문단으로 읽을 수 있고 다음 문단의 시작도 구별되어야 합니다.
- **경계:** 모든 줄에 같은 외부 여백을 주거나 사용자 문단을 목록으로 자동 변환하지 않습니다. 내용이 늘면 높이를 확보합니다.
- **검수:** 한 줄·세 줄·여러 문단 글에서 문단 경계를 식별하며 원문 줄바꿈이 유지되는지 확인합니다. 근거: S01, 원문 보존 계약.

### A06 읽기 폭과 최대 폭

- **뜻:** 한 줄 길이와 넓은 화면에서 콘텐츠가 퍼질 수 있는 한계입니다.
- **적용:** 긴 설명·메모의 읽기 폭과 여러 항목을 비교하는 표의 작업 폭을 구별합니다. 창 너비보다 실제 본문 영역의 폭을 기준으로 합니다.
- **경계:** 모든 화면을 중앙의 좁은 칼럼으로 고정하지 않습니다. 폭이 넓은 표·Canvas에는 목적에 맞는 확장을 허용합니다.
- **검수:** 320px 분할 영역과 넓은 창에서 글자 축소·페이지 전체 가로 이동 없이 일반 본문을 읽는지 확인합니다. 근거: S03, S15, 기존 계약.

### A07 정렬과 들여쓰기

- **뜻:** 요소의 시작점·기준선을 맞추고 상하위 관계를 거리로 표현하는 방식입니다.
- **적용:** 본문과 반복 행의 기준선을 맞추고 목차 깊이는 일정한 들여쓰기로 구별합니다. 숫자 비교가 필요한 열은 숫자 정렬을 일관되게 합니다.
- **경계:** 중앙 정렬을 장식용 기본값으로 쓰지 않습니다. 깊은 목차에서 들여쓰기가 이름의 폭을 모두 차지하면 경로 표현을 보완합니다.
- **검수:** 짧은 이름과 긴 두 줄 이름에서 체크·메타 정보·행 조작의 위치가 예측 가능하고 계층이 유지되는지 확인합니다. 근거: S04, 기존 계약.

## 5. 여백과 정보 밀도

참조: S01·S11과 기존 용어사전 05절. ‘표준 간격’과 ‘인접 목록의 압축’은 공식 글의 설명이며 다음 적용 조건은 프로젝트 초안입니다. [공식 간격 설계](https://www.notion.com/blog/updating-the-design-of-notion-pages)

### B01 여백

- **뜻:** 내용과 조작을 구별하고 관계를 드러내는 빈 공간입니다.
- **적용:** 같은 묶음 내부보다 다른 묶음 사이를 더 분명히 구분합니다. 클릭 범위·읽기·긴 이름의 줄바꿈을 위한 공간을 확보합니다.
- **경계:** 빈 공간 자체를 세련됨의 점수로 삼지 않습니다. 장식성 빈 공간 때문에 자주 쓰는 선택이 화면 아래로 밀리면 조정합니다.
- **검수:** 가까운 요소가 같은 묶음으로 읽히고, 필요한 정보가 불필요한 스크롤 없이 비교되는지 확인합니다. 근거: S11, 사용자 선호.

### B02 간격의 리듬

- **뜻:** 반복되는 내용이 일정한 간격 규칙으로 이어지는 성질입니다.
- **적용:** 제목·설명·입력·목록의 관계별 간격을 정하고 공통 토큰을 사용합니다. 같은 역할과 이웃 관계에서는 같은 규칙을 적용합니다.
- **경계:** 모든 요소의 높이를 같게 만들거나 모든 글줄을 고정 기준선에 끼워 맞추지 않습니다. 높이가 다른 사용자 글을 수용합니다.
- **검수:** 제목·문단·체크목록이 섞인 화면에서 임의 여백과 한 화면 전용 보정이 반복되지 않는지 확인합니다. 근거: S01, 공통 토큰 계약.

### B03 인접성에 따른 간격

- **뜻:** 요소의 위아래 이웃 관계에 따라 묶음 안과 묶음 밖 간격을 달리하는 규칙입니다.
- **적용:** 연속 목록 항목은 한 묶음으로 읽히게 하고 문단·다른 구역으로 전환될 때 간격을 구분합니다. 선택 입력에서는 누름 영역을 먼저 확보합니다.
- **경계:** 조작 행을 문서 목록과 동일한 작은 패딩으로 강제하지 않습니다. 이웃이 바뀌어도 편집 중 캐럿·포커스를 잃지 않게 합니다.
- **검수:** 목록 1개·연속 목록·목록 뒤 문단·제목 뒤 목록·긴 항목의 간격과 터치 대상이 모두 유지되는지 확인합니다. 근거: S01, S14.

### B04 정보 밀도

- **뜻:** 같은 공간에서 비교·읽기·조작할 수 있는 정보의 양입니다.
- **적용:** 공부 기록의 여러 주제·방법 후보는 함께 확인하게 하고, 드문 상세 통계·보충 설명은 명시적 펼침으로 제공합니다.
- **경계:** 글자 축소로 밀도를 높이거나 매 항목을 큰 카드로 만들어 비교를 어렵게 하지 않습니다. 목록 압축을 기능·조건 삭제로 해결하지 않습니다.
- **검수:** 실제 여러 주제를 고르고 수정할 때 화면 왕복·기억해야 할 값·행동 횟수가 늘지 않는지 확인합니다. 근거: S10–S11, 기존 계약.

### B05 평면 표현

- **뜻:** 광택·질감·강한 입체 효과를 절제하고 글자·경계·상태로 요소를 표현하는 방식입니다.
- **적용:** 기본 본문·목록은 평면으로 두되 입력·클릭·선택·겹치는 레이어의 단서는 유지합니다.
- **경계:** 그림자가 전혀 없는 것을 절대 조건으로 삼지 않습니다. 클릭할 수 있는 글과 일반 글이 똑같아지는 표현은 피합니다.
- **검수:** 마우스를 올리지 않은 상태와 터치 환경에서도 주요 조작을 식별하는지 확인합니다. 근거: S12, 사용자 선호.

### B06 구분선과 경계

- **뜻:** 내용 묶음이나 영역의 범위를 알려주는 선입니다.
- **적용:** 실제 구역 경계·표 행·입력 범위에 공통 선을 사용합니다. 간격과 제목만으로 충분한 곳에는 중복된 상자를 늘리지 않습니다.
- **경계:** 문단마다 선을 넣거나 포커스·오류 선을 기본 경계와 구별 못 하게 연하게 만들지 않습니다.
- **검수:** 선의 위치와 용도가 화면 사이에서 같고, 확대·다크 모드에서도 필요한 경계가 보이는지 확인합니다. 근거: S05, 기존 계약.

### B07 모서리 반경

- **뜻:** 상자·버튼·레이어 모서리의 둥근 정도입니다.
- **적용:** 역할별 공통 반경을 사용합니다. 문서처럼 이어 읽는 곳에 큰 둥근 박스를 반복하는 표현은 줄이는 방향으로 검토합니다.
- **경계:** Notion의 공식 반경값은 이번에 확인하지 못했습니다. 현행 2세대 10·14·20·28px을 Notion값으로 부르거나 화면별로 다른 값으로 덮어쓰지 않습니다.
- **검수:** 반경을 바꿀 필요가 있으면 공통 토큰·영향 화면·기존과 새 시안 비교를 함께 기록합니다. 근거: 사용자 선호, 기존 토큰 계약.

## 6. 색과 아이콘과 깊이

참조: S03·S12·S16, 기존 Apple A6, 용어사전 07·08절. 중립색 중심이라는 방향은 사용자 선호를 해석한 적용안이며, 특정 색 코드가 공식 Notion 표준이라는 뜻은 아닙니다.

### C01 중립색과 기본 팔레트

- **뜻:** 본문·바탕·보조 영역에서 시선을 과하게 경쟁시키지 않는 색 체계입니다.
- **적용:** 기본 내용에는 중립적인 바탕과 글자를 쓰고, 강조색은 역할이 있을 때 사용합니다. 기존 역할 토큰과 사용자 설정을 출발점으로 합니다.
- **경계:** 순백·미색 중 하나를 공식 정답으로 단정하지 않습니다. 현행 녹색 중심 토큰을 새 팔레트로 바꾸는 작업은 중앙 개정과 화면 비교로 다룹니다.
- **검수:** 각 유채색에 행동·상태·계층 등의 의미가 있고 단순 장식색이 반복되지 않는지 확인합니다. 근거: 사용자 선호, 기존 계약.

### C02 의미색

- **뜻:** 선택·오류·출제 상태처럼 특정 뜻을 가진 색입니다.
- **적용:** 출제 가능성 주황·확정 빨강 등 기존 의미를 유지하고 이름·아이콘·문구를 함께 제공합니다. 선택과 학습 성취를 별도 표현합니다.
- **경계:** Notion 느낌을 위해 의미색을 모두 회색으로 바꾸지 않습니다. 상태마다 새로운 팔레트를 만들지도 않습니다.
- **검수:** 홈·목차·Kanban·Canvas·출제 입력에서 같은 항목의 뜻이 같고 색 없이도 상태를 읽는지 확인합니다. 근거: 사용자 최신 정정, 기존 계약.

### C03 대비

- **뜻:** 글자·조작·배경을 시각적으로 구별할 수 있는 밝기 차이입니다.
- **적용:** 실제 배경과 합성된 색으로 글자 대비를 확인합니다. 일반 글자 4.5:1, 큰 글자 3:1의 AA 기준은 S16의 분류·예외와 함께 적용합니다.
- **경계:** 보조 설명·플레이스홀더가 작고 회색이라는 이유로 판독성을 포기하지 않습니다. 큰 글자 기준을 임의로 완화하지 않습니다.
- **검수:** 기본·선택·포커스·오류와 밝은/어두운 테마의 해당 글자를 측정하고 검사 범위를 남깁니다. 근거: S16, 기존 계약.

### C04 아이콘과 시각적 단서

- **뜻:** 항목의 종류나 가능한 행동을 짧게 알아보게 하는 기호입니다.
- **적용:** 같은 역할에는 같은 아이콘 체계를 쓰고 독립 버튼에는 접근 이름을 제공합니다. 처음 쓰는 핵심 행동은 쉬운 라벨과 함께 표시합니다.
- **경계:** 페이지용 이모지 선택을 모든 버튼에 이모지를 붙이라는 규칙으로 확대하지 않습니다. 아이콘의 보이는 크기와 누름 영역을 구분합니다.
- **검수:** 설명 없이도 주요 행동을 구별하고, 키보드·접근성 이름으로 같은 대상을 찾는지 확인합니다. 근거: S03, S12–S14.

### C05 일러스트와 커버

- **뜻:** 페이지의 정체성·설명·정서를 보조하는 이미지입니다.
- **적용:** 자료 이해나 페이지 식별에 도움이 될 때 사용하며 공부 기록의 첫 행동을 밀어내지 않게 합니다. 사용자가 배치한 이미지는 보존합니다.
- **경계:** Notion의 브랜드 일러스트를 필수 장식으로 삼거나 매 화면에 대형 커버를 추가하지 않습니다. 실제 자료는 장식처럼 자르지 않습니다.
- **검수:** 이미지 실패·대체 설명·화면 축소에서 행동을 찾을 수 있고 자료 전체를 확인할 경로가 있는지 봅니다. 근거: S03, 기존 계약.

### C06 깊이와 그림자

- **뜻:** 겹침과 앞뒤 관계를 나타내는 시각적 표현입니다.
- **적용:** 일반 문서 흐름은 낮은 깊이로 두고, 열린 팝오버·메뉴·다이얼로그의 구별에 경계·그림자를 제한적으로 사용합니다.
- **경계:** 모든 카드에 떠 있는 효과를 주지 않습니다. 그림자만으로 선택·오류·읽기 전용을 표현하지 않습니다.
- **검수:** 실제 겹친 레이어의 경계와 조작 가능 범위를 구별하며, 스크롤·화면 가장자리에서 메뉴가 잘리지 않는지 확인합니다. 근거: S12–S13, 기존 계약.

### C07 밝은 테마와 어두운 테마

- **뜻:** 바탕·글자·경계·상태색을 환경에 맞게 조합한 표현입니다.
- **적용:** 동일한 역할 토큰을 테마별로 정의하고 OS/사용자 선택을 따릅니다. 위계·조작·학습 의미는 동일하게 유지합니다.
- **경계:** 화면별 색 반전으로 해결하지 않습니다. 종이 느낌을 이유로 사용자 다크 모드 설정을 무시하지 않습니다.
- **검수:** 테마를 바꾸어도 입력·선택·포커스가 유지되고 오류·메모·표가 읽히는지 확인합니다. 근거: 기존 디자인 시스템, 사용자 선호.

## 7. 탐색과 상세 열기

참조: S04·S06·S13, 용어사전 04·12·13절. Notion 공식 설명의 side peek는 왼쪽 원래 보기를 계속 조작할 수 있는 방식입니다. 비모달 패널과 모달을 구별하는 근거로 사용합니다. [공식 보기와 상세 열기](https://www.notion.com/help/views-filters-and-sorts)

### D01 사이드바와 트리

- **뜻:** 주요 작업과 중첩 항목을 탐색하는 영역입니다.
- **적용:** 과목·목차의 실제 계층을 펼쳐 확인하고 현재 항목을 표시합니다. 이름 수정·이동은 원래 ID와 연결 관계를 유지합니다.
- **경계:** 토글로 하위를 여는 행동과 항목 본문을 여는 행동을 구별합니다. 정해진 3단계에 실제 목차를 억지로 맞추지 않습니다.
- **검수:** 펼침·선택·긴 이름·깊은 계층·좁은 화면과 키보드 탐색에서 현재 위치를 찾는지 확인합니다. 근거: S04, S13, 기존 계약.

### D02 경로와 뒤로 가기

- **뜻:** 경로는 데이터의 부모 계층, 뒤로 가기는 방문 이력으로 이전 위치에 복귀하는 동작입니다.
- **적용:** 과목·단원·주제의 상위 경로를 확인하며, 실제 복귀에는 검색·선택·스크롤을 이어 줍니다. 직접 URL 진입도 정의합니다.
- **경계:** 부모로 이동을 브라우저 Back과 같은 동작으로 처리하지 않습니다. 초안·자유 글을 경로 URL에 넣지 않습니다.
- **검수:** 목록에서 상세 진입 후 복귀와 직접 상세 진입의 복귀를 각각 확인합니다. 근거: S08, 기존 탐색·보존 계약.

### D03 탭과 보기 전환

- **뜻:** 같은 맥락의 화면 묶음이나 같은 데이터의 표현을 바꾸는 선택입니다.
- **적용:** 선택된 탭·보기 이름을 표시하고 전환 후 대상·관련 필터를 유지합니다. 탐색 링크와 실제 탭의 의미를 구현에서 구별합니다.
- **경계:** 보기 전환을 새로운 공부 기록 생성·완료 행동으로 처리하지 않습니다. 모든 탐색 링크에 탭 역할을 붙이지 않습니다.
- **검수:** 키보드 전환·페이지 복귀·새로고침에서 선택 상태와 데이터 의미가 유지되는지 확인합니다. 근거: S06, S13, 기존 계약.

### D04 목록과 표

- **뜻:** 목록은 항목의 흐름, 표는 동일 속성의 행·열 비교를 표현합니다.
- **적용:** 목차·행동의 나열은 목록, 여러 주제의 날짜·반복·상태 비교는 정렬된 표나 행을 사용합니다. 의미상 필요한 열은 유지합니다.
- **경계:** 표에 필터·수식을 쓰는 기능까지 외형만으로 추가하지 않습니다. 자유 글·조건을 무조건 말줄임으로 숨기지 않습니다.
- **검수:** 긴 항목과 많은 행에서 머리글·행 대상·선택을 식별하며 관련 영역만 가로 스크롤되는지 확인합니다. 근거: S06, S15, 기존 계약.

### D05 검색과 필터와 정렬

- **뜻:** 검색은 질의로 찾기, 필터는 조건으로 범위 제한, 정렬은 표시 순서 변경입니다.
- **적용:** 적용한 조건과 결과 범위를 보여주고 지우기·수정 경로를 제공합니다. 조건 변경은 표시를 바꾸며 원본 기록을 보존합니다.
- **경계:** 결과 없음과 데이터 없음과 조회 실패를 합치지 않습니다. 검색 입력을 입력 중 재조회 때문에 초기화하지 않습니다.
- **검수:** 빠른 입력·조건 조합·결과 0·이탈 후 복귀에서 최신 조건·결과·선택이 맞는지 확인합니다. 근거: S06, 기존 계약.

### D06 사이드 패널과 미리보기

- **뜻:** 목록과 관련 상세를 나란히 두어 작업 맥락을 이어 주는 영역입니다.
- **적용:** 폭이 충분하면 원래 목록과 주제 상세를 함께 다룰 수 있게 합니다. 비모달이면 배경 목록도 실제 조작 가능합니다.
- **경계:** 옆에서 열렸다는 이유로 모달 포커스 가두기를 적용하지 않습니다. 좁은 폭에서는 읽을 수 있는 독립 화면·레이어로 바꾸고 복귀 상태를 유지합니다.
- **검수:** 목록 A→상세 A→상세 B→닫기에서 초안·선택·스크롤이 보존되고 오래된 응답이 대상을 바꾸지 않는지 확인합니다. 근거: S06, S13, 기존 계약.

### D07 모달 다이얼로그

- **뜻:** 뒤의 작업을 일시적으로 막고 특정 확인·입력에 집중시키는 창입니다.
- **적용:** 진입 시 적절한 초점, 뒤 영역의 조작 제한, 닫기와 원래 조작으로 초점 복귀를 제공합니다. 미저장 초안의 처리도 정의합니다.
- **경계:** 짧은 항목 수정마다 모달을 의무화하지 않습니다. 닫기·취소·삭제를 같게 처리하지 않습니다. 닫는 동작은 데이터 손실 경계를 따릅니다.
- **검수:** Tab·Escape·닫기·저장 실패·키보드 열린 좁은 화면에서 나가고 복귀할 수 있는지 확인합니다. 근거: S13, 기존 계약.

## 8. 콘텐츠와 직접 조작

참조: S02·S05·S10·S13. 블록 기반 외형은 Notion의 실제 특징이지만 이 프로젝트의 저장 구조나 학습 의미를 블록 모델로 자동 교체하는 권한은 아닙니다. [공식 블록 설명](https://www.notion.com/help/what-is-a-block)

### E01 블록과 조합

- **뜻:** 글·목록·표·안내처럼 독립된 콘텐츠 단위를 한 페이지에 구성하는 방식입니다.
- **적용:** 역할별 작은 요소를 조합하고 관련 내용과 조작을 함께 둡니다. 데이터 ID·원문·관계와 화면 배치를 구분합니다.
- **경계:** 모든 학습 정보를 자유 편집 문서 하나로 바꾸지 않습니다. 시각적 블록 변경을 기록 삭제·병합으로 해석하지 않습니다.
- **검수:** 배치·표시 변경 전후 원문·ID·연결·학습 사건 수가 유지되는지 확인합니다. 근거: S02, 기존 계약.

### E02 인라인 편집

- **뜻:** 읽던 대상의 자리에서 값을 수정하는 방식입니다.
- **적용:** 대상·현재 값을 유지하며 편집 진입과 완료·취소·실패를 구별합니다. 저장 중에도 해당 글의 캐럿·선택을 보존합니다.
- **경계:** 글을 눌러 이동하는 행동과 편집 진입을 충돌시키지 않습니다. Notion과 유사한 느낌만을 위해 일반 입력을 contenteditable로 교체하지 않습니다.
- **검수:** 긴 이름·한글 입력·취소·실패·빠른 대상 전환에서 다른 항목을 수정하지 않는지 확인합니다. 근거: S07의 맥락 설계, 기존 계약.

### E03 체크박스와 학습 체크

- **뜻:** 특정 정의에 대한 이진 선택이며, 화면 모양 자체가 성취 의미를 정하지 않습니다.
- **적용:** 활동 시도 체크는 일부 수행·막힘을 포함한 기록으로 유지합니다. 관련 메모·반복·시험 전 서술 점검의 조건을 연결합니다.
- **경계:** 체크를 이해·독립 해결·목표 달성으로 확대하지 않습니다. 재체크·저장 재시도를 새 공부 회차로 세지 않습니다.
- **검수:** 체크·해제·메모 수정·재시도 후 기록과 반복 수가 정의대로 남고 원문이 유지되는지 확인합니다. 근거: 사용자 TRACE 정정, S13.

### E04 버튼과 링크

- **뜻:** 버튼은 동작 실행, 링크는 위치·자원 이동을 제공합니다.
- **적용:** 행동명은 짧은 동사로 쓰고 자주 하는 핵심 행동을 쉽게 찾게 합니다. 보조 행동은 강조를 줄여도 클릭 단서를 유지합니다.
- **경계:** 주요 버튼은 무조건 검정·유색이라는 공식 규칙을 만들지 않습니다. 페이지마다 여러 버튼을 같은 강도로 강조하거나 의미가 없는 글을 버튼처럼 보이게 하지 않습니다.
- **검수:** 클릭 결과·키보드 동작·busy·disabled·실패 후 재시도를 예측할 수 있는지 확인합니다. 근거: S12–S13, 기존 계약.

### E05 단일 선택과 다중 선택

- **뜻:** 한 대상 또는 여러 대상을 표시·조작 범위로 고르는 행동입니다.
- **적용:** 선택된 대상과 일괄 변경 범위를 보여주고 해제·취소·되돌리기를 제공합니다. 선택과 활동 체크를 구별합니다.
- **경계:** 한 화면 여러 주제 기록을 단일 선택으로 축소하지 않습니다. 화면 밖 선택·필터로 숨은 선택도 범위를 확인하게 합니다.
- **검수:** 검색·스크롤·필터 뒤 선택 범위와 일괄 적용 대상이 일치하는지 확인합니다. 근거: 기존 사용자 요구, S13.

### E06 드래그와 드래그 핸들

- **뜻:** 대상을 끌어 이동하는 동작과 그 동작을 시작할 수 있음을 알리는 단서입니다.
- **적용:** 핸들과 놓을 위치·유효 여부를 표시합니다. 메뉴로 이동·앞뒤 순서 변경 등 비끌기 대안을 제공합니다.
- **경계:** 글자 선택과 끌기를 충돌시키지 않습니다. 개인 Canvas의 자동 배치나 관계 변경을 평범한 화면 갱신에 섞지 않습니다.
- **검수:** 키보드·터치 대안, 취소·잘못된 놓기·스크롤 중 이동에서 데이터 관계와 개인 배치가 보존되는지 확인합니다. 근거: S02·S04, 기존 계약.

### E07 펼침과 점진적 공개

- **뜻:** 필요한 상세 정보·드문 설정을 사용자가 요청할 때 여는 방식입니다.
- **적용:** 자주 쓰는 입력·방법 후보는 기본 화면에 두고 상세 통계·과거 이력·긴 설명은 이름 있는 펼침으로 제공합니다. 열린 상태를 필요 범위에서 유지합니다.
- **경계:** 마감·오류·현재 선택 조건을 숨기지 않습니다. 점진적 공개를 주제마다 다음 버튼을 누르는 단계별 마법사로 바꾸지 않습니다.
- **검수:** 기본 작업을 상세 열기 없이 수행하고 상세 경로도 찾을 수 있으며, 열린 내부 입력이 닫힘·복귀로 사라지지 않는지 확인합니다. 근거: S10, 기존 계약.

## 9. 도구의 발견과 조작 상태

참조: S07–S09·S12–S13. Notion의 맥락 도구와 익숙한 관례는 공식 설계 설명의 특징입니다. 아래 키보드·터치 대안은 프로젝트 책임으로 구체화합니다. [맥락에 따른 도구 설계](https://www.notion.com/blog/the-design-thinking-behind-notion-ai), [발견 가능성을 다룬 설계 글](https://www.notion.com/blog/designing-synced-blocks)

### F01 발견 가능성과 시그니파이어

- **뜻:** 기능을 찾아낼 수 있는 정도와, 가능한 행동을 알려주는 보이는 단서입니다. 어포던스는 실제 가능한 행동과 사용자 사이의 관계입니다.
- **적용:** 핵심 행동에는 이름·아이콘·입력 경계 등 단서를 둡니다. 클릭 가능성과 선택 결과를 실제 동작에 맞춰 표현합니다.
- **경계:** ‘깔끔함’을 위해 자주 쓰는 조작을 숨겨 두지 않습니다. 툴팁이나 단축키를 외워야만 시작하는 구조를 피합니다.
- **검수:** hover 없이도 처음 보는 사용자가 기록·수정·상세·복귀의 시작점을 찾을 수 있는지 확인합니다. 근거: S08·S12, 사용자 요구.

### F02 맥락 메뉴와 팝오버

- **뜻:** 해당 대상 가까이에서 관련 명령이나 짧은 편집을 제공하는 레이어입니다.
- **적용:** 어떤 항목의 메뉴인지 명시하고 필요한 명령만 배치합니다. 메뉴·목록 선택·편집 팝오버의 역할별 초점과 키보드 규칙을 따릅니다.
- **경계:** 모든 레이어를 모달이나 ARIA menu로 통일하지 않습니다. 삭제·이동처럼 범위가 큰 행동은 결과·대상을 함께 보여줍니다.
- **검수:** 화면 가장자리·아래쪽 행·스크롤·Escape·바깥 클릭·저장 실패에서 잘림과 입력 손실이 없는지 확인합니다. 근거: S07·S13, 기존 계약.

### F03 호버

- **뜻:** 포인터가 요소 위에 놓인 상태이며 클릭·선택·키보드 초점과 별개입니다.
- **적용:** 보조 핸들·드문 메뉴의 강조를 높이는 데 사용하되 공간을 예약합니다. focus-within·터치에 동등한 진입 경로를 제공합니다.
- **경계:** 터치에서 첫 탭이 예고 없이 다른 대상을 실행하거나 hover 유무로 유일한 기능이 사라지지 않게 합니다.
- **검수:** 포인터 없음·키보드·행 hover 전후에서 버튼 위치·행 폭·클릭 결과가 안정적인지 확인합니다. 근거: S12–S13, 기존 계약.

### F04 포커스

- **뜻:** 키보드 입력이나 다음 조작을 받는 대상입니다.
- **적용:** focus-visible을 식별 가능하게 하고 열린 레이어의 역할에 맞춰 이동·복귀합니다. 저장과 재렌더로 편집 초점을 빼앗지 않습니다.
- **경계:** 시각적 절제를 이유로 outline을 제거하지 않습니다. 비모달 패널에 모달식 초점 가두기를 적용하지 않습니다.
- **검수:** Tab 순서·모달 닫기·행 갱신·검색·오류 뒤의 초점과 캐럿이 작업을 이어 주는지 확인합니다. 근거: S13, 기존 계약.

### F05 눌림과 선택과 비활성

- **뜻:** pressed는 조작 중 또는 토글된 상태, selected는 선택 상태, disabled는 실행할 수 없는 상태입니다. busy와 읽기 전용도 각각 다릅니다.
- **적용:** 각 요소에 실제로 필요한 상태를 정의하고 배경·경계·문구·접근 상태를 함께 사용합니다. 실행 불가의 이유와 가능한 다음 행동을 제공할 필요를 검토합니다.
- **경계:** 비활성을 연한 회색 한 가지로만 처리하거나 선택을 성공·성취와 같은 표시로 사용하지 않습니다.
- **검수:** 선택→실행→저장 중→성공/실패의 흐름에서 각 상태를 구별하고 재시도할 수 있는지 확인합니다. 근거: S13, 기존 계약.

### F06 툴팁

- **뜻:** 짧은 보충 설명을 일시적으로 표시하는 요소입니다.
- **적용:** 보조 설명에 사용하고 hover·키보드 초점에서 접근 가능하게 합니다. 필수 설명과 핵심 행동명은 기본 화면에도 둡니다.
- **경계:** 편집 가능한 긴 내용·버튼은 툴팁에 넣지 않습니다. 터치에서 툴팁이 없는 경우에도 기능 뜻을 이해할 수 있어야 합니다.
- **검수:** 화면 가장자리·초점 이동·Escape와 터치에서 필수 내용을 놓치지 않는지 확인합니다. 근거: S13, 기존 계약.

### F07 명령 메뉴와 단축키

- **뜻:** 검색하거나 키 조합으로 명령·대상에 빠르게 접근하는 경로입니다.
- **적용:** 기존 단축키와 충돌하지 않게 하고 클릭·터치 경로를 유지합니다. 명령이 적용될 현재 범위를 표시합니다.
- **경계:** Notion의 슬래시 명령을 모든 입력에 추가하지 않습니다. 한글 조합·본문 입력 중 문자를 가로채거나 기존 원문을 바꾸지 않습니다.
- **검수:** 조합 중 키 입력·편집 중 단축키·명령 검색·Escape 취소·실행 뒤 초점을 확인합니다. 근거: S09, 기존 계약.

## 10. 입력과 저장과 복구

이 절은 주로 프로젝트의 [화면 설계 작업지침](화면%20설계%20작업지침.md)과 데이터 보존 계약을 구체화합니다. Notion 스타일의 공식 저장 사양이라고 주장하지 않습니다. 작은 사용성 문제를 사용자가 먼저 신고해야 발견되는 구조를 예방합니다.

### G01 라벨과 플레이스홀더

- **뜻:** 라벨은 입력의 뜻, 플레이스홀더는 비어 있을 때의 형식 예시입니다.
- **적용:** 입력 뒤에도 대상과 뜻이 남는 라벨을 제공합니다. 선택 입력 여부·필요 조건을 행동 가까이에서 짧게 설명합니다.
- **경계:** 장식을 줄이기 위해 라벨을 없애지 않습니다. 선택 메모를 필수로 바꾸거나 실제 사용자 답을 예시로 꾸며 넣지 않습니다.
- **검수:** 값이 채워진 상태·오류·긴 라벨·접근 이름에서 입력의 뜻과 조건이 유지되는지 확인합니다. 근거: 기존 계약, S13.

### G02 미리 채우기와 값 재사용

- **뜻:** 이미 알고 있는 값을 다시 입력하지 않게 제공하는 방식입니다.
- **적용:** 기존 값은 수정 가능하게 보여주며 원본·새 입력·초안을 구분합니다. 여러 주제에 같은 값을 적용할 때 범위를 알려줍니다.
- **경계:** 모름·미정을 추정값으로 확정하거나 과거 서술을 새 수행으로 복사하지 않습니다.
- **검수:** 새 공부·기존 수정·여러 대상 일괄 입력에서 원문·날짜·학습 사건의 뜻이 유지되는지 확인합니다. 근거: 사용자 TRACE 정정, 기존 계약.

### G03 한글 조합과 편집 상태

- **뜻:** IME 조합 중 글자와 확정된 글자, 캐럿·선택·초점을 구별하는 편집 상태입니다.
- **적용:** 조합 중 Enter는 확정과 제출을 구별합니다. 입력·자동저장·검색·집계 갱신이 같은 편집 대상을 불필요하게 다시 만들지 않게 합니다.
- **경계:** 합성 composition 이벤트 통과를 실제 OS 한글 입력 성공으로 보고하지 않습니다. 변환·공백 정리를 입력 도중 강제하지 않습니다.
- **검수:** 실제 한글 연속 입력·조합 중 Enter·붙여넣기·중간 캐럿 수정과 저장을 확인하고 물리 기기 여부를 구분합니다. 근거: 기존 계약.

### G04 저장 피드백과 자동저장

- **뜻:** 변경이 어디에 보관되고 어떤 단계까지 확인됐는지 알리는 반응입니다.
- **적용:** 화면 반영·로컬 보관·서버 저장·Sync·백업을 구분하고 응답에 맞는 짧은 상태를 제공합니다. 실패 시 해당 입력과 재시도 경로를 유지합니다.
- **경계:** 차분한 화면을 위해 실패를 숨기거나 실제 응답 전 ‘저장 완료’를 표시하지 않습니다. 매 체크마다 팝업으로 흐름을 끊지 않습니다.
- **검수:** 연속 변경·오프라인·응답 실패·새로고침·재접속에서 값·상태·복구 범위가 일치하는지 확인합니다. 근거: 기존 저장 계약.

### G05 취소와 실행 취소

- **뜻:** 취소는 진행 중 의도를 중단하는 것, 실행 취소는 이미 적용된 효과를 되돌리는 것입니다.
- **적용:** 각 동작의 실제 범위와 원문·선택·초안의 처리 기준을 정합니다. 되돌릴 수 있다고 안내한 변경은 실제 되돌릴 수 있게 합니다.
- **경계:** 요청 취소를 저장된 변경의 롤백으로 취급하지 않습니다. 닫기·체크 해제를 원문 삭제로 연결하지 않습니다.
- **검수:** 수정·체크·일괄 적용·이동의 취소와 되돌리기 결과를 원본과 대조합니다. 근거: 기존 계약.

### G06 비동기 응답과 중복 방지

- **뜻:** 뒤늦게 도착하는 처리 결과와 반복 요청의 효과를 관리하는 책임입니다.
- **적용:** 응답의 대상·요청·개정을 확인하고 같은 저장 의도의 재시도를 식별합니다. 버튼 상태와 저장 주체의 중복 방지를 함께 정의합니다.
- **경계:** 빠른 A→B 전환 뒤 A 응답이 B의 값을 덮어쓰지 않게 합니다. 버튼 비활성화만으로 모든 중복 방지가 됐다고 보고하지 않습니다.
- **검수:** 지연된 응답·더블클릭·응답 유실 후 재시도에서 최신 대상과 기록 수가 맞는지 확인합니다. 근거: 기존 계약.

### G07 빈 상태와 결과 없음과 오류

- **뜻:** 원본 데이터 없음, 조건에 맞는 결과 없음, 조회·저장 실패는 서로 다른 상태입니다.
- **적용:** 확인된 사실과 가능한 다음 행동을 짧게 보여줍니다. 부분 성공은 성공한 범위와 남은 실패를 구별합니다.
- **경계:** 정보 없음·미입력을 실패·낮은 능력으로 바꾸지 않습니다. 대응해야 하는 오류를 사라지는 토스트에만 두지 않습니다.
- **검수:** 빈 초기 데이터·검색 결과 0·불러오기 실패·일부 저장 실패에서 원문을 보존하고 올바른 복구 경로가 있는지 확인합니다. 근거: 기존 계약.

## 11. 기기와 움직임과 공통 구현

참조: S05·S13–S16 및 프로젝트 기기·문구·토큰 계약. 일반 접근성 기준을 Notion 고유 스타일로 부르지 않습니다.

### H01 반응형과 리플로

- **뜻:** 가용 공간·확대·화면 키보드에 맞춰 내용의 흐름과 배치를 다시 구성하는 방식입니다.
- **적용:** 실제 본문 폭을 기준으로 열·버튼·설명을 재배치합니다. 일반 읽기 내용은 좁은 폭에서도 세로 흐름으로 읽게 합니다.
- **경계:** 휴대전화에서 열이 아래로 이어지는 Notion 안내는 참조 사례입니다. 프로젝트의 읽는 순서·필수 기능을 보존하며 글자 일괄 축소·가로 넘침 숨기기로 해결하지 않습니다.
- **검수:** 320·390px, iPad 분할 폭, 200% 확대, 좁은 높이와 키보드에서 읽기·저장·닫기를 확인합니다. 2차원 표·Canvas 예외는 별도 이유를 적습니다. 근거: S05·S15, 기존 계약.

### H02 누름 영역

- **뜻:** 아이콘의 보이는 크기와 별개인 실제 클릭·터치 반응 범위입니다.
- **적용:** 현행 핵심 텍스트 조작 48px·아이콘 44px 기준을 유지하며 긴 라벨은 높이를 늘립니다. 인접 대상이 겹치지 않게 합니다.
- **경계:** 이는 프로젝트 편의 기준입니다. WCAG 2.5.8 AA의 24×24 CSS px 또는 규정된 예외를 44px 의무로 오기하지 않습니다.
- **검수:** 조작 범위·간격·포커스가 실제 표시와 일치하고 인접 체크·메뉴를 잘못 누르지 않는지 확인합니다. 근거: S14, 현행 디자인 시스템.

### H03 키보드와 접근 역할

- **뜻:** 마우스 없이도 역할에 맞는 키 조작·이름·상태로 화면을 사용하는 경로입니다.
- **적용:** 네이티브 요소를 우선하고 필요한 패턴은 APG를 참조합니다. 모달·탭·트리·메뉴의 키 규칙을 각각 적용합니다.
- **경계:** 보이는 모양이 비슷하다고 버튼·링크·체크박스를 같은 역할로 구현하지 않습니다. VoiceOver 전용 지원·검증은 2026-10-03 사용자 결정으로 웹앱 전 기능에서 제외합니다. 일반 키보드·터치·초점·레이블 검증은 유지합니다.
- **검수:** 이름·상태·키보드 순서·활성화·닫기·초점 복귀를 실제 브라우저에서 확인하며 보조기술 검증은 별도로 기록합니다. 근거: S13, 기존 계약.

### H04 마이크로인터랙션과 동작 줄이기

- **뜻:** 체크·열기·저장처럼 작은 변화에 대한 짧은 반응과 움직임을 줄이는 설정입니다.
- **적용:** 상태 변화 이해에 필요한 반응을 제공하고 공통 시간을 사용합니다. reduced-motion에서는 의미·피드백은 유지하며 불필요한 움직임을 줄입니다.
- **경계:** 기록 완료를 과한 축하 효과·능력 향상으로 표현하지 않습니다. 기존 친근한 배웅 문구의 의미를 버리거나 새 효과를 일괄 추가하지 않습니다.
- **검수:** 빠른 반복 조작·동작 줄이기·저장 실패에서 화면이 흔들리거나 버튼 위치가 움직이지 않는지 확인합니다. 근거: 기존 계약, 사용자 선호.

### H05 스크롤과 복귀 맥락

- **뜻:** 사용자가 보던 위치·선택·검색·탭·열린 상세를 작업 흐름에 맞게 이어 주는 상태입니다.
- **적용:** 상세 닫기·Back·재진입의 복원 범위를 정하고 스크롤 뒤 새로 표시되는 항목에도 같은 상태·강조를 적용합니다.
- **경계:** 모든 이동에서 무조건 맨 위로 보내거나 이전 대상의 스크롤을 새 대상에 그대로 적용하지 않습니다. Canvas 좌표와 뷰포트를 구별합니다.
- **검수:** 목록 아래→상세 편집→복귀, 검색 후 복귀, 갱신 후 새 행에서 위치·값·초점이 맞는지 확인합니다. 근거: 기존 계약.

### H06 마이크로카피와 행동 안내

- **뜻:** 버튼·상태·도움말의 짧은 문구로 다음 행동과 결과를 알려주는 표현입니다.
- **적용:** 쉬운 한글 행동명과 자연스러운 존댓말을 사용합니다. 필요한 때 실제 자료 확인→작은 공부 행동→돌아와 남길 곳을 짧게 안내합니다.
- **경계:** Notion의 영어 문구·Title Case를 그대로 옮기지 않습니다. 약어 학습을 입력의 전제로 삼거나 공부 후 기록마다 다시 책을 펴게 하지 않습니다.
- **검수:** 처음 쓰는 사람이 대상·행동·저장 범위를 이해하며, 좁은 화면에서 문구·단위·조건이 잘리지 않는지 확인합니다. 근거: 사용자 정정, 기존 Apple A4·A16.

### H07 토큰과 공통 컴포넌트와 변형

- **뜻:** 반복되는 색·크기·간격의 이름과, 같은 행동을 일정하게 구현하는 재사용 요소입니다. 변형·상태·테마는 구별합니다.
- **적용:** 값은 토큰, 행동은 공통 요소, 화면만의 배치는 화면에서 관리합니다. 새 규칙은 영향을 받는 화면과 함께 적용합니다.
- **경계:** 외부 ‘Notion 스타일’ CSS를 각 화면에 중복 복사하거나 모든 요소를 하나의 거대한 조건문에 합치지 않습니다.
- **검수:** 같은 항목·상태가 화면마다 같고 변경 후 인접 화면·스크롤 마운트·사용자 설정이 보존되는지 확인합니다. 근거: 기존 토큰·컴포넌트 계약.
