# 화면과 입력

[코드 지침](../AGENTS.md)을 상속합니다.

- 사용자 결정으로 [최우선 디자인·UI·UX 지침](../../docs/design-ui-ux-priority.md)의 관련 기준을 먼저 적용하고 [디자인 시스템](../../docs/design-system.md)과 [컴포넌트 계약](../../docs/component-matrix.md)에 연결합니다. 기존 Notion 등 외형 참고보다 새 기준을 우선하며 기존 토큰 체계·공통 요소·브라우저 기본 기능을 재사용합니다. 필요한 시각 값은 담당 원본에서 조정하되 원문·초안·사용자 설정·배치·학습 의미·저장/권한을 유지합니다.
- Instagram `DdT0nKbILi6` 전 장의 [채택 기준](../../docs/design-system.md#2026-10-01-디자인-시스템-게시물-전체-채택)을 적용합니다. 기초 토큰/글자/배치 → 공통 부품의 속성/상태 → 반복 과업 구역을 실제 사용처로 연결합니다. 동일 역할은 기존 부품을 확장하고 필요한 새 변형의 계약을 갱신합니다. 그림의 예시 수치로 원문·개인 설정·배치를 바꾸지 않습니다.
- 한글 조합·커서·포커스·초안·뒤로 가기·취소·되돌리기를 유지합니다. 화면을 줄인다는 이유로 선택 글·이유·예외·설정을 삭제하지 않습니다. 의미색과 사용자 설정은 공통 보존 계약을 따릅니다.
- 펜 표시·짧은 ‘불편/불안’ 피드백은 [화면 설계 5절](../../../docs/화면%20설계%20작업지침.md#5-펜으로-표시한-영역과-불편불안-피드백-해석)을 적용합니다. 표시를 승인으로 읽지 않고 관찰과 원인 가설을 구별하여 실제 앱의 국소 수정을 진행합니다.
- 바뀐 화면의 핵심 조작·복귀 경로를 확인합니다. 저장과 관련된 변경이면 관련 저장 경로도 확인합니다. 모든 화면·테마·기기 검사를 첫 결과의 선행조건으로 추가하지 않습니다.
- CSS 변경은 `npm run check:design`으로 공통 토큰 참조·직접 값·오타를 확인합니다. 정당한 예외는 디자인 시스템의 선언별 이유 표기를 따릅니다. 이 검사는 공통 부품의 선택·상태 의미·실제 화면 확인을 대신하지 않습니다.

- 2026-10-01 사용자가 지정한 다섯 모사 환경의 확인은 [기기 환경 검증](../../docs/device-environments.md)과 공통 정책3.1절을 따릅니다. 앱 변경에 `npm run test:devices`를 실행하고, 바뀐 핵심 조작·저장·기능 제한의 회귀를 다섯 환경에 연결합니다. 실제 기기 연결을 다시 선행조건으로 요구하지 않습니다.

- 수학·과학 인터랙티브 화면·도해는 [수학 인터랙티브 설계·검증 기준](../../../docs/수학%20인터랙티브%20설계·검증%20기준.md)의 관련 MI01–MI12를 필수 적용합니다. 표현 역할/대응/순서, 공통 조작/초기 상태, 실제 LaTeX, WCAG/APG, 반복 사용·복귀를 구현과 관측 근거에 연결하며 지침 저장·자동 검사만으로 완료를 보고하지 않습니다.
