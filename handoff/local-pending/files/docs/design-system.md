## 구현과 적용

### 2026-10-02 천문대 정체성의 색채·UI·UX 기준값

**후속 사용자 정정:** 아래 천문대 기준값은 현재의 공통 기본값이며, 앞으로의 고급 렌더링·조명·애니메이션·상호작용 구현에 따라 조정할 수 있다. 이전 수치를 기술의 상한으로 강제하지 않는다. [기술 적응 원칙](observatory-design-standard.md)에 따라 변경 이유·범위·실제 확인 결과를 값 원본과 소비 경로에 연결하며 천문대 정체성·위젯 전체 보존·접근성과 자료/개인 설정을 유지한다.

후속 사용자 「본 정체성에 맞게 수정이 필요하다면 그 기준도 수정해」에 따라 기존 중립색·모서리·그림자·아이콘·움직임의 수치와 외형도 변경 대상으로 둔다. 아래 과거 토큰 표는 현재 구현을 설명하며 천문대 정체성의 새 역할별 값보다 우선하는 영구 제한이 아니다. 새 목표값은 아래 연결한 원본 한 곳에서 관리하고, 기능적 읽기/조작 가능성과 원문·개인 설정을 함께 보존한다.

사용자 「여기까지, ux, ui, 디자인 기준으로 값을 정해둬라」에 따라 [천문대 UX·UI·디자인 확정 기준](observatory-design-standard.md)과 [기준값 원본 v2.0.0](observatory-experience-baseline.json)을 채택한다. 어두운 실내·창틀·따뜻한 종이 작업면·공통 픽셀 부품·네 고정 장소·문구/모션/수리 반응의 값과 적용 조건을 그 원본에서 관리한다. 새 색은 `materials.interior/paper`, 치수는 `metrics`, 픽셀은 `pixelTreatment`, 동작은 `spatialWorkspace/motion/language/enginePresentation`이다. 공통 치수·서체·모션의 기존 토큰 참조와 rem/개인 설정을 보존하며 필요한 외형은 새 기준으로 조정한다.

현재 `scripts/sync-math-observatory.mjs`는 기존 `workSurfaceColors`와 픽셀 반경을 실제로 소비한다. 이 색 블록은 v1.1 호환값으로 유지하며 새 v2 색을 적용했다는 뜻이 아니다. JSON의 최상위 버전 로그와 실제 소비한 값의 버전을 구별한다. 홈의 `ObservatoryRoom/Desk` 창가 표현은 이미 코드에 연결되어 있으며, 전체 네 방향 이동/종이 작업면/v2 색의 소비 및 실제 화면/배포 상태는 [확정 기준의 적용 상태](observatory-design-standard.md#7-적용-상태와-이후-변경)에서 구별한다. 적용은 기존 색 생성 경로와 공통 부품을 통해 수행하고, 확장 중인 천문대의 장면/수리 반응/상호작용 개수를 고정하지 않는다. 원문·개인 배치·출제/오류/자료 의미색을 보존한다.

#### 현재 구현의 전수 대조와 유지보수

정적 오류·접근성 판단 보류·Firefox와 관련 저장/편집 경로의 후속 보수는 [후속 수정 결과](design-system-remediation-20261001.md)에 연결합니다. Effect의 실제 재실행 조건, 읽기 전용 보기 키와 편집 칸의 정체성, 이름 있는 Card/그래프 조절/독립 스크롤 구역의 의미를 실제 호출처에서 유지합니다. 화면 순회는 각 화면의 기본 크기와 확대를 분리하고 원래 문서를 남기는 해시 이동의 스타일/구독 누적도 확인합니다.

2026-10-01 사용자 “다시 수정하고 전수검증해”에 따라 위 11개 채택 영역을 실제 구현과 대조했습니다. 첫 화면 코드81개/CSS32개와 마지막 현재 소스86개/CSS34개·30개 화면 경로·공통 부품 예시16개가 대조 대상이며, 코드 편집 버튼/체크/오류 안내와 개념 검토 체크를 공통 부품에 연결했습니다. 목차 역할 글자의 밝은 테마 대비, 수식 B 설명의 어두운 테마 대비, 필기 영역의 키보드 스크롤과 조작 구역 이름을 보완했습니다. 전체 검사와 실패 재검사의 버전·결과·남은 조건은 [전수 대조 결과](design-system-verification-20261001.md)에 둡니다. 지침을 추가했다는 사실과 실제 구현/검사 결과를 구별하며, 이 문서와 해당 결과를 앞으로의 관련 변경에서 재사용합니다.

#### 이후 작업에서 실행하는 기준

1. **기초를 확인하고 부품으로 연결합니다.** 관련 토큰·Typography·배치와 공통 부품의 API/상태를 먼저 확인하고 재사용합니다. 기존 기능의 수정에도 적용하되 기반 전체의 재구축을 작은 화면 결과의 선행조건으로 삼지 않습니다.
2. **새 차이는 필요한 변형으로 표현합니다.** 동일 역할이면 기존 부품의 속성/상태를 확장합니다. 다른 책임이나 반복되는 조합이 확인됐을 때만 새 부품/패턴을 만들고 계약과 사용처를 갱신합니다. 한 번 쓰는 구획까지 모두 추상화하거나 반복 사용 근거 없는 변형을 추가하지 않습니다.
3. **설계 도구와 실제 구현을 대응시킵니다.** Figma 작업에서는 변수·컴포넌트 속성·인스턴스·내용에 맞춘 배치와 앱 토큰·props·부품의 관계를 남깁니다. 등록된 자산/생성 명령을 재사용하며 등록만으로 앱 연결 완료라고 하지 않습니다. 자동 실시간 동기화는 실제 설치/실행 증거가 있을 때만 보고합니다.

## Light/Dark와 사용자 설정

`document.documentElement.dataset.theme`가 light/dark이면 명시 설정을 따르고, 속성이 없으면 OS `prefers-color-scheme`을 따른다. 화면별 색상 반전을 하지 않는다. 기존 사용자 글꼴·간격·색 설정의 실데이터 Import는 후속 Phase이며 지금 자동 이전했다고 주장하지 않는다.

색의 hex와 shadow 숫자는 token 파일에만 둔다. CSS media query에는 custom property를 쓸 수 없어 40rem 조건을 사용하며 같은 토큰의 명시 예외로 문서화한다. 화면의 도형·막대 값 등 데이터 의존 치수는 일반 간격 토큰과 별도다.

- 확인: 색상 직접 값·색 함수, 글꼴/크기/굵기/행간/자간 직접 값, 절대 간격·모서리·그림자 직접 값, 정의되지 않은 디자인 토큰, 변수 fallback 안의 직접 값. 지역 별칭으로 우회한 값도 소비 속성의 역할을 따라 확인합니다. 공통 `src/ui/tokens.css`는 실제 값의 정의를 소유합니다.
- 허용: 0·0px, inherit/normal/none/auto/transparent/currentColor 등 기본 CSS 의미, 토큰의 계산식·단위 없는 배율, 비율 간격, env 안전 영역, 이미지 URL, 미디어 조건. 폭·높이·위치·변환·격자 치수·SVG stroke-width·기존 경계 두께 등 도형/레이아웃 값은 이 좁은 검사의 대상이 아닙니다. 강제 색상 모드의 시스템 색은 그 미디어 조건 안에서 허용합니다. 런타임 목차 깊이 `--outline-indent`는 디자인 토큰으로 오인하지 않습니다.
- 국소 예외: 필요할 때 바로 앞에 `/* design-token-exception: padding -- 외부 임베드가 요구하는 고정 여백 */`처럼 **다음 한 선언의 속성과 구체적인 이유**를 적습니다. 전체 파일의 검사를 끄지 않으며, 예외로 토큰 오타나 파싱 오류를 숨기지 않습니다. 예외 수는 결과에 표시됩니다. 새 토큰·예외의 필요성과 역할 적합성은 작업자가 판단합니다.
- 한계: TSX 인라인 스타일·외부 라이브러리의 CSS는 검사하지 않습니다. 토큰이 실제 선택자/테마에서 제공되는지, 같은 역할의 부품을 재사용했는지, 상태의 실제 의미·접근성·저장 신뢰·시각적 만족은 정적 검사만으로 보장하지 않습니다. 관련 공통 부품과 실제 앱에서 확인합니다.

화면의 기존 크기를 보존하기 위해 detail(자료 안내 `.9rem`), metric(통계 숫자 `1.5rem`), chart(차트 글자 `12px`), title/brand tracking(`-.035em`/`.12em`) 역할을 토큰으로 옮겼습니다. 본문·Caption 등의 기존 크기는 바꾸지 않습니다. 개인 진입의 16/24/48px 간격, 그래프 라벨의 크기/행간, 시험 타이머·주제 카드의 글자 역할도 같은 값의 기존 토큰을 참조합니다. 시험 화면의 compact 폭은 기존 fallback과 같은 40rem로 정의합니다. 메모 오류 문구의 존재하지 않던 `--color-error` 참조는 기존 오류 의미색 `--color-danger`로 수정합니다. 저장·ID·초안·원문·배치를 변경하는 작업은 아닙니다.

도구 선택은 [PostCSS](https://github.com/postcss/postcss/blob/main/docs/api.md)와 [postcss-value-parser](https://github.com/postcss/postcss-value-parser)의 공개 파싱 API를 재사용하고, **프로젝트의 토큰 정책만 작은 검사로 구현**했습니다. 기존 Vite의 PostCSS 8.5.28을 직접 개발 의존성으로 명시하고 값 파서 4.2.0을 추가합니다. [Stylelint 기본 규칙](https://stylelint.io/user-guide/rules/)과 [declaration-strict-value](https://github.com/AndyOGo/stylelint-declaration-strict-value)는 일반 CSS 검사/변수 사용 강제 후보로 확인했습니다. 이번에는 이미 있는 파서를 이용하여 토큰 정의·fallback·지역 별칭·선언별 예외를 하나의 제한된 검사로 다루고, 기존 Biome·Storybook·Playwright 경로를 유지합니다. 이 자체 정책을 공인 표준이나 전체 CSS 검증으로 표현하지 않습니다. 더 넓은 CSS 문법·관례 검사 필요가 생기면 Stylelint 도입을 해당 요구에서 다시 판단합니다.
