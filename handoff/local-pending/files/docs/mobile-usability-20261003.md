`text-wrap` 후보를 같은 WebKit 빌드에 적용해 비교했다. `inter-character`는 이 실행에서 지원되지 않았고 `line-break: anywhere`·`word-break: break-all`로는 공백이 줄지 않았다. 기본 `wrap`이 공백을 줄여 이를 선택했다. 이는 이번 문단에 대한 관측이며 WebKit 내부 알고리즘 전체의 원인 설명은 아니다. [MDN의 text-wrap 설명](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-wrap)과 [scroll-padding-bottom 설명](https://developer.mozilla.org/en-US/docs/Web/CSS/scroll-padding-bottom)의 브라우저 속성을 기존 구현에 연결했다. 기존 WCAG 기준은 아래에 유지하며 제품 전체 적합성 판정으로 확대하지 않는다.

나눔명조에서 파생한 `ManSeekSong Paper` 700/native95% 서체 파일을 교체하거나 transform으로 본문을 축소하지 않았다. 원문·sourceId `01-015`·읽기 배포 자료·저장 키를 재생성하지 않았다. 기본 16px/29.6px 및 넓은 본문 18px, justify/start를 확인했고, 기존 CSS 변수의 개인 서체·크기·줄높이 오버라이드를 합성 조건에서 유지했다. 개인 폭을 고정하거나 덮어쓰는 새 규칙을 추가하지 않았으며, 320px·분할 창·폭 변경 뒤 본문 재배치를 확인했다. 실제 개인 계정의 모든 설정 조합을 전수 시험한 결과는 아니다.

## 발견한 문제

### 1. 버튼에 초점을 옮겨도 하단 메뉴가 버튼을 가린다 — 우선 수정

402×681 WebKit에서 첫 장면을 읽고 `처음부터 보기` 버튼을 화면 안으로 자동 스크롤한 뒤, 스크롤 위치가 안정될 때까지 기다렸다. 버튼은 y=632.80–680.80px, 고정 메뉴는 y=615.25–681px이었다. 버튼 중앙의 실제 hit test는 메뉴를 가리켰다. 버튼에 초점을 옮겨도 같은 위치에 남았다.

문서 끝으로 추가 스크롤하면 버튼은 y=431.80–479.80px에 노출된다. 따라서 영구적인 기능 접근 불가는 아니지만, 자동 스크롤/초점 이동이 사용자에게 조작 대상을 드러내지 못하는 결함이다. 320px 추가 조건에서는 같은 가림이 발생하지 않았다.

관련 구현: `src/app.css`의 좁은 화면 고정 `.bottom-nav`, `src/ui/concept-library.tsx`의 reader footer/관찰 이동, `src/ui/concept-library.css`의 `.concept-reader-footer`.

수정 방향: 실제 메뉴 높이와 safe area를 반영한 스크롤 여백을 읽기/초점 이동 대상에 연결한다. 현재 스크롤 위치·선택 장면·초안을 보존하면서 목표 버튼 전체가 메뉴 위에 드러나는지 확인해야 한다.

### 2. 양쪽 정렬에서 공백이 크게 늘어난다 — 사진과 동일 재현

402px WebKit의 360px 본문 폭에서 글자는 16px, 줄높이는 29.6px, 700 명조, 양쪽 정렬/마지막 줄 시작 정렬이었다. 두 번째 문단의 일반 공백은 마지막 줄에서 약 4–5px, 앞줄에서 최대 19px로 늘어났다. 첨부 사진과 같은 문단의 벌어진 간격과 낱말 중간 줄바꿈을 실제 screenshot에서 확인했다. 320px에서는 최대 17px였다.

같은 빌드의 인앱 브라우저에서는 같은 문단이 더 촘촘하게 표시되었다. 화면 폭·서체·정렬 속성이 맞거나 페이지 가로 넘침이 없다는 사실만으로 한국어 가독성의 성공을 판정할 수 없다. 엔진별 조판 차이는 관측했지만 내부 줄바꿈 알고리즘의 원인을 확정하지는 않았다.

관련 구현: `src/ui/concept-library.css`, `src/ui/paper-typography.css`, `src/ui/paper-typeface.css`, `src/ui/observatory-feature-identity.css`의 실제 CSS 우선순위.

수정 방향: 승인된 700/native95%/justify/start와 개인 서체·폭·원문을 유지하면서 좁은 한국어 문단의 줄바꿈·정렬 방법을 WebKit에서 조정한다. 왼쪽 정렬로 일괄 전환하거나 원문에 공백/줄바꿈을 삽입해 해결하지 않는다. 공백 19px는 이번 관측값이며 자체적으로 정한 WCAG 수치가 아니다.

### 3. 메뉴에서 현재 위치가 화면 밖에 남는다

402px와 320px에서 고정 메뉴 18개가 1,293px 한 줄에 놓인다. 개념 전집을 열어도 메뉴 scrollLeft=0, 현재 항목은 x=847.48–919.14px에 남아 보이지 않는다. 사진에서도 양옆 항목이 부분적으로 잘려 있다. 가로 스크롤 기능 자체와 현재 위치 표시/추가 기능 발견 가능성은 별도 문제다.

관련 구현: `src/app.css:533`과 `src/ui/navigation-bar.tsx:12`. 메뉴는 현재 상태를 `aria-current`로 표시하지만 직접 진입/읽기 선택 시 해당 항목을 보이는 범위로 이동시키는 동작이 없다.

수정 방향: 현재 항목을 항상 보이는 범위로 노출하고 추가 메뉴가 있다는 단서를 제공한다. 기능 수와 기존 링크/복귀를 보존하며, 주요 이동과 전체 메뉴의 구성을 승인된 레이아웃 기준 안에서 조정한다. 가로 메뉴라는 이유만으로 WCAG 위반을 단정하지 않는다.

- [Focus Not Obscured 2.4.11](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html): 초점 이동 후 고정 메뉴가 조작 대상을 가리는지 확인. 이번 확인을 제품 전체 WCAG 적합성 감사로 표현하지 않는다.
