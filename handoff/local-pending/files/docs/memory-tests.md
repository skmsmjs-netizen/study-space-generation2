# 암기 항목과 쪽지시험

## 생성 대기 상한 · 2026-10-01

사용자 ‘시간 오래 걸리면 절대 안 된다’ 요청으로 암기항목 생성의 기존 약3분 대기를 제거했다. 새 초안은 기본3항목이며 짧은 질문과 필수 조건을 갖춘 간결한 답안을 요청한다. 필요한 조건·단위·예외는 유지한다. 기존 수동 항목 수·출제 초점·검토 결과·저장된 초안은 변경하지 않는다. 이미 등록한 항목으로 쪽지시험을 시작할 때는 GPT를 호출하지 않는다.

[OpenAI의 지연 최적화 안내](https://developers.openai.com/api/docs/guides/latency-optimization)의 출력 길이 감소와 작은 모델 선택 원칙을 현재 계정 모델 목록과 기존 완료 응답 계약에 연결했다. 암기항목 요청에만 계정 목록의 Luna 모델을 우선하고, 없으면 연결된 기존 모델을 사용한다. Luna 이름에 따른 후보 선택이며 실제 제공 모델의 생성 시간/품질을 측정한 증거는 아니다. 일반 자료용 모델 설정은 바꾸지 않는다. 공급자에 없는 모델·API 키·추가 크레딧·자동 재요청을 추가하지 않았다.

클라이언트는 상태 조회·인증·생성 요청·본문 수신 전체를 하나의10초 상한으로 묶는다. 상한에 도달하면 대기를 거부하고 fetch를 취소하며 늦게 도착한 상태/결과로 새 추론 또는 결과 적용을 시작하지 않는다. 로컬 middleware는 주제 생성 요청의 서버 인증/권한 재확인과 실제 추론에 같은 취소 신호를 전달한다. 입력과 기존 등록 항목은 유지하며 새 생성은 사용자의 직접 요청에만 시작한다. 정상 완료 후에는 타이머를 지운다. 10초는 앱의 대기 종료 기준이며, GPT 생성 완료나 운영체제의 타이머 실행 시점을 보장하는 수치가 아니다.

확인용 실제 UI/HTTP에15초 응답을 넣어 종료/서버 요청 취소·원문 보존·새로고침 복원·정상 응답 복귀를 확인한다. 실제 GPT 추론 속도/구독 사용·공개 배포는 이번 확인에 포함하지 않는다. 실행 자료와 정확한 결과는 work/topic-memory-speed-20261001/README.md·verification.json에 기록한다.

## 응답 수신과 가정 응답의 직접 확인 · 2026-10-01

사용자 ‘어떤 응답을 받았다고 치고 받는 단계까지 구현’ 요청으로 실제 generateTopicMemory의 HTTP 응답 수신을 src/data/topic-memory-response.ts로 분리·보완했다. 완료한 UTF-8 JSON을 모두 읽고 질문/답안·주제 ID·중복 ID·요청 당시 범위를 검증한 뒤에만 기존 검토 초안에 전달한다. 한글 중간에서 나뉜 전송도 보존하며 최대30항목의 도메인 문자 제한을 포함하는 2MB 이내에서 수신한다. 통신 중단·불완전/HTML/빈 응답·다른 범위·과대 응답은 성공으로 적용하지 않고 입력을 유지한다. 오류 뒤 연결 설정도 같은 암기시험에서 연다. 기존 공식 DevKit의 response.completed 확인과 사용자 검토·초안/등록 규칙을 재사용하며 계정/한도 제한을 바꾸지 않는다.

work/topic-memory-receive-20261001의 별도 로컬 화면에서 실제 MemoryTests → generateTopicMemory → HTTP → localStudyAIPlugin → generateGPTTopicMemory → 수신 검증 → 검토/초안 → 공통 저장 명령을 IAB로 직접 실행했다. 계정·GPT runtime만 확인용으로 대체하고 외부 통신은 막았다. 회로이론/수동 소자/커패시터 예시 질문·답안3개를 받아 답안 수정·항목 제외·reload 유지, 등록 실패→저장만 재시도→중복 없음(항목2개), 기준 답 숨김→시험 답안 작성→비교→미판정 시험1개 저장을 확인했다. 이후 불완전 응답·한도 오류에서 기존 항목2/시험1/공부 기록0/출제 조건을 유지하고 정상 응답3개로 복귀했다. 총 확인용 호출4회(정상 완료2, 불완전1, 한도 오류1)이며 실제 구독 사용·운영 서버 저장은 아니다.

관련17검사·Chromium/WebKit2흐름·현재 소스 타입/빌드·디자인·수신 모듈 lint 통과. 공유 의존의 undici 오류 및 work 사본 중복 발견으로 공유 Vitest 실행은 실패했으며, 같은 현재 소스와 정상 의존의 격리 사본에서17검사를 확인했다. 개인 기록/자격증명/구독 설정·공개 배포는 변경하지 않았다. 시험 실행 방법·현재 포트·증거는 work/topic-memory-receive-20261001/README.md 및 verification.json이다.

2026-10-01 사용자의 ‘입력한 개념·답안으로 암기시험을 만들고 수식은 스케치로 등록’ 요청을 실제 웹앱에 구현한 범위입니다.

메뉴의 **암기시험** 또는 주제 화면의 **암기시험 만들기**에서 엽니다. 주제에 질문·개념과 기준 답안을 등록하고, 현재 공부 범위에서 과목·주제·문항 수를 골라 쪽지시험을 시작합니다. 기준 답안과 응시 답안은 글이나 펜 필기로 작성합니다. 기준 답안은 그림만 있어도 됩니다. 모든 공부 기록에 개념 등록을 요구하지 않습니다.

## 실제 흐름

1. 암기 항목 등록 → 주제 선택 → 질문·개념과 기준 답안 입력 → 항목 저장.
2. 과목·주제와 문항 수 선택 → 등록 항목을 중복 없이 섞어 출제. 등록 수보다 문항 수가 크면 실제 출제 수를 미리 표시합니다.
3. 문항별 글·펜 답안 입력. 응시 중 기준 답안은 화면/DOM에 표시하지 않으며 모든 문항을 지난 후 시험을 마칩니다. 이전 문항으로 돌아갈 수 있습니다.
4. 출제 당시 기준 답안과 나란히 비교하여 맞음·부분적으로 맞음·틀림·판단 보류·미판정을 직접 남깁니다. 무응답은 틀림·맞음·부분적으로 맞음으로 처리하지 않습니다.
5. 시험 결과 저장 → 재접속·지난 시험 조회 → 틀리거나 부분적으로 맞은 문항을 다시 시험. 지난 시도의 응답·결과는 보존합니다.

시험 중단은 현재 답안 원문을 초안 보관본에 보관하고 항목 목록으로 돌아갑니다. 항목 편집 취소와 보관도 현재 초안을 보관하며, 항목 보관은 소프트 삭제입니다. 복원 시 같은 ID·원문·이력을 유지합니다.

- 카드·시험은 공통 `StudyRepository`와 개인 원장/outbox를 사용합니다. 로컬 저장과 서버 수신은 기존 저장 상태로 구별합니다. 서버 기능 목록에 해당 명령이 없으면 전송 불가를 알리고 초안을 유지합니다.

- 초안은 사용자/공간/탭으로 나누며 새로고침 시 이어집니다. 손상 초안·경합 원문을 덮어쓰지 않고 보관/파일 내보내기를 제공합니다. 저장 실패의 최신 입력은 구조를 자르지 않고 유지합니다.

이번 스케치는 PNG·사진 업로드가 아니라 기존 메모와 같은 벡터 선입니다. 공통 원장에 좌표를 저장하고 원문을 손실 없이 압축합니다. 별도 이미지 Storage나 용량 플랜 변경을 구현했다고 보고하지 않습니다. 이미지 가져오기·OCR·AI 변형 출제·손글씨 자동 채점·시험 제한시간은 이번 구현 범위 밖입니다.

## 2026-10-01 목차·주제로 GPT 암기항목 생성

민석의 ‘필기나 교재 본문뿐 아니라 입력한 목차·주제로도 출제’ 정정을 채택했다. 개인 공간의 암기시험 → GPT로 암기항목 만들기 → 과목/상위 목차/주제와 항목 수 선택 → 이 목차로 생성 → 질문·기준 답안 수정/제외/확인 → 확인한 항목 등록 → 기존 쪽지시험 흐름에 연결한다. 필기 본문이나 문제 답안의 사전 입력은 필요하지 않다. 기본은 선택한 주제 1개·3항목이며 같은 과목의 여러 주제 선택은 펼쳐서 제공한다. 다른 과목의 이름이 같은 주제를 섞지 않는다.

### 기존 방법과 연결 선택

- 이전에 확인한 [OpenAI Structured Outputs 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 ‘형식 준수와 내용 정확성은 다름’ 기준을 재사용했다. 기존 공식 local DevKit의 Responses 완료 스트림과 구독 포함 사용량 경로를 그대로 사용하고, 이번 JSON 결과는 앱의 명시적인 타입/길이/주제 ID 검증을 통과한 경우만 받는다. 현재 연결에 없는 구조화 출력 기능을 사용했다고 주장하지 않는다. 일반 지식으로 출제하며 실제 교재의 근거 문장·수업 범위·시험 출제 확정이라는 출처는 만들지 않는다.
- 기존 owner AI 인증·승인 확인·추가 크레딧 OFF 확인·계정에서 조회한 모델·공유 20회/시간 제한을 재사용한다. 새 API 키/유료 대체 모델/자동 재시도는 추가하지 않는다. 실제 응답의 형식 검증은 내용이 옳다는 보장이 아니므로 등록 전 질문과 답안을 확인하고 고칠 수 있게 한다.
- 암기시험의 기존 초안 안전 저장/충돌 사본/보관본, saveMemoryCard·개인 원장/outbox·서버 codec과 비교/재시험 흐름을 재사용한다. 새 DB 컬렉션이나 SQL 마이그레이션은 추가하지 않는다. 새로 만든 부분은 목차 기반 생성의 입력/출처 계약, 로컬 생성 endpoint, 검토·등록 화면이다.

### 반복 사용과 보존

- 한 번에 1–30항목·동일 과목 최대20주제를 선택한다. 이는 이번 앱의 처리량 제한이며 학습량의 표준/효과 기준이 아니다. 선택을 조용히 잘라 처리하지 않는다. 여러 주제 목록은 높이를 제한하고 스크롤하며 전체 이름을 읽을 수 있게 한다.
- 생성할 때만 최신 과목/목차의 ID·이름·버전을 다시 읽는다. 결과를 받은 뒤의 목차 변경은 기존 검토 결과를 덮어쓰지 않는다. 등록 시 현재 또는 보존된 수정 이력에서 과목·주제·상위 경로를 검증한다.
- 받은 결과/수정한 질문·답안/포함·확인 선택은 기존 owner+namespace+탭 초안에 저장한다. 화면을 떠난 뒤 도착한 완료 결과도 같은 초안에 보관한다. 저장 공간 오류·동시 수정은 기존 안전 저장/복구 흐름을 사용하며 현재 결과를 파일로 보관할 수 있다. 브라우저 종료/강제 새로고침으로 전송 자체가 끊기면 새 생성은 자동 시작하지 않는다.
- 닫기/새 생성 전에 이전 초안의 보관본을 남긴다. 등록 오류는 이미 받은 결과를 유지해 저장만 재시도한다. 같은 생성 ID의 재등록과 같은 주제의 질문·답안이 정확히 일치하는 재생성은 기존 항목/수정본/보관 상태를 유지한다. 의미가 비슷하다는 이유만으로 다른 조건의 항목을 삭제하지 않는다.
- 등록된 항목은 topicGeneration에 ‘주제 기반 생성’, 생성 ID/항목 ID/시각/모델, 당시 입력 목차, 원래 생성 질문·답안과 확인 여부를 보존한다. 사용자 수정 답안과 구별한다. 이후 편집은 최초 출처를 유지하고 시험에는 그때의 출처를 복사한다. 기존 글·스케치·자료 기반 materialSource·수동 등록 항목을 유지한다. 공부 횟수/TRACE/숙달은 생성이나 등록으로 바꾸지 않는다.
